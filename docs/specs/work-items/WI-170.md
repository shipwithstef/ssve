## Problem

WI-168 and WI-169 give us the GENERATION mechanisms but no FORCING function. A user could ignore the auto-generated journeys forever and the same coverage gap that produced WI-184/195/196 would remain.

## Proposal

Tier-1 validator `test-framework/evals/tier-1/validate-chrome-journey-coverage.sh` that runs at every `route-workflow` session-start in `convert` repo mode (and after `onboard-repo`):

1. Scan `src/Layout.jsx` (or stack-equivalent) for chrome controls (same logic as WI-168's parser).
2. Cross-reference against `docs/specs/journeys/Chrome-*.feature.md` and `J-CAP-*.feature.md`.
3. For any uncovered control, emit:
   ```
   [chrome-coverage WARN] <surface>:<line> exposes <control> with no journey coverage. Run: write-journeys --auto-discover-chrome
   ```
4. Adaptation window: 30 days. After that, severity escalates to HIGH and `route-workflow` blocks lane execution until coverage is added or `concern-waived: chrome-coverage — <reason>` is added to the lane-tasks file.

**Why 30-day adaptation window:** retroactively forcing coverage on an existing project of Example Marketplace's scope (16+ chrome controls) would WAR-room the user. Soft-warn for 30 days lets them work through the backlog organically, then hard-block to ensure new chrome lands with coverage.

**Out-of-scope:**

- Greenfield (`bootstrap`) projects — chrome doesn't exist yet at session start; WI-170 is convert-mode only.
- Per-project opt-out via `.svc/capability-registry.json` `chrome-coverage-disabled: true` (escape hatch for projects where the chrome model genuinely doesn't apply, e.g., headless API).

## Acceptance criteria

- AC1: Running `validate-chrome-journey-coverage.sh` in Example Marketplace today emits ≥1 WARN for the language switcher (until WI-168 generates the journey).
- AC2: After WI-168 generates the chrome journeys + commits them, validator passes.
- AC3: Adaptation timer logic: validator reads `.svc/chrome-coverage-installed-at` timestamp; if `now - installed_at > 30 days`, severity flips WARN → HIGH.
- AC4: Escape hatch via `concern-waived: chrome-coverage — <reason>` in lane-tasks works.
- AC5: greenfield/bootstrap projects skip the check entirely.
