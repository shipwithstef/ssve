# WI-189: Skill corpus violates its own 500-line progressive-disclosure norm

## Problem

The framework reliability review found HIGH issue F-019: Skill corpus violates its own 500-line progressive-disclosure norm.

## Evidence

Top offenders include `base44-environment` 1601 lines, `write-journeys` 1406 lines, `design-ui` 1316 lines, `build-personas` 1140 lines, and `validate-feature` 1109 lines.

## Impact

Large skills consume context, hide critical gates, and slow every triggered session.

## Proposed Fix

Extract mode-specific references and leave only routing, contract, and self-verify in `SKILL.md`.

## Acceptance Criteria

- AC1: INVALIDATED AS FILED. The current canonical convention explicitly says existing legacy skills are not to be refactored wholesale only to satisfy the line-count convention.
- AC2: `test-framework/evals/tier-1/validate-progressive-disclosure-scope.sh` proves the canonical scope and this closeout.
- AC3: No skill contracts were refactored because that would contradict `references/skill-conventions.md`; the new validator locks the current scope instead.
- AC4: `bash test-framework/evals/run-all-evals.sh` passes with the invalidation validator included.

## Closeout

**Status:** CLOSED-INVALID
**Closed:** 2026-05-11
**Commit:** this closeout commit

### Verdict

Invalid as filed. The review finding correctly observed that many legacy `SKILL.md`
files exceed 500 lines, but it treated a future-authoring convention as a
retroactive corpus-wide requirement.

`references/skill-conventions.md` is explicit:

- `SKILL.md` should keep workflow and decision points while depth moves to references.
- The convention applies to new skills authored on or after 2026-04-28.
- Existing legacy skills are not refactored wholesale only to satisfy this convention.
- Legacy skills are converted opportunistically when they are already being substantively edited.

Current line counts confirm the corpus is still large, so this is not marked
fixed. It is closed because the filed remediation would force a risky mass
refactor that current doctrine explicitly rejects.

### Evidence

- `wc -l */SKILL.md | sort -nr` still shows legacy large skills, so no false claim of corpus slimming is made.
- `references/skill-conventions.md` defines legacy wholesale refactor as a non-goal.
- `test-framework/evals/tier-1/validate-progressive-disclosure-scope.sh` locks that scope.

### Acceptance Criteria Disposition

- AC1: Not implemented as filed; invalidated by canonical progressive-disclosure scope.
- AC2: Satisfied by `validate-progressive-disclosure-scope.sh`.
- AC3: Satisfied by preserving skill contracts and validating the doctrine boundary.
- AC4: Satisfied by full tier-1 passing with this validator.
