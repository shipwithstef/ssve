# WI-347: Implement the Absolute Plan Standard

## Problem

Under the current Serious Vibe Coding (svc) planning model, [plan-changeset/SKILL.md](file:///workspace/seriousvibecoding/plan-changeset/SKILL.md) explicitly prohibits writing exact code payloads or context-rich `before/after` diff blocks in plan manifests, and fails to require step-by-step CLI execution command sequences.

This leaves significant creative discretion to the developer or execution model during the implementation phase (`execute-changeset`). The result is frequent spec-to-code drift, unrun test blocks, arbitrary git commits, and silent G5/G6 quality gate bypasses.

## Impact

Without an absolute blueprint, the token-economy division of labor between strategic planning (Opus 4.7) and mechanical execution (MiMo-V2-Pro / Sonnet 4.6) degrades. The executing agent is forced to invent implementation details, variable names, and error handling, causing execution failures and high re-dispatch costs.

## Fix

We will implement the **Absolute Plan** standard by mutating five key framework areas:
1. **Skill Definition (`plan-changeset/SKILL.md`):** Remove the code payload ban. Mandate a `## Changeset Blueprint` section (for CREATE payloads and context-rich MODIFY diffs), a step-by-step `## Execution Command Sequence` section (containing a copy-pasteable, non-interactive fenced bash pipeline from worktree checkout to merge), and a `## Prerequisite Alignment Matrix` to map planned tasks directly back to UX transitions, UI visual tokens, Technical Design components, and Style Contract imports.
2. **Execution Decoupling (`execute-changeset/SKILL.md`):** Enforce **Zero-Context Execution-Only Payload Isolation (The Lean Executor)** so that the orchestrator strips all upstream specs, UX, UI, and competitor files when dispatching tasks to MiMo or Sonnet subagents, providing only the task's blueprint and execution sequence. Enforce the **Sequential, Cost-Aware Multi-Option Exploration & Debugging Loop** where the Orchestrator Parent intercepts failures (with specific exit codes `NEEDS_CONTEXT = 75` or `BLOCKED = 76`), executes a lightweight `execution-diagnose` probe (representing a non-chaining execution-mode routine modeled after `diagnose-bug` P2-P3) to isolate the root cause, synthesizes 2-3 alternative execution paths using a structured `.svc/task-context-gap.json` schema, prioritizes and runs them sequentially to preserve the token budget, tiers debugging tasks to high-reasoning models (Sonnet 4.6 / Codex / host-best), and gracefully rolls back and escalates an Attempt Ledger only if all options fail.
3. **Plan Linter (`scripts/verify-plan-mechanical.sh`):** Add `C7-FAIL` (verifies the bash execution sequence block), `C8-FAIL` (verifies MODIFY diff fences), and `C9-FAIL` (verifies the prerequisite matrix).
4. **Review Protocol (`references/plan-review-protocol.md`):** Add `h: Command Determinism` and `i: Blueprint Completeness` to the primary adversarial review dimensions.
5. **Receipt Schema (`schemas/receipts/plan-manifest.schema.json`):** Require `changeset_blueprints` and `execution_command_sequence` arrays, validating their structural completeness.
