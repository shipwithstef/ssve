# WI-298: Delivery graph schema and route-workflow compiler

## Goal

Define the additive `delivery_graph` schema and make `route-workflow` compile it before any downstream mutating or end-to-end work begins.

## Required Shape

The graph must capture:

- normalized user intent
- repo mode and change type
- selected lane and delivery mode
- risk flags
- platform contracts
- evidence families
- required skills
- conditional mandatory skills
- optional skills
- skipped/N/A skills with evidence
- verification tiers
- mutation history
- closeout classification requirement

## Acceptance Criteria

- AC1: `route-workflow/references/task-graph-protocol.md` defines the `delivery_graph` schema.
- AC2: `route-workflow/references/lane-model.md` defines initial graph compilation rules for the seven lanes.
- AC3: `route-workflow/SKILL.md` contains only a short pointer to the graph compiler contract, preserving WI-215's hot-path trimming goal.
- AC4: `scripts/task-graph.mjs` or a dedicated compiler helper can initialize a lane task file with a valid `delivery_graph`.
- AC5: Fixtures cover at least framework change, browser-visible product change, backend/Base44 change, docs-only change, and retroactive corrective closure.
