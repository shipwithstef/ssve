# WI-157: Fix visual-output post-skill hook path mismatch for design-logo

**Type:** framework
**Status:** VERIFIED
**Severity:** HIGH
**Filed:** 2026-05-08
**Source:** route-workflow framework audit

## Audit Verdict — VALID (ship as filed)

Confirmed silent path mismatch:
- `route-workflow/SKILL.md` line 191 (visual-output post-skill hook): expects `docs/specs/<skill>/in-app-verification/`
- `design-logo/SKILL.md`: writes to `docs/specs/logo-pack/in-app-verification/`

The hook checks the wrong path → never finds the captures → hook either silently fails or auto-invokes redundant capture script. Either way the gate is broken for design-logo.

**Ship plan:**
1. Pick canonical: most likely align design-logo to write `docs/specs/design-logo/in-app-verification/` (matches hook expectation; matches the convention used by other visual-output skills).
2. Update design-logo/SKILL.md write path + any references in its body.
3. Migration: if existing repos have evidence under `logo-pack/`, write a one-time migration note in the WI commit body.
4. Tier-1 validator: enumerate visual-output skills (from route-workflow line 187), confirm each writes to `docs/specs/<skill-name>/in-app-verification/`.

## Problem
The live-evidence post-skill hook checks `docs/specs/<skill>/in-app-verification/` (e.g., `docs/specs/design-logo/in-app-verification/`). But `design-logo/SKILL.md` writes screenshots to `docs/specs/logo-pack/in-app-verification/`.

The hook's path template does not match the skill's actual output path.

## Impact
For `design-logo`, the hook will never find pre-existing screenshots and will always trigger the fallback capture script, adding latency and cost.

## Acceptance Criteria
- [x] Audit all visual-output skills for their actual in-app-verification paths
- [x] Align hook path resolution with skill output contracts
- [x] Either: (a) standardize all skills to `docs/specs/<skill-name>/in-app-verification/`, or (b) make the hook read the skill's declared output path from frontmatter
- [x] Update `landing-page`, `design-ui`, `design-logo`, and external addon skills

**Next:** `improve-framework` → `plan-changeset` → `execute-changeset`

## Closeout

Closed 2026-05-10. Live audit showed `design-logo` had already moved to `docs/specs/design-logo/in-app-verification/`, while `design-ui` intentionally writes per-screen captures under `docs/specs/ui/<screen>/in-app-verification/`. The hook contract now resolves the screenshot directory from each local visual-output skill's `outputs.produces` entry with `artifact: live-page-screenshots`, falling back to `docs/specs/<skill>/in-app-verification/` for external addons without local contracts.

`landing-page` and `design-ui` now declare `live-page-screenshots` outputs; `design-logo` already did. The tier-1 visual-evidence validator now fails if any svc-native visual-output skill lacks the declared artifact path or if route-workflow stops resolving declared paths.
