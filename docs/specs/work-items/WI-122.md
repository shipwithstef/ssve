## Problem

`scripts/preflight.mjs` (WI-096) validates that a skill's required inputs exist and
outputs are writable. Today it's invoked manually at the top of skills. A skill
that forgets the call will operate on partial state. Wiring preflight as a
PreToolUse hook for the `Skill` tool catches this systemically.

## Scope

### In scope
- Extend `scripts/preflight.mjs` with `--hook` mode that reads stdin payload, runs preflight when tool_name=Skill and a `.svc/preflight-<skill>.json` config exists, always exits 0
- Add PreToolUse entry in `hooks/hooks.json` matched `*` (with internal early-return for non-Skill events) — soft warn only

### Out of scope
- Per-skill preflight config files (skills opt-in by creating `.svc/preflight-<skill>.json`)
- Hard-block mode (current implementation is soft-warn only)

## Acceptance criteria

1. `scripts/preflight.mjs --hook` reads stdin and exits 0 for non-Skill events. ✅
2. For Skill events with no co-located config, exits 0 silently. ✅
3. For Skill events with bad config, prints JSON WARN to stderr but exits 0. ✅
4. PreToolUse entry in `hooks/hooks.json` runs `node scripts/preflight.mjs --hook`. ✅
5. Existing `validate-preflight-coverage.sh` still passes. ✅
6. Tier-1 sweep passes. ✅
7. lint-skills-manifest clean. ✅
