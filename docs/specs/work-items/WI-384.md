# WI-384: Action-point learning injection (extend the WI-361 signal injector to learnings)

**Status:** in_progress (worktree wi384; action-time injector + lib + fires ledger + validator built & verified — 12/12; injector edit user-authorized 2026-06-08)
**Lane:** framework
**Size:** M
**Stage:** S2
**Source:** flow-architecture audit (wf_e0063433), 2026-06-08

## Problem
Learnings reach the agent only via SessionStart, which shows the LAST 5 tracked entries (`hooks/svc-learning-preload.mjs` `MAX_TRACKED=5`, `.slice(-5)`, recency-only) — so ~88 of 93 framework learnings (88 carry non-empty `files` arrays = perfect injection keys) never fire, and the few that do arrive hours before the action they guard. Separately, 0/116 learnings carry a `fires` field, so the elevation predicate (confidence≥8 AND fires≥3) is unfireable.

## Mechanism
Index learnings by their `files` arrays and `skill` field; inject 1-3 matching learnings as PreToolUse/PostToolUse additionalContext the moment the agent first touches a matching path or invokes a matching skill. Extend `hooks/svc-learning-preload.mjs` (NOT a phantom injector slice). Retire the honor-system "grep learnings before acting" step on injector hosts; keep SessionStart preload as fallback.

## Mechanism (as built)
A new PreToolUse hook + a shared index lib + a fires ledger:
1. **`hooks/lib/learning-index.mjs`** — `loadLearnings` (framework + project ledgers), `matchByPath` (files[]-keyed) / `matchByCommand` (Bash-error-class), order-stable (confidence desc, key asc); `firesCount` + `elevationCandidates` (the now-computable predicate).
2. **`hooks/svc-learning-inject.mjs`** — PreToolUse (Edit|Write|Bash): matches the touched path/command, injects ≤3 learnings as `additionalContext` with `permissionDecision:"allow"` (never blocks), per-session memo dedup, appends fresh fires to `.svc/learning-fires.jsonl`. Fail-open (any error → exit 0; never breaks a tool call). *(New `hooks/svc-*` file placed under explicit user authorization past the config-protection guard.)*
3. **wiring** — `scripts/wire-hooks.mjs` + `hooks/hooks.json` register it; `.svc/perf-baseline.json` PreToolUse bumped 10→11 (the deliberate WI-397 latency-review).
4. **ledgers** — `.svc/learning-fires.jsonl` tracked (append-only, union-merge per WI-398); `.svc/learning-injections-*.json` session memo gitignored. SessionStart preload stays as fallback.

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-learning-injection.sh`
- **failure_class:** the action-time learning injector silently DENYING/blocking a tool call (it must be additive-only), losing match determinism (so the same path injects different/ordered-differently learnings), or failing to record fires (re-capping the elevation predicate).
- **promotion_signal:** condition 3 — protects a framework hot path (a new PreToolUse hook on every Edit/Write/Bash, `rules/plan-changeset-trigger.md` signal 2); a regression that turns it from additive to blocking would break every tool call.
- **expected_runtime_budget:** <1s (synthetic in-memory match + a few live hook spawns over a temp ledger; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** the hook runs on every Edit/Write/Bash; an additive→blocking or non-deterministic regression is catastrophic and silent, so the additive-only + order-stable + fail-open invariants must be re-proven every lint.

## Value-preservation
Pure add, increases value: no gate currently enforces learning application, so nothing is weakened. Token cost ~300-600 only on match vs growing the session-start preload toward 93 entries.

## Vision fit (whole-company / versatile PM)
Delivers the right runbook to the right desk at the exact moment of action — the company's training-and-knowledge function finally reaching the worker who needs it, which is what "continuously improves" actually means in practice.
