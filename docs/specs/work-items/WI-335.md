## Problem

The journey contract hardening landed execution traces and bridge validation,
but two routing/maintenance residuals remain. First, `write-journeys --refresh`
is not automatically triggered at milestone boundaries, so journey preconditions
can drift until a user notices. Second, the journey skills still carry duplicate
task-graph boilerplate that should either be deduplicated or intentionally
preserved with a rationale.

- `FRAMEWORK-STATE.md` still records the milestone refresh trigger and duplicate
  journey boilerplate as known gaps.

## Acceptance Criteria

- [x] Define the exact milestone-boundary condition that should trigger
      `write-journeys --refresh --all`, or reject the trigger with a documented
      false-positive analysis.
- [x] If accepted, wire route-workflow or verify-promotion to recommend or run
      the refresh before roadmap/readiness handoff.
- [x] Add a tier-1 fixture for the refresh-trigger decision.
- [x] Deduplicate task-graph boilerplate in `write-journeys` and
      `test-journeys`, or document why phase receipts fully supersede that
      cleanup.
- [x] Add a drift check so future task-graph boilerplate edits do not require
      hand-maintaining duplicate journey-skill blocks.

Run after WI-334 if journey validators need the refresh output shape.

## Closeout

Implemented on 2026-05-12.

- Added `scripts/check-journey-refresh-trigger.mjs` to make the milestone
  refresh decision deterministic.
- Updated `verify-promotion/SKILL.md` to run or recommend
  `write-journeys --refresh --all` before roadmap/readiness handoff when a
  milestone is complete, no active WIs remain, journeys exist, and shipped
  behavior changed.
- Updated `write-journeys/SKILL.md` Mode 7 with the same trigger.
- Documented that `references/phase-receipts.md` supersedes duplicate
  task-graph boilerplate cleanup for journey skills, and added a validator
  check so the rationale stays present in both journey skills.
