## Problem

The parallel dispatch planner can read `affects_files`, `affected_files`, and
`Affected Files` sections, but the canonical WI schema and WI-authoring skills
do not yet require or emit affected-file metadata. That means dispatch quality
still depends on free-text path extraction or blocks as `scope-unknown`.

## Acceptance Criteria

- [x] Extend `references/work-item-schema.md` with optional structured
  `Affected Files`, `Affected Specs`, `estimated_minutes`, `needs_model`, and
  `needs_transport` fields or an equivalent canonical body section.
- [x] Update WI-authoring skills to emit affected-file metadata when known.
- [x] HIGH/CRITICAL WIs must include non-empty affected-file metadata or an
  explicit `unknown` scope with a reason.
- [x] Add a tier-1 validator that catches new HIGH/CRITICAL WIs missing the
  metadata or the explicit unknown-scope reason.
- [x] Update `dispatch-waves` documentation to consume the canonical field
  rather than relying on incidental path grep.
