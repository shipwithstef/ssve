# WI-299: Delivery graph validators for evidence families and N/A skip ledgers

## Goal

Make graph completeness mechanically checkable. A lane task graph must not look complete while required evidence families, conditional mandatory skills, or skipped steps are untracked.

## Required Enforcement

- Browser-visible work requires visual evidence or valid visual N/A proof.
- User/admin-facing runtime behavior requires `test-journeys` or `write-e2e` evidence or valid N/A proof.
- Backend, external integration, auth, data, concurrency, or high-blast-radius work requires `audit-implementation` or valid N/A proof.
- Non-trivial plans require `review-plan` or valid trivial/prior-review proof.
- Base44 deploy-affecting work requires `base44-environment` obligations.
- Graph mismatch, missing route logs, user-challenged closeout, or retroactive closure requires `audit-session-execution`.
- Any omitted lane step requires a registry-backed skip condition or graph-level N/A evidence.

## Acceptance Criteria

- AC1: A tier-1 validator fails lane task files with missing required evidence families.
- AC2: A tier-1 validator fails omitted lane steps without `skipped_skills[]` evidence.
- AC3: `references/skip-conditions.json` covers graph-level skip condition ids used by the validator.
- AC4: Validator fixtures include pass/fail cases for visual, runtime, backend/Base44, docs-only, and challenged-closeout graphs.
- AC5: The validator accepts historical task graphs without `delivery_graph` only when they predate this WI or are explicitly marked legacy.
