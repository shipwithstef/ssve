# WI-340: Enforce review-receipt merge guard on Codex shell merge path

**Type:** bug
**Status:** VERIFIED
**Severity:** high
**Filed:** 2026-05-12
**Source:** PR #113 landing observation after WI-323
**Lane:** framework
**Related:** WI-323, WI-312
**Closed:** 2026-05-12

---

## Problem

WI-323 added a review-receipt schema and Bash-guard fixture for `gh pr merge`,
but the Codex shell/API path used during PR #113 still allowed the merge command
to reach GitHub without a durable `.svc/review-receipts/pr-<n>.json` receipt or
logged bypass being present in the branch.

That means the rule is mechanically validated for the hook payload shape, but
not yet enforced at every merge-capable host surface. A user or agent can still
merge through a shell path that does not invoke the installed host guard.

## Evidence

- PR #113 merged on 2026-05-12 with merge commit
  `c687cb32c032dc46487b82b1850094524d90b88d`.
- `scripts/validate-review-receipt.mjs --pr 113` would have had no durable
  receipt candidate in `.svc/review-receipts/` or `docs/specs/reviews/`.
- The remote merge succeeded before branch cleanup, while the local `gh`
  command only failed afterward when it tried to touch a local `main` worktree.
- `validate-review-receipt-merge-guard.sh` covers the intended guard behavior,
  but not the Codex `exec_command` shell surface that issued the merge.

## Acceptance Criteria

- [x] Add enforcement or a required wrapper so `gh pr merge` cannot run from
      Codex shell/API sessions without a matching review receipt or logged
      bypass.
- [x] Add a tier-1 fixture that exercises the Codex shell/API command surface,
      not only a synthetic Bash-guard payload.
- [x] Update route-workflow or land-changeset guidance so PR merge commands use
      the enforced wrapper consistently.
- [x] Backstop closeout: post-merge verification must report whether a review
      receipt or bypass was present for the merged PR.

## Route Recommendation

Run as framework hardening. Start with `diagnose-bug` to identify the exact
host boundary where Codex command execution bypasses installed hook enforcement,
then implement through `improve-framework` with a focused tier-1 guard.

## Closeout

Closed 2026-05-12. The raw host-hook path is no longer the only enforcement
surface for PR merges:

- Added `scripts/merge-pr-with-review-receipt.mjs`, a merge wrapper that runs
  `scripts/validate-review-receipt.mjs` before invoking `gh pr merge`. The
  wrapper resolves `--repo owner/name` and runs the GitHub merge outside the
  local git worktree so `gh` cannot fail after merge by trying to check out a
  local `main` that is already used by another worktree.
- Updated `scripts/worktree.sh promote --auto-merge` and post-review command
  guidance to use the wrapper instead of raw `gh pr merge`.
- Updated `land-changeset/SKILL.md` to require the wrapper from repo root and
  explicitly call out Codex shell/API hook bypass risk.
- Updated `hooks/svc-workflow-guard.mjs` block text so direct Bash-guard blocks
  point users to the wrapper.
- Extended `validate-review-receipt-merge-guard.sh` with direct wrapper
  assertions for missing receipt, valid receipt, and logged bypass. These
  exercise the Codex shell/API command surface rather than only a synthetic hook
  payload.
