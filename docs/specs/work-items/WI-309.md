# WI-309: Cross-system falsification and old-path proof

**Type:** enabler
**Status:** VERIFIED

**Filed:** 2026-05-11

## Problem

Cross-system failures can survive when agents patch the most visible path instead of modeling the system boundary and falsifying competing hypotheses. The framework needs a first-class contract map and old-path/new-path proof requirement for migrations, OAuth, hosted-login, webhook, native-app, and other multi-system flows.

## Evidence

- `proposals/done/2026-04-29-cross-system-flow-paradigm.md`

## Acceptance Criteria

- [x] Add a System Contract Map artifact for cross-system work.
- [x] Add falsification-mode probes that test likely root causes before choosing a fix.
- [x] Require old-path failure proof before declaring a migration or alternate path fixed the symptom.
- [x] Add iteration caps that escalate a WI after repeated failed attempts on the same hypothesis.
- [x] Wire cross-system signals into route-workflow so the contract map is not optional for affected work.

## Route Recommendation

Implement as framework work that extends diagnose-bug, design-tech, and test-journeys for cross-system flows.

## Notes

This is a separate concern from WI-308: WI-308 is backend data/security-specific; this WI is multi-system flow reasoning and proof.

## Closeout Evidence

Implemented a cross-system verification pack:

- `_shared/system-contract-map.md` defines the canonical contract-map artifact
  for flows crossing runtimes, origins, protocols, SDKs, or storage layers.
- `scripts/validate-system-contract-map.mjs` validates map structure:
  flow diagram, handoff table, origin/storage matrix, external-platform
  invariants, falsification probes, old-path/new-path proof, and iteration
  escalation.
- `scripts/validate-cross-system-probe-evidence.mjs` validates structured
  probe JSON with confirmation and falsification checks, plus same-input
  old-path-fails/new-path-passes proof for migration/path-swap fixes.
- `scripts/check-cross-system-iteration-cap.mjs` blocks third
  `diagnose-bug` invocations that lack `cross-system-suspected`,
  `system_contract_map.path`, and `review-cross-model` escalation.
- `route-workflow` now detects cross-system signals and requires a contract map
  before mutating work.
- `diagnose-bug`, `design-tech`, `test-journeys`, `execute-changeset`, and
  `review-gate` now require the map/probe/old-path proof at their respective
  phases.
- `test-framework/evals/tier-1/validate-cross-system-contract-map.sh` replays
  good and bad contract maps, confirmation-only probes, migration proof, and
  third-invocation escalation fixtures.
