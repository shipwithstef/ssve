# WI-137: setup script does not symlink `_shared/` directory contents

**Type:** bugfix
**Status:** VERIFIED
**Severity:** high
**Filed:** 2026-04-28
**Severity-bumped:** 2026-04-29 — cross-host audit found `_shared/product-question-format.md` (the framework's most-cited convention, 17 call sites) was silently missing on 4 of 5 hosts, degrading every product-question gate to advisory-only without warning.
**Source:** Discovered during WI-135 distribution. After `./setup --host claude`, `~/.claude/skills/_shared/` exists as an empty directory; new content like `_shared/before-starting.md` (added in WI-135) is not symlinked. Same gap on all 5 hosts (claude, codex, opencode, kimi, gemini). The pre-existing `_shared/constraint-profiles.md` and `_shared/product-question-format.md` were also missing from host installs, indicating the gap is older than WI-135.
**Lane:** framework

## Symptom

After running `./setup --host <h>`, content written into the framework's `_shared/` directory is unreachable from skill invocations because:
1. `~/<host>/skills/_shared/` directory exists but is empty.
2. Skills referencing `_shared/<file>` get "file not found" at runtime.
3. The new "Before Starting" convention introduced in WI-135 silently fails its `_shared/before-starting.md` reference until a manual symlink is added.

## Root cause

`setup` symlinks every directory under the repo root that matches its skill-discovery rules, but `_shared/` is not in those rules. The directory was created at some point (Apr 21 mtime) but never populated by setup, only by manual `mkdir`.

## Fix direction

Audit (2026-04-29) revealed the gap is purely config: setup's existing `infra_dirs` dir-symlink loop (lines 165-180) handles whole-directory symlinking correctly — `_shared` is just absent from every host manifest. Fix shape:

1. Add `"_shared"` to `infra_dirs` in each of `provision/hosts/{claude,codex,opencode,kimi,gemini}.json`. **No setup-script change required.**
2. Add tier-1 validator `validate-shared-content-symlinks.sh` that asserts every `_shared/<file>` is reachable from every detected host install on the machine (not just the active one — multi-host setups silently rot otherwise).
3. Add a meta-rule to `lint-skills-manifest.mjs`: any top-level dir containing skill-referenced content must appear in `infra_dirs` of every host manifest (or have an explicit exception). This prevents recurrence.

## ACs

- AC-01 — `./setup --host claude` populates `~/.claude/skills/_shared/` with all files from the framework's `_shared/`.
- AC-02 — Re-running `setup` is idempotent; pre-existing manual `_shared/` directories with per-file symlinks are cleanly replaced by the new dir-symlink (existing `rm -rf` at setup line 176 handles this — make the brownfield path explicit in the validator).
- AC-03 — Tier-1 validator `validate-shared-content-symlinks.sh` exists and exits 0 only when every shared file is reachable from every detected host install on the machine.
- AC-04 — All 5 supported hosts (claude, codex, opencode, kimi, gemini) populate `_shared/`.
- AC-05 — Brownfield clean-up: hosts that previously had partial manual symlinks (currently: codex/opencode/kimi/gemini have only `before-starting.md`; claude has all 3) end up with a single dir-symlink → framework `_shared/`, no leftover broken links.
- AC-06 — Validator iterates **every** detected host install path on the machine (not just the active host), so multi-host setups can't silently drift.
- AC-07 — Meta-check in `lint-skills-manifest.mjs`: linter fails CI if a top-level dir contains content referenced from any SKILL.md but is missing from any host manifest's `infra_dirs` (excepting `rules/` which has its own dedicated install path).

## Audit findings (2026-04-29) — silent-failure surface

14 SKILL.md files reference `_shared/`:
- `_shared/product-question-format.md` — 17 call sites (every product-question gate)
- `_shared/before-starting.md` — 5 call sites
- `_shared/constraint-profiles.md` — 3 call sites

Pre-fix host state:
| Host | `_shared/` state |
|---|---|
| claude | dir + 3 file-symlinks (manually patched) |
| codex / opencode / kimi / gemini | dir + only `before-starting.md` (manually patched) |

Other top-level dirs (`references/`, `proposals/`, `templates/`, `examples/`, `hooks/`, `provision/`, `scripts/`) all symlink correctly across hosts; `rules/` has its own install path. `_shared/` is uniquely affected — hence the meta-rule (AC-07) is the structural fix.

## Why medium severity

Skills that reference `_shared/*.md` (notably the new "Before Starting" convention from WI-135 and the existing `_shared/product-question-format.md` referenced by every product-question gate) silently fail to load context until manual fix. This degrades framework conventions to advisory-only without warning.
