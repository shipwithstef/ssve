# WI-522: Declare `story_receipt_sha256` in the verify-promotion receipt schema

**Type:** framework hygiene
**Status:** closed (2026-08-23 — implemented by the WI-541 landing `c91948d`: schemas/receipts/verify-promotion.schema.json declares `story_receipt_sha256` as a 64-hex string; see INDEX row)
**Severity:** low
**Filed:** 2026-08-04
**Source:** WI-521 Batch C review (finding S3); deferred at landing because the change classifies HIGH and cross-family review was unavailable
**Lane:** framework

## Problem

WI-521 landed the story-receipt cross-link: `scripts/svc-auto-drive.mjs` writes `story_receipt_sha256` into the `verify-promotion` receipt body it constructs, derived from the merge commit's own tree, `null` on ambiguity or git error. The reviewer verified this is real and not decoration.

`schemas/receipts/verify-promotion.schema.json` does not declare the field. `additionalProperties` is undefined there, so it is **tolerated but not validated** — an undeclared extra property. If that schema ever gains `additionalProperties: false`, the cross-link breaks silently.

## Why it was deferred rather than landed with WI-521

This is a one-line optional-property addition, but `scripts/classify-change-risk.mjs` classifies any `schemas/` touch as `schema-migration`, which escalates the whole commit to **risk tier `high`**. The impact-triad guard requires high-tier changes to carry a **different-family** independent review — and Codex quota was exhausted for that entire run, so both executor and reviewer were Anthropic.

The available responses were: falsify the family fields, split the commit to dodge the classifier, or not land the change. The first two are the exact forgery and evasion this WI exists to prevent — WI-521's own Batch C review had already caught a forced-green receipt and a fence present in the producer but absent from the consumer. So the change was reverted and filed here.

**This is the guard working as designed**, not a defect in it. A schema change genuinely does warrant cross-family review; the correct response to being unable to supply one is to defer the change, not to lower the bar for it.

## Scope

- Add `story_receipt_sha256` to `properties` in `schemas/receipts/verify-promotion.schema.json` as optional, pattern `^[0-9a-f]{64}$`.
- Land it under a **different-family** adversarial review (Codex, per the reviewer allowlist), which is the whole reason it was held.
