# WI-446: Fix deriveGraphStatus terminal-state bug (task-graph.mjs)

**Type:** framework
**Status:** verified (merged PR #105; parent WI-440)
**Severity:** medium
**Filed:** 2026-06-29
**Source:** ultracode framework audit (parent cluster WI-440); confirmed by hand + live blast-radius scan.
**Lane:** bugfix (framework)
**Depends on:** none

## Goal
Correct `deriveGraphStatus` in `scripts/task-graph.mjs` so a graph with no open work
derives an honest terminal status, instead of falling through to `"pending"`.

## Root cause
`deriveGraphStatus` (scripts/task-graph.mjs) treated a `skipped` task as non-terminal:
it returned `"completed"` only when *every* task was literally `completed`, so any graph
with no `in_progress`/`pending`/`blocked` task but ≥1 `skipped` task hit the bare
`return "pending"` fallthrough. But `skipped` is a first-class status
(`VALID_STATUSES`/`VALID_GRAPH_STATUSES`), a `"skipped"` graph status is already consumed
by the code (`if (graph.status === "skipped") return false;`), and `validateGraph` throws
when a stored `graph.status` disagrees with the derived value.

## Live blast radius (scanned 2026-06-29)
18 real `.svc/lane-tasks-*.json` graphs are terminal-but-not-all-completed:
- **12 `completed+skipped` mixes** (`WI-357..361/363/364/370`, archived `WI-134..139`)
  store `"completed"` but derive `"pending"` → an **active `stored ≠ derived` mismatch**
  that would throw in `validateGraph`.
- **6 all-skipped** (`WI-CLN-11..15`, `WI-MIMO-B1`) store `undefined` (latent) and would
  mis-derive `"pending"`.

## Fix
After the `in_progress`/`pending`/`blocked` checks (no open work remains — every task is
terminal), derive `"skipped"` when every task is `skipped`, otherwise `"completed"`:

```js
if (tasks.every((task) => task.status === "skipped")) {
  return "skipped";
}
return COMPLETED_STATUS; // all terminal, ≥1 completed → graph done
```

(The narrow "all-skipped only" variant was rejected — it would leave the 12 mixed graphs
still mis-deriving `"pending"`.)

## No-loss / no-regression evidence
- Changes the derived value ONLY for terminal non-all-completed graphs — exactly the broken
  case. Open-work cases (`in_progress`/`pending`/`blocked`) are untouched.
- **Zero currently-passing graph starts failing:** no terminal graph stores `"pending"`
  (every all-skipped stores `undefined`; every mixed stores `"completed"`), so the 12 mixed
  graphs go mismatch→match and nothing regresses.
- **No test encodes the old fallthrough:** `framework-test-catalog` skip scenarios assert
  command success only; the helper validators test the `skip_reason` field and task-level
  `next`; `graph-status` prints `graph.status ?? derive` (stored wins).
- **Consumers read stored status**; the completion guard already treats the 12 as
  `"completed"`. `"skipped"` graph status is already handled.
- Full tier-1 run: this change adds **zero** new failures (the 4 reds are pre-existing
  base state + session residue, none referencing `task-graph.mjs`).
