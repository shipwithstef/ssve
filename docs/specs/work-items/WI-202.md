# WI-202: User typo normalization is not part of routing

## Problem

The framework reliability review found HIGH issue F-032: User typo normalization is not part of routing.

## Evidence

The same proposal lists recoverable typo examples and a pre-routing normalization step at lines 96-107.

## Impact

Fast, typo-heavy user messages are parsed shallowly, causing wrong skill selection and over-engineering.

## Proposed Fix

Normalize the user message before route classification and log the normalized interpretation in hidden routing context.

### Resolution

`route-workflow` now has a pre-routing typo normalization contract. Recoverable
typing noise and known skill-name variants are normalized before route
classification, while original user text remains available for audit.

### Changes

- Added `### Pre-Routing Typo Normalization` to `route-workflow/SKILL.md`.
- Added `route-workflow/references/intent-normalization.md` with the source
  proposal's typo examples, allowed transformations, guardrails, and routing
  audit fields.
- Required material normalizations to log `normalized_intent`,
  `normalization_applied`, and `normalization_evidence` in routing context.
- Added `test-framework/evals/tier-1/validate-intent-normalization-routing.sh`.
