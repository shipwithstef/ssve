# WI-180: `Before Starting` context loading is mostly advisory

## Problem

The framework reliability review found HIGH issue F-010: `Before Starting` context loading is mostly advisory.

## Evidence

`validate-skill-before-starting.sh` reports 72 advisory missing sections and only 5 passes. The script exempts pre-cutoff or undated skills at [validate-skill-before-starting.sh](/workspace/seriousvibecoding/test-framework/evals/tier-1/validate-skill-before-starting.sh:68).

## Impact

Skills still load context inconsistently, which increases rework and context-token waste.

## Proposed Fix

Convert advisory findings into a family-level context-loading registry and keep direct `## Before Starting` sections mandatory for new skills.

The intended behavior is not minimum context and not read-all. Skills must build a bounded context plan, use indexes and dependencies, read complete relevant context for the affected surface, and add/update missing dependency mapping when it is needed to avoid guessing.

## Resolution

Closed 2026-05-11. `_shared/before-starting.md` now defines relevance-closure context loading: start from the session contract or active WI, use `.svc/spec-index.json`, work-item indexes, manifest metadata, and linked specs/validators/reviews, then stop only when remaining links cannot affect the run.

Legacy skills without a direct section are covered by `references/context-loading-registry.json`. New skills authored on or after 2026-04-28 still fail if they omit `## Before Starting`.

## Verification

- `route-workflow/SKILL.md` now tells the router to build a bounded context plan and follow relevant dependency links before dispatch.
