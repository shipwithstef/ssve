# WI-109: validate-feature cannot be skipped without explicit override

**Type:** feature
**Status:** VERIFIED
**Closed:** 2026-04-25
**Merged PR:** #22
**Severity:** medium
**Filed:** 2026-04-25
**Source:** WI-099 T2-B (promoted after 2026-04-25 re-triage; WI-095 gate confirmed not to cover this)
**Lane:** framework

## Goal

Mechanically refuse to advance past a lane step that requires `validate-feature` unless an override is logged to `.svc/pipeline-decisions.jsonl` with `decision_type:"taste"` and a rationale.

## Context

Evidence (from /insights 2026-04-24 triage, preserved in WI-099):
- WI-077 skipped `validate-feature`, classified entities as KILL on missing-code reasoning, required full revert + v2 rerun.
- Pattern: pipelines that skip the business-judgment step produce technically clean deliverables that solve the wrong problem.

WI-099 originally deferred this item pending WI-095 (hard close-out gate). WI-095 has now landed and its validator (`validate-wi-closeout-evidence.sh` + `verify-wi-closeout.mjs`) confirmed to NOT cover the validate-feature-skip case — it checks status consistency, DONE.md, INDEX.md, git log references, but does not gate on whether `validate-feature` ran upstream. Therefore T2-B is not subsumed and needs its own enforcement.

## Acceptance Criteria

- **AC-01** New tier-1 validator `test-framework/evals/tier-1/validate-feature-gate.sh` scans each VERIFIED WI in `docs/specs/work-items/` and verifies that for lanes requiring `validate-feature` (greenfield, brownfield-feature), one of the following is true:
  - `.svc/pipeline-decisions.jsonl` has an entry with `skill:"validate-feature"` referencing this WI's `run_id`, OR
  - `.svc/pipeline-decisions.jsonl` has a `decision_type:"taste"` entry with `skill:"validate-feature"` AND `decision:"skip-validate-feature"` AND a non-empty `reasoning` field, referencing this WI's `run_id`.
- **AC-02** Lanes that do NOT require `validate-feature` (framework, bugfix, refactor) are exempt — validator skips them without error.
- **AC-03** On first run against the current corpus, the validator lists historical gaps as warnings (not failures) for the first 7 days, then flips to blocking. Grace period prevents retroactive churn on already-merged WIs.
- **AC-04** `route-workflow/SKILL.md` updated to document the gate and the override contract.
- **AC-05** A reference document `references/validate-feature-override.md` spells out when an override is appropriate (framework self-bootstrapping, trivial docs-only changes, etc.) and when it is abuse.

Revert the feature commit; validator removed; pipeline returns to trusting skills to self-gate on validate-feature.
