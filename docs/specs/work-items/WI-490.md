# WI-490: Phase-guard deep hardening — semantic binding + reachability-independent exec-record

**Type:** framework
**Status:** IDENTIFIED
**Severity:** high
**Filed:** 2026-07-16
**Source:** gpt-5.6-sol/high independent review of WI-489 (round 2), findings EXEC-005 and EXEC-006
**Lane:** framework
**Related:** WI-489, WI-488

---

## Problem

WI-489 added the phase-to-review-kind guard and hardened its sanctioned path
(`review-plan-codex.sh` always binds and fails closed; `plan_manifest_sha256`
required; exec-record notes scanned across `base..HEAD`; retro-plan override
freshness fixed). The independent reviewer confirmed those fixes but identified
two residuals that require deeper, larger changes and were deliberately deferred
so WI-489 could land with a threat model narrowed to the **sanctioned adapter
path**. In a multi-user / multi-agent deployment a determined DIRECT caller of
the canonical launcher (bypassing `review-plan-codex.sh`) can still evade the
guard.

### EXEC-005 — the phase binding is self-asserted, not semantically verified

`parsePhaseBinding` validates only field SHAPE. It never verifies
`plan_manifest_sha256` against the reviewed plan or a durable `plan-manifest`
receipt, never establishes the WI from authoritative plan state, and never
verifies that `pre_execution_base` is the recorded pre-execution boundary. A
direct caller can supply `pre_execution_base=HEAD` (empty implementation diff),
an arbitrary WI with no matching exec-record, and any syntactically valid hash,
and the guard allows the plan review. Missing bindings also remain allowed
unless `SVC_EXTERNAL_REVIEW_REQUIRE_PHASE_BINDING=1` is set. So EXTREV-136..139
are enforced for the sanctioned adapter, not for the canonical launcher itself.

### EXEC-006 — exec-record note scan is bypassable after history rewrite

`findExecRecordForWi` enumerates only commits in `base..HEAD` (plus HEAD). Git
notes on `refs/notes/svc-receipts` persist when a noted execution commit becomes
unreachable (after `reset`/`rebase`). Resetting HEAD to the pre-execution base
empties the range and leaves no divergence, so the durable exec-record on the
displaced commit is missed and the plan review is allowed — contradicting the
irreversible "once execute-changeset has begun" rule.

## Proposed direction (to be planned)

- Make `--phase-binding` MANDATORY for every `review_kind=plan` in the canonical
  launcher (flip the default; migrate the ~40 existing plan fixtures).
- Bind to durable plan state: recompute the plan hash from an explicitly supplied
  plan file / canonical package component and compare; derive/verify the WI and
  `pre_execution_base` against the `plan-manifest` receipt rather than trusting
  caller-supplied values.
- Enumerate the authoritative notes ref independently of current-branch
  reachability (or maintain a durable WI→exec-record index); fail closed on
  malformed matching evidence.
- Fixtures: forged base=HEAD binding; missing plan-manifest receipt; reset and
  rebase making the exec commit unreachable with no mirror and no divergence.
