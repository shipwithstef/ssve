# WI-519: `stage-activation.mjs` is unwired — §2 conditional activation cannot fire

**Type:** framework defect (inert mechanism)
**Status:** identified
**Severity:** high
**Filed:** 2026-08-04
**Source:** WI-512 global cross-batch review — the finding no single batch reviewer could see
**Lane:** framework

## Affected Files

- `scripts/stage-activation.mjs`, `skills/route-workflow/SKILL.md`, the canonical stage registry, its task-graph consumer, and focused activation validators.

## Problem

WI-512 landed `scripts/stage-activation.mjs`: it evaluates each non-essential stage against quote-derived conditions, hardcodes six essential stages as always-active, and exits 2 if a conditions file tries to condition one. It works — it was smoke-tested, its negative fixture exits 2, and the shipped registry bug that made everything `na` was found and fixed.

**Nothing invokes it.** A repo-wide grep finds exactly two references: `route-workflow/SKILL.md:207`, which states a *validity rule* for an `na` that someone else produced, and the retired `quick-fix` body, which points at it as where speed now comes from. No skill, hook, or checklist step ever runs it.

So goal A's headline lever — "a 1-line fix no longer pays the 6-phase ceremony" — is documented but cannot fire. The `na` validity rule governs a value nothing generates, and the retirement notice redirects to a mechanism that never runs.

Compounding it: the script's stage names (`perf`, `translations`, `device-proof`, `visuals`, `pricing`, `marketing`) map to nothing else in svc, so even a produced record currently has no consumer.

## Why this slipped

This is the same defect class Batch 2's reviewer graded HIGH and fixed — `check-plan-deploy-dependency.mjs` was written, correct, and invoked by nothing. It recurred in Batch 3 and no batch reviewer caught it, because each was scope-locked to its own diff and "is anything outside my slice calling this?" is by construction not answerable from inside one slice. Worth remembering as an argument for the global pass, not just for more per-batch rigor.

## Scope

- Add a real invocation point. The natural one is `route-workflow`, adjacent to the existing `na`-validity rule (row 2b), mirroring the shape `review-plan/SKILL.md:128` already uses for its mechanical check.
- Decide what consumes the output: which stage names correspond to real svc stages, and what a consumer does with `result:"na"`. A record nobody reads is the same as no record.
- Only then is §2 landed. Until it is, do not describe conditional stage activation as delivered.

## Acceptance criteria

- [ ] **AC-1** A documented, reachable invocation runs `stage-activation.mjs` during a real routing pass — demonstrated in a live run, not asserted.
- [ ] **AC-2** Each emitted stage name maps to a real svc stage, or is removed.
- [ ] **AC-3** A consumer acts on `result:"na"` — and an `na` without a cited condition evaluation is rejected, per the rule already in `route-workflow`.
- [ ] **AC-4** The essential-stage fence still exits 2 after wiring.
- [ ] **AC-5** A grep for the script's name finds an invocation, not only prose about it.
