## Problem

Concurrent mobile worktrees need co-installable dev builds and collision-free version identities, while release versions must remain canonical and change exactly once at land. The framework currently has no generic adapter contract for this separation.

## Acceptance Criteria

- [x] **AC-483-1:** Two branches produce distinct stable app identities and can coexist on-device when a consumer adapter supports it. *(Verified by stable derivation and 100-branch collision fixtures.)*
- [x] **AC-483-2:** Ten builds in one minute receive strictly increasing valid dev codes and unique artifact names. *(Verified by same-epoch burst and concurrent allocator fixtures.)*
- [x] **AC-483-3:** Dev identities cannot satisfy canonical release proof. *(Verified by explicit dev-as-release rejection.)*
- [x] **AC-483-4:** Canonical version changes once at land and clears the remote or recorded release floor. *(Verified by reserved/built/committed lifecycle, idempotency, and stale-floor fixtures.)*
- [x] **AC-483-5:** Built manifest identity matches artifact filename and receipt. *(Verified against fresh adapter inspection and real artifact SHA-256 bytes.)*
- [x] **AC-483-6:** Framework tests require no mobile SDK; Gradle/Xcode changes occur only in a separate consumer WI. *(Verified by fake argv adapter execution and consumer-file diff denial.)*

## Route recommendation

Execute after WI-482 verify-promotion. Framework supplies schema, identity engine, and fake adapters; real-device proof belongs to a downstream mobile-repo changeset.
