## Problem

`.svc/` state files (orchestrator-state.json, lane-tasks-*.json,
pipeline-decisions.jsonl) are written via direct `fs.writeFileSync` from
multiple call sites today. A crash mid-write leaves a half-written file
that breaks every downstream reader. Concurrent writers (e.g., a user
session and a background hook) can also race.

## Scope

### In scope
- `scripts/state-io.mjs` — `readJsonAtomic` + `writeJsonAtomic` (tmp+fsync+rename)
- `scripts/state-lock.mjs` — `acquireLock(path, {staleMs})` returning release fn
- `test-framework/evals/tier-1/validate-atomic-state-writes.sh` — soft-warn on direct writes outside state-io.mjs

### Out of scope
- Lane-tasks compare-and-set version numbers (future WI)
- Migrating existing writers to atomic IO (this WI provides the lib; future WIs adopt it per call site)
- init-project-state.mjs is template copy of non-`.svc/` JSON files (templates), so no migration needed there

## Acceptance criteria

1. state-io.mjs exports readJsonAtomic and writeJsonAtomic. ✅
2. state-lock.mjs exports acquireLock with stale auto-expiry. ✅
3. Validator soft-warns on direct fs.writeFileSync to `.svc/` JSON outside state-io.mjs. ✅
4. Tier-1 sweep passes (validator is exit 0 only). ✅
5. lint-skills-manifest clean. ✅
