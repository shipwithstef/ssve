# WI-205: `route-workflow` claims live-evidence hook behavior that is not a real hook

## Problem

The framework reliability review found HIGH issue F-035: `route-workflow` claims live-evidence hook behavior that is not a real hook.

## Evidence

`route-workflow/SKILL.md` says route-workflow checks and invokes live evidence after visual-output skills at [route-workflow/SKILL.md](/workspace/seriousvibecoding/route-workflow/SKILL.md:192), but this is skill text, not a host hook entry in `hooks/hooks.json`.

## Impact

A model can skip the described behavior and no installed hook will enforce it.

## Proposed Fix

Implement this as an actual Stop/PostToolUse hook or downgrade the wording to an explicit self-verify obligation.

### Resolution

F-035 was valid. The live-evidence section in `route-workflow/SKILL.md` described a "post-skill hook" even though no host hook entry existed for that behavior. This is now explicitly modeled as a route-workflow/task-graph obligation, not host-hook enforcement.

### Changes

- Renamed the route-workflow section to "Route-workflow visual-evidence obligation for visual-output skills".
- Added explicit wording that the behavior is not a host-installed hook and must not be described as hook enforcement until a real host hook is wired.
- Updated the visual live-evidence validator to fail if the route-workflow section drifts back to fake hook language.
- Updated the related WI-199 wording so verified V-ladder docs reference the task-graph obligation instead of a non-existent live-evidence hook.
