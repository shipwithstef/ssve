# WI-125 — Generic detached-Kimi runner so any svc skill can offload long Kimi jobs without burning parent (Claude) tokens

**Status:** VERIFIED
**Lane:** framework
**Created:** 2026-04-25
**Baselined:** 2026-04-26

**Closed-via:** PR #43 squash-merged to main (`6a2b245`).
**Branch:** wi-125-kimi-detached-runner
**Source:** 2026-04-25 conversation with builder (Stefan). Builder has heavy unused Kimi quota and wants the orchestrator (Claude) to dispatch Kimi-heavy work as background jobs, then judge the outcome — instead of either (a) the builder typing into kimi-cli directly, or (b) the orchestrator blocking foreground turns on long Kimi runs.

## Problem

Today, every svc skill that delegates to Kimi shells out via foreground Bash (e.g. `scripts/review-plan-kimi.sh`). Two ceilings constrain this:

1. **Claude Code Bash tool ceiling** — 10 min hard cap on foreground/background Bash calls. Kimi reasoning runs that exceed 10 min get killed.
2. **Hook timeouts** — set per-hook in `wire-kimi-hooks.mjs` (mostly 10 min, review hooks intentionally 20 min). Orchestrator-driven Kimi runs invoked via Bash bypass hooks but are still capped by ceiling (1).

There is no shared, skill-agnostic way to launch a Kimi job that:
- Returns immediately (no parent token cost during the run).
- Survives past the 10-min Bash ceiling for skills that legitimately need longer.
- Is observable via a stable on-disk log path so the orchestrator can poll/judge later.
- Is cleanly killable and discoverable (PID file, job registry).

Each skill currently re-implements its own one-off backgrounding (or doesn't, and lives with the cap). Result: no skill takes full advantage of builder's idle Kimi quota for long-form analysis, ingestion, deep extraction, or alternative-solution exploration.

## Scope

### In scope
- New script `scripts/run-kimi-detached.sh` with signature:
  ```
  run-kimi-detached.sh \
    --skill <skill-id> \
    --prompt-file <path> \
    [--max-seconds N]            # default 1800 (30 min); review skills override to 1200
    [--label <free-text>]        # for human-readable log naming
  ```
  Returns JSON to stdout in <1s:
  ```json
  {
    "job_id": "kimi-<skill-id>-<unix-ts>-<rand>",
    "log_path": "/tmp/svc-kimi-jobs/<job_id>.log",
    "pid_path": "/tmp/svc-kimi-jobs/<job_id>.pid",
    "max_seconds": 1800,
    "started_at": "2026-04-25T..."
  }
  ```
- New script `scripts/kimi-job-status.sh <job_id>` returns `{state: running|done|killed|timeout, exit_code, elapsed_seconds, log_tail_kb}`.
- Job registry at `/tmp/svc-kimi-jobs/index.jsonl` — append-only line per launch; `kimi-job-status.sh --list` reads it.
- Per-skill default cap table in `references/model-routing.md` (review=1200, ingestion=3600, research=3600, exploration=1800, default=1800). Caller may override but cannot exceed `KIMI_DETACHED_HARD_CAP` env (default 7200).
- Cleanup: `scripts/kimi-job-cleanup.sh` purges `/tmp/svc-kimi-jobs/*` entries older than 24h (cron-able).
- Reference doc `references/kimi-detached-pattern.md` documenting when a skill should use this vs foreground Bash. Default heuristic: foreground if expected duration <2 min, detached if ≥2 min OR if the skill wants to fan out N Kimi jobs in parallel.
- Tier-1 validator `validate-kimi-detached-runner.sh`:
  - Script exists and is executable.
  - `--help` documents all flags.
  - Smoke launch with `--prompt-file /tmp/empty` returns valid JSON in <2s.
  - Job registry append works.
  - `kimi-job-status.sh` returns `done` for the smoke job within 5s.

### Out of scope
- Migrating any specific existing skill to use the new runner. That happens per-skill in follow-up WIs (one per opt-in skill) so each migration can be reviewed in isolation.
- Replacing `scripts/review-plan-kimi.sh` — review's 20-min hook cap is intentional doctrine; that script stays foreground.
- Equivalent runners for Codex / Gemini / Claude (sibling pattern, separate WI if demand emerges).
- A `Monitor`-tool integration for log streaming (nice-to-have; orchestrator can poll on demand).

## Acceptance criteria

1. `scripts/run-kimi-detached.sh` exists, is executable, returns JSON in <2s for a smoke prompt.
2. The launched Kimi process survives past the parent Bash call's exit (proven by `ps -p <pid>` succeeding 30s after the Bash call returned).
3. `scripts/kimi-job-status.sh <job_id>` correctly reports state transitions (`running` → `done` or `timeout`).
4. Per-skill cap defaults are read from `references/model-routing.md`; missing skill falls back to default cap.
5. `KIMI_DETACHED_HARD_CAP=N` env truncates any caller-requested cap.
6. `validate-kimi-detached-runner.sh` passes in tier-1 sweep.
7. Reference doc clearly states when NOT to use this runner (review skills, sub-30s prompts, hook contexts).
8. No existing skill is modified by this WI (purely additive — gates the rollout).
