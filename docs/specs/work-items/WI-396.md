## Problem
Two reachable determinism bypasses reproduced live:
1. **Exempt-prefix code bypass:** `docs/specs/payload.js` containing `export function evil(){ if(process.env.SECRET){ return process.env.SECRET } }` returns `eligible:true` from `scripts/quick-fix-eligibility.mjs` — arbitrary code ships with ZERO 5-receipt envelope, while the identical file under `scripts/` is correctly rejected. No regression test guards this.
2. **Presence-only receipt validation:** `check-chain-receipts.mjs:115-135` `validateReceipt` only checks `k in receipt` — a review-exec receipt with a fabricated/empty `diff_hash` passes; nothing recomputes and compares.

## Mechanism (as built)
1. **Exempt-code bypass:** `isExemptPath` now denies any code/source extension (`.js/.mjs/.cjs/.ts/.tsx/.sh/.bash/.py/.rb/.go/.rs/...`) regardless of path — code never rides the docs/state carve-out. The reproduced `docs/specs/payload.js` now classifies via normal criteria → ineligible (structural/size), as does a >30-line `.sh`.
2. **Receipt-content binding:** `validateReceipt` rejects an `exec-record`/`review-exec` whose `diff_hash` is not a well-formed 64-hex sha256 (the reproduced empty/garbage vector). The full-envelope path additionally binds those receipts to the commit TREE (`tree_hash`, squash-invariant — unlike diff_hash, which is range-ambiguous); `emit-receipt` populates it; grandfathered so existing main envelopes stay valid.
3. **Bonus (root cause):** `loadSchema` used a **cwd-relative** path → returned null from any other directory, turning `validateReceipt` into a no-op that validated EVERY receipt. Made SCRIPT_DIR-absolute so the content gate always runs — this was *why* the forgery passed at all.
