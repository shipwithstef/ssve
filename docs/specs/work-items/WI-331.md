# WI-331: Compression anomaly and deployed-unverified state enforcement

**Type:** enabler
**Status:** VERIFIED
**Severity:** high

## Problem

WI-305 now forces AC-by-AC feature validation ledgers, and WI-320 tracks explicit
delivery-tier declaration. The remaining gap from the deployed-unverified
proposal is state and anomaly enforcement: a compressed or unusually fast lane
can still finish without a machine-readable compression ratio, a distinct
deployed-but-not-verified status, or an automatic audit escalation.

## Evidence

- `proposals/done/2026-04-25-prevent-deployed-unverified-shipping.md#P0`
- `proposals/done/2026-04-25-prevent-deployed-unverified-shipping.md#P1`
- `proposals/done/2026-04-25-prevent-deployed-unverified-shipping.md#P2`
- Current `references/work-item-schema.md` still routes `SHIPPED` and similar
  terms to the closed bucket, with no canonical `DEPLOYED-UNVERIFIED` state.
- Current delivery graph validators require registry-backed skipped skills, but
  do not compute compression ratios or escalate high-ratio sessions.

## Acceptance Criteria

- [x] Define a canonical `DEPLOYED-UNVERIFIED` or equivalent pending-verification
      state in the work-item schema.
- [x] Update `list-work-items` so deployed-unverified work is not routed to the
      closed/DONE bucket.
- [x] Require `verify-promotion` or closeout classification to be the only path
      from deployed-unverified to verified.
- [x] Add a task-graph or delivery-tier field that records compression ratio or
      an explicit estimate-vs-actual rationale for compressed lanes.
- [x] Trigger `audit-implementation` before `land-changeset` when compression
      exceeds the configured threshold.
- [x] Add a tier-1 fixture that fails a high-compression lane without audit
      escalation and pending-verification state.

## Route Recommendation

Implement after WI-320 so delivery tier and compression metadata share one graph
shape instead of parallel fields.

## Closeout

Implemented on 2026-05-12.

- Added `DEPLOYED-UNVERIFIED` as an open work-item state in
  `references/work-item-schema.md` and documented the open bucket in
  `list-work-items/SKILL.md`.
- Added delivery-graph compression metadata in
  `scripts/compile-delivery-graph.mjs`.
- Added validation in `scripts/validate-delivery-graph.mjs` so high-compression
  lanes require a rationale, `deployed-unverified` state, and
  `audit-implementation` before `land-changeset`.
- Updated `scripts/classify-delivery-graph-closeout.mjs` so
  `deployed-unverified` cannot classify as framework-complete.
- Added `test-framework/evals/tier-1/validate-deployed-unverified-compression.sh`.
