## Problem

SVC cannot bootstrap or load the first skill when a host exports a nonexistent `XDG_RUNTIME_DIR`, as observed on the current WSL Codex host. Runtime-path policy is duplicated across framework consumers, and the Codex loader mutates graph activation before it proves that session receipt storage is usable. During the required WI-506 plan review, the phase guard also classified mandatory pre-execution `blend-external` outputs as implementation, creating a framework-owned deadlock between lane compliance and review eligibility.

## Root cause

**Immediate:** Non-empty XDG configuration is treated as an existing trusted runtime root.

**Enabling:** Multiple consumers implement different fallback, ownership, and failure policies.

**Systemic:** Tests model valid XDG and absent XDG but omit invalid-but-set hosts and the graph/session receipt transaction boundary.

**Review-phase classifier:** `PHASE_EXEMPT_PREFIXES` recognizes `docs/`,
`proposals/`, and `.svc/` planning state but omits the exact attribution and
knowledge artifacts that `blend-external` is required to write before
`review-plan`.

## Review backlog

- Low, non-blocking: retain the documented requirement that an explicit
  `SVC_RUNTIME_DIR` be a pre-existing, real, current-user `0700` directory; this
  is the supported remediation when a user's `~/.cache` itself is symlinked.
- Informational: the runtime-selector recurrence scan intentionally covers the
  production executable roots (`hooks/`, `scripts/`, and `bin/`). Broader test
  and skill-local scans can be evaluated separately without weakening this
  bugfix's exact one-exception assertion.
- Resolved during execution review: every provisioned host that installs
  `hooks/` also installs the sibling `scripts/` directory, as exercised by the
  all-host installation validator; `ensureOwnedDirectory` is not dead code and
  remains used by `atomicWriteJson`.
- Resolved during final execution review: Git authority locks distinguish busy,
  infrastructure error, and application refusal; malformed holders deny until
  independently verified exact-OID operator recovery; live contention does not create a candidate object; uncertain
  cross-host holders fail closed with exact ref/OID/host/PID operator recovery.
  Time-based cross-host lock theft is explicitly rejected. A failed exact-OID
  release is surfaced as `lock_release_error` rather than hidden behind an
  operation-success result.
- Resolved during implementation audit: the phase classifier disables rename
  detection so staged and committed implementation-to-exempt moves expose both
  paths and remain post-execution divergence with zero provider calls.
- Medium follow-up: add bounded canonical cleanup for persistent advisory
  completion counters and compatibility markers. These files are private and
  non-authoritative; cleanup must never infer or mutate WI authority.
- Medium follow-up: instrument the installed Stop guard in a copied-host fixture
  and assert the exact zero/common-path and at-most-one/relevant-path resolver
  subprocess budget, in addition to the current functional and latency checks.
- Medium follow-up (`WI506-EXEC-R2-001`): bound correctness-lock Git subprocess
  cost on hook hot paths. Consider process-lifetime repository/object-format
  memoization and a single holder read, while retaining exact-old-object CAS.
- Medium follow-up (`WI506-EXEC-R3-001`): preserve the post-operation release
  discriminator through ensure/migration callers so they never describe an
  already-completed mutation as an acquisition failure or enter rollback.
- Medium follow-up (`WI506-EXEC-R3-002`): canonicalize `repoRoot` before deriving
  the repository-skill candidate and add a symlinked-ancestor compatibility
  fixture while retaining per-component symlink rejection below that root.
- Low follow-ups (`WI506-EXEC-R2-002` through `005`): suppress the recovery
  command when a final busy reread has no concrete OID; add out-of-band operator
  acquisition-time evidence that never grants takeover; evaluate a stable
  reboot/machine token for ephemeral hostnames; and document that
  `refs/svc/authority-locks/**` is machine-local coordination state excluded
  from mirror-style refspecs.
