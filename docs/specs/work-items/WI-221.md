# WI-221: Mechanically enforce improve-framework quick-fix size threshold

## Goal

Make the `improve-framework` quick-fix/direct-edit threshold mechanically enforceable instead of relying on the agent to notice that a patch grew beyond the planned size.

## Context

`improve-framework/SKILL.md` says framework changes touching more than two files or more than 50 lines must go through the normal svc pipeline. During WI-216, the route decision allowed quick-fix only if the change stayed small, but the final implementation touched more than two files and exceeded 50 lines once tests, WIs, state, and audit artifacts were included.

The implementation was later landed correctly, but the threshold violation was only caught by manual audit. This needs a permanent guard.

## Acceptance Criteria

- AC1: A tier-1 validator or pre-commit helper detects when a framework-lane quick-fix/direct-edit decision exceeds `>2 files` or `>50 changed lines`.
- AC2: The detector checks `.svc/pipeline-decisions.jsonl` for the selected route and the current diff or staged diff size.
- AC3: If the threshold is exceeded without a plan-changeset artifact or explicit logged override, validation fails with a clear recovery message.
- AC4: The recovery message says to either create a plan-changeset, split the patch, or log an explicit user-approved override.
- AC5: Fixtures cover: within-threshold quick-fix pass, over-threshold quick-fix fail, over-threshold with plan-changeset pass, and over-threshold with explicit override pass.

## File Impact

- `improve-framework/SKILL.md`
- `route-workflow/SKILL.md` or route references if route decisions need a normalized field
- `scripts/` for the detector if implemented as a shared helper
- `test-framework/evals/tier-1/`
- `.svc/pipeline-decisions.jsonl` route shape documentation

### Verdict

Invalid as filed. The requested size-threshold enforcement would mechanize an obsolete rule.

`improve-framework/SKILL.md` still said `>2 files` or `>50 lines` must route through the normal pipeline, but `rules/plan-changeset-trigger.md` already supersedes that size-only trigger with a risk-based trigger. Enforcing the stale size threshold would reintroduce false positives by forcing harmless additive/documentation patches through ceremony while still missing small hot-path contract changes.

### Actual Fix

- Updated `improve-framework/SKILL.md` to reference `rules/plan-changeset-trigger.md`.
- Replaced the size-only MUST with risk-signal/exemption routing.
- Added `test-framework/evals/tier-1/validate-plan-changeset-trigger-alignment.sh` so `improve-framework` cannot drift back to the obsolete threshold.

### Evidence

- `rules/plan-changeset-trigger.md` says it supersedes the earlier size-based trigger.
- `bash test-framework/evals/tier-1/validate-plan-changeset-trigger-alignment.sh` PASS.

### Acceptance Criteria Disposition

- AC1-AC5: NOT IMPLEMENTED AS FILED — invalidated by current canonical rule. Mechanical prevention now protects the corrected risk-based doctrine instead of the stale size threshold.
