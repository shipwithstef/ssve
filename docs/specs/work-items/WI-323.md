## Problem

Framework PRs can still be merged with no machine-checked independent
review-gate receipt. WI-219 documents when review-gate is required, but the Bash
surface that runs `gh pr merge` does not yet block missing review receipts.

## Evidence

- `proposals/done/2026-04-25-deterministic-quality-hooks.md#G-3`
- `proposals/done/2026-04-25-deterministic-quality-hooks.md#G-9`
- `route-workflow/references/lane-model.md` defines the framework review-gate
  policy, but `scripts/worktree.sh` and `svc-bash-guard` do not verify a PR
  receipt before merge.
- Implemented by `references/review-receipts.md`,
  `scripts/validate-review-receipt.mjs`, `hooks/svc-workflow-guard.mjs`, and
  `test-framework/evals/tier-1/validate-review-receipt-merge-guard.sh`.

## Acceptance Criteria

- [x] Define the review-receipt schema for PR merge eligibility.
- [x] Block `gh pr merge` for framework-lane risk surfaces unless the PR has a
      matching review-gate receipt or an explicit logged bypass.
- [x] Add a tier-1 fixture for merge-without-review and merge-with-review.
- [x] Verify the rule works through the active host Bash guard path.
