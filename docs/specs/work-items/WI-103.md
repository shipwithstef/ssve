# WI-103: Destructive Git Ops Must Prove No-Loss Before Running

**Type:** feature
**Status:** VERIFIED
**Closed:** 2026-04-25
**Merged PR:** #22
**Severity:** high
**Filed:** 2026-04-24
**Source:** session observation — agent ran `git reset --hard origin/main` after "continue autonomously"
**Lane:** framework

## Goal

Agents must not run destructive git commands (`reset --hard`, `push --force`, `clean -f`, `branch -D`, `checkout -- .`, `restore .`) without first gathering + surfacing evidence that nothing would be lost. "Continue autonomously" is NOT authorization for destructive ops.

## Context

In a parallel session (2026-04-24), after the user typed "continue autonomously", the agent ran:

```
git checkout main && git fetch origin && git reset --hard origin/main
```

It happened to be safe (branch was already at origin/main, no uncommitted changes, no unpushed commits). But the pattern is wrong:
- If there'd been uncommitted work → gone silently.
- If a local commit was ahead of origin → gone silently.
- If a stash was live → unreachable without reflog surgery.

The global rule in CLAUDE.md already flags `reset --hard` as a destructive op requiring user confirmation. This WI codifies the check procedure so the rule is operational, not aspirational.

## Acceptance Criteria

### US-01 — Pre-flight required before destructive git ops

- AC-01.1 A rule file `rules/git-destructive-preflight.md` defines the mandatory check sequence:
  1. `git status --short` — must be empty, OR each modified/untracked file must be explicitly justified.
  2. `git log origin/<branch>..HEAD --oneline` — must be empty, OR each local-only commit must be justified.
  3. `git stash list` — must be empty, OR the stash entries must be referenced in justification.
  4. `git reflog -n 5` — sanity check for recent HEAD moves.
- AC-01.2 Rule is registered in `skills-manifest.json` rulesRegistry (validator WI-078 catches drift).
- AC-01.3 Rule is injected via CLAUDE.md rules section (existing injection mechanism).

### US-02 — Hook-level guard (optional, higher leverage)

- AC-02.1 A PreToolUse hook `hooks/svc-git-destructive-guard.mjs` inspects Bash tool invocations, detects the destructive patterns, and blocks (exit 2) unless preflight evidence is in the tool-call rationale OR an explicit bypass phrase appears in the user's last message (e.g., "force reset", "discard everything").
- AC-02.2 Hook is wired via `scripts/wire-hooks.mjs` for claude host.
- AC-02.3 Tier-1 validator asserts the hook is wired and that `rules/git-destructive-preflight.md` is registered.

### US-03 — Learning + tier-1 pass

- AC-03.1 Learning appended: `destructive-git-ops-need-proof-of-no-loss` confidence 9.
- AC-03.2 Full tier-1 sweep PASS.

## Non-Goals

- Blocking non-destructive ops (`pull`, `fetch`, `merge --ff-only`, `checkout <branch>`).
- Making destruction impossible — explicit user request still wins.
