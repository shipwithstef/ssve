# WI-529 — Production closeout truth and Codex enforcement convergence

**Status:** VERIFIED
**Severity:** critical
**Base:** `0d75cb1d697d3c031e871f2bd182066a47f7bbb8`

## Outcome

Close the residual framework gaps after Execution Controller v2 without weakening evidence: truthful AGY review receipts, a genuinely launcher-routed and enabled Codex composite mutation gate, and an explicit safe consumer-repository surface.

## Scope

- Additive AGY compatibility in mandatory chain receipt schemas and tests.
- Normalize only repeated identical AGY structured documents; contradictory or malformed responses remain rejected.
- Route the existing serialized Codex PreToolUse dispatcher through the durable launcher.
- Fail setup when any governed wirer does not bind every declared routing marker to exactly one effective command.
- Preserve legacy receipts, unrelated hooks, user config entries, and all existing review/runtime semantics.
- Treat an explicitly disabled governed Codex command as drift; setup must re-enable the exact managed command without changing unrelated hook state.
- Define consumer repository identity and project-local skills without making a consumer checkout an executable source for framework enforcement.

## Non-goals

- No direct Gemini CLI review route.
- No reviewer policy redesign.
- No product behavior, database, payment, or deployment change.
- No removal of existing proof gates.

## Acceptance criteria

- **AC-529-1:** `review-plan` and `review-exec` receipts accept `agy` as primary or fallback and still reject unknown hosts.
- **AC-529-2:** AGY resolves mechanically to Google family and cannot self-review Google-authored work.

- **AC-529-4:** The dispatcher retains its exact child set including the skill-load enforcer, with no duplicate concurrent enforcer.
- **AC-529-5:** Setup, migration, drift detection, and self-heal bind governed tokens to one effective command and reject split-marker laundering or duplicate governed commands.
- **AC-529-6:** Hermetic focused tests and the repository Tier-1 suite show no new regression.
- **AC-529-7:** After landing, Codex setup and live drift check both pass from canonical main.
- **AC-529-8:** Canonical AGY transport produces one schema-valid result when the installed CLI repeats an identical document, without accepting conflicting documents.
- **AC-529-9:** Codex setup, migration, verification, drift, and self-heal reject a launcher-routed dispatcher whose effective `hooks.state` entry is explicitly disabled; setup re-enables only that exact managed entry.
- **AC-529-10:** Onboarded consumers can declare repo identity in `.agents/repository.json` and project-local skills through a committable `.agents/skills/` surface while framework executables continue resolving only from the durable central installation.
