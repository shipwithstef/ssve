# WI-198: End-to-end commitment is not a first-class session mode

## Problem

The framework reliability review found CRITICAL issue F-028: End-to-end commitment is not a first-class session mode.

## Evidence

`proposals/done/2026-05-08-end-to-end-execution-without-permission-checkpoints.md` shows repeated pauses after the user committed to full end-to-end completion, with the proposed `execution_mode: end_to_end` starting at line 39.

## Impact

The framework keeps returning coordination burden to the user at verification seams.

## Proposed Fix

Extend session-contract schema with `execution_mode`, implement natural-continuation rules, and add a Stop hook that blocks question-style trailers under end-to-end mode.

## Closeout

Closed 2026-05-10. `route-workflow` now recognizes `execution_mode: "end_to_end"` in `.svc/session-contract.jsonl`, documents the commitment phrases that set it, and states that natural follow-up work continues without confirmation until verified, blocked, or explicitly redirected. `_shared/session-contract.md` defines the shared schema and policy meaning.

Mechanical enforcement landed in `hooks/svc-task-completion-guard.sh`: when the newest session contract has `execution_mode: "end_to_end"`, the Stop hook scans `last_assistant_message` or the recent transcript for permission-seeking trailers (`if you want`, `let me know`, `should I`, `standing by`, trailing user-directed questions, etc.) and blocks the stop with an instruction to continue the next natural action. AP-32 documents the anti-pattern.
