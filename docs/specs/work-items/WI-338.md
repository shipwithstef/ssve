# WI-338: Mid-task hint persistence and skill resolver

## Problem

WI-201 fixed the critical method-correction routing path: route-workflow now
normalizes noisy user text, classifies mid-task corrections, and applies the
minimum viable method swap instead of starting a new goal.

The source proposal also asked for durable `mid_task_hints[]`, a resolver for
skill names mentioned in casual user text, and an audit-session signal for
artifact-count overreaction. Those are still useful because they make repeated
method corrections visible in later audits.

## Evidence

- `proposals/done/2026-05-09-intelligent-intent-parsing.md#F-04`
- `proposals/done/2026-05-09-intelligent-intent-parsing.md#F-05`
- `proposals/done/2026-05-09-intelligent-intent-parsing.md#F-06`
- `route-workflow/references/intent-classification.md` defines the classifier,
  but `.svc/lane-tasks-<WI>.json` has no durable `mid_task_hints[]` contract.
- `audit-session-execution/SKILL.md` does not currently flag method-correction
  overreaction by artifact-count asymmetry.

## Acceptance Criteria

- [x] Add a `mid_task_hints[]` lane-task field for user correction text,
      normalized intent, classification, applied method swap, and timestamp.
- [x] Add a skill-catalog hint resolver that maps casual mentions such as
      `test journey`, `visual tracking`, and `qa skills` to known skill names
      without starting a new lane.
- [x] Add audit-session-execution guidance or a validator fixture for
      artifact-count overreaction when a method correction implied a small swap.
- [x] Extend `validate-mid-task-correction-routing.sh` or add a sibling
      validator to cover persistence and skill resolution.

mapping work lands.
