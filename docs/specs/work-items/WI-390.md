**Status:** in_progress (worktree wi390; relational store schema + fail-closed builder + pointer-not-prose/orphan-tag validators + generate-don't-lint renderer + slice-ownership reference + validator built & verified — 14/14. v1 fenced to svc-native specs)

## Problem
The pipeline asserts "the feature spec is the single source of truth" (`audit-ac/SKILL.md:62`, `write-spec/SKILL.md:48`), but the join key wiring every artifact — the AC ID (`DISC-01`) — is free text re-typed into 5+ artifacts: the spec AC table, journey Gherkin tags (`@DISC-01`), sync-spec-code Implementation Notes, plan-changeset AC/test mapping, audit-implementation's checklist, and the spec's own Test column. No machine-readable store holds the story→AC→journey→test→task relationships; `write-journeys/SKILL.md:369` literally instructs the LLM to "build the feature graph" mentally, after a full-prose spec read, every run.

## Mechanism
`.svc/feature-graph.json` as canonical RELATIONAL store: nodes `{story, ac, journey-scenario, test, task, persona}`; edges between them. Each AC node carries `{id, qa_status, e2e_status, test_ref, status, file_anchor}` — a POINTER to the prose AC text, NOT a copy. Each skill reads/writes only its slice (write-spec→ac/story nodes; write-journeys→scenario→ac edges; write-e2e→test→ac edges; plan-changeset→task→ac edges). Coverage matrices become deterministically rendered views — the WI-364 generate-don't-lint pattern transplanted to the product pipeline.

## Mechanism (as built)
1. **`schemas/feature-graph.schema.json`** — the relational store shape (nodes: story/ac/journey-scenario/test/task/persona; edges; AC node carries `file_anchor` POINTER, forbids prose copy).
2. **`scripts/build-feature-graph.mjs`** — `buildGraph`/`validateGraph`/`parseAcTable` (pure, exported) + CLI. Parses the AC table → `ac` nodes with `file_anchor` pointers (no prose copy); journey/test `@AC` tags → `scenario-covers-ac`/`test-covers-ac` edges; an orphan tag → build FAILS. FAIL-CLOSED: no parseable AC table → non-zero (never an empty clean graph).
3. **`scripts/render-coverage-matrix.mjs`** — generate-don't-lint via the WI-364 marker engine; `--check` exits 1 on graph↔matrix drift, `--write` regenerates. The matrix carries AC id + status columns, never the prose description.
4. **`references/feature-graph.md`** — slice-ownership contract (write-spec→ac/story; write-journeys→scenario edges; write-e2e→test edges; plan-changeset→task edges) + the AC4 carve-outs; pointer in `audit-ac`.
5. **validator** — `test-framework/evals/tier-1/validate-feature-graph.sh`.

- [x] v1 fenced to svc-native/greenfield specs; brownfield deferred; sequence AFTER WI-364 (cited). *(Verified: builder requires the `| AC | Description | QA | E2E | Test |` contract, fail-closed otherwise; reuses WI-364's marker engine.)*

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-feature-graph.sh`
- **failure_class:** the feature graph copying AC prose (instead of a pointer — a second drifting prose store), a silent fail-OPEN parser emitting an empty graph that validates clean, an orphan `@AC` tag passing unnoticed, or the coverage matrix drifting from the graph undetected.
- **promotion_signal:** condition 3 — the graph + render-don't-lint sit on the product pipeline's coverage-verification path (audit-ac/verify-promotion); a prose-copy or fail-open regression silently re-introduces the join-drift class this WI removes.
- **expected_runtime_budget:** <1s (pure builder/validator unit + a temp-dir CLI roundtrip; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** the pointer-not-prose + fail-closed + orphan-tag invariants are the whole value; a regression that lets prose back in or fails open is silent and re-creates the drift, so they must be re-proven every lint.

## Value-preservation
Increases value on the join-drift class; win re-baselined honestly to ~20-35% (only ~27% of a spec is relational) + a qualitatively new instant-query capability. The graph never becomes the authoritative prose store, so the drift gates keep their evidence source.

## Vision fit (whole-company / versatile PM)
Gives the product-manager role a single living operating system wiring stories→ACs→journeys→tests→tasks — the PM's actual cockpit, replacing scattered prose memos with one queryable graph the whole company reads.
