## Problem

Two compounding drags, both audit-verified:

1. **Capability friction:** the Claude host pays ~13 synchronous node spawns per Edit, 5 per Bash, 2 per Read (live settings.json census), and five guards demonstrably misfire against cooperating agents (exact-match destructive preamble; out-of-repo write gating; display-only Stop-block cap; command-string-only commit checks; cross-session state bleed). The guards' hard-deny posture ignores Claude Code's native `permissionDecision:"ask"` flow, so the trained behavior is *workarounds* (/tmp+cp, git plumbing) — strictly worse for safety than the native tools the guards block.

2. **Dormant multipliers:** the 2026-06-08/09 marathon shipped the S2–S5 substrates (stage isolation, review station, baton, tiering, fires ledger), and the SKILL.md prose mandates them — but **no native subagent definitions exist** for the stage executors or review lenses (violating the locked-agent policy WI-372 the framework itself enforces), **zero activation runs** have exercised them, the chain itself has **zero journey/AC coverage** (only J01–J03 discussion journeys exist), and graded tiering is default-off with no qualifying-streak tracker.

Each fix is individually small; together they convert the shipped substrate into the actual productivity step-change. Honest multiplier math in §Value.

## Subagent design constraints (BINDING for B1–B3 — from official Claude Code guidance, fetched 2026-06-10)

User directive: subagents "can occasionally regress quality and overspend tokens — design by latest Claude Code guidelines." Researched via claude-code-guide against code.claude.com/docs (sub-agents, costs, agent-view, settings). These constraints are acceptance-blocking for B1–B3:

**1. Dispatch decision tree (when NOT to spawn).** Official guidance lists "multiple phases share significant context (planning → implementation → testing)" as a MAIN-CONVERSATION case, and warns "running several sessions or subagents at once multiplies token usage" (agent teams ≈7×). Therefore:
- Stage isolation (B2) triggers ONLY on M+ WIs where predicted orchestrator context would hit the DEGRADING tier (`references/context-budget.md`); S-sized WIs stay inline-serial. The route-workflow:187 prose gets this threshold added.
- A subagent is justified only when (a) verbose output would flood the orchestrator context and only a summary is needed, (b) tool/permission restriction is the point (lenses), or (c) fresh-context independence improves review quality. Single-fact lookups and known-target work stay inline (existing `tool-selection.md` rule).

**2. Token economics.** Fresh subagents reload CLAUDE.md + memory hierarchy + git status every spawn — a fixed cost floor per dispatch. Counters: (a) ≤4 parallel lenses, schema-forced ≤1K-token returns (summary-bottleneck cap); (b) prefer **forked subagents** (v2.1.117+, prompt-cache reuse makes them cheaper than fresh spawns) for context-heavy continuations once the fork flag is stable — track `CLAUDE_CODE_FORK_SUBAGENT` rollout; (c) no nested spawns (officially unsupported — chain from the orchestrator); (d) `svc-state-janitor` runs `background: true`.

**3. Model tiering (official: "Reserve Opus for complex architectural decisions… Use Haiku for simple subagent tasks").** Per `references/model-registry.json` labels: `svc-stage-plan` → [PLAN] tier; `svc-stage-exec` → [EXEC]; `svc-lens-spec-fidelity`/`svc-lens-correctness`/`svc-lens-security` → [REVIEW]; `svc-lens-perf` (mechanical checks) + `svc-state-janitor` → [PASS]/Haiku; `svc-journey-qa` → [REVIEW]. Every agent file declares `model` explicitly — `inherit` is forbidden for lenses (cost) and for stage-exec (determinism).

**4. Quality-preservation rules.** (a) Fresh subagents that skip or compress context MUST have critical rules restated in the locked prompt (official: Explore/Plan skip CLAUDE.md — "If a rule must [reach the subagent], restate it in the prompt"); for svc this means the baton path, receipt obligations, and NUL/state-io rules are IN the agent definition, not assumed ambient. (b) Lenses get `tools: Read, Grep, Glob, Bash` + read-only posture; `svc-stage-exec` gets `isolation: worktree`. (c) Every agent declares `maxTurns` (lenses ≤15, stages ≤80, janitor ≤20). (d) Hash-bound baton inputs, never prose summaries, between stages (WI-380 invariant). (e) `description` fields state precise delegation criteria so auto-delegation cannot misfire.

**5a. Orchestration primitives (clarified 2026-06-10, user question + stored CC knowledge).** "ultracode" = the Workflow tool (deterministic script fan-out, shared budget, schema-forced results) — the sanctioned multi-agent primitive. **Agent teams stay OFF** (experimental CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS: ~7× tokens, no worktree teammates, SendMessage-resume locked behind it — live-confirmed unavailable 2026-06-10; the fresh-agent+baton fallback did the same patch round at 69K tokens). Track FORKED subagents (CLAUDE_CODE_FORK_SUBAGENT) as the cheap continuation primitive to adopt when stable.

**5. Measure-then-promote.** No subagent topology becomes the DEFAULT route on evidence-free grounds: B2/B3 each record a cost+quality comparison against the serial baseline (total tokens, findings caught, iteration count, wall-clock). Promotion requires quality non-regression AND token delta ≤1.5×; otherwise the topology stays opt-in and the comparison is filed in the run record. Kill-switch: `SVC_STAGE_ISOLATION=off` (or absence of the agent files) falls back to the serial prose chain — the chain NEVER depends on subagents to function.
