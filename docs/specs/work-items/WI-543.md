## Problem

`scripts/wire-grok-hooks.mjs` writes flat TOML into `~/.grok/config.toml`:

```toml
[[hooks]]
event = "SessionStart"
matcher = "*"
command = "/home/dianast/.nvm/versions/node/v24.13.0/bin/node ~/.grok/skills/hooks/svc-session-start-healthcheck.mjs"
timeout = 10
```

`FRAMEWORK-STATE.md` documents that shape. Current Grok user-guide
(`~/.grok/docs/user-guide/10-hooks.md`) documents a **different** shape:

```toml
[[hooks.SessionStart]]
matcher = "*"
hooks = [
  { type = "command", command = "...", timeout = 30 },
]
```

Live Grok sessions on 2026-08-17 executed **only**
`global/settings:*` handlers (Claude `~/.claude/settings.json` via
`[compat.claude] hooks = true`). The SessionStart event had exactly five
runs — the five Claude SessionStart entries. The Grok-native
`timeout = 10` healthcheck in `config.toml` never appeared.

Consequence: Grok-native timeouts, matchers, and Stop/PreToolUse guards
written by `wire-grok-hooks.mjs` are not the hooks the TUI is running.
Claude-compat copies run instead, with Claude's missing timeouts and
Claude's `node` PATH assumptions.

## Root cause (one line)

The wirer emits a Kimi-style flat `[[hooks]]` table; current Grok parses
(and the TUI displays) the nested `[[hooks.<Event>]]` object documented
in Grok's own hook guide, so the wired file is dead weight and Claude
compat is the only live path.
