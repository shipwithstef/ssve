# WI-502: Canonical operation scope and durable authority

**Type:** framework authority regression and capability extension
**Status:** VERIFIED
**Severity:** critical
**Filed:** 2026-07-20
**Lane:** framework
**Related:** WI-484, WI-486, WI-487, WI-494, WI-496, WI-498, WI-499, WI-501
**Journey:** `docs/specs/journeys/J-FW-05-multi-session-contention.feature.md`

## Problem

Codex mutation authority is resolved from the session-level hook `cwd`, even when a tool call declares a different explicit `tool_input.workdir` or names mutation targets in another worktree. This creates both failure directions:

- a command explicitly based in an ungoverned directory can be denied because the session started in a governed repository;
- a command or patch explicitly targeting a governed worktree can be allowed because the session started outside Git.

The current binding/claim model then stops at one immutable owning session. It has no atomic controller handover, generation-bound child delegation, within-WI execution graph, scoped child receipt, or sequential merge-back proof. Shell path inspection also cannot provide filesystem containment by itself.

## Reproduction evidence

All probes invoked the current Codex enforcer directly and made no filesystem mutation.

1. `cwd=<seriousvibecoding-main>`, Bash `workdir=/tmp`, command `touch harmless-probe` → denied for no active task.
2. `cwd=/tmp`, Bash `workdir=<WI-502-worktree>`, command `touch governed-probe` → allowed.
3. `cwd=/tmp`, `apply_patch` with an absolute `*** Add File` target inside the WI-502 worktree → allowed.

The earlier WI-494 adversarial review already reported the same `tool_input.workdir` omission in `docs/specs/reviews/wi494-codex-enforcer-exec-review-log-iter2.yaml`, but it was dismissed against the then-known payload contract.

## Root cause

**Immediate cause:** `hooks/codex/lib/codex-hook-context.mjs` derives the effective repository exclusively from top-level `payload.cwd`; it does not resolve explicit operation workdir or file targets before authority lookup.

**Enabling condition:** path classification is split across `codex-hook-context`, `hook-payload`, and `svc-worktree-isolation-guard`; each has a different partial parser and none produces one canonical operation scope for all mutation guards.

**Systemic cause:** current worktree-local claim and binding state proves one session tuple but is not a durable lease/capability system. Current dispatch contracts rely on prose and post-hoc changed-file lists rather than pre-issued, generation-bound child authority.

## Required outcomes

### Operation scope

- [x] OS-01 Preserve the canonical session cwd and its original repository identity separately from operation scope.
- [x] OS-02 Read an explicit workdir only from a host/tool adapter field whose payload contract is verified; resolve relative values against session cwd and canonicalize with `realpath`.
- [x] OS-03 Reject missing, dangling, invalid, non-directory, or contradictory explicit workdirs for mutations.
- [x] OS-04 Resolve the exact Git worktree root and canonical common Git directory for session cwd, effective workdir, and every mutation target.
- [x] OS-05 A non-Git effective workdir does not make a governed target ungoverned.
- [x] OS-06 `apply_patch` covers every Update/Add/Delete and move/rename source and destination; new targets canonicalize the nearest existing parent.
- [x] OS-07 Edit/Write and supported structured tools extract every supported `path`/`file_path` target.
- [x] OS-08 All mutation targets belong to exactly one worktree and repository; mixed scopes deny, workdir and target scope agree, symlinks canonicalize, and nested repositories/submodules require their own authority.
- [x] OS-09 Sanctioned loader/bootstrap command shapes validate both their executable and explicit graph/script/worktree targets.
- [x] OS-10 The same normalized operation-scope result feeds the Codex authority enforcer and universal worktree isolation guard.

### Shell boundary

- [x] SB-01 Reject structured or obvious cross-root Bash forms including `git -C`, directory-changing command segments, absolute mutation operands, and absolute output redirections when they escape authority.
- [x] SB-02 Do not claim that syntax inspection proves arbitrary Bash containment.
- [x] SB-03 Supported host profiles declare their real filesystem containment mechanism and fail closed for mutating child execution when containment is unavailable.
- [x] SB-04 Documentation states that PreToolUse hooks are an authority guardrail, not a complete shell security boundary, wherever host sandbox/wrapper containment is absent.

### Controller authority

- [x] AU-01 A mutation principal is derived from stable host + session id + optional stable agent id; role/name alone never grants ownership.
- [x] AU-02 Repository identity is a digest of the canonical common Git directory; worktree identity remains exact and separate.
- [x] AU-03 One controller lease records lease id, principal, WI, worktree, generation, state, issue/renew/expiry times, and CAS revision.
- [x] AU-04 Same-session resume reattaches without changing generation after repository/WI/worktree/graph validation.
- [x] AU-05 New-session handover uses prepare/accept, a one-time expiring secret, CAS, generation increment, old-receipt invalidation, frozen children, and an audit receipt.
- [x] AU-06 Recovery requires positive same-host liveness evidence or configured expiry, fails closed on corrupt evidence, increments generation, and records reason/evidence.
- [x] AU-07 Existing v1 claims/bindings never silently become v2 authority; migration is explicit, backed up, digest-checked, and reversible.

### Delegated mutation and merge-back

- [x] DG-01 The WI lane retains one `execute-changeset` stage while a versioned nested execution graph represents waves and leaf task states.
- [x] DG-02 Every mutating child receives one inner worktree, one stable principal, one task-specific generation-bound capability, explicit allowed/denied paths, base SHA, expiry, and depth.
- [x] DG-03 Parent persists the parent-to-child edge before launch; hooks never infer parenthood from names, roles, or shared session ids.
- [x] DG-04 Concurrent scopes are pairwise disjoint after dependency and shared-resource expansion; unknown or shared scopes serialize.
- [x] DG-05 Child hook checks principal, capability status/expiry, controller generation, exact inner worktree, allowed/denied paths, task state, and skill receipt.
- [x] DG-06 Children cannot mutate parent graph/lease, sibling state, shared receipts, or delegate unless depth explicitly permits it.
- [x] DG-07 Completion receipts bind delegation, principal, generation, task, base/head/commits, exact files, diff digest, validation digest, cleanliness, and completion time.
- [x] DG-08 Parent validates descent, scope, digest, denied/shared files, clean state, validation, and current assumptions; merge-back remains sequential with source-to-integration commit mapping and post-merge revalidation.
- [x] DG-09 Handover freezes old-generation child results; the new controller must adopt, wait-with-new-receipt, revoke, or restart each child.
- [x] DG-10 Timeout, crash, scope violation, conflict, unknown files, owner exit, nested delegation, and duplicate task acceptance have deterministic terminal behavior.

## Delivery boundary

WI-502 owns the complete contract and one reviewed implementation changeset, but execution is checkpointed in four reversible slices: canonical operation scope, v2 controller lease/handover, delegated execution/merge-back, and host containment/rollout. No partial slice is promoted as complete authority; each slice must pass its focused red/green fixture before the next begins.

## Register discoveries

The authority correction stays one governed WI with four mandatory implementation slices. Separate authority child WIs are not created because partial schemas would create two simultaneous authority systems; the plan instead supplies checkpointed rollback anchors and prevents promotion between slices.

Independent discovery: WI-503 records the canonical external-review adapter's relative custom-artifact-path receipt-display failure observed after the successful WI-502 Fable review. It is not an authority semantic and remains outside this changeset.

## Learnings

A top-level session cwd is context, not operation scope. Every mutation guard must compare canonical workdir and canonical targets before authority resolution, and every derived child right must be an explicit generation-bound capability rather than an inferred relationship.
