## Problem

The framework has standalone skills for feature validation, AC audit, journey writing, E2E writing, runtime journey testing, visual evidence, review, and promotion, but route-workflow does not force those outputs into one AC-by-AC feature closeout ledger. Agents can run fragments of validation and still summarize a user-facing feature as complete without proving every acceptance criterion across persona, journey, runtime, E2E/manual, visual, and saved-state evidence.

## Evidence

- `proposals/done/2026-05-11-framework-improvement-feature-validation-closeout-ledger.md`
- `proposals/done/2026-04-25-prevent-deployed-unverified-shipping.md`
- `proposals/done/2026-05-05-evolution.md`
- Current delivery graph evidence families omit `feature_validation_closeout`.
- Existing WI-197/WI-198/WI-199 prevent parts of the failure, but do not create a single mandatory feature ledger.

## Acceptance Criteria

- [x] Add `feature_validation_closeout` as a delivery graph evidence family for user-facing and admin-facing feature work.
- [x] Add a canonical `FEATURE_VALIDATION_LEDGER.md` template under the feature evidence path.
- [x] Add `scripts/validate-feature-closeout-ledger.mjs` that checks every feature AC appears exactly once with persona, journey/scenario, runtime, E2E/manual, evidence path, and final result columns.
- [x] Route-workflow inserts the full validation graph for feature-class work: `validate-feature`, `write-spec` or `sync-spec-code`, `audit-ac`, `build-personas` check, `write-journeys`, `write-e2e` when automatable, `test-journeys`, `track-visuals`, `review-gate`, and `verify-promotion`.
- [x] Review-gate cannot PASS a user-facing feature without a valid ledger or explicit non-user-facing rationale.
- [x] Verify-promotion cannot mark a user-facing feature `framework-complete` without a valid ledger.
- [x] A WI-233-style replay fixture fails when only API probes, dialog screenshots, or partial saved states exist.
- [x] Existing verified WIs that cover adjacent pieces are cross-linked, not duplicated.

## Route Recommendation

Run `improve-framework` with this WI as the single implementation target. This is the highest-priority connector between the standalone validation skills the user called out.

## Notes

This WI is the direct fix for the token-wasting failure class where the framework spends effort on receipts or visual fragments but does not connect them into complete feature validation.
