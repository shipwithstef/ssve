# WI-193: Tier-2 assertions are often presence checks rather than process checks

## Problem

The framework reliability review found HIGH issue F-023: Tier-2 assertions are often presence checks rather than process checks.

## Evidence

[FRAMEWORK-STATE.md](/workspace/seriousvibecoding/FRAMEWORK-STATE.md:366) records that `diagnose-bug-typo` passes on strings such as "root cause" and "pattern" rather than substantive execution.

## Impact

Agents can satisfy tests with placeholder text.

## Proposed Fix

Replace string-existence assertions with structured output schemas and negative fixtures.

## Acceptance Criteria

- AC1: The specific F-023 failure mode is fixed for the cited `diagnose-bug-typo` scenario by structured process assertions that reject placeholder "root cause" / "pattern" text without concrete evidence.
- AC2: `test-framework/evals/tier-1/validate-tier2-process-assertions.sh` proves both the positive fixture and the negative placeholder fixture.
- AC3: `test-framework/evals/tier-2/run-tier2.sh`, `scripts/tier2-process-assertions.mjs`, and `test-framework/evals/tier-2/scenarios/diagnose-bug-typo.md` are updated in sync.
- AC4: `bash test-framework/evals/run-all-evals.sh` passes with the WI-193 validator included.

## Closeout

Status: VERIFIED on 2026-05-11.

Implemented:

- Added `scripts/tier2-process-assertions.mjs`, a structured assertion helper for tier-2 scenario artifacts, output, and lane-task phase receipts.
- Wired `test-framework/evals/tier-2/run-tier2.sh` to run process assertions when scenarios declare `### Process Checks`.
- Added concrete process checks to `test-framework/evals/tier-2/scenarios/diagnose-bug-typo.md`: bug brief exists, wrong/correct field comparison, file:line evidence, concrete pattern scan, and `P3-RootCause` phase receipt.
- Added `test-framework/evals/tier-1/validate-tier2-process-assertions.sh` with a positive substantive fixture and a negative placeholder fixture.
