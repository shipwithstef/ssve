# WI-348: Wave closeout validator for multi-WI follow-up batches

## Problem

Exploratory and dispatch-style runs can file or close a large batch of related
follow-up WIs. Existing guards validate individual WIs, journey terminality,
task graphs, and worktree hygiene, but they do not provide one command that
reconciles the whole batch before an agent says "all are closed."

That leaves room for false closure: one missing WI doc, stale INDEX row,
incomplete lane graph, absent runtime evidence artifact, or leftover scoped
worktree can hide inside an otherwise valid wave.

## Impact

Batch closeout errors are expensive because the user has to audit the whole
set manually. They also make future sessions misread partially closed waves as
complete, especially after exploratory testing where follow-up WIs are created
from runtime discoveries.

## Fix

- Add `scripts/validate-wave-closeout.mjs`.
- Add `references/wave-closeout-validation.md`.
- Teach `route-workflow` to require the validator for batch closeout claims.
- Teach `dispatch-waves` to use the same gate before saying every dispatched
  WI is closed.
- Add tier-1 coverage for happy path, missing index row, missing lane graph,
  missing evidence, latest failing evidence, expected-count mismatch, and
  scoped residual worktree.

## Acceptance Criteria

- [x] Validator accepts `--from/--to`, `--ids`, `--expect-count`, `--root`,
      `--evidence-root`, and `--worktree-scope`.
- [x] Validator fails when any WI doc is missing or non-terminal.
- [x] Validator fails when any INDEX row is missing or non-terminal.
- [x] Validator fails when any `.svc/lane-tasks-WI-<n>.json` is missing,
      incomplete, or fails `task-graph.mjs validate` when available.
- [x] Validator fails when a WI has no recognized JSON runtime evidence.
- [x] Validator fails when the newest recognized JSON evidence has a non-zero
      failure, unexpected, error, or timeout count.
- [x] Validator fails when `git worktree list --porcelain` shows a residual
      scoped worktree for the WI batch.
- [x] `route-workflow` and `dispatch-waves` document the wave closeout gate.
- [x] Tier-1 replay coverage proves the positive and negative fixtures.
