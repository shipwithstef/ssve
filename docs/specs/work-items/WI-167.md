# WI-167: Fix relative paths in route-workflow/SKILL.md that break when installed

**Type:** framework
**Status:** VERIFIED
**Severity:** CRITICAL
**Filed:** 2026-05-08
**Source:** route-workflow framework audit

## Audit Verdict — VALID, CRITICAL severity correct (ship)

Confirmed: `route-workflow/SKILL.md` lines 62-63, 75 use `bash ../../scripts/detect-host.sh` and `bash ../../scripts/resolve-model.sh`. Relative paths break when:
- Skill is loaded from a non-standard cwd
- Skill is symlinked from a different directory tree
- Host's skill-loader resolves SKILL.md without chdir into the skill's directory

The same file uses host-aware absolute resolution correctly at lines 91, 96-102. Lines 62-63 and 75 are inconsistent with the file's own pattern.

**Ship plan:**
1. Replace `../../scripts/X` with the `<SKILLS_PATH>/scripts/X` pattern shown later in the file (with the host-table reference for resolution).
2. Bundle with WI-151 as the "host-portability sweep" PR.
3. Tier-1 validator (shared with WI-151): grep all `*/SKILL.md` for relative path bash invocations (`bash \.\./`); fail if found.

## Problem
`route-workflow/SKILL.md` references:
- `bash ../../scripts/detect-host.sh` (line 62)
- `bash ../../scripts/resolve-model.sh STRAT --json` (line 63)
- `../../references/host-capabilities.md` (line 75)

When installed via `./setup` to `~/.kimi/skills/route-workflow/SKILL.md`, `../../scripts/` resolves to `~/.kimi/skills/scripts/` which does not exist.

## Impact
Every host-specific path in route-workflow is broken when the skill is installed. The skill assumes it's being read from the repo root, not from an installed skills directory.

## Acceptance Criteria
- [x] Replace all relative paths with host-resolved paths (use `detect-host.sh` output or `<SKILLS_PATH>` variable)
- [x] Audit all other skills for same broken relative path pattern
- [x] Add tier-1 validator that scans all SKILL.md files for `../` or `../../` paths and flags them
- [x] Verify all paths work when skill is installed on all 5 hosts

**Next:** `improve-framework` → `plan-changeset` → `execute-changeset`
