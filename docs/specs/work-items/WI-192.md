# WI-192: Tier-3 coverage remains effectively absent

## Problem

The framework reliability review found HIGH issue F-022: Tier-3 coverage remains effectively absent.

## Evidence

[FRAMEWORK-STATE.md](/workspace/seriousvibecoding/FRAMEWORK-STATE.md:364) records tier-3 coverage at 1/35 scenarios. Current repo has 36 tier-2 scenario files but tier-3 only contains runner and judge prompts.

## Impact

The adversarial judge layer is advertised but does not cover most skills.

## Proposed Fix

Batch tier-3 across all tier-2 outputs with cost ceilings and per-skill regression baselines.

## Acceptance Criteria

- AC1: The specific F-022 failure mode is fixed by a tier-3 coverage plan that covers every registered tier-2 scenario across completeness, actionability, and consistency.
- AC2: `test-framework/evals/tier-1/validate-tier3-coverage-plan.sh` proves the plan covers all tier-2 scenarios and that tier-3 low scores fail the runner.
- AC3: `test-framework/evals/run-all-evals.sh`, `test-framework/evals/tier-3/run-tier3.sh`, `scripts/tier3-coverage-plan.mjs`, and `test-framework/evals/tier-3/skill-baselines.json` are updated in sync.
- AC4: `bash test-framework/evals/run-all-evals.sh` passes with the WI-192 validator included.

## Closeout

Status: VERIFIED on 2026-05-11.

Implemented:

- Added `scripts/tier3-coverage-plan.mjs` to derive tier-3 judgments from registered tier-2 scenarios.
- Added `test-framework/evals/tier-3/skill-baselines.json` with score floor, dimensions, cost ceiling, and per-skill overrides.
- Updated `test-framework/evals/run-all-evals.sh` to validate the tier-3 plan before judging and batch completeness/actionability/consistency.
- Updated `test-framework/evals/tier-3/run-tier3.sh` so unparseable or below-floor judge output fails instead of silently passing.
