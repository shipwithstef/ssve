## Problem

`docs/specs/plans/FRAMEWORK_OPTIMIZATION_PLAN.md:15` proposes OPT-01: auto-parse markdown candidate specs (`docs/specs/candidates/*.md`) into SQLite, justified as "Follows repo `.gitignore` line 60".

Both halves fail verification:

- **No markdown candidate format exists anywhere.** The only candidate artifact is `docs/specs/candidates/consumer-experience-pool.json`, and `docs/specs/contract-maps/candidate-triage-projection.md:28` fixes the contract at `docs/specs/candidates/<topic>.json`. Implementing OPT-01 would have meant inventing a file format from nothing and shipping it as an optimization.
- **The cited rationale is provably false.** `.gitignore:60` is a comment about per-session rule-injection memos (WI-361/398) and has nothing to do with candidates — verified on `HEAD` as well as the working tree. The `.json` is legitimately tracked; there is no rule it violates.

OPT-01 was the largest item in the batch. It was correctly not built, but a refuted item that simply disappears is indistinguishable from one that was forgotten — hence this WI.

## The decision to make

Either:

1. **Define a markdown candidate spec format deliberately** — with a stated reason why markdown beats the existing JSON contract for candidate specs — and then implement ingestion against that defined format; or
2. **Delete OPT-01** from `FRAMEWORK_OPTIMIZATION_PLAN.md`, recording that its premise did not survive verification.

Option 2 is the default absent a concrete argument for markdown candidates. Do not implement ingestion for a format nobody has specified.

## Acceptance criteria

- [ ] **AC-1** OPT-01 is either deleted from the plan with its refutation recorded, or a markdown candidate format is specified before any parser is written.
- [ ] **AC-2** If any other item in that plan cites a `.gitignore` line as justification, that citation is verified too — one false rationale suggests the class was not checked.
