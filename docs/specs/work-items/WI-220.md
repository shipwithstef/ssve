# WI-220: Require landing-state verification before audit-session closeout

## Goal

Prevent `audit-session-execution` from calling framework implementation work "closed" while validated changes remain uncommitted, unpushed, unmerged, or unverified after merge.

## Context

The WI-216 closeout audit correctly found and fixed an implementation defect, but the first closeout stopped at "audit artifact written + WI status completed" while the implementation was still only local work. The user had to challenge the stop point before the work was committed, PR'd, squash-merged, and post-merge verified.

That is an audit closeout gap. A session audit that touches framework implementation artifacts must distinguish:

- report complete
- implementation committed
- PR opened
- PR merged
- post-merge validation complete
- local checkout clean and aligned with `origin/main`

## Acceptance Criteria

- AC1: `audit-session-execution/SKILL.md` gains a mandatory landing-state section before any final "closed" or "complete" verdict when the audited session created or modified repo files.
- AC2: The section requires evidence from `git status --short --branch`, current branch, PR state when a PR exists, merge commit, and post-merge validator output.
- AC3: If dirty local changes remain, the audit verdict must be `implementation-not-landed` or equivalent, not `closed`.
- AC4: Add a tier-1 validator or fixture that fails if `audit-session-execution` lacks the landing-state closeout wording.
- AC5: The recovery text tells the agent to commit, open PR, merge, and post-merge verify, or explicitly log a user-approved "do not land" decision.

### Resolution

`audit-session-execution` now has a mandatory landing-state closeout gate for
audits where the session created or modified repository files. The audit can
finish as a report while implementation remains explicitly not landed; it can no
longer call local dirty/unmerged work closed.

### Changes

- Added `## Landing-State Closeout Gate` to `audit-session-execution/SKILL.md`.
- Required `## Landing-State Verification` report evidence from git status,
  current branch, PR state when a PR exists, merge evidence, and post-merge
  validator output.
- Added explicit verdicts: `audit-report-complete`,
  `implementation-not-landed`, `implementation-landed-verified`, and
  `do-not-land-approved`.
- Added `test-framework/evals/tier-1/validate-audit-session-landing-state.sh`
  to prevent the gate from being removed or weakened.
