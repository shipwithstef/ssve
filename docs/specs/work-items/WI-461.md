## No-loss spine
The escape hatch "verify less / drop gates" is REJECTED — the 0-quality-loss floor is absolute. Every child changes *where/when/how* verification runs, never *whether*. (8) in particular must demonstrate non-regression under the WI-399 gate before promotion; until then it is opt-in experiment.

## Child specs

### WI-462 — (17) pre-loop verification discipline guard  [P0]
- Mechanical pre-check invoked before any multi-run verification loop (e.g. in the no-loss-verify harness and in route-workflow's verification-heavy task graphs): assert `pwd` == repo root (validators are cwd-sensitive; wrong-cwd inflated this session's failure count 12–15 and triggered a phantom race-hunt) AND an OLD-baseline run in the SAME worktree/env has completed (so env-reds are separated from real regressions BEFORE the loop). BLOCK + emit the canonical fix if violated.
- No-loss: purely additive guard; cannot change any validator's verdict, only the order/cwd of running them.
- AC: red→green regression (a wrong-cwd or no-baseline loop entry is blocked); ~11/17-class waste prevented in a replay fixture.

### WI-463 — (1) no-loss-verify harness  [P0]
- `scripts/no-loss-verify.mjs <runner> --suspects <list>`: (1) prep clean worktree env once (residue + fresh contract); (2) OLD-baseline-same-env once; (3) NEW once; (4) loop ONLY the suspect+parallel-batch set N× for stability; (5) seeded-failure check; (6) report the delta (parallel-batch-clean? new failures ⊆ baseline?).
- No-loss: runs the SAME validators; just orchestrates the comparison so the proof is rigorous in ~4 runs instead of ~17.
- AC: on a hot-path refactor fixture, harness reproduces the no-loss verdict in ≤4 full-suite-equivalents; suspect-loop catches a seeded race.

### WI-464 — (9) no-loop merge halt + merge-helper standing permission  [P1]
- Stop-hook/`/goal` guard: when the only-remaining condition is an auto-mode-blocked self-merge / push-to-default, emit a terminal `blocked-on-user` state ONCE and stop re-firing (no infinite nag).
- Doc: a standing `Bash(node scripts/merge-pr-with-review-receipt.mjs:*)` permission recipe (the helper enforces non-self receipt + PASS + non-empty evidence, so it does not weaken two-party review).
- No-loss: does not bypass the merge gate; only stops the loop + documents the sanctioned permission.

### WI-465 — (10) destructive-preamble de-friction  [P2]
- `hooks/svc-workflow-guard.mjs` destructive-preamble matcher: strip markdown (`**`, backticks) before matching; accept ONE preamble that names a batch of same-kind targets to authorize them together in the next turn. Keep the prior-turn requirement.

### WI-466 — (11) pre-commit drift-check cadence  [P2]
- `hooks/svc-pre-commit-multi-host-check.sh`: move the 8-host `./setup` drift detection to pre-push, OR make it incremental (only hosts whose source changed). Per-commit full multi-host setup (>2min, SIGTERM at the 2-min default) is the wrong cadence.

### WI-467 — (12) contract-freshness auto-refresh  [P2]
- `hooks/svc-session-contract-freshness.mjs`: on an active in-repo session, auto-append a fresh contract line instead of HARD-blocking the write (still log staleness). Non-blocking refresh removes a recurring ~3-write-per-session stall.

### WI-468 — (13) emit-envelope generator  [P2]
- `scripts/emit-envelope.mjs`: build all 5 chain receipts (plan-manifest/exec-record/review-plan/review-exec/audit) from git (diff_hash/tree_hash/files) + the Codex review output + templates; call `emit-receipt` ×5; verify with `check-chain-receipts`. Removes hand-authored JSON + the fabrication risk.

### WI-469 — (8) conductor + parallel executors — measured experiment  [P3]
- Default-promote WI-380/382 transport for multi-item epic runs ONLY, behind WI-383 measured-tiering + WI-399 economics (≤1.5× tokens, non-regression). **Subagent dispatch ONLY (Agent/Task), never `-P`/xargs.** Prove the 0-quality-loss gate (`.svc` state races via WI-398 merge driver, discipline replication, context-handoff loss) BEFORE any default flip. Until proven: opt-in.
