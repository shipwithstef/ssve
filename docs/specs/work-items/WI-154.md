**Type:** framework

## Audit Verdict — VALID (ship as filed)

Confirmed: `route-workflow/SKILL.md` frontmatter has `chain.lanes: {}` empty. Since route-workflow IS the lane router, this is structurally wrong — it should declare the seven lanes it routes between.

**Ship plan:**
1. Populate `chain.lanes` with the 7 canonical lanes (greenfield, brownfield-conversion, brownfield-feature, bugfix, drift, refactor, framework) referencing `references/lane-model.md` for each lane's skill sequence.
2. Add a tier-1 validator that route-workflow's `chain.lanes` keys match `laneDefinitions` in `skills-manifest.json`.
3. Bundle with WI-153 + WI-164 in the frontmatter completeness sweep.

## Problem
`route-workflow/SKILL.md` frontmatter has:
```yaml
chain:
  lanes: {}
  progressive: false
  self_verify: true
```
The central routing skill's own metadata doesn't describe its lane relationships. Lane definitions live in `skills-manifest.json` and `references/lane-model.md`, not in the skill contract.

## Impact
Any automated tool reading skill frontmatter to understand lane topology gets nothing from the most important skill.
