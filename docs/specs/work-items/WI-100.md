# WI-100: capture-idea --from-proposal parser bugs — Goal TBD + AC dropped under nested headings

**Type:** bugfix
**Status:** VERIFIED
**Closed:** 2026-04-24
**Merged PR:** #12
**Severity:** high
**Filed:** 2026-04-24
**Source:** framework-session observation (A2 in evolve-framework tier-A queue)
**Lane:** framework

## Goal

Fix two defects in `capture-idea --from-proposal` that silently corrupt every emitted WI:

1. **`## Goal` renders `_TBD — defer to plan-changeset_`** even when the proposal has a `## Goal` section with real content. Root cause: `renderWi` reads `leaf.goal` (heading-derived text, empty for monolithic proposals) for the `## Goal` section while the parser writes the real goal into `blocks.goals` (since `BLOCK_NAMES["goal"] → "goals"`). Result: monolithic proposals always render `## Goal` as TBD and repeat the content under `## Goals`.

2. **`## Acceptance Criteria` is dropped entirely** when the proposal nests `### US-XX` subheadings under it. Root cause: `extractBlocks` flushes the current block on *any* heading, regardless of level. When `## Acceptance Criteria` is followed by `### US-01`, the AC block is flushed empty before any content appears, then the `### US-01` heading is not a recognized block name so subsequent lines fall through. Reproduced on 3 of 7 April 24 framework proposals (`reviewer-safety`, `skip-conditions-registry`, `wire-hooks-hygiene`).

## Goals

- Single authoritative `## Goal` section in emitted WI — prefer `blocks.goals` content when available, fall back to heading-derived `leaf.goal`, then TBD.
- `## Acceptance Criteria` preserves all content under a block regardless of nested subheadings (e.g., `### US-XX`), until the next heading that matches a different known block name.
- New fixtures + regression test in `capture-idea/references/tests/` covering both failure modes.

## Non-Goals

- Do not rewrite the extractBlocks state machine beyond what's needed for these two bugs.
- Do not change the WI render schema (Frontmatter / section list).
- Do not backfill already-emitted WIs — they were manually corrected.

## Acceptance Criteria

- **AC-01** Parsing `proposals/done/2026-04-24-framework-improvement-wire-hooks-hygiene.md` produces a non-empty `acs` block containing all four US-XX subsections.
- **AC-02** Running emit-wis.mjs in `--dry-run` against any monolithic proposal with a `## Goal` section produces a WI whose `## Goal` section contains the proposal's actual goal text (not `TBD`).
- **AC-03** New fixture `fixture-nested-us-headings.md` round-trips through the parser and emits a WI whose `## Goal` and `## Acceptance Criteria` are both fully populated.
- **AC-04** Full tier-1 sweep PASS.
- **AC-05** Existing fixtures (`fixture-proposal-phased.md`, `fixture-monolithic.md`, `fixture-leaf-ac-inherited.md`) continue to parse with the same leaf count.
- **AC-06** Learning `parser-drops-nested-heading-content` logged at confidence 9 in `references/framework-learnings.jsonl`.
