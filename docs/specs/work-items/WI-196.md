# WI-196: Atomic state write validator is advisory-only

## Problem

The framework reliability review found HIGH issue F-026: Atomic state write validator is advisory-only.

## Evidence

`validate-atomic-state-writes.sh` is described as "Always exits 0; offenders are advisory" in the validator source.

## Impact

Even after a state-IO standard exists, direct writes can continue.

## Proposed Fix

Flip to blocking for `.svc/*.json`, `.svc/*.jsonl`, work-item indexes, and lane-tasks after migration.

### Resolution

`validate-atomic-state-writes.sh` now fails closed for the direct literal
`.svc/*.json` / `.svc/*.jsonl` write pattern it is responsible for detecting.
The broader dynamic-path, lock-file, append discipline, and migration work
remains tracked by [WI-195](WI-195.md).

### Changes

- Changed `validate-atomic-state-writes.sh` from advisory exit-0 behavior to
  hard-fail behavior when offenders are found.
- Expanded detection from `writeFileSync` only to `writeFileSync`,
  `writeFile`, `appendFileSync`, and `appendFile` for literal `.svc`
  JSON/JSONL paths.
- Added an internal self-test fixture that proves a bad direct write is detected.
- Added an internal allowed fixture proving state-io mediated writes do not trip
  the validator.

### Evidence

- `bash test-framework/evals/tier-1/validate-atomic-state-writes.sh` PASS.
- `bash -n test-framework/evals/tier-1/validate-atomic-state-writes.sh` PASS.
