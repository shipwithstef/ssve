## Problem

The active-intent bridge treats every standalone `stop` token as an affirmative
request to stop. A terminal mandate such as “Do not yield or stop for manual
confirmation until all deliverables, code changes, and proofs are verified” is
therefore persisted as a wildcard suppression and prevents unrelated active work
items from exerting completion pressure.

## Evidence

- Live consumer state: `/home/user/app-workspaces/example-marketplace-port/.svc/active-intent-state.json`
  recorded `classification: stop`, `wi: *`, at `2026-09-05T12:18:54.548Z` for the
  exact negated mandate.
- Pre-fix behavioral replay of `classifyActiveIntent()` returns
  `{classification:"stop", suppress:true, wi:"*"}` for both the exact composite
  sentence and `never stop until all deliverables are verified`.
- WI-354 requires literal correction phrase `stop` to suppress but contains no
  acceptance criterion or fixture for negated use of that token.

## Reproduction and Classification

**Trigger:** submit the exact prompt “Do not yield or stop for manual confirmation
until all deliverables, code changes, and proofs are verified”.

**Expected behavior:** negated `stop` is not a stop request and does not create a
wildcard suppression entry; a literal affirmative `stop` still suppresses.

**Actual behavior:** the unconditional `/\bstop\b/` candidate wins and writes a
wildcard `stop` suppression.

**Bug domain:** Code. The failure is deterministic for any payload containing a
negated standalone stop token and reproduces in the pure classifier without host
or fixture dependencies.

**Causal class:** Action — prompt classification writes the wrong intent action.

## Root Cause

The immediate cause is the unconditional stop-token regular expression in
`hooks/lib/active-intent.mjs`. The enabling condition is precedence: explicit WI
continuation is guarded, but stop suppression has no equivalent negation check.
The system allowed this because WI-354's behavioral corpus proves affirmative
stop, ignore, unrelated, continuation, and scope isolation only; it omitted
negative examples where `stop` appears inside a command to continue.

## Smallest Safe Fix

Limit the code delta to `classifyActiveIntent()` in the shared active-intent
library: reject the affirmative stop candidate when its occurrence is governed by
a nearby explicit negation. Extend the existing behavioral validator with direct
classifier fixtures and keep all WI-354 end-to-end guard fixtures unchanged.

## Learnings

Keyword intent classifiers need positive and negated golden cases. A literal
action token is not sufficient evidence when a local negation changes its
polarity; behavioral tests must cover the exact composite operator language that
triggered the regression.
