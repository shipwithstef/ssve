## Goal
Add an `ingest-guide` skill that takes manually-pasted long-form social content (X threads, LinkedIn posts, blog mirrors, etc.) and runs it through extraction → validation → routing decision.

## Context
The builder reads many high-signal guides on X and other social platforms and wants a frictionless path from "I just pasted this" to either (a) discarded, (b) stored as reference knowledge, or (c) promoted into a new svc skill — without manually deciding the placement each time.

## Hypothesized Value
Closes the loop between external knowledge ingestion and the svc skill catalog. Ensures valuable patterns get adopted as skills (rather than lost in a chat scroll), and that less-valuable but still useful patterns get filed as searchable knowledge.

## Broad Scope
- Input: pasted unstructured text (no fetcher in v1 — manual paste only).
- Pipeline:
  1. Invoke refactored `research` skill (WI-090) to extract structured knowledge — what the guide actually says + what it claims (techniques, results, conditions).
  2. **Claim-vs-knowledge comparison:** for each claim/technique extracted, check it against existing internal knowledge (`references/knowledge/`, project specs, prior learnings) and mark each one as:
     - **already-known** — we have this; note where.
     - **new** — we don't have this; needs validation.
     - **contradicts-known** — clashes with existing knowledge; flag for human review.
  3. **Experiment design (only for `new` and `contradicts-known` items):** propose a concrete, runnable experiment to validate the claim — what to do, what success looks like, smallest possible scope. Knowledge is only adopted after we execute and see the value, not on the strength of the claim alone.
  4. **Benefit framing:** for each validated technique, articulate (a) how it could benefit the user's current product project, and (b) how it could benefit the svc framework itself. Both angles, separately.
  5. Apply the validation rubric (signal, novelty, actionability, source credibility) on top of steps 2–4.
  6. Routing decision (one of three branches):
     - **Discard** — log decision, no artifact.
     - **Store as reference knowledge** — write to `references/knowledge/<domain>/` (using WI-090's domain gate). Include claim status + experiment outcome + benefit framing.
     - **Promote to new skill** — hand off to `create-skill` with a draft brief that includes the validated experiment as proof; ask the builder where to wire it (on-demand vs embedded in an existing lane).
- Decision and outcome logged to `.svc/pipeline-decisions.jsonl`.

**Doctrine note:** knowledge is earned by execution, not by extraction. The comparison + experiment + benefit-framing steps are how this skill stays honest — pasting a guide does not yet make it knowledge.
