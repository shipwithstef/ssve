# WI-501: enforcement escape hatch + read-only command classification

**Type:** bugfix (Codex host usability; enforcement structural defects)
**Status:** identified
**Severity:** high — jointly these made the Codex host effectively unusable and are the
root cause of the WI-494/496/497/498/499 whack-a-mole (five WIs, each patching one
symptom of the same two structural defects).
**Filed:** 2026-07-19
**Lane:** framework
**Source:** owner — "this hooks and shit keep breaking codex, it works very bad… any generic
way to solve it so I can use codex to fix itself". Root-caused live, then proven by running a
real Codex session against it.

## Problem

**EG-01 — enforcement had no escape hatch.** Both governed hooks (`svc-codex-skill-load-enforcer`
PreToolUse, `svc-task-completion-guard` Stop) route through `bin/svc-enforce.mjs`, which honored
**no** disable switch of any kind. So whenever enforcement itself misbehaved, the agent was
blocked from mutating the very files needed to fix it — a self-sealing deadlock. Every
enforcement bug therefore escalated into a full framework WI. That is precisely why the same
failure class recurred five times.

**EG-02 — read-only commands were classified as governed mutations.** `isReadOnlyTool()` in
`hooks/codex/lib/codex-hook-context.mjs` rejected any command matching `/[;&|`$<>\n'"\\]/`
before consulting the safe-list. So `pwd && rg -n "x" README.md` — a pure read — was classified
a governed mutation and denied. Agents chain and quote constantly, so this denied *reading files*
whenever no task graph was active. This is the concrete "works very bad" symptom, and it also
seals the bootstrap deadlock: you must read files to create the task that would permit reading.

## Fix

**EG-01 (`bin/svc-enforce.mjs`):** dependency-free break-glass, evaluated FIRST — before the
bootstrap/source/core validation — so it still works in the exact states that otherwise fail
closed (deleted checkout, missing core, dangling source).
- Armed by `SVC_BREAK_GLASS=1` (process/session-scoped) or a `~/.svc/BREAK-GLASS` file.
- The file form **auto-expires** (default 4h, `SVC_BREAK_GLASS_TTL_HOURS`) and then fails **safe**
  back to fully governed — it cannot silently become permanent.
- Every bypass appends to `~/.svc/break-glass-audit.jsonl` and prints a loud stderr banner.

**EG-02 (`hooks/codex/lib/codex-hook-context.mjs`):** classify **every segment** of a compound
command instead of rejecting the whole command on sight of an operator or quote.
- Hard-reject remains for constructs that can hide execution regardless of the visible command
  name: backticks, `$(`, `${`, redirects, newline, backslash.
- The split is **quote-aware** (`splitUnquoted`): an operator inside quotes is argument text, not
  a shell operator, so `rg -n "alpha|beta" f.md` is one segment. Unterminated quote ⇒ refuse.
- Every segment must independently be a known read-only command; `true`/`false`/`:` are trivial
  no-op segments so `… || true` classifies.

## Acceptance criteria
- [ ] EG-01a: a command denied while governed is ALLOWED under `SVC_BREAK_GLASS=1`, with banner + audit row.
- [ ] EG-01b: the `~/.svc/BREAK-GLASS` file form expires past TTL and fails safe back to DENY.
- [ ] EG-02a: read-only compound/quoted/piped commands are ALLOWED (`pwd && rg -n "a|b" f`, `ls | head`, `… || true`).
- [ ] EG-02b: mutations and unsafe constructs still DENY (`rm`, chained `rm`, redirect, `$(...)`, `touch`, unterminated quote).
- [ ] EG-03: tier-1 green; `node --check` clean on both files.

## Known-remaining (NOT fixed here)
Instance #6 of the bootstrap deadlock is still live and was **reproduced during this WI's own
verification**: `scripts/svc-ensure-worktree.mjs --wi <WI> --branch <b>` — the enforcer's own
documented recovery command — is denied in **every** form tested (named WI, numeric WI, with
`--from`). The Codex session under test named it exactly: *"The guard is rejecting its own
documented recovery command."* WI-496 was supposed to close this class. Break-glass steps over
it; it does not fix it. → follow-up WI required.
