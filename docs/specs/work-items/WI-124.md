# WI-124 — SessionStart self-heal for stale host-install symlinks and hook script paths

**Status:** VERIFIED
**Lane:** framework
**Created:** 2026-04-25
**Closed:** 2026-04-25
**Branch:** wi-124-session-start-self-heal
**Source:** Recurring `Cannot find module svc-stop-quality.js` class of error after background-agent worktree churn repointed `~/.claude/skills/hooks` (or absolute paths inside `~/.claude/settings.json`) at a worktree, then dangled when the worktree was removed.

## Problem

WI-116 added `svc-session-start-healthcheck` as a soft warn for dangling
symlinks under `~/.claude/skills/`. It only printed; it did not repair.
In addition, host-install drift can manifest in a second place not covered
by the symlink scan: absolute hook command paths inside
`~/.claude/settings.json` can point at scripts that no longer exist (e.g.
`node /home/.../skills/hooks/svc-stop-quality.js` after a `.js → .mjs`
rename). The result is a persistent broken-hook error on every session.

## Scope

### In scope
- Upgrade `hooks/svc-session-start-healthcheck.mjs` to:
  1. Scan dangling symlinks under `~/.claude/skills/` (existing behaviour)
  2. Parse `~/.claude/settings.json` and check every absolute `node …/foo.{js,mjs}` and `bash …/foo.sh` path resolves
  3. If any issue is found, detect the repo root (via `~/.claude/skills/.source-repo` pointer or by walking the `scripts` symlink target) and re-run `bash <repo>/setup --host claude`
  4. Re-scan; report remaining issues clearly. Never exit non-zero.
- Add `SVC_SELF_HEAL_DISABLE=1` env var bypass.
- New tier-1 validator `validate-session-start-self-heal.sh` covering: healthy state silent, dangling symlink detection, env-var bypass.
- Harden `setup`'s worktree guard: bypass via `SVC_SETUP_ALLOW_WORKTREE=1` now also requires non-empty `SVC_SETUP_ALLOW_WORKTREE_REASON`. Caller must name the reason in plain text.
- Update `validate-host-manifests.sh` (the only caller of the bypass) to provide the reason.
- Extend `scripts/check-install-drift.sh` to detect missing absolute paths in `settings.json` hook commands (same class of error the SessionStart hook detects).

### Out of scope
- Self-heal for Kimi/Codex/Gemini SessionStart equivalents (left for follow-up; same pattern applies).
- Auto-running `setup` from any other lifecycle event (e.g., PreToolUse) — too aggressive.

## Acceptance criteria

1. `hooks/svc-session-start-healthcheck.mjs` exits 0 silently when state is healthy.
2. With a dangling symlink under `$HOME/.claude/skills`, the hook prints a `self-heal: detected N issues` line on stderr.
3. With `SVC_SELF_HEAL_DISABLE=1`, the hook skips repair entirely.
4. `setup` refuses to run from a worktree unless **both** `SVC_SETUP_ALLOW_WORKTREE=1` **and** `SVC_SETUP_ALLOW_WORKTREE_REASON='<text>'` are set.
5. New tier-1 validator passes (T1/T2/T3).
6. `scripts/check-install-drift.sh` flags missing `settings.json` hook command paths.
7. Tier-1 sweep: 46 scripts pass (45 baseline + 1 new validator), 0 fail.
8. `lint-skills-manifest` clean.

## Self-heal trigger

Detection runs at every SessionStart. Repair fires only when at least one
of these conditions is true:
- A dangling symlink exists somewhere under `$HOME/.claude/skills/`
- A `node /abs/path.{js,mjs}` or `bash /abs/path.sh` token in `$HOME/.claude/settings.json` points at a non-existent file

Repair = run `bash <repo>/setup --host claude` with stdout suppressed.
Repo root is detected from `~/.claude/skills/.source-repo` or by walking
the `scripts` symlink target.

## Risk

LOW. The hook is observe-only on the healthy path (silent exit). Repair
runs setup, which is itself idempotent and refuses to write from a
worktree (now with a stricter reason gate). Hook never exits non-zero, so
SessionStart cannot be blocked.

## Rollback

Revert this commit. Symlink scanning falls back to WI-116 warn-only behaviour;
no auto-repair. `setup`'s worktree guard reverts to allowing
`SVC_SETUP_ALLOW_WORKTREE=1` without a reason. New tier-1 validator
disappears.
