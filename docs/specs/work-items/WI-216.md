# WI-216: Mechanically enforce destructive git preamble

## Goal

Block destructive git operations unless the required `DESTRUCTIVE:` preamble was emitted immediately before the command.

## Context

The audit found that force-pushes during PR-stack rebases had pre-checks but lacked the structured preamble required by `rules/destructive-git-ops.md`. This is an agent-discipline failure that should be turned into mechanical enforcement.

## Acceptance Criteria

- AC1: A Bash PreToolUse hook detects `git push --force*`, `git reset --hard*`, `git clean -f*`, and `git branch -D*`.
- AC2: The hook refuses the command unless the most recent assistant message contains `DESTRUCTIVE: running` within the configured time window.
- AC3: The hook emits a clear recovery message showing the expected preamble format.
- AC4: Tier-1 fixtures cover blocked destructive ops, allowed ops with fresh preamble, and non-destructive git commands.
- AC5: Host wiring includes every provisioned hook-capable host that supports Bash guard matching.

## File Impact

- `hooks/`
- `provision/hosts/*.json`
- `test-framework/evals/tier-1/`
- `rules/destructive-git-ops.md`

## Completion

Implemented in `hooks/svc-workflow-guard.mjs` under the existing `--bash-guard` path. The guard now blocks `git push --force*`, `git reset --hard*`, `git clean -f*`, and `git branch -D*` unless a fresh assistant preamble is visible through `last_assistant_message` or a recent `transcript_path` assistant entry.
