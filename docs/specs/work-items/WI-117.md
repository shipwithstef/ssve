## Problem

`.svc/pipeline-decisions.jsonl` is the source of truth used by
`svc-skill-artifact-authenticity` (WI-114), G-2 verification, audit-session-execution.
Today: any process can append any JSON shape. A malformed entry breaks every
downstream reader; a maliciously-shaped entry could spoof a skill invocation to
bypass G-4 authenticity.

## Scope

### In scope
- New JSON Schema at `references/pipeline-decisions-schema.json`
- New tier-1 validator `validate-pipeline-decisions-schema.sh` enforcing schema line-by-line
- New canonical CLI writer `scripts/log-decision.mjs` validating same rules

### Out of scope
- PreToolUse hook to block raw appends bypassing the writer (future WI)
- Migrating all existing writers to the canonical CLI (future WI)

## Acceptance criteria

1. Schema declares required (ts, skill, decision) and optional (wi, kind, run_id) fields. ✅
2. Validator parses every JSONL line and rejects missing/invalid fields. ✅
3. CLI writer enforces same rules and exits non-zero on bad input. ✅
4. Existing log file passes validator. ✅
5. Tier-1 sweep passes. ✅
6. lint-skills-manifest clean. ✅
