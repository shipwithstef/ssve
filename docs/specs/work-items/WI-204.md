# WI-204: Chrome controls are not covered as journey sources

## Status: Closed — duplicate of WI-168 + WI-170

This item was filed from review finding F-034 ("chrome controls are not covered as journey sources"). On audit, the same gap is already covered end-to-end by two existing items:

- **[WI-168](WI-168.md)** — `write-journeys --auto-discover-chrome` parses `Layout.jsx` / `MobileHeader.jsx` / `Sidebar.jsx`, extracts interactive control roots, and emits skeleton chrome journeys. This is the **discovery + generation** half of F-034's fix.
- **[WI-170](WI-170.md)** — tier-1 validator `validate-chrome-journey-coverage` runs at session-start in convert-mode repos, WARNs on uncovered chrome, and escalates to HIGH after 30 days. This is the **forcing function** half of F-034's fix.

Together, WI-168 and WI-170 fully cover the chrome-as-journey-source gap. F-034 should be considered resolved when both land.

## Original Problem (preserved for reference)

The framework reliability review found CRITICAL issue F-034: Chrome controls are not covered as journey sources. Global controls reachable from every page can break independently of any feature spec.
