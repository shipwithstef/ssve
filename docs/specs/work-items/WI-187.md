# WI-187: Cursor and Antigravity are provisioned without hook enforcement

## Problem

The framework reliability review found HIGH issue F-017: Cursor and Antigravity are provisioned without hook enforcement.

## Evidence

`provision/hosts/cursor.json` and `provision/hosts/antigravity.json` set `"hooks": false` while setup advertises both hosts.

## Impact

Skills install, but critical framework guards do not mechanically run in those hosts.

## Proposed Fix

Mark these hosts as skills-only/limited in route output and block claims of cross-host enforcement until verified wirers exist.

## Acceptance Criteria

- AC1: The specific F-017 failure mode from the source review is fixed or explicitly invalidated with evidence.
- AC2: A targeted validator, replay fixture, or documented verification command proves the fix.
- AC3: Relevant framework state, docs, hooks, or skill contracts are updated in sync.
- AC4: `bash test-framework/evals/run-all-evals.sh` no longer fails because of this finding, or the remaining failure is tracked by a separate WI.

## Closeout

Closed 2026-05-10. Cursor and Antigravity remain supported install targets, but the framework now classifies them as skills-only hosts until verified hook wirers exist.

Changes:
- Added `hook_enforcement_hosts` and `skills_only_hosts` to `references/canonical-gates.json`.
- Extended `test-framework/evals/tier-1/validate-cross-host-hook-conformance.sh` so any host with `capabilities.hooks=false` must be listed as skills-only and must not appear in any canonical hook gate's `must_hosts` or `may_hosts`.
- Updated `references/host-capabilities.md`, `route-workflow/SKILL.md`, and `README.md` to distinguish skills installation from hook enforcement for Antigravity and Cursor.
- Confirmed Codex setup uses `[features] hooks = true`, not deprecated `[features] codex_hooks`.
