## Problem

Native-wrapper UI bugs can falsely look fixed when the web app works, the bundle builds, or static code evidence shows the intended patch shipped. In Example Marketplace, the Capacitor Android language toggle still froze or failed to change after earlier Radix/i18n work because the failing behavior lived in the native WebView overlay/state timing path, not in the ordinary browser path.

The framework already has broad cross-system proof and verification-tier rules, but it does not specifically force native runtime UI proof and structural escalation for repeated Capacitor/WebView overlay failures. That allowed repeated one-off fixes against the visible symptom instead of earlier escalation to the shared mobile select/drawer architecture.

## Evidence

- Example Marketplace Capacitor Android language toggle: web behavior worked, but Android runtime tap behavior failed.
- Earlier Radix-focused work addressed one symptom class (`BubbleInput` / value reset) but did not remove the deeper mobile overlay structure that kept Radix Select semantics coupled to a mobile drawer path.
- The fix that finally held was structural: make the mobile Select path context-owned, remove Radix from the mobile path, disable drawer body/background side effects for that control, and defer the language value commit until after drawer close.
- The decisive acceptance signal was real Android Capacitor tap behavior: select language, observe the label/state change, drawer/sidebar closes, app remains clickable, and persisted language changes.

## Acceptance Criteria

- [ ] `route-workflow` detects native runtime UI signals such as `Capacitor`, `Android WebView`, `iOS WebView`, native shell, mobile drawer/select/modal, pointer-events freeze, click-death, or "works on web but not Android/iOS" and labels the route as requiring native-runtime UI proof.
- [ ] `diagnose-bug` requires a native runtime hypothesis ledger for these bugs: browser path, WebView/native path, overlay teardown, body/pointer side effects, hidden input/form semantics, state commit timing, and persistence.
- [ ] A repeated same-class failure in the same component family escalates from one-off diagnosis to structural component review before another narrow patch is accepted.
- [ ] Closeout rules forbid unqualified `VERIFIED` when the only evidence is web Playwright, bundle grep, build success, or shipped-code parity for a native-runtime UI bug.
- [ ] Valid closeout evidence must include device/emulator/runtime tap proof, or an explicit blocked-native-validation state with the remaining risk named.
- [ ] Add a regression fixture based on the Example Marketplace language toggle pattern: web passes, Android user report fails, earlier Radix patch is insufficient, structural mobile Select/drawer refactor plus Android tap proof is required.
- [ ] Update verification-tier reporting so native-runtime UI bugs can be marked `V0` for static/build/web evidence and only graduate after native runtime proof.

## Route Recommendation

Run through `improve-framework`. Lane = framework. Plan-changeset class = `contract-change`. Severity = HIGH because this prevents repeated false-positive closeouts for mobile apps where the actual failure only appears in Capacitor/WebView runtime behavior.
