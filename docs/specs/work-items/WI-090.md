## Goal
Refactor the `research` skill so a single invocation reliably extracts the full content of a source in one pass and writes it into the correct knowledge domain.

## Context
Observed pain points using the current `research` skill (gemini-cli sub-agent) in real sessions:
1. Gemini does NOT extract all info in one pass — the user has to re-prompt repeatedly, bit-by-bit, to get full coverage of a source.
2. No pre-scoping step — the agent dives in without first measuring how much content exists or planning the extraction pass.
3. Sometimes stores extracted knowledge in the WRONG knowledge domain folder under `references/knowledge/`.

## Hypothesized Value
One-shot research that doesn't require babysitting. Higher signal-to-noise in `references/knowledge/`, fewer mis-filed entries to clean up later, and a foundation that downstream skills (WI-091 ingest-guide, WI-092 parallel orchestrator) can rely on without compounding error.

## Broad Scope
- **Sub-agent fallback chain:** `gemini-cli` is the default first-choice agent. If gemini-cli is out of credits, errors, or stalls / fails to finish a pass mid-way, the skill must hand off to Claude as fallback so the run completes in the same invocation rather than leaving a partial extraction behind. Configurable via env / profile.
- **Pre-scope phase:** agent first analyzes the input to estimate volume, sections, and required extraction depth before extraction begins. Output of this phase is a plan the orchestrator can inspect.
- **Single-pass extraction:** one comprehensive pass that covers everything identified in pre-scope. No iterative bit-by-bit prompting from the caller.
- **Domain classification gate:** before writing to `references/knowledge/<domain>/`, agent must justify the chosen domain against the existing knowledge taxonomy and either (a) confirm an existing domain or (b) propose a new domain explicitly rather than silently mis-filing.
- Fine-tuned system prompt aligned with `references/knowledge-protocol.md` output schema.
