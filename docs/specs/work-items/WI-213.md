# WI-213: Phase-receipts Phase D — gate flip + Stop hook enforcement

## Goal

After Phase C (WI-212) completes — every skill in the corpus declares phases or is explicitly exempted — flip the framework to enforce phase receipts globally. Two coordinated changes:

1. **Tier-1 validator `validate-skill-receipt-shape.sh` flips advisory → blocking.** A `required_for_completion: true` phase that is absent from a completed task's `skill_receipt.phases_executed[]` becomes a tier-1 FAIL.
2. **Stop hook `svc-task-completion-guard.sh` reads receipts.** Before allowing a `completed` transition, the hook parses the active skill's `phases:` block and the task's receipt. Block on missing required-phase entries with an actionable diff.

This is THE gate flip — once it lands, "the skill said X" becomes mechanically verifiable, not just self-reported.

## Why a separate WI

- Phase A (WI-191) is schema. Phase B/C migrate skills. Phase D is enforcement.
- Splitting the enforcement flip from the migrations means: (a) we can revert Phase D without losing the schema or the migrations; (b) reviewers can focus the enforcement design on its own PR.

## Scope

1. Modify `test-framework/evals/tier-1/validate-skill-receipt-shape.sh` — change the trailing `exit 0` to `exit $((FAIL > 0 ? 1 : 0))` and adjust the output messaging from "Phase A advisory" to "Phase D enforcing." Keep the bad-fixture self-test, but flip its expected outcome to FAIL (not ADVISORY).
2. Extend `hooks/svc-task-completion-guard.sh` — add a check that, for each task transitioning to `completed`:
   - reads the skill's `phases:` block (look up by `metadata.skill` → load `<skill>/SKILL.md` frontmatter)
   - lists `required_for_completion: true` phases
   - checks each is present in `skill_receipt.phases_executed[]`
   - blocks with structured diff if any is missing
3. Wire the hook check via the existing F-011 stdin path (already fixed in commit 62f320d).
4. Add tier-1 validator `validate-stop-hook-phase-enforcement.sh` — exercise the Stop hook against good (all phases present) + bad (missing required phase) fixtures; exit 0 only if hook blocks the bad fixture.
5. Update `references/anti-patterns.md` to add AP-3X "Skill closes task without matching phase receipt."

## Acceptance criteria

- AC1: Tier-1 validator `validate-skill-receipt-shape.sh` FAILs when any migrated skill's task closes without matching `phases_executed[]` for its `required_for_completion` phases.
- AC2: Stop hook blocks `completed` transitions on missing required-phase entries; emits actionable diff naming the missing phase id.
- AC3: Tier-1 validator `validate-stop-hook-phase-enforcement.sh` exists, exercises both fixture paths, and passes when the hook correctly blocks the bad fixture.
- AC4: A historical lane-tasks file from before Phase A (where receipts had only `{skill, loaded_at, loaded_via}`) is still valid — the validator checks against declared phases at the time of the run, not retroactively.
- AC5: AP-3X documented in `references/anti-patterns.md` with cross-link to WI-213.
- AC6: `bash test-framework/evals/run-all-evals.sh` passes (no new tier-1 failures).
- AC7: PR description includes a rollback plan: revert Phase D = `git revert <PR-merge-commit>` returns the validator to advisory mode and restores the Stop hook to its pre-Phase-D state. Schema and migrations are preserved.

## Dependencies

- **WI-191 (Phase A)** — schema must exist
- **WI-211 (Phase B)** — canonical 5 must declare phases

## Risk

The gate flip is a one-way door if not designed carefully. Mitigation: AC7 mandates the rollback plan; the entire Phase D change must be a single squash-merge so revert is one commit.

## Cost estimate
