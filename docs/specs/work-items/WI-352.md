# WI-352: WI-scoped parallel session isolation for hooks, accumulators, and worktrees

## Problem

WI-351 attempted to fix parallel session crosstalk in stop hooks using session_id-based isolation. Deep review and 12-scenario simulation revealed the approach is fundamentally wrong:

1. **Wrong isolation unit:** `session_id` breaks with subagents (different IDs for same WI), context compaction (new session ID, same WI), and cross-model review (reviewer blocked by executor's tasks). The correct isolation boundary is the **Work Item (WI)**, not the session.

2. **Dead code:** `session_id` is never written to `session-contract.jsonl` (0/186 entries). The session-matching loop in the completion guard always falls through to `tail -1` — the exact race condition WI-351 was supposed to fix.

3. **Worktree blind spot:** `worktree.sh` never creates `.svc/` in worktrees. Hooks walk up the directory tree to main's `.svc/`, causing worktree sessions to read main's task graphs, write to main's accumulator, and check main's session contract. Zero isolation for worktree-based feature work.

4. **Subagent edits unchecked:** Subagent stop hooks exit early (isSubagent check). With session-scoped accumulators, the parent's quality check doesn't include subagent edits. Files go completely unchecked.

5. **No role awareness:** The completion guard has no concept of session role (executor vs. reviewer vs. research). Cross-model reviewers get blocked by the executor's pending tasks.

6. **Orphaned state:** 333 counter files leaked in `/tmp/svc-completion-guard/`. No TTL, no cleanup, no stale detection for crashed sessions with stuck `in_progress` tasks.

## Fix Architecture

### Core Principle: WI is the isolation boundary, not session

1. **Shared WI resolution chain** (`hooks/lib/resolve-wi.mjs`): `SVC_WORKER_WI` env → hook payload `.wi` → WI claim file → git branch name → single in_progress graph → session-contract fallback

2. **WI-scoped accumulator**: `.svc/svc-edited-files-<WI>.json` instead of `...-<session_id>.json`. Subagents on same WI share it (correct); different WIs are isolated (correct); context compaction doesn't lose files (correct).

3. **WI claims** (`.svc/claims/<WI>.claim.json`): prevents two sessions executing the same WI; auto-expires on crash via TTL + PID check.

4. **Worktree `.svc/` init**: `worktree.sh create` initializes `.svc/` with lane-tasks and session-contract in the worktree directory so hooks find local state.

5. **Role-aware guard**: Non-execution roles (reviewer, research, audit) skip the completion guard.

6. **Stale state self-healing**: Clean orphaned claims, accumulators, `/tmp/` counters, and stuck `in_progress` tasks at session start.
