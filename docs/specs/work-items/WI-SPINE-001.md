## Goal

Build the Knowledge Spine foundation: the on-disk retrieval architecture that makes svc skills retrieve knowledge predictively instead of rediscovering it every session. App lanes immediately benefit (spec-reading token cost drops ≥60%); infra lanes (later WIs) require it as their phase-0 gate.

## Hypothesized Value

Concrete: ≥60% reduction in token cost for spec-reading operations across all lanes (measurable via tier-2 eval). Closes the rediscovery defect class that user complaint 2026-04-30 surfaced.

## Broad Scope

Five concrete deliverables in this WI:

1. **`recall-stack-knowledge` skill** — new skill directory `recall-stack-knowledge/` with SKILL.md following the standard frontmatter contract. Inputs: caller_skill, requested_topics[], recall_depth. Outputs: knowledge slices injected into context + entry appended to `.svc/knowledge-recall.jsonl`. Self-verify: 0-hit recall on declared-surface topic FAILs and triggers research auto-spawn.

2. **`.svc/spec-index.json` + builder script** — `scripts/build-spec-index.mjs` that scans `docs/specs/**/*.md` and emits `.svc/spec-index.json` mapping each section heading to `{tags, topics, last_modified, byte_range}`. Initial build is full-scan; incremental updates via PostToolUse hook.

3. **PostToolUse hook for spec-index** — wire a hook on `Edit|Write` against `docs/specs/**/*.md` that calls `scripts/build-spec-index.mjs --incremental <changed-file>`. Per `rules/host-capability-research.md`, verify Claude Code / Kimi CLI / Codex CLI / Gemini CLI hook docs before wiring; degrade gracefully on hosts without PostToolUse (advisory full-rebuild on demand).

4. **Frontmatter contract extension** — add four optional fields to skill SKILL.md frontmatter schema: `requires_topics[]`, `produces_topics[]`, `recall_depth: layer-1|layer-2|layer-3|escalate`, `idempotent: true|false|once-only`. Default behavior preserved when fields absent. Update `scripts/lint-skills-manifest.mjs` to validate the new fields when present (presence not required).

5. **Tier-1 validator `validate-no-rediscovery.sh`** — scans `.svc/knowledge-recall.jsonl` for any `(skill, topic)` pair recalled >3 times in 24h; emits warning (not error in Phase A — becomes blocking in Phase E per WI-SPINE-005).

## Persona Fit

Framework contributor / svc user / agent operator. Beneficiaries: every existing app-lane WI immediately gets cheaper spec-reading; every future infra WI gets the gate it needs at phase-0.

- AC2: `.svc/spec-index.json` is generated by `scripts/build-spec-index.mjs` against this repo's existing `docs/specs/**/*.md`; index is valid JSON with the documented schema; section count matches manual count within ±5%.
- AC3: PostToolUse hook wired in at least one host (Claude Code first); hook re-runs incremental build on every spec edit; hook emits no errors on hosts without PostToolUse support (graceful no-op).

- AC6: Tier-2 token-cost eval shows ≥60% reduction for the canonical "read section X of feature spec Y" workload before vs after spec-index. (Stub measurement acceptable in Phase A; tightened in Phase B.)
- AC7: All existing tier-1 + tier-2 evals stay green (zero regression on existing 7 lanes).
