## Problem
execute-changeset's parallel architecture (parallel groups, inner worktrees, Sonnet subagents via dispatch-worker.sh) is dead: `.svc/dispatch-log.jsonl` = 5 entries, all opus-override inline. The transport is why — `claude -p` is auth-dead (WI-357) and bills against the Agent SDK credit after 2026-06-15 (WI-374). Native `agent(prompt, {isolation:'worktree', schema})` runs in-session on subscription and IS the inner-worktree design already specified at `execute-changeset/SKILL.md`.

## Mechanism
A workflow template over the manifest task graph: independent nodes as parallel worktree-isolated agents with schema-forced result objects, sequential merge-back, then the unchanged holistic-review step.

## Mechanism (as built — single-WI core)
1. **`scripts/lib/disjoint-scopes.mjs`** — the closed-loop fail-safe disjoint-file primitive (extracted from WI-387; one audited place). `scopesIntersect`/`disjointScopes`.
2. **`scripts/partition-task-graph.mjs`** — `partitionTaskGraph(tasks)` (pure): dependency-ordered waves; a wave is parallel ONLY if its task file-sets are disjoint, else **escalate-to-sequential**; cycle/unknown-dep → fail-closed. + CLI.
3. **`schemas/task-node-result.schema.json`** — the schema-forced parallel-task result (replaces grep-for-SVC_WORKER_SUMMARY).
4. **`references/task-graph-parallel-exec.md`** + execute-changeset wiring (native `agent({isolation:'worktree', schema})`; pipeline stage order; non-Claude fallback).
5. **validator** — `test-framework/evals/tier-1/validate-task-graph-partition.sh`.

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-task-graph-partition.sh`
- **failure_class:** the partition fence failing OPEN — parallelizing a wave whose task file-sets actually overlap (two agents clobber the same file concurrently), or not escalating-to-sequential on overlap, or passing a cyclic/unknown-dep graph.
- **promotion_signal:** condition 3 — the single disjoint-file validator is the entire safety case for parallel MUTATING task execution; a fail-open corrupts the changeset.
- **expected_runtime_budget:** <1s (pure partition unit + 2 CLI runs; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** "the single validator is the difference between fenced and vibes" — a silent fail-open lets two worktree agents race the same file, so it must be re-proven every lint.
