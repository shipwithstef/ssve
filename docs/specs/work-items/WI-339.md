## Problem

WI-199 blocks V0 bundle-grep substitution for browser-visible closeouts, and
WI-200 adds deterministic sampling plus per-item verification tier reporting for
multi-PR campaigns. The source proposal also asked for every bundle-grep output
to self-label as V0-only and for final/cumulative closeout summaries to refuse
unqualified `VERIFIED` wording whenever any row remains V0-only.

Those reporting constraints are adjacent to the hard block, but not fully
captured as a standalone validator contract.

## Acceptance Criteria

- [x] Require bundle-grep/static proof helpers or closeout reports to label
      themselves as `Verification tier: V0`.
- [x] Add a cumulative-summary validator or self-verify check that blocks
      unqualified `VERIFIED` / `complete` wording when any browser-visible item
      is V0-only.
- [x] Preserve WI-200's sampled-row table requirements and extend them to
      single-lane cumulative summaries where no PR list exists.
- [x] Add a fixture based on the i18n campaign closing-turn failure that fails
      before this reporting rule and passes after it.

## Route Recommendation

Run after WI-199/WI-200; this is closeout-reporting hardening, not the main
runtime-evidence enforcement path.

## Closeout

Implemented on 2026-05-12.

- `scripts/validate-verification-closeout-summary.mjs` requires static proof to
  self-label as `Verification tier: V0`.
- The validator blocks unqualified `VERIFIED` / `complete` wording while a
  browser-visible row remains V0-only.
- `verify-promotion/SKILL.md` now requires the validator before closeout and
  extends sampled-row fields to `single_lane_summary` when no PR list exists.
- `test-framework/evals/tier-1/validate-verification-closeout-summary.sh`
  includes the i18n-style bad closeout fixture and a passing qualified
  single-lane fixture.
