# WI-162: Consolidate three canonical skill-order arrays into single source of truth

**Type:** framework
**Status:** VERIFIED
**Severity:** HIGH
**Filed:** 2026-05-08
**Source:** route-workflow framework audit

## Audit Verdict — RESCOPE (do not merge the arrays)

The three arrays exist for distinct purposes:
- `includedSkills` (76) — full registry of svc-native skills
- `corePackForRouting` (42) — router-suggestable subset (excludes auto-invoked gates per WI-150 design call)
- `bootstrapStartSequence` (22) — minimal greenfield init order
- (`pipeline` array — canonical product-build sequence)

"Consolidate" would erase deliberate semantic distinctions. The actual problem is that the **role boundaries between these arrays aren't documented** — readers can't tell whether a missing skill is a bug or by-design.

**Ship plan (rescoped):**
1. Convert to: "Document role boundaries between `includedSkills` / `corePackForRouting` / `bootstrapStartSequence` / `pipeline` arrays."
2. Add schema-level docstring in `skills-manifest.json` and a section in `AGENTS.md` explaining the four arrays.
3. Tier-1 validator: each entry in the smaller arrays must exist in `includedSkills`; documented exceptions go in an explicit `documented_exclusions` block.

**Do not ship as filed** — would damage the system.

## Problem
Three arrays in `skills-manifest.json` describe similar flows with different contents:
- `bootstrapStartSequence`: 22 entries
- `pipeline`: 16 entries
- `laneDefinitions.greenfield.skills`: 24 entries

There is no single source of truth for "the canonical skill order."

## Impact
Maintenance burden: changing one array requires manual sync to the others. Risk of divergence.

## Acceptance Criteria
- [x] Decide which array is primary (recommend: `laneDefinitions.greenfield.skills` as the superset)
- [x] Derive `bootstrapStartSequence` and `pipeline` from the primary array via metadata flags (e.g., `inBootstrap: true`, `inPipeline: true`)
- [x] Update `scripts/lint-skills-manifest.mjs` to enforce derivation rules
- [x] Document the single-source-of-truth design in `AGENTS.md §9`

**Next:** `improve-framework` → `write-spec` → `plan-changeset`

## Closeout

Closed 2026-05-10 as the audit-rescoped fix, not the original merge-the-arrays proposal. `includedSkills` is now explicitly documented as the registry superset, while `corePackForRouting`, `bootstrapStartSequence`, `pipeline`, and `laneDefinitions.<lane>.skills` keep separate roles. `skills-manifest.json` now carries `manifestArrayRoles`, `AGENTS.md §9` explains the boundaries, and `scripts/lint-skills-manifest.mjs` enforces that every smaller array entry remains a member of `includedSkills`.

The original derivation-by-flags ACs were intentionally rejected by the WI's own Audit Verdict because they would erase semantic distinctions between arrays. The shipped invariant is subset membership plus documented roles.
