## Problem

Journey and E2E skills work in isolation, but the framework still has proposal-only debt around connecting journey generation, E2E authoring, runtime execution, trace validation, selector discipline, and debug paths into a hard contract. This leaves gaps where journeys exist but do not prove execution, or E2E failures require ad hoc debugging instead of a skill-backed path.

## Acceptance Criteria

- [x] Decide and implement either a `debug-e2e` skill or a formal `diagnose-bug` E2E mode.
- [x] Add selector discipline to `write-e2e` and `test-journeys`, forbidding positional role selectors unless there is no stable alternative and the exception is justified.
- [x] Add a journey execution trace validator that proves generated journeys were executed or explicitly skipped with registry-backed reasons.
- [x] Add bridge checks from `write-journeys` output to `write-e2e` input so automatable journeys are not dropped.
- [x] Add or update tier-2/tier-3 journey skill scenarios to check process evidence, not only file presence.
- [x] Cross-link existing chrome/i18n journey WIs rather than reopening covered work.

## Route Recommendation

Run as a framework implementation epic after WI-305 defines the ledger interface. Split into child WIs if plan-changeset finds the selector, debug, trace, and bridge work cannot land safely together.

## Closeout Evidence

Implemented as a direct contract-hardening package instead of a standalone
`debug-e2e` skill:

- `diagnose-bug` now documents `mode: e2e-test` / `--mode=e2e-test`, including
  trace-first artifact review, persistence bisect, helper-app parity, tenant/scope
  checks, transient assertion checks, selector ambiguity checks, hypothesis
  ranking, and old-path-fails/new-path-passes proof.
- `route-workflow/references/intent-routing.md` routes failing/flaky E2E and
  Playwright selector failures to `diagnose-bug --mode=e2e-test`.
- `write-e2e` now requires `verify-journey-e2e-bridge.mjs` before writing tests
  from generated journeys and `validate-e2e-selector-discipline.mjs` at closeout.
- `test-journeys` now requires terminal scenario evidence with
  `validate-journey-execution-trace.mjs` and inherits selector discipline for
  E2E follow-ups.
- `write-journeys` now requires bridge validation before handing E2E-ready
  journeys to `write-e2e`.
- Tier-2 scenarios for `test-journeys`, `write-journeys`, and `write-e2e` now
  declare `### Process Checks` for execution evidence instead of only file
  presence.
- Existing chrome/i18n journey work remains referenced through related WIs
  WI-168, WI-169, WI-170, WI-190, WI-191, WI-211, WI-234, WI-267, and WI-305;
  this closeout does not reopen those covered surfaces.
