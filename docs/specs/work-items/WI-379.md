**Type:** framework

**Lane:** framework

## Goal
`hooks/svc-task-completion-guard.sh` exports the payload ($INPUT) and $LANE_TASKS_LIST as env vars to node at 3 sites (:105, :264, :686 incl. lib/active-intent.mjs). Same root cause as the pillars-check regression (envp counts toward ARG_MAX). These fail SOFT today (`|| true` / `2>/dev/null` / `if !`) and Stop payloads are small, so no live break — but a large Stop payload or lane-task list would silently degrade the safety-critical completion guard. Apply the same stdin-pipe / tempfile pattern; extend `validate-hook-payload-not-argv.sh` to sweep ALL svc hooks (it is currently scoped to the pillars hook).

## Guardrails
- The completion guard is the most safety-critical hook — prove behavior-identical (existing completion-guard tier-1 validators must stay green) before/after, per-site
- active-intent.mjs reads process.env.INPUT — port it to read a payload-file path, or keep small-payload env for that lib only with a documented size assertion
- Broaden the regression validator's hook list once all sites are fixed (today it greps only the pillars hook to stay green)

## Affected Files
- hooks/svc-task-completion-guard.sh, hooks/lib/active-intent.mjs, test-framework/evals/tier-1/validate-hook-payload-not-argv.sh
