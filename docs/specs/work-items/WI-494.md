# WI-494: Codex skill-load enforcer — zero-state bootstrap deadlock

**Type:** bugfix
**Status:** identified
**Severity:** critical
**Filed:** 2026-07-17
**Source:** live Codex session (gpt-5.6-sol, v0.144.5) in a non-svc repo — every tool call denied for ~6 turns, goal formally blocked
**Lane:** framework
**Related:** WI-486 (introduced the bootstrap exception), WI-487 (durable install enforcement)
**Scope (revised 2026-07-17, owner directive):** Defect A (bootstrap deadlock) ONLY.
Defect B (read classification widening) is descoped to a follow-up WI — see
"Descoped" section below.

---

## Problem (root cause)

`hooks/codex/svc-codex-skill-load-enforcer.mjs` denies governed mutation without an
owned in_progress task. Two independent defects make it deny *everything* in a repo
that has no lane-task graph yet.

### Defect A — the bootstrap exception cannot bootstrap (critical)

`isSkillLoaderShape()` is the only escape hatch when no task is in_progress. It calls
`laneGraphs(ctx.repo_root, env)` (line 71) and returns `false` unless exactly one graph
is owned. `laneGraphs` (`hooks/codex/lib/codex-hook-context.mjs:238-256`) derives the
graph exclusively from a validated ownership tuple pointing at a file that **already
exists on disk**.

So in a repo with zero graphs, the only command the hook can allow is
`node scripts/codex-load-skill.mjs --graph <graph>` — for a graph that does not exist.
Creating it (`scripts/svc-ensure-worktree.mjs`, or writing `.svc/lane-tasks-<WI>.json`)
is itself a governed mutation with no active task, so it is denied. **The graph cannot
exist until it exists.** WI-486 built the exception for *first skill load*; it never
covered *first graph creation*.

Observed: Codex correctly diagnosed this as a deadlock, retried the documented recovery
(`route-workflow` bootstrap), was denied again, and marked the goal blocked after the
3-turn threshold. No user action can clear it — the owner's explicit approval to create
the file changed nothing, because the hook, not permission, is the refusal.

### Defect B — read classification denies ordinary read-only tooling (high)

`isReadOnlyTool()` (`codex-hook-context.mjs:227-236`) allows reads before any task
inventory runs — correct in principle (WI-486 SIB-01/03). But its allowlist is
`ls|pwd|cat|head|tail|wc|sha256sum`, `test`, plus safe `git`/`rg`/`find`
(`codex-hook-context.mjs:187-191`). There is no `kubectl`, `gh`, or `argocd`, so
ordinary read-only investigation is classified as governed mutation and denied.

Compounding it: line 234 bails out of read-only classification entirely when the
command contains any of `; & | ` $ < > ' " \` — so **every quoted read is a mutation**,
including `kubectl -o jsonpath='{...}'` and `gh api -q '.x'`. Even allowlisting those
binaries would not fix the quoted forms. The lexical fast path is a deliberate
simplification (its comment says so), but "requires a receipt" degrades to "is
permanently denied" once Defect A blocks receipt creation.

The two defects compose: A makes the graph uncreatable, B makes read-only diagnosis of
*why* impossible. Net effect — the Codex host is unusable in any repo without a
pre-existing owned graph, which is every repo on first contact.

## Fix

- **A (shipped):** extend the bootstrap exception to cover graph *creation*, not only
  graph *consumption* — allow the canonical `svc-ensure-worktree.mjs` invocation (and
  the lane-task write it performs) when no graph is owned, validated with the same
  ownership-tuple discipline `isSkillLoaderShape` applies to the loader. Zero-state is
  a legitimate state, not a violation; it must have exactly one authorized exit.
- **B (DESCOPED — follow-up WI):** widen read classification to the read verbs the
  framework actually routes (`kubectl get|describe|logs`, `gh api|run|pr` read
  subcommands, `argocd app get`), and stop treating quoting as proof of mutation —
  classify by parsed argv, not by lexing for shell metacharacters. Quote-bearing reads
  must classify as reads. See "Descoped" section above.
- **Host parity:** record as a `taste` decision that the Claude host deliberately gets
  **no** port of this enforcer (see below). No code change.

## Host parity decision (no Claude port)

`provision/hosts/claude.json` is fully capable of hosting this hook — `hooks: true`,
`PreToolUse` in `hook_events`, identical `decision_format`
(`hookSpecificOutput.permissionDecision`), 11 PreToolUse hooks already wired, one of
which (`svc-workflow-guard.mjs`) already blocks. The authority layer is already shared
(WI-486 SIB-19: `hooks/lib/resolve-wi.mjs`). The port would be small. We are choosing
not to do it:

1. **`skill_load_mode` is the whole reason the hook exists.** claude.json declares
   `skill_tool`; codex.json declares `direct_skill_file`. On Claude the Skill tool is a
   host mechanism — a skill cannot be claimed as loaded without being loaded. On Codex
   there is no skill tool, so svc must manufacture proof (`codex-load-skill.mjs` +
   receipt) and deny mutation until it exists. Half this hook is a prosthetic for a
   capability Claude has natively.
2. **Porting imports both defects** into the host where the exempt class lives
   (docs/specs, docs/analysis, proposals, references/knowledge, append-only
   `.svc/*.jsonl` — WI-360). A governed-mutation deny blocks all of it.
3. **It contradicts the host's own direction.** WI-392's `svc-owner-inject` is
   explicitly ADDITIVE and never blocks; WI-393 demoted always-on rules to signal
   injection. Hook latency is a named top-two liability in the 2026-06-06 evaluation. A
   12th PreToolUse hook resolving the tuple and running `validateTaskGraphShape` on
   every tool call is the wrong direction.
4. **The fail-closed layer that matters is host-independent.** The pre-push 5-receipt
   envelope validates the entire `remote..local` range regardless of host. Ungoverned
   mutation on Claude cannot reach `origin/main`.

Honest residual: Claude catches ungoverned mutation at Stop
(`hooks/svc-task-completion-guard.sh`), i.e. late, where Codex catches it at
PreToolUse. If early denial is ever wanted on Claude, the defensible slice is narrow —
deny only chain-stage mutations (execute/land) without an owned task, fail **open**
otherwise, never gate reads — and it should be measured before promotion, not ported.
That is explicitly **not** this WI.

## Descoped (owner directive, 2026-07-17)

Defect B (read classification widening — CED-03/04/05, the `gh`/`kubectl`/`argocd`
allowlist and the argv-based read classifier that replaced the lexical bail) is
**DESCOPED from WI-494** into a follow-up WI. Both G6 review-exec criticals
(`gh --web`/`-w=true`, `gh --cache`) landed inside that widening — it is a fragile
denylist-style surface that deserves its own dedicated design pass, not a rider on
the bootstrap-deadlock fix. `hooks/codex/lib/codex-hook-context.mjs` is reverted to
byte-identical with `origin/main` (its pre-WI-494 `isReadOnlyTool` — the small
`ls|pwd|cat|head|tail|wc|sha256sum|test` + safe `git`/`rg`/`find` allowlist, lexical
metacharacter bail). WI-494 now covers **Defect A only** (the bootstrap deadlock:
`isBootstrapShape` + the bootstrap-intent marker + `scripts/svc-ensure-worktree.mjs`
graph-creation exception). See `.svc/pipeline-decisions.jsonl` (2026-07-17T16:05) for
the decision record.
