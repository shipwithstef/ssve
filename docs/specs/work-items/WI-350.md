# WI-350: test-journeys analytics and replay provider-visible evidence contract

## Problem

Example Marketplace proved a real PostHog E2E journey with a run marker, consent-gated
initialization, exact provider-side event lookup, and replay/session evidence.
The shared `test-journeys` skill still allows future agents to treat a browser
journey pass as sufficient proof even when the requested claim is provider
visibility in analytics or replay.

## Impact

- Provider-visible analytics/replay work can close with only local Playwright or
  browser evidence.
- E2E runs may be hard to find in PostHog or another analytics provider when no
  unique marker is required.
- Privacy claims can be under-verified if event properties are not checked for
  prohibited PII.

## Acceptance Criteria

- [x] `test-journeys/SKILL.md` requires a unique run marker for analytics,
  telemetry, replay, or provider-visible journey claims.
- [x] The skill requires consent/bootstrap setup before app initialization when
  analytics is consent-gated.
- [x] The skill requires provider-side lookup by exact run marker, event name,
  session id, or replay id after the journey passes.
- [x] The skill requires a durable evidence artifact that records event names,
  safe properties, prohibited PII checks, replay/session presence when in scope,
  and test traffic markers.
- [x] The skill explicitly rejects claiming provider-visible evidence from a
  Playwright/browser pass alone.
- [x] A tier-1 validator protects the new contract.
