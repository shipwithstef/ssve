## Goal
Convert the audit's loose plan into a tracked WI epic so the surviving
improvements ship one-per-run under the refuse-mode chain, each independently
verifiable, with **no functional or quality loss**. Targets are (a) constructs
with literally zero value (byte-identical duplication, stale mirrors, prose
drift) and (b) work that can be done much faster / at higher quality
(parallelization, hot-path hook consolidation, progressive disclosure).

## Key meta-finding (why the epic is small)
The audit confirmed the framework has **no duplicate validators and no removable
gates** — its ceremony is intact. The big structural "consolidations" a naive
pass would propose (one wire-hooks generator, a shared merge framework,
cross-skill shared templates, naive eval parallelization, "fixing" the
route-workflow relative refs) were **all rejected as functionality-losing** (see
§Rejected in the plan file). The real wins are a smaller, surgical set: hot-path
latency, context economy, and a few clean dedups.

## Child specs

### WI-453 — A1: parallelize the tier-1 eval suite (safely)
- **Now:** `test-framework/evals/run-all-evals.sh` runs ~227 validators in two
  sequential `for` loops (`*.sh` then `*.mjs`) ≈ 393 s wall-clock. Hit on every
  framework dev run *and* every G5 self-review.
- **Change:** run validators as bounded parallel jobs (e.g. `xargs -P` /
  background jobs), each writing its exit code to a per-job temp file; aggregate
  `TIER1_PASS/FAIL/TIMEOUT` **after** the join (no in-loop shared counter);
  preserve the 180 s per-script timeout; never `&&`-chain (must run all and
  report all failures).
- **No-loss:** every validator runs exactly once, same env/timeout, all
  assertions intact. Two confirmed-safe constraints: (1) the ~2 validators that
  invoke a sibling tier-1 validator (`validate-delivery-graph-replay-autorun.sh`,
  `validate-hook-host-residuals.sh`) are self-contained — they call the
  dependency themselves, so isolation holds; (2) the only shared state is the
  counter, moved to post-join aggregation. Validators already use `mktemp`.
- **AC:** old vs new produce an identical PASS/FAIL set; identical exit code on a
  seeded failure; all ~227 still execute (count check); ~60-75% wall-clock cut.

### WI-454 — A2: consolidate hot-path context-injection hooks
- **Now:** separate hook process-spawns fire on every `Edit|Write` (rule-injector
  + learning-inject + owner-inject), each a ~45-50 ms node cold-start. Confirmed
  redundant: both `svc-rule-injector.mjs` and `svc-owner-inject.mjs` independently
  read `skills-manifest.json` on that path.
- **Change:** merge the per-event injectors into one dispatcher that loads the
  manifest once and runs each injector's matching logic in-process, writing the
  same per-session memo files and the same host injection output. (Precedent:
  WI-399 A1 folded phase-boundary-detector into svc-workflow-guard.)
- **No-loss:** every injector keeps its independent matching + dedup + render;
  only the process boundary and the duplicate manifest read are removed. Output
  to the host is byte-identical. Hook-spawn-count gate
  (`validate-hook-latency.sh`, `.svc/perf-baseline.json`) is *lowered*
  deliberately in the same change.
- **AC:** golden-output test — merged hook vs the 3 originals on identical
  payloads → identical memo files + identical stdout; full tier-1 green; lowered
  spawn budget passes `validate-hook-latency.sh`.

- **No-loss:** each section is self-contained reference material with no

- **AC:** progressive-disclosure validators green; each moved section's reference

### WI-456 — B1: consolidate the PostToolUse state-sync trio
- **Now:** `svc-edit-accumulator` + `svc-lane-tasks-validator` +
  `svc-phase-receipt-autoemit` all fire on `Edit|Write` PostToolUse. ~90 ms/edit.
- **Change:** merge into one spawn.
- **No-loss + extra care:** the lane-tasks-validator **hard-blocks (exit 1/2)**
  while the other two are fail-open — the merged hook MUST preserve that ordering
  and block semantics (validate first, or run it so its non-zero exit still
  propagates). Each subsystem's dedup keeps retries idempotent.
- **AC:** golden-output + a seeded invalid lane-tasks file must still hard-block.

### WI-457 — B2: introduce `scripts/lib/validator-base.mjs`
- ~34 `scripts/validate-*.mjs` repeat the same issue-collect/report/exit scaffold
  (~400-600 L). Extract a small base (`addIssue/getIssues/reportAndExit`,
  `findFilesMatching`); migrate the ~30 standard ones, leave the ~4 complex
  (`validate-wi-promotion.mjs`, `validate-chrome-journey-coverage.mjs`, …)
  standalone.
- **No-loss:** exit codes / error formats / discovery logic identical; migrate
  incrementally with each validator's own test still green.

### WI-458 — C1: dedup `norm()` path fn
- `hooks/lib/learning-index.mjs:48` and `hooks/lib/owner-index.mjs:66` carry a
  byte-identical `norm()`. Extract to `hooks/lib/normalize-path.mjs`, import in
  both. **No-loss:** identical behavior, single source.

### WI-459 — C2: collapse `VALID_STATUSES` / `VALID_GRAPH_STATUSES` — REJECTED
- `scripts/task-graph.mjs:7-8` declares two sets that are *currently* identical.
- **Rejected (no-loss bias):** they are semantically distinct domains — valid
  *task* statuses vs valid *graph* statuses — that merely coincide today.
  Collapsing them to one constant couples two independent domains on core chain
  machinery (a future graph-only or task-only status would silently affect the
  other) for a 1-line saving. Keep the separation; not built.

### WI-460 — C6: orphan `references/project-secrets-hygiene.md`
- Zero inbound references. **Wire it into review-security / a secrets rule, or
  remove.** Prefer wiring-in over deletion (no-loss bias toward keeping the
  guidance reachable).
