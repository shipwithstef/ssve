# WI-559: Canonical review and execution dispatch adapter convergence

**Type:** framework bugfix
**Status:** LOCALLY REVIEWED (Grok r10 pass; landing, central install, and HoursHub replay pending)
**Severity:** critical
**Filed:** 2026-08-23
**Source:** HoursHub Scout capture durability execution gate replay
**Lane:** bugfix
**Related:** WI-551, WI-546, WI-489, WI-367
**estimated_minutes:** 90
**Risk Flags:** cross_runtime_integration
**Cross-system status:** suspected; contract map and pre-execution
`review-cross-model` are mandatory because the mechanical iteration-cap scanner
counts the diagnostic task and its process phases as 11 invocations.

## Goal

Make the canonical plan-review and execute-dispatch entry points consume the
owner-external WI-551 resolver at invocation time, including the configured
default mode, eligible station selection, non-numeric WI identities, and exact
Grok Build executor tuple.

## Reproduction

From the HoursHub product worktree at plan SHA
`2dcde8d6fef69c77976e4db0862aaa7567a9a774`:

1. Run `review-plan-codex.sh` with no reviewer-mode override. It fails before a
   provider call with `mode "production" is not configured`, although the owner
   policy declares `default_mode: mixed-grok-cursor`.
2. Retry with `SVC_REVIEWER_MODE=mixed-grok-cursor`. It fails before a provider
   call because the adapter requires exactly one independent external station
   while the resolved topology contains two.
3. Retry with the configured `fable` station. It fails before a provider call
   with exit 4 because the adapter parses only `WI-[0-9]+` and the authoritative
   branch/plan identity is `WI-SCOUT-CAPTURE-DURABILITY-01`.
4. Run the mandatory execution preflight. `resolve-model.sh EXEC --json` resolves
   `grok:grok-4.6`, while `execute-dispatch-preflight.sh` emits
   `DISPATCH=sonnet` from its retired MiMo/Sonnet probe.

## Expected behavior

- Canonical review uses the owner policy's configured default mode when no
  explicit mode is supplied.
- The launcher selects the eligible external station through the one WI-551
  resolver; multiple configured stations do not make the adapter unusable.
- A single authoritative named or numeric WI binds the plan review; ambiguity
  and branch/plan mismatch still fail before provider invocation.
- Execution preflight selects and reports the current exact owner-policy EXEC
  tuple. The dispatch log and pre-commit guard accept only a matching successful
  execution dispatch.

## Actual behavior

Legacy defaults duplicated in the adapters override or contradict the landed
owner policy and prevent the sanctioned Grok execution path.

## Root cause

WI-551 centralized dispatch resolution, but four compatibility surfaces retained
pre-WI-551 policy decisions: hardcoded `production`, singular-station cardinality,
numeric-only WI parsing, and the retired MiMo/Sonnet execution matrix. The
execute guard then independently recognizes only MiMo/Sonnet/Opus, so even a
correct Grok invocation cannot satisfy the commit gate. No focused replay crossed
the full product-manifest-to-review-to-executor-to-guard path.

## Acceptance criteria

- [x] AC-559-1: Omitting reviewer mode uses the protected policy's
  `default_mode`; an explicit configured mode remains supported and an unknown
  mode fails closed.
- [x] AC-559-2: The plan adapter delegates external-station selection to the
  canonical resolver. Zero eligible stations fails closed; multiple configured
  stations do not fail merely because their count is greater than one. An
  owner-selected Cursor Fable or Sol station is transported read-only by the
  canonical launcher, passes the findings schema with an exact reviewer tuple,
  and produces a schema-valid exact-tuple receipt with requested-accepted or
  stronger model attestation.
- [x] AC-559-3: Numeric `WI-559` and named
  `WI-SCOUT-CAPTURE-DURABILITY-01` identities bind exactly. Missing, ambiguous,
  and branch/plan-mismatched identities still produce zero provider calls.
- [x] AC-559-4: Execution preflight requires exactly one active same-WI
  canonical manifest before considering its colocated single-document review
  log, requires current path/digests and an execution-authorized root terminal
  state, and emits the current owner policy EXEC mode/orchestrator/host/family/
  model/effort rather than probing MiMo quota.
- [x] AC-559-5: Grok dispatch uses installed CLI controls `--cwd`,
  `--model grok-4.6`, `--reasoning-effort high`, `--permission-mode auto`,
  `--no-subagents`, `--disable-web-search`, and a private fsynced
  `--prompt-file`; no payload-sized argv or bypass-permissions mode. The
  containment root and Grok cwd are the same canonical worktree root.
- [x] AC-559-6: Fsynced dispatch evidence records the exact manifest, review,
  mode/phase/station/orchestrator, resolved tuple, and exit code through a
  parent-directory-FD-anchored append; the execute guard accepts a
  recent successful exact match and rejects stale, future, failed, wrong-mode,
  wrong-orchestrator, wrong-host/model, dirty-tree, or legacy-only evidence.
- [x] AC-559-7: Existing numeric-WI, no-WI, multi-WI, mismatch, policy security,
  fallback, and external-review receipt fixtures remain green.
- [ ] AC-559-8: The original HoursHub review and execution preflights replay
  green after the framework is landed and installed, before product mutation.

non-numeric consumer WI, and non-legacy executor tuple in one end-to-end fixture.
