## Problem
After execute-changeset freezes the diff, the chain serializes up to 5 read-only passes over the SAME package (diff main..HEAD + manifest + spec): review-gate G5, review-exec G6, audit-implementation, plus benchmark-landing/track-visuals on visual lanes. None has a data dependency on another (audit P1 and review-exec both read `git diff main..HEAD` independently). review-gate and review-exec both route to the SAME `review-cross-model` primitive — two adversarial passes over one diff.

## Mechanism
Load the frozen diff package ONCE, fan out the G5 auditor, the cross-family Codex reviewer, the audit specialists, and the visual lens as parallel subagents; merge into one finding ledger; run ONE convergence loop; then a mechanical re-verify (tests + tier-1 + re-review of HIGH findings only). Emit all three receipt types from the consolidated run.

## Mechanism (as built)
A deterministic merge core + a lens schema + a protocol doc + prose wiring (NO new skill, NO hot-path hook, NO mutating fan-out):
1. **`scripts/review-station-merge.mjs`** — pure/deterministic merge: dedup-by-file:line, keep-highest-severity, attribute-to-lens; emits the keyed re-review map (originating lens per HIGH/CRITICAL, NEVER_GATE locations always keyed) + independent per-lens caps. Fail-closed on malformed input.
2. **`schemas/review-lens-finding.schema.json`** — the StructuredOutput each read-only lens subagent returns (orchestrator never re-parses free text).
3. **`references/parallel-review-station.md`** — the wave protocol: freeze-once, fan-out the 7 lenses, mechanical barrier-merge, per-lens 3-round caps, keyed HIGH re-review (re-freeze first), post-barrier sequential receipts, measure-first, non-Claude serial fallback. Cites the in-class read-only-fan-out permission (`workflow-fanout-protocol.md`).
4. **wiring** — review-exec P3 (wave mode), audit-implementation (specialists join the wave), route-workflow Pipeline Continuation (dispatch the wave once on Claude host).
5. **validator** — `test-framework/evals/tier-1/validate-review-station-wave.sh`.

## Acceptance Criteria (deterministic exit)
- [x] A fix re-review re-runs the ORIGINATING lens/specialist (keyed dispatch), not just a generic cross-model pass — NEVER_GATE security/data-migration coverage of fixes preserved. *(Verified: `keyedReReviewMap` keys each HIGH/CRITICAL to its `originating_lens`; validator proves a NEVER_GATE LOW location is still keyed.)*
- [x] Per-lens iteration caps preserved (a single merged counter ≠ three independent 3-round caps). *(Verified: `perLensCaps` returns one `{rounds_used,cap:3}` per lens id; validator asserts 3 independent caps.)*
- [x] Barrier merge is mechanical dedup-by-file:line / keep-highest-severity — NEVER orchestrator re-adjudication (keeps self-preferential bias out). *(Verified: pure function; validator golden — collision keeps CRITICAL, both lenses attributed, run-twice identical.)*
- [x] Receipts emitted post-barrier only (git-notes writes are not concurrent-safe); diff re-frozen before the targeted HIGH re-review. *(Encoded in the protocol (steps 5,7) + the merge output `note`; wiring states sequential post-barrier emission.)*
- [x] Measure-first AC: instrument current serial latency/tokens on one framework-lane run before restructuring; non-Claude hosts fall back to serial. *(Serial-baseline `mechanical` decision logged to `.svc/pipeline-decisions.jsonl` (skill: review-station); live per-lens timing instrument runs on the next real lane review; host gate + serial fallback in the protocol + all three wiring points.)*

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-review-station-wave.sh`
- **failure_class:** the post-exec review-merge losing determinism (same lens findings → different/ordered-differently merged ledger), silently dropping or down-ranking a finding (dedup not keep-highest), losing keyed-re-review attribution (a fix re-runs the wrong/generic lens, dropping NEVER_GATE coverage), or fail-OPEN on malformed lens output.
- **promotion_signal:** condition 3 — the merge sits on the mandatory chain's post-exec gate (G6/audit); a non-deterministic or finding-dropping regression would silently weaken every review.
- **expected_runtime_budget:** <1s (in-process pure-function golden + a couple CLI invocations; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** the merge is the single point where N adversarial lenses become one gate decision; a determinism/keep-highest/keyed-attribution regression is catastrophic and silent, so the invariants must be re-proven every lint.
