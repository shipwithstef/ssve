# WI-098: Atomic WI Number Allocation in capture-idea

**Type:** feature
**Status:** VERIFIED
**Closed:** 2026-04-24
**Merged PR:** #13
**Severity:** medium
**Filed:** 2026-04-24
**Source:** capture-idea (live-session gap)
**Lane:** framework

## Goal
Parallel sessions invoking `capture-idea` must not collide on WI numbers. Allocation must be atomic.

## Context
In this live session (2026-04-24), two parallel sessions both claimed WI-079, and another queued WI-080 while a third session was mid-write on the same number. My batch had to be renumbered mid-flight to WI-090–093 to avoid clobbering. This will keep happening as parallel-session workflows get more common (see WI-082/092 and /insights "On the Horizon" parallel-execution direction).

## Hypothesized Value
Parallel sessions stop stepping on each other. Number collisions that currently need human detection + manual renumbering disappear structurally.

## Acceptance Criteria

- **AC-01** `emit-wis.mjs` reserves each WI number via an atomic `fs.writeFileSync(path, '', {flag:'wx'})` that throws `EEXIST` if another process already reserved it.
- **AC-02** On `EEXIST`, the emitter bumps to the next number and retries without user intervention or data loss.
- **AC-03** Pre-existing WI-NNN.md files (whether reservations or real content) are NEVER clobbered by a new emit.
- **AC-04** Dry-run mode skips reservation and only reports which numbers would be claimed.
- **AC-05** Regression test in `validate-capture-idea-from-proposal.sh` proves concurrent-reservation scenario.
- **AC-06** Full tier-1 sweep PASS.

## Implementation Notes

- POSIX `O_CREAT|O_EXCL` (Node's `'wx'` flag) is the atomic primitive; no separate lock file is needed.
- Scope is `--from-proposal` mode in this WI. Intake mode of `capture-idea` should receive the same treatment as a follow-up once intake's WI-creation path is audited (noted in WI-099 deferred backlog if a gap is found).
- A reconciliation script for orphan/empty reservations > N minutes old is also deferred — current observed failure mode is collision, not orphan cleanup.
