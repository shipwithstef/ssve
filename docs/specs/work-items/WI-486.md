# WI-486: Session-scoped multi-WI bootstrap

**Type:** framework concurrency regression
**Status:** VERIFIED
**Severity:** high
**Filed:** 2026-07-15
**Lane:** framework
**Source:** proposals/2026-07-15-framework-improvement-multi-wi-session-bootstrap.md and Fable 5 high-effort intake review
**Related:** WI-484, WI-485
**Affected Files/Specs:** Codex context/skill guards, Claude ownership guards, session-worktree binding, worktree bootstrap, and multi-session fixtures

## Problem

With multiple foreign live task graphs, the framework cannot safely bootstrap a new isolated WI. Repository-wide ambiguity is treated as current-session authority failure before reads or bounded bootstrap can proceed, and unrelated default-checkout residue blocks the helper path.

## Affected Files

- Codex context and exact-skill guards
- Claude ownership and completion guards
- Session/worktree binding and worktree-bootstrap helpers
- Multi-session replay fixtures

## Acceptance criteria

- [ ] Reads remain allowed with multiple foreign graphs while arbitrary unbound mutation remains denied.
- [ ] A bounded operation creates a new worktree, graph, claim, and session binding without modifying foreign state.
- [ ] Concurrent bootstrap of the same new WI is atomic: one complete winner, one actionable clean loser.
- [ ] Only a validated explicit session/worktree/WI binding selects governed authority.
- [ ] Forged graph overrides, foreign paths, shell chaining, and replayed bindings remain denied.
- [ ] Unrelated tracked and untracked default-checkout residue survives bootstrap byte-for-byte unchanged.
- [ ] Claude and Codex enforce the same ownership invariant; exact skill-load receipts remain required after bootstrap.
- [ ] Legacy/unsupported graphs never become implicit authority; disk migration is explicit, backed up, receipted, and excludes fresh foreign state.
- [ ] Compatibility handling has a session/state-digest loop breaker and terminal recovery result.

## Route recommendation

Full framework regression chain. Start with `diagnose-bug`; preserve the existing deny posture while making supported isolated bootstrap reachable.
