# WI-336: Design-time testability contract for chrome controls

**Type:** enabler
**Status:** VERIFIED
**Severity:** medium
**Filed:** 2026-05-12
**Source:** proposals/done/2026-04-27-no-positional-role-selectors.md#companion-app-code-obligation
**Lane:** framework
**Related:** WI-307, WI-168, WI-170

## Problem

WI-307 blocks brittle positional selectors in generated E2E tests, but the
companion design obligation remains unimplemented. Layout-heavy apps should
make important chrome controls testable by design, through accessible names or
stable app-controlled selectors. Without that, E2E authors are forced into
exceptions after the UI is already built.

## Evidence

- `proposals/done/2026-04-27-no-positional-role-selectors.md#Companion-app-code-obligation`
- `write-e2e/SKILL.md` now prefers stable accessible names and `data-testid`
  when no reliable name exists.
- `design-ui` and `design-tech` do not currently require chrome-control
  testability metadata when designing layout/chrome components.

## Acceptance Criteria

- [x] Update design-stage guidance so interactive chrome controls get stable
      accessible names and, when needed, `data-testid` or equivalent selectors.
- [x] Add a self-verify row or validator that catches new chrome/layout
      components with unlabeled interactive controls.
- [x] Keep the selector hierarchy aligned with
      `scripts/validate-e2e-selector-discipline.mjs`.
- [x] Add a fixture showing the design-time rule prevents a later positional
      selector exception.

## Route Recommendation

Run as medium-priority UI/testability hardening; it is a companion to the
already-verified selector discipline gate.

## Closeout

Implemented on 2026-05-12.

- Added `scripts/validate-design-chrome-testability.mjs` to check chrome/layout
  control design docs for accessible names and stable selectors.
- Updated `design-ui/SKILL.md` with a Chrome Control Testability contract that
  requires accessible names, `data-testid` or equivalent selectors, and
  `@chrome-control:<id>` traces where appropriate.
- Updated `design-tech/SKILL.md` to run the chrome testability validator when
  technical designs introduce or alter layout/chrome components.

  `test-framework/evals/tier-1/fixtures/design-chrome-testability/`.
