# WI-398: S5 — mutable `.svc` state merge protocol (multi-orchestrator coordination)

**Status:** in_progress (worktree wi398; driver + validator + per-clone install built & verified — 13/13)
**Lane:** framework
**Size:** M
**Stage:** S5 (enables safe parallel transport)
**Source:** path-to-10 re-eval (wf_c44a939b) + live collision, 2026-06-08

## Problem
Parallel orchestrators collide on mutable `.svc/*.json` state. Only `*.jsonl` has `merge=union` in `.gitattributes`; the JSON state files (orchestrator-state, lane-tasks, claims, gate-stats) have no merge driver. **Live-confirmed during the re-eval run:** two orchestrator sessions raced on main; a pathspec `--amend` scooped the sibling session's uncommitted `.svc` ledger writes into a rewritten pushed commit (unwound via mixed reset, no loss). The Insights report independently measured multi-clauding at 25% of messages / 9 overlap events — this is the normal operating mode, not an edge case.

## Mechanism (as built)
A deterministic 3-way JSON merge driver, registered per-clone, gated in tier-1:
1. **`scripts/svc-json-merge-driver.mjs`** — 3-way merge (git `%O %A %B`). Lossless by construction (every key/element on either side survives a clean merge); conflicts ONLY on a true overlapping scalar/modify-delete edit (exit 1 → git records a normal conflict — never silent loss). Array elements merge by `id`/`task_id`/`ac_id`/`sha`/`key` identity. Reads ONLY git-supplied absolute argv paths (foreign-worktree safe).
2. **`.gitattributes`** — `.svc/*.json` + `.svc/**/*.json` → `merge=svc-json`; `.svc/*.jsonl` stays `merge=union` (append-only). All 65 mutable tracked `.svc/*.json` resolve to `svc-json` via `git check-attr` (the ground truth).
3. **`scripts/install-svc-merge-driver.sh`** — registers the driver COMMAND in machine-local `.git/config` (the name is versioned in `.gitattributes`, the command is not). Absolute, quoted driver path from `git rev-parse --show-toplevel` (AC3). `--repo`/`--driver` overrides let onboarded projects register the framework's driver against their own repo. Wired into `./setup` and `init-project-state.mjs`.
4. **`test-framework/evals/tier-1/validate-svc-state-merge-safety.sh`** — fails closed if any mutable tracked `.svc/*.json` does NOT resolve to `svc-json`; plus a live isolated-git fixture proving the two-session collision merges without loss AND that a true overlap still conflicts.
5. **`references/svc-state-merge-protocol.md`** — protocol doc + the `--amend`-don't-scoop-sibling-writes operational rule.

**Non-breaking:** absent driver registration, git falls back to its default text merge (safe conflict markers, never corruption) — the driver is a strict upgrade, not a dependency.

## Acceptance Criteria (deterministic exit)
- [x] `.gitattributes` merge driver registered for each mutable `.svc/*.json`; validator FAILS on any unregistered mutable `.svc/*.json`. *(Verified: 65/65 resolve to `svc-json`; validator goes red when setup-wiring/attr is removed.)*
- [x] Negative fixture: a two-session collision on the same state file resolves without loss. *(Live `git -C` fixture in the validator: disjoint collision → `{t1,t2,t3}`+`{a,b,c}` rc=0; scalar overlap → conflict rc=1. Also proven for an onboarded project's `capability-registry.json`.)*
- [x] Companion guard: foreign-worktree writes use absolute paths / `git -C` (per the `completion-guard-foreign-claim-resolution` learning). *(Driver uses only argv paths, never chdir/relative-`.svc` write; installer registers an absolute path; validator asserts all three; protocol doc states the `--amend` rule.)*

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-svc-state-merge-safety.sh`
- **failure_class:** mutable `.svc/*.json` committed by parallel sessions merging into corrupt/invalid JSON (or silently losing one side) — the coordination substrate (lane-tasks, registries, receipts) the chain reads.
- **promotion_signal:** condition 1 (observed ≥2×: the live `--amend`-scoop collision on 2026-06-08 + the Insights-measured 9 overlap events) AND condition 3 (protects a hot path — `.svc/*.json` config format is a contract per `rules/plan-changeset-trigger.md` risk signal 1; a corrupt-merge regression breaks routing/claims/receipt-reconcile).
- **expected_runtime_budget:** <3s (a `git check-attr` loop over 65 paths + two isolated `git -C` merges; no network, no LLM).
- **why_tier_2_or_targeted_is_insufficient:** the corruption is silent and accrues per-merge across every parallel session; only an every-lint fail-closed gate catches a newly-added unprotected `.svc/*.json` before it ships and bites a future multi-clauding run.

## Value-preservation
Pure add, increases value: closes the determinism hole that parallel transport (WI-380/387/388) would otherwise open. Without it, parallelizing mutations runs over an unprotected state store.

## Vision fit (whole-company / versatile PM)
Gives the company a protocol for multiple managers working at once without overwriting each other's records — the coordination layer any multi-team company needs, and the precondition for the user's real 25%-multi-clauding workflow to be safe.
