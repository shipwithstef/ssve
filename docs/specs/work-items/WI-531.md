# WI-531 — Zero-block hooks and instant governed provisioning

**Status:** VERIFIED-L3
**Severity:** critical
**Filed:** 2026-08-11
**Base:** `ac42091bc0015f87f9cdae50251570021d7c17fb`
**Children:** WI-532 through WI-536

## Affected Files

- `hooks/codex/`, `hooks/lib/`, and `hooks/svc-worktree-isolation-guard.mjs`: read classification, task activation, operation scope, and controller authority.
- `scripts/svc-ensure-worktree.mjs`, `scripts/codex-load-skill.mjs`, `setup`, `scripts/check-install-drift.sh`, and `scripts/svc-migrate-install.mjs`: recovery and provisioning entry points.
- `provision/hosts/`, focused Tier-1 validators, WI/spec/plan/review/receipt artifacts: host topology and proof.

## Outcome

Make governed SVC sessions feel immediate without weakening mutation authority: proven reads always run, the first approved task activates atomically, preserved same-owner worktrees resume without owner-recovery shell commands, legitimate runtime targets canonicalize deterministically, and unchanged host provisioning is a byte-stable no-op. Then reduce the complete Tier-1 baseline to zero failures and zero timeouts.

## Acceptance criteria

- **AC-531-1:** Proven read-only commands, including quoted, piped, redirected, `git` inspection, external-file reads, and help/version probes, run without a WI, task graph, lease, or owner override.
- **AC-531-2:** The canonical repo-local `codex-load-skill` first-task activation works from the newly ensured WI worktree; it atomically changes only the first runnable task to `in_progress` and creates its load receipt.
- **AC-531-3:** `svc-ensure-worktree --authority-v2` is idempotent for the exact same principal/WI/worktree/generation and returns structured recovery state without orphan migration artifacts.
- **AC-531-4:** A unique Git-registered preserved worktree is adopted and same-owner branch/lineage drift is repaired under CAS without changing HEAD, user files, or generation; foreign, ambiguous, duplicated, outside-root, or symlinked authority stays fail-closed before mutation.
- **AC-531-5:** Explicit `continue`/`resume` intent reattaches or atomically hands over the exact same WI; routine recovery never requires the user to paste an `svc-owner-recovery arm` command.
- **AC-531-6:** Operation targets canonicalize absolute, relative, and symlink-aware paths before scope comparison. Legitimate configured runtime paths survive DB resets; invalid targets return structured diagnostics without poisoning branch authority.
- **AC-531-7:** One automatic repair and one retry is the maximum. Repeated identical framework denials do not mark the product goal blocked and do not produce a three-denial user loop.
- **AC-531-8:** Host hook topology matches each host manifest exactly, preserves unrelated hooks/config tables, and proves command-bound governed markers on the effective installed command.
- **AC-531-9:** `./setup --host <host>` defaults to digest-based incremental provisioning; an unchanged host is a byte-stable no-op and `--full` performs an explicit rebuild.
- **AC-531-10:** `./setup --all-hosts` provisions all eight manifests with per-host locks and bounded concurrency. No-op p95 targets are <=2 seconds per host and <=10 seconds for all hosts.
- **AC-531-11:** Codex read-hook p95 is <=100 ms on the native focused benchmark and no performance shortcut removes authority, receipt, containment, or external-state proof.
- **AC-531-12:** Sample candidate `49afc597` resumes its preserved worktree without manual recovery; the Lightning fixture-repair flow remains authorized after DB reset; an unbound completed session can run read-only diagnosis.
- **AC-531-13:** Phase B child WIs WI-532..WI-536 partition every current Tier-1 failure/timeout exactly once and close only when the full suite reports zero failures and zero timeouts.
- **AC-531-14:** Self-review, Sol exact-candidate review, and the configured AGY Gemini 3.6 Flash High review contain zero unresolved Critical/High findings.
- **AC-531-15:** Governed squash merge, canonical-main setup, all-host drift, repeated bootstrap, live consumer canaries, and receipt-chain validation pass on the final SHA.
