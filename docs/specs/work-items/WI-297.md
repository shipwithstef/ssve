# WI-297: Dynamic progressive delivery graph epic

## Goal

Make `route-workflow` compile and maintain a deterministic delivery graph for framework and product work:

1. Initial graph compilation before downstream dispatch.
2. Mandatory spine for the selected lane.
3. Conditional mandatory branches when signals are present.
4. Explicit optional and N/A branches with evidence.
5. Progressive graph mutation when skills discover new facts.
6. Bounded returns to earlier gates when contradictions or missing evidence appear.
7. Closeout classification that distinguishes runtime acceptance from framework completion.

The desired end state is not "agent improvises smarter." It is "the framework records every logical flow, evaluates branch conditions before proceeding, and blocks untracked skips."

## Ordered Child WIs

Implement in this order:

1. [WI-298](WI-298.md) — delivery graph schema and route-workflow compiler.
2. [WI-299](WI-299.md) — graph completeness validators and N/A skip ledger.
3. [WI-300](WI-300.md) — `skill_outcome` contract and progressive graph mutation.
4. [WI-301](WI-301.md) — closeout classification, completion-scope parity, and retrospective closure guard.
5. [WI-302](WI-302.md) — replay fixtures and autorun graph proof.

## Prerequisite Coordination

- [WI-219](WI-219.md) should land before enforcement PRs so framework-lane graph and hook changes have explicit review-gate policy.

- [WI-213](WI-213.md) must be coordinated with WI-299/WI-301 so graph completion consumes phase receipts instead of inventing a parallel completion system.

## Non-Goals

- Do not encode every historical deferred proposal into this epic.
- Do not put the graph rules directly into the `route-workflow` hot path.
- Do not allow open-ended loops. Returns to earlier gates must use named actions and bounded reasons.
