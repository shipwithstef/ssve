# WI-156: Add disambiguation protocol to intent-routing.md for overlapping triggers

**Type:** framework
**Status:** VERIFIED
**Severity:** HIGH
**Filed:** 2026-05-08
**Source:** route-workflow framework audit

## Audit Verdict — VALID (ship as filed)

Confirmed: `route-workflow/references/intent-routing.md` has overlapping triggers with no documented disambiguation rule:
- "I have an idea for…" → `validate-feature`
- "I have an idea I want to build" → `capture-idea`
- "build me a…" → greenfield lane

The current implicit rule is "first match wins" by table order, but the table order isn't designed for disambiguation — it groups by intent class.

**Ship plan:**
1. Add an explicit **Disambiguation Protocol** section to `intent-routing.md` stating the resolution order: (a) longest-match-wins, (b) explicit-skill-name-wins, (c) imperative-decision-word-wins, (d) fall through to validate-feature for ambiguous "ideas".
2. For each currently-overlapping trigger pair, add a row showing the specific phrase that disambiguates them.
3. Tier-1 validator: parse intent-routing.md, fail if any trigger string is a strict prefix of another without an annotated tiebreaker.

## Problem
`route-workflow/references/intent-routing.md` declares "first match wins" but has overlapping triggers:
- "build me a..." → Lane 1 (Greenfield)
- "I have an idea for..." → `validate-feature`
- "add ... to the app" → `validate-feature` (or Lane 3)

A user saying "I have an idea for a new app" matches both greenfield and validate-feature. No precedence resolution exists.

## Impact
Non-deterministic routing for the framework's entry point. Same prompt may route differently depending on table scan order.

## Acceptance Criteria
- [ ] Identify all overlapping trigger pairs in intent-routing.md
- [ ] Define explicit precedence hierarchy (e.g., explicit skill name > idea-validation > greenfield > feature-extension)
- [ ] Document disambiguation questions for ambiguous cases
- [ ] Add tier-1 validator that flags new overlaps when intent-routing.md changes
