# WI-306: Provider fidelity and saved-outcome validation for generated deliverables

**Type:** enabler
**Status:** VERIFIED
**Severity:** critical
**Filed:** 2026-05-11
**Source:** proposals/done/2026-05-11-framework-improvement-provider-fidelity-for-ai-visuals.md
**Lane:** framework
**Related:** WI-305, WI-264, WI-267

---

## Problem

Generated or integration-backed outputs can currently pass validation when some content exists, even if the content came from the wrong provider, a fallback, a placeholder, or a draft-only state. For AI image/content features, success must prove provider/source fidelity and persisted saved-state visibility, not only that an image URL or text draft exists.

## Evidence

- `proposals/done/2026-05-11-framework-improvement-provider-fidelity-for-ai-visuals.md`
- Example Marketplace WI-233 source-fidelity correction described in the proposal.
- Current delivery graph has no provider/source fidelity evidence family.

## Acceptance Criteria

- [x] Route-workflow/write-spec/validate-feature extract provider fidelity when the user or spec names a primary provider.
- [x] Feature ACs distinguish primary-provider success, allowed degraded fallback, and forbidden fallback.
- [x] Review-gate fails provider-backed ACs when fallback/mock/placeholder evidence is used as primary-provider evidence without explicit approval.
- [x] Track-visuals review mode checks generated image source, semantic relevance, saved-state visibility, and product quality.
- [x] Test-journeys treats generation flows as incomplete until start, generate, draft, save, return, and persisted display states are validated.
- [x] Evidence summaries report source/provider, fallback policy, and saved outcome, not just success/failure.
- [x] Add a replay fixture based on the Example Marketplace WI-233 failure.

## Route Recommendation

Implement after or alongside WI-305 because the provider-fidelity result should feed the feature validation ledger rows.

## Notes

This is not a visual-polish WI. It is an acceptance-fidelity gate for any feature where source/provider identity is part of the user promise.
