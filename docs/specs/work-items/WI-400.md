# WI-400: `ad-video-script` skill — placement-aware 60s performance ad-video scripts

**Type:** framework
**Status:** in_progress
**Severity:** medium
**Filed:** 2026-06-18
**Source:** User research session (agents-vs-skills + ad-video-script role model + self-improving agent literature, 2026-06-18)
**Lane:** framework
**Depends on:** WI-372 (native locked-agent policy — for the WI-401 agent), generate-visuals (asset routing, reused)
**Follow-on:** WI-401 (`ad-strategist` evolving locked agent + CTR/CPA feedback loop / leveling-up memory)

## Goal
Add a new native svc skill `ad-video-script` that writes performance ad-video scripts modeled on a **Senior Direct-Response Creative Strategist** — not a generic copywriter. Primary output contract: a **60-second** modular script, **or many variants when placement / awareness-stage qualifies** (the user directive: "60 sec video or many if it qualifies"). Placement is a first-class brief input that switches the script template, the swipe corpus, and the success metric.

This v1 is the **playbook** (the skill). The **evolving agent** that wields it and levels up from performance data is deliberately split to WI-401, because the "gets better over time" property requires a real CTR/CPA signal (deployment + data), which v1 cannot fabricate.

## Why (grounding)
- Research established the real-world role: a DR Creative Strategist owns the data loop (thumb-stop → hold → CTR → CPA/ROAS), obsesses the first-3s hook, matches Schwartz awareness stage, and writes modular "Lego-block" scripts so hooks A/B against a held-constant body.
- The SaaS field (Arcads/Creatify/ICON) **generates but does not close the loop**; open-source is near-empty → genuine whitespace for a loop-closing in-house capability.
- svc already owns ~80% of the leveling-up machinery (`learnings.jsonl` + confidence 1–10 + promotion-to-rules ≈ ExpeL's scored insight pool; `build-personas`; `mine-builder`; `generate-visuals` routes to Veo 3 for motion). The gap is the script-authoring skill + the agent that wields it.

## Scope (this WI)
1. New skill dir `ad-video-script/SKILL.md` with frontmatter (`name`, `description`, `inputs`, `outputs`, `chain`, `progressive`, `self_verify`, `human_checkpoint`).
2. **Output contract:** a machine-usable **BEAT SHEET** JSON (`product, scenario, placement, awareness_stage, duration_s, angle, character_lock, style_lock, beats[]` — each beat: `vo, image_prompt, motion_prompt, seed_from_prev` — plus `audio, proof[], cta`) AND a human-readable script render. Beats scale to duration (≈6 × ~10s for a 60s spot; proportionally fewer for 30s/15s cuts) because no model makes a coherent 60s clip in one shot (Veo 8s / Runway-Kling-Pika ~10s ceiling). One base; **many variants emitted when ≥2 placements or ≥2 awareness stages qualify**. The beat sheet is the artifact the planned `ad-video-producer` (WI-402) renders.
   - **Per-product grounding (mandatory first step):** the skill reads the actual product (landing page / spec) before writing — the Example Marketplace case proved a generic tool sells the wrong product to the wrong ICP and invents non-existent features.
3. **Placement-aware logic:** feed-ad / landing-explainer / PDP / launch → each selects template + swipe corpus pointer + eval metric. `duration_s` defaults 60 but down-cuts (e.g. 30/15) when the placement's native length warrants, noted as additional qualifying variants.
4. Wiring (reuse, don't rebuild): `build-personas`/`validate-feature` for ICP+offer inputs; `generate-visuals` (Veo 3 path) for any visual/b-roll asset routing; `social-content` overlap noted (short-form video scripting) with a Relationship-to-existing-skills map.
5. Manifest sync across the 5 source-of-truth files (`skills-manifest.json` includedSkills + appropriate lane(s) + corePack decision, README, EXTERNAL_ADDONS, REPO_MODES if applicable, route-workflow Core Pack if added there) — lint must pass.
6. A documented **"v2 hook"** stub: where the WI-401 feedback loop will plug in (campaigns ledger path, eval-gate threshold, winning-examples bank) — described, not built.
