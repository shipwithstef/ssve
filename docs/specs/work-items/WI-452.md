# WI-452: Hooks must resolve `.svc/` runtime state against the repo root, not cwd

**Type:** framework
**Status:** verified (merged PR #107, 2026-06-29; parent WI-440)
**Severity:** medium
**Filed:** 2026-06-29
**Source:** root-cause analysis of tier-1 red `validate-session-contract-freshness` (A3) + blocked `/tmp` scratchpad writes, observed 2026-06-29. Distinct from the proposal's F3 (a Stop-guard session-ownership gap in `svc-task-completion-guard.sh`); this WI is specifically the `.svc`-resolves-to-cwd runtime-state pollution finding.
**Lane:** bugfix (framework) — hot-path hooks; requires plan-changeset + review-exec (NOT an inline bulk edit).
**Depends on:** none

## Goal
Stop svc hooks from polluting non-repo working directories (notably `/tmp`) with
`.svc/` runtime state. Hooks must write per-session runtime state under the
**target/repo root's** `.svc/` (or skip when there is no svc repo), never under a
cwd-relative `.svc/` that happens to be `/tmp`.

## Root cause (confirmed 2026-06-29)
Several hot-path hooks write runtime state via a **cwd-relative** `.svc/` path:
- `hooks/svc-rule-injector.mjs:141` — `memoPath = path.join(cwd, ".svc", "rule-injections-<session>.json")` where `cwd = call.cwd || CLAUDE_PROJECT_DIR || process.cwd()`.
- `hooks/svc-loop-guard.mjs` — state file `.svc/loop-guard-state-<sid>.json` (relative; resolved against process cwd).
- (audit scope: also check `svc-owner-inject.mjs`, `svc-learning-inject.mjs`, and any other hook writing a `.svc/*-<session>.json` memo.)

When a tool call's cwd is `/tmp` (scratchpad writes, subagent/workflow processes
launched from `/tmp`), these hooks create `/tmp/.svc/…`. Observed: `/tmp/.svc/`
accumulated `loop-guard-state-*.json`, `rule-injections-*.json`,
`active-intent-state.json`, `sessions/` across multiple sessions (Jun 27–29).

## Downstream impact (why it matters)
Combined with a stray `/tmp/.git` directory, the accumulated `/tmp/.svc` made
`/tmp` look like an svc-governed repo to `findRepoRoot` + the `.svc`-presence
check. As a result:
- `hooks/svc-session-contract-freshness.mjs` **hard-blocked legitimate `/tmp`
  scratchpad writes** ("Session contract is MISSING in /tmp").
- tier-1 `validate-session-contract-freshness` A3 fixture **failed** ("target
  outside svc-governed repo passes: expected exit=0 got 2"), because its
  `mktemp -d` target resolved its repo-root to the polluted `/tmp`.

(The machine symptom was cleared by removing `/tmp/.git` + `/tmp/.svc`; this WI is
the durable code-level prevention so it cannot recur.)

## Proposed fix (design — to be finalized in plan-changeset)
- Resolve the `.svc/` runtime directory against the **target file's repo root**
  (the same `findRepoRoot` the freshness hook already uses), not cwd.
- If the target/cwd is **not** inside an svc-governed repo (no `.git`+`.svc`
  ancestor), **skip writing** the memo/state (the state has no home and no
  consumer there) — do NOT create a `.svc/` in an arbitrary dir.
- Apply consistently across all hooks that persist `.svc/*-<session>.json`
  runtime state; add a shared helper in `hooks/lib/` so the resolution lives in
  one place.
- Consider hardening `findRepoRoot` / the freshness hook to require a real git
  repo (a `.git` *directory with a valid HEAD*), so a stray empty `.git` dir
  cannot fool repo detection.

## No-loss / negative-impact notes
- In a normal repo session (cwd == repo root) behavior is unchanged — the memo
  still lands in the repo `.svc/`. Only the no-repo / `/tmp` case changes (from
  "pollute an arbitrary `.svc/`" to "skip" or "write to the real repo root").
- This is a hot-path change across multiple hooks → MUST go through
  plan-changeset → review-exec; never bulk-edit the hot path inline.

## Acceptance criteria
- [ ] A tool call with cwd outside any svc repo produces **no** `.svc/` directory
      in that cwd (regression test with a `/tmp`-style fixture).
- [ ] In-repo behavior byte-identical (memo/state still written to the repo `.svc/`).
- [ ] `validate-session-contract-freshness` A3 stays green even when `/tmp` is a
      git repo (fixture hardened or hook requires valid `.git`).
- [ ] Full tier-1 introduces no new failures.

## Implementation (2026-06-29)
Shared resolver `hooks/lib/svc-state-dir.mjs` → `resolveSvcStateDir(startDir)`: walks
up for the nearest ancestor with an **existing `.svc/` directory**, returns its path
or `null`. (Resolved against `.svc` presence, not `.git` — matches the long-standing
`findSvcDir` semantics in active-intent/stop-quality, and avoids breaking test fixtures
+ onboarded trees that carry `.svc` without a sibling `.git`. Requiring a PRE-EXISTING
`.svc` is the cycle-breaker: the first would-be write outside an onboarded repo resolves
to `null` and is skipped, so `/tmp/.svc` is never seeded.)

Seeder hooks now resolve their `.svc` dir via the shared helper and **skip when it is
`null`** (no svc repo → no persistence, no pollution); in-repo behavior is unchanged:
`svc-loop-guard`, `svc-rule-injector`, `svc-owner-inject`, `svc-learning-inject`,
`svc-subagent-start`, `svc-subagent-stop`, `svc-notification-surface`,
`svc-session-end-log`, `svc-pre-compact-snapshot`, and `svc-stop-quality.js`
(whose `findSvcDir` previously **fell back to creating `cwd/.svc`** — the sneakiest
seeder; now returns `null`, callers skip). `svc-phase-receipt-autoemit` is a reader
(`readdirSync`, caught) — not a seeder, unchanged.

**Self-heal for an already-polluted `/tmp` (Codex review P1):** `.svc`-presence alone
treats an existing `/tmp/.svc` (from a prior buggy run / sandbox) as authoritative, so
the resolver/seeders + `svc-session-contract-freshness` also **never treat the system
temp ROOT itself** (`os.tmpdir()`, `/tmp`, `$TMPDIR`) as an svc repo — pollution lives
directly at `/tmp/.svc`, never at a legit repo root, and real fixtures live in subdirs
of the temp root (e.g. `/tmp/tmp.XXXX`), which still resolve. This makes the fix
self-healing (an already-polluted `/tmp` is ignored, freshness stops blocking `/tmp`
writes) WITHOUT requiring `.git` (which would have broken `.svc`-only test fixtures).
`svc-session-contract-freshness.findRepoRoot` got the same temp-root skip (the
user-facing blocking symptom). Verified end-to-end: a polluted temp root (`.git`+`.svc`)
→ freshness exits 0 (unblocked).

**Verification:** new tier-1 `validate-svc-state-dir-no-tmp-pollution.sh` — resolver
unit (4) + loop-guard & stop-quality out-of-repo→no-`.svc` / in-repo→state-written
(red→green). Full tier-1: **zero net-new failures** (231 pass; the only reds are
pre-existing/env/session — `no-svc-residue`, `pipeline-decisions-recent`, an unrelated
expired proposal — none reference the resolver). Codex adversarial review: see receipts.

## Out of scope (documented follow-up)
**Kimi host shell hooks** (`hooks/kimi/*.sh`, ~12 reference cwd-relative `.svc`, e.g.
`svc-kimi-stop-failure.sh` → `$CWD/.svc/error-log.jsonl`) have the SAME seeder class
but are a **separate host surface**: they run only under the Kimi CLI (Kimi is
out-of-scope as an orchestrator on this machine per CLAUDE.md; "other hosts keep the
full install until injector parity lands"), and the fix needs a Bash equivalent of
`resolveSvcStateDir` (walk up for `.svc`, skip the temp root). The `/tmp` pollution +
freshness-gate breakage this WI resolves occurred under the **Claude** `.mjs` hooks.
The Kimi shell seeders are a follow-up WI, NOT covered here — surfaced by Codex
round-3 review and deliberately scoped out (the tier-1 validator's surface loop is
explicitly the Claude-host `.mjs` seeders).
