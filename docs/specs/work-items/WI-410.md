# WI-410: Blind-Control-Plan Floor — prove the framework plan is never worse than a bare-model baseline

**Status:** in_progress (worktree wi410-control-plan; spec authored, chain entering plan-changeset)
**Lane:** framework
**Size:** M
**Source:** owner directive ("as long as framework doesn't introduce something worse I want this") + ultracode research dossier `docs/analysis/wi410-control-plan-research.md` (wf_f24ea3a8), 2026-06-22

## Problem
The framework cannot currently prove it adds value over a bare prompt. The owner's lived complaint — "I get less out of this than a simple prompt" — has no instrument to confirm or refute it per-run. svc has rich machinery that measures or improves the framework's OWN output (`explore-solutions` baseline-to-beat, `mine-receipts` tiering, company-fleet measure-then-promote) but **nothing compares the ceremony plan against a framework-free control**. So ceremony that has quietly become net-negative (Bitter-Lesson harness rot) is indistinguishable from ceremony that earns its tokens, and a framework plan that silently drops a good idea the bare model had ships undetected.

## Mechanism (best-of-2 retention, NOT refine-the-blind)
Research correction (load-bearing): refining the blind plan *with* the framework is intrinsic self-correction, which **degrades** quality with no external signal (Huang et al. ICLR 2024: GPT-4 GSM8K 95.5→89.0; OAgents reflection −6.62% on hard tasks). So the mechanism is **best-of-2 retention**, where the blind plan is an immutable, returnable candidate:

1. **Capture B (blind plan):** a context-starved sub-invocation — spec + ACs only, explicit "no svc skills/checklists/review-tier knowledge" — same model family as the framework author (the control we want is *framework vs bare-prompt-same-model*, the literal "sheep" comparison; a different model would measure capability, not framework value). Contamination is logged, never denied.
2. **Deterministic delta (`scripts/blind-floor-check.mjs`, pure):** classify every B-element vs the framework plan F by structural key `(path, task-id, AC-id)` into KEEP / REFINE / ADD / REMOVE / ALTER. KEEP, REFINE, ADD auto-allowed. REMOVE/ALTER of a *correct* B-element are the only rows needing judgment.
3. **Cross-family judge (`scripts/blind-floor-judge.sh`, fork of `review-plan-codex.sh`):** only the REMOVE/ALTER rows go to an independent judge selected by `scripts/resolve-adversarial-reviewer.sh` (Claude→Codex/Gemini — never Claude-judges-Claude). Judge must certify `strict_improvement` or the removal is rejected. Verdict defaults to REJECT on uncertainty; judge is instructed "longer is NOT better" (verbosity-bias counter).
4. **Floor decision:** shipped plan M = F iff zero uncertified REMOVE/ALTER rows; otherwise re-add the element, or **ship B verbatim** (`floor_verdict=blind-adopted`). This retention escape hatch is what makes "never worse than blind" true *by construction*, with zero dependence on the judge.
5. **ROI receipt:** emit a `control-plan` receipt (via existing `emit-receipt.mjs --type`) to `refs/notes/svc-receipts` — `floor_verdict`, full element ledger, judge block, model/profile/registry_version, tree_hash. `blind-adopted` IS a logged negative-ROI signal ("framework did not earn its tokens here").

## Invariant — NEVER-WORSE-THAN-BLIND (honest bound)
- **Mechanically enforced + fail-closed** for verbatim removals of exactly-keyed elements (`blind-floor-check.mjs` exits non-zero on any uncertified REMOVE/ALTER).
- **Judge-conditional** for semantic weakening (REFINE-vs-ALTER has no ground truth — mitigated, not proven, by the cross-family judge + pessimistic tie-break).
- **Unconditional only via blind-retention** (ship B verbatim when certification is impossible).
- **Verdict provenance (G6 finding, honest bound):** every certification is **content-bound** — it carries `for_content_sha` over the exact `B→F` change it certifies, so a stale/replayed verdict from a different B/F pair is rejected (`scripts/blind-floor-check.mjs` + `stale-verdict` fixture prove this). v1 still **trusts the verdict's self-reported `reviewer_family`** — a forged file claiming `openai` is not detected by the check alone. Forge-resistance (binding the verdict to the actual judge *host*, not its self-report) is the **v2 `check-chain-receipts` host re-derivation fence**; it is safe to defer because v1 is WARN/shadow (the floor blocks nothing until v2).
- The spec MUST NOT claim full mechanical enforcement — that overstatement would itself be the false-green class the framework exists to prevent. svc/orchestrator code MAY compute KEEP/ADD + the candidate REMOVE/ALTER set but is **FORBIDDEN to write `certified_strict_improvement`** (separation of duties; that field is parsed only from the cross-family judge YAML). Promotion gates on the **exit code, never on orchestrator prose**.

## Economics & scope (v1 = WARN/shadow, default OFF)
Generating B doubles plan-stage tokens, and context economy is the framework's worst dimension (3/10). So: **SKIP** quick-fix/trivial (≤3 files) + WI-360 exempt classes; **RUN** only on infra-path (`review-plan`'s existing classifier) + WI-size M+; **call `resolve-adversarial-reviewer.sh` BEFORE generating B** (no judge → don't pay 2× for a discarded plan); armed via `.svc/chain-policy.json` opt-in + `.svc/dual-track.off` kill-switch. v1 runs WARN-only — it logs/emits the receipt but does **not** block and is **not** in `REQUIRED_TYPES_FULL`. Promotion to BLOCK is deferred until shadow data clears the bar.

## Acceptance Criteria
- [ ] **AC1 (floor proof, load-bearing):** `blind-floor-check.mjs` exits non-zero when F removes/weakens a correct B-element without a cross-family `certified_strict_improvement` verdict. Proven by fixtures `planted-silent-removal` (must fail) + `weakening-as-refinement` (must fail).
- [ ] **AC2 (retention escape hatch):** judge-unavailable / `.svc/dual-track.off` / budget-exceeded → ship B verbatim (`floor_verdict=blind-adopted`), exit 0. Proven by fixture `judge-unavailable`.
- [ ] **AC3 (anti-self-grade):** no svc/orchestrator path writes `certified_strict_improvement` (static assertion); `check-chain-receipts.mjs` rejects any receipt whose REMOVE/ALTER certifier family == anthropic.
- [ ] **AC4 (determinism):** `blind-floor-check.mjs` is run-twice-golden (identical inputs → identical ledger + exit; no `Date.now` in the pure path).
- [ ] **AC5 (receipt + durability):** valid `control-plan` receipt emitted to `refs/notes/svc-receipts` on the proof-session SHA and read back.
- [ ] **AC6 (judge independence):** floor judge selected by `resolve-adversarial-reviewer.sh`; receipt `reviewer_family != anthropic` on any pass verdict.
- [ ] **AC7 (token-gating):** SKIPs quick-fix/trivial + WI-360 exempt; RUNs infra+M+; resolver called before B-generation. Proven by a routing test over sample WI classes.
- [ ] **AC8 (shadow-mode safety):** v1 WARN-only — proven by a static assertion that `REQUIRED_TYPES_FULL` in `check-chain-receipts.mjs` does NOT contain `control-plan` (confirms shadow, not block-mode). The enforcement-wired test (gate blocks a non-exempt commit) is deferred to v2 when control-plan joins `REQUIRED_TYPES_FULL`.
- [ ] **AC9 (eval wiring):** `validate-blind-floor.sh` discovered + green under `run-all-evals.sh --tier1` (all negatives included), alongside every existing tier-1 validator.
- [ ] **AC10 (honest AC):** spec states the invariant bound precisely (mechanical+fail-closed for verbatim removals; judge-conditional for weakening; unconditional only via retention) and does NOT claim full mechanical enforcement.

## Resolved open questions (taste decisions — overridable by owner)
1. **Blind model:** same model family, context-starved (the true bare-prompt control); configurable; contamination logged. *Not* a different/weaker model (would confound framework-value with capability).
2. **Element granularity:** reuse `plan-manifest`'s structured shape keyed by `(path, task-id, AC-id)`; do not invent a parallel atom taxonomy.
3. **BLOCK-promotion threshold:** ≥20 shadow plans AND ≥1 real silent-removal caught that `review-plan` missed, before flipping into `REQUIRED_TYPES_FULL`.
4. **Token ceiling (kill-switch):** 1.5× the rolling single-track plan-stage median.
5. **Delete-criterion:** if shadow data shows only ties (framework never strictly beats AND never silently subtracts), DELETE the feature + log a negative-ROI receipt (Anthropic "add complexity only when simpler solutions fall short"). Decided after shadow window.
6. **Verbosity bias:** pessimistic tie-break to blind + "longer is not better" judge instruction + strip authorship/length cues before the judge where feasible.

## Vision fit
This is the self-proving spine: it makes "I get less than a simple prompt" structurally impossible (blind is the floor) AND continuously measurable (the diff IS the framework's per-run ROI). It is also the Bitter-Lesson defense — harness that never beats blind is flagged for deletion; judgment that consistently beats blind is protected. The framework grows honestly because every addition must out-perform the bare model or be returned to it.
