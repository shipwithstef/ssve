# WI-497: unify WI-id convention — one canonical validator, named WIs everywhere

**Type:** bugfix (systemic invariant unification)
**Status:** identified
**Severity:** high (a partial fix fails a security gate OPEN — see below)
**Filed:** 2026-07-18
**Source:** owner — svc `onboard-repo` produces NAMED WIs (`WI-SOCIAL-01`, `WI-LOC-UX-01`, `WI-013-DAYONE`) but ~25 governance sites hardcode `/^WI-\d+$/`, so svc cannot govern the WI format svc itself creates
**Lane:** framework
**Related:** WI-496 (bootstrap-script binding — same disease, narrower)

---

## Problem (diagnosis — census complete)

The WI-id validity check is copy-pasted `~25×` across `~18` files as `/^WI-\d+$/` with **no single
source of truth**, so svc's own convention drifted: `onboard-repo` emits named WIs, the gates accept
only numeric. Verified live: `WI-777` bootstraps in example-marketplace, `WI-SOCIAL-01` is denied purely on
id format.

**A partial fix is dangerous, not merely incomplete.** The first adversarial review (round 1) proved
that widening only the bootstrap path leaves `hooks/codex/svc-codex-stop-firewall.mjs` numeric-only →
a named-WI session is **silently un-governed at completion (fail-OPEN)**. The invariant must move
together or a security gate opens.

## Root-cause fix: centralize

Create ONE canonical helper — `hooks/lib/wi-id.mjs` exporting
`export const WI_ID_RE = /^WI-[A-Z0-9]([A-Z0-9-]*[A-Z0-9])?$/;` and `isValidWiId(s)`. Accepts numeric
(`WI-9`, `WI-494`) + named (`WI-SOCIAL-01`, `WI-013-DAYONE`, `WI-SPINE-001`); rejects lowercase,
empty, trailing/leading hyphen, and every path/shell-metacharacter id. **No `/i` flag** (uppercase is
the convention; per `rules/common/regex-identifier-conventions.md`, `/i`+`[A-Z]` cancels it). The
`--wi` value is argv-lexed before validation, so there is no injection surface. Route every validation
site through this helper — that is what stops the drift from recurring.
