# WI-381: Pipeline baton — machine-readable per-WI handoff (extend plan-manifest receipt)

**Lane:** framework

**Stage:** S2
**Source:** flow-architecture audit (wf_e0063433), 2026-06-08

## Problem
The feature spec is contractually re-read at 7 chain-skill starts per WI and the manifest by 6 (manifests observed to 1,215 lines). Existing machine state carries NO work content: `.svc/orchestrator-state.json` = `{activeWi,lastAction,nextTask}`; `.svc/lane-tasks-*.json` = phase status only; receipts only prove phases ran. `verify-promotion/SKILL.md` documents the "context reuse rule" but ships no artifact.

## Mechanism (as built)
Extend `schemas/receipts/plan-manifest.schema.json` with 2 baton fields + a hash-bound staleness gate:
1. **`scripts/lib/normalize-ac-table.mjs`** — deterministic `acTableSha256(specText)` over normalized AC signatures. Handles BOTH formats (checklist WIs + AC-table feature specs); INSENSITIVE to checkbox/progress flips + `*(...)*` verification annotations, SENSITIVE to real AC text revisions. Shared by distiller + validators (consistent by construction).
2. **schema** — `ac_digests` (`spec_path`, `spec_ac_table_sha256`, `entries[]`) + `mocked_deps[]`; `ac_digests` added to `required` (AC4). Description states it's a NAVIGATION index, live spec authoritative (AC2).
3. **`scripts/check-chain-receipts.mjs`** — RECOMPUTES `acTableSha256` against the spec **as it is in that commit's tree** (`git show <sha>:spec_path`, sanitized) and fails on mismatch (AC1/AC3 — not the old key-presence check). v3+ plan-manifests carry the baton; v1/v2 grandfathered (mirrored in `emit-receipt.mjs` → non-breaking for in-flight/other-harness emissions).
4. **`test-framework/evals/tier-1/validate-baton-ac-binding.sh`** — proves progress-insensitivity + revision-sensitivity + recompute-fails-on-drift, both formats; asserts the schema contract.
5. **wiring** — baton `reads:` declared in `execute-changeset`, `audit-implementation`, `land-changeset`, `verify-promotion` first phases (review-exec already had it = 5 chain skills); `plan-changeset` instructed to distill the baton at `schema_version: 3`; `references/chain-receipt-contract.md` documents the authority + staleness contract.

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-baton-ac-binding.sh`
- **failure_class:** a plan-manifest baton's `ac_digests` going STALE (spec ACs revised after distillation) while downstream skills trust it as their AC nav index — silent drift between the briefing memo and the authoritative spec.
- **promotion_signal:** condition 3 — protects a framework hot path (`schemas/receipts/plan-manifest.schema.json` config format + `scripts/check-chain-receipts.mjs`, both in `rules/plan-changeset-trigger.md`); a stale-baton regression corrupts every chain skill's first-phase context and the promotion gate.
- **expected_runtime_budget:** <1s (pure in-process hashing; no git/network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** the baton is read at 5 chain-skill starts per WI; a silently stale binding misroutes attention on every one. Only an every-lint fail-closed recompute keeps the navigation index honest against the live spec.

## Value-preservation
Pure substrate, increases value: generated FROM the reviewed manifest after review-plan PASS, regenerated on revision → can only carry reviewed content. audit-implementation keeps diffing against the actual spec; the baton routes attention, never replaces the gate's evidence source.

## Vision fit (whole-company / versatile PM)
Gives every department a one-page briefing memo instead of re-reading the whole filing cabinet — the shared institutional memory that lets roles hand off cleanly at company speed.
