# WI-201: Mid-task method corrections are misrouted as new goals

## Problem

The framework reliability review found HIGH issue F-031: Mid-task method corrections are misrouted as new goals.

## Evidence

`proposals/done/2026-05-09-intelligent-intent-parsing.md` documents the agent dispatching new work instead of applying a small method correction, with classifier proposal at lines 60-83.

## Impact

The framework burns tokens and time while missing the user's actual correction.

## Proposed Fix

Add method-correction vs scope-correction vs goal-change classification before rerouting mid-task user messages.

### Resolution

`route-workflow` now classifies active follow-up messages before treating them
as a new goal. Method corrections preserve the current task graph and apply the
smallest method swap, preventing the source failure where an account/helper hint
became a new E2E-spec-writing task.

### Changes

- Added `### Mid-Task Correction Classification` to `route-workflow/SKILL.md`.
- Added `route-workflow/references/intent-classification.md` with the
  method-correction, scope-correction, goal-change, and status-question classes.
- Changed intent-switch detection so method corrections, scope corrections, and
  status questions are not treated as unrelated new goals.
- Required routing context fields: `mid_task_classification`,
  `classification_evidence`, `minimum_viable_swap`, and
  `new_artifacts_allowed`.
- Added `test-framework/evals/tier-1/validate-mid-task-correction-routing.sh`.
