## Goal
Skills that need production verification use available browser automation (Playwright MCP) directly. Never hand off to the user to "open a browser and check" when an automated path exists.

## Context
WI-081-followup and WI-063 both had Claude ask the user to verify in a browser, even though Playwright MCP was available. Round-trips, frustration, and trust-loss for no reason.

## Hypothesized Value
Eliminates a recurring small-friction pattern that compounds across sessions.

## Broad Scope
- Add a doctrine line to `route-workflow` and to verify-class skills (`verify-promotion`, `audit-implementation`, `test-journeys`):
  > "For any 'verify on production' step, use Playwright MCP / available browser automation directly. Never ask the user to open a browser. If automation is unavailable in the current host, say so explicitly and propose an alternative automated check."
- Optionally: add a tier-1 eval that flags occurrences of "please verify in browser" / "open the URL" patterns in skill outputs (heuristic; won't catch everything but catches the obvious).
- Cross-link from CLAUDE.md global rules so all sessions inherit the guard.
