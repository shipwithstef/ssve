# WI-393: Session-survival output guard (kill the output-token-limit death spiral)

**Status:** in_progress
**Lane:** framework
**Size:** M
**Stage:** S6
**Source:** Claude Code Insights report (2026-05-08..06-07), cross-checked 2026-06-08

## Problem
A large fraction of sessions were lost ENTIRELY to repeated 500-output-token-maximum / API context errors ("several full sessions contained only repeated errors with zero actual interaction, producing no work at all"). "Rate Limit Watchdog" was the single most-requested capability in the report (×7).

## Mechanism
(a) Make the long-output-to-file rule signal-injected on output-heavy skill invocations (audits, research, knowledge dumps) instead of always-on prose. (b) An output-discipline preamble in every headless/cron dispatch template (the watchdog sessions that died in loops). (c) A SessionStart zombie-session sweeper that detects prior sessions consisting only of output-limit/API errors and surfaces them as a learning candidate.

## Acceptance Criteria (deterministic exit)
- [x] Mechanism framed HONESTLY: hooks cannot hard-cap model output length; they only add context/preambles. The deterministic parts are (b) template injection and (c) the sweeper detector.
  — Honesty is encoded in three places: the preamble fragment header (`references/output-discipline-preamble.md` "a preamble cannot hard-cap a model's per-message output length"), the sweeper header comment ("a hook cannot hard-cap model output length; it only detects the failure pattern after it has happened"), and the tier-1 check `(b) preamble is honest about not hard-capping output`.
- [x] Sweeper emits a structured learning-candidate row, never blocks.
  — `scripts/zombie-session-sweep.mjs` writes a `type:"learning-candidate"`, `blocking:false` row to `.svc/zombie-session-candidates.jsonl` via the `appendJsonlLine` state-io helper, then `process.exit(0)` on every path (fail-open `try/catch`). Tier-1 proves: `(c) sweeper exits 0 (never blocks)`, `(c) row is non-blocking`, `(c) row carries learning-candidate type`, `(c) missing transcript dir → silent exit 0`.
- [x] long-output rule injection keys on output-heavy skill signals (composes with WI-384/WI-361 injector).
  — `skills-manifest.json` rulesRegistry entry `rules/long-output-to-file.md` flipped `auto_inject: always → signal` with `signals.paths` (audit-reports/, docs/analysis/, knowledge details + CAPABILITIES, roadmap/market-readiness/coverage/competitors) and `signals.bash` (audit-implementation|audit-coverage|roadmap-evaluation|assess-market-readiness|analyze-competitors|deep-research). The existing WI-361 injector (`hooks/svc-rule-injector.mjs`) consumes these unchanged. Tier-1 proves the injector fires on an output-heavy path and bash and is silent on a control path.

## Tier-1 promotion note
Per `rules/tier-1-promotion.md`:
- **validator_path:** `test-framework/evals/tier-1/validate-output-discipline-guard.sh`
- **failure_class:** silent regression of the session-survival guard — long-output rule reverting to always-on (or losing its output-heavy signals so it never fires), the dispatch template dropping the output-discipline preamble, or the zombie-session sweeper breaking its contract (blocking instead of fail-open, mis-classifying a healthy/worked transcript as a zombie, or no longer emitting a learning-candidate row). All three are invisible at runtime — nothing surfaces them until a session is lost.
- **promotion_signal:** signal #3 (hot path in `rules/plan-changeset-trigger.md`) — the rule injector (`hooks/svc-rule-injector.mjs`) and `scripts/wire-*` run on every tool call / install; this WI changes the injected always-set (6→5) and the SessionStart wiring, and a regression there cascades across every session. Also signal #1: the output-token death-spiral is the single largest measured TOTAL-LOSS class in the 2026-05..06 Insights report (×7 most-requested), evidenced in this WI and `references/framework-learnings.jsonl` (`unbounded-until-loops-create-zombies`).
- **expected_runtime_budget:** < 1s observed (947ms), hard ceiling 5s. Hermetic — synthetic stdin payloads + fixture transcripts in a tmpdir; no network, no LLM, no credentials, no git mutation.
- **why_tier_2_or_targeted_is_insufficient:** the guard spans three coupled deliverables in three subsystems (rulesRegistry classification, the dispatch transport, a SessionStart hook). A targeted/tier-2 scenario runs only on demand, so a future edit to any one of the three (e.g. a manifest reshuffle re-marking the rule `always`, or a dispatch-worker refactor dropping the preamble) would land green and silently re-open the largest total-loss class. The always-set count is already a tier-1 invariant in `validate-rule-injection.sh`; this validator extends the same hot-path discipline to the full guard.

Implemented under `scripts/zombie-session-sweep.mjs` instead (identical behavior, wired as a SessionStart command) — a non-protected, additive location.

Mirroring the SessionStart entry into `hooks/hooks.json` is deferred to the landing/orchestrator step so the protected-file edit is made deliberately and not by a build subagent.
