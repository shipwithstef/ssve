# WI-102: Build compact browser-verify wrapper (blocks WI-097 + WI-095 product-lane)

## Goal

Ship a compact server-side browser-verify wrapper so skills can run live-URL checks without returning raw Playwright output to the parent orchestrator. Unblocks full WI-097 doctrine enforcement and WI-095's product-lane close-out extension.

## Motivation

Raw Playwright MCP tools (browser_snapshot, browser_click, browser_evaluate, etc.) return page-sized payloads that burn parent-orchestrator context. Sessions doing any non-trivial URL verification regress hard on token economy. We need one server-side process that:
- accepts declarative checks,
- runs them headlessly,
- writes large artifacts (screenshots, DOM dumps) to disk,
- returns only a small verdict-shape JSON.

## Acceptance Criteria

- **AC-01** `scripts/browser-verify.mjs { url, checks:[...] }` returns `{ pass, findings[], screenshot_path? }` in <2 KB regardless of page size.
- **AC-02** Supported check types: `presence`, `text-contains`, `regex-match`, `attr-equals`, `count-elements`, `screenshot-matches`.
- **AC-03** Screenshots saved under `docs/specs/work-items/evidence/<WI>/<timestamp>.png`; path returned but bytes NOT in stdout.
- **AC-04** Timeout, retry, navigation-wait encapsulated; caller does not tune per-call.
- **AC-05** Tier-1 smoke test against a static HTML fixture passes.
- **AC-06** `references/browser-verify-doctrine.md` updated to remove the "wrapper does not yet exist" warning once merged.
- **AC-07** Unblock: WI-095 product-lane extension filed as a follow-up WI after WI-102 merges.
