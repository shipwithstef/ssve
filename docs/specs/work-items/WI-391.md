# WI-391: write-e2e emits @AC-ID tags into test source + writes back coverage columns

**Status:** in_progress
**Lane:** framework
**Size:** M
**Stage:** S3
**Source:** flow-architecture audit backfill (wf_884dc38c), 2026-06-08

## Problem
`audit-ac/SKILL.md:122-126` asserts write-e2e owns the spec's Test/E2E columns, yet NO step in `write-e2e/SKILL.md` writes those columns, and NO AC tag is emitted into test source (verified: grep of write-e2e + test-journeys for `@AC`/`@DISC` returns zero — the convention lives only in journey `.feature.md` files). So sync-spec-code Step 3's file:line audit is a hand-copy-rot reconciliation with no machine-readable test-side anchor.

## Mechanism
1. Add an `@AC-ID` annotation mandate to write-e2e (and test-journeys' QA path): every test self-tags the AC(s) it exercises, in test source.
2. write-e2e writes the spec Test/E2E columns from those tags (closing the audit-ac:122-126 gap).
3. EXTEND the existing `verify-journey-coverage.mjs` / `verify-journey-e2e-bridge.mjs` linkers to validate test-source `@AC-ID` ↔ spec AC (research-before-build — do not build a new linker).

## Acceptance Criteria (deterministic exit)
- [x] sync-spec-code's TEST-tier check becomes a verifier over derived tags; do NOT delete Steps 2-3 — REVERTED, partial-impl, multi-tier `[DB][API][UI][TEST]`, and false-positive classes stay LLM-judged (a tag-grep can't distinguish "removed" from "never tagged"). — `sync-spec-code/SKILL.md` Step 2 gains a `[TEST]`-tier corroboration note pointing at `scripts/verify-test-ac-tags.mjs` for the present-and-tagged case, explicitly leaving REVERTED / partial / multi-tier / false-positive classes LLM-judged (Steps 2-4 untouched).
- [x] New tier-1 orphan-tag freshness check (mirrors WI-364's tamper eval). — `test-framework/evals/tier-1/validate-test-ac-tag-freshness.sh` (9/9 pass, 241ms): orphan `@AC-<ID>` (AC renamed/removed) FAILs, present-and-tagged PASSes, untagged suite PASSes (no false orphan), wrong-case tag is ignored (case is load-bearing).
- [x] Greenfield/svc-native first; backfilling tags across onboarded test suites out of scope for v1. — verifier and write-back are additive process in `write-e2e`/`test-journeys`; the linker reports vacuous-PASS on untagged suites, so no backfill is forced on already-onboarded projects.

## Value-preservation
Pure add, net positive: derived TEST-tier coverage cannot lie about a still-present correctly-tagged test, while every judgment-bearing drift class keeps its LLM pass.

## Vision fit (whole-company / versatile PM)
Makes QA coverage self-evident and self-checking — the quality department stops hand-maintaining a spreadsheet and the tests themselves declare what they cover.

## Relationships
Independent of WI-390 but composes: once `feature-graph.json` exists, AC tags are the natural population source for `test→ac` edges. Can ship standalone or as WI-390 phase 2. Cites WI-364 as the derive-then-verify precedent.


## Tier-1 promotion note

Per `rules/tier-1-promotion.md`, this WI adds a tier-1 validator and names:

- **validator_path:** `test-framework/evals/tier-1/validate-test-ac-tag-freshness.sh`
- **failure_class:** silent rot of the spec `Test`/`E2E` coverage columns and the
  `[TEST]`-tier audit — a `@AC-<ID>` tag in test source naming a spec AC that was
  renamed or removed (orphan tag), and the absence of any machine-readable
  test-side anchor that `audit-ac`:122-126 and `sync-spec-code` Step 3 otherwise
  reconcile by hand.
- **promotion_signal:** signal #3 (protects a framework hot path —
  `test-framework/evals/tier-1/`, run on every lint; the validator also guards the
  skill-contract surface of `write-e2e`/`test-journeys`/`sync-spec-code` that this
  WI extends) AND signal #2 (the hand-copy-rot reconciliation class is the one
  `rules/learning-preload.md`-style derive-then-verify precedent WI-364 already
  promoted; this is its test-source twin).
- **expected_runtime_budget:** < 5s (measured 0.24s — hermetic mktemp fixtures,
  no network, no LLM, no browser).
- **why_tier_2_or_targeted_is_insufficient:** the verifier IS the deterministic
  exit for AC #1 (the `[TEST]`-tier check "becomes a verifier"); it must run on
  every lint so that an orphan tag introduced by a spec AC rename is caught at the
  same gate that already validates the journey/E2E linker family
  (`validate-journey-e2e-contract.sh`). A tier-2 LLM scenario cannot deterministically
  diff tags vs spec ACs, and a targeted-only script would not fire on unrelated
  changes that rename an AC out from under a still-present test tag — which is
  exactly the rot this guards.
