# WI-197: No mechanical block on closeouts that delegate verification to the user

## Problem

The doctrine exists. `verify-promotion/SKILL.md:103` already defines a hard V0/V1/V2/V3 verification ladder, and `references/anti-patterns.md` records AP-31 against user-delegated verification. The original WI implied missing doctrine — that framing is wrong.

The actual gap is **mechanical enforcement outside model compliance**. Today, a skill or agent can close a behavioral AC with phrases like:

- "Please open the page and verify the toast appears"
- "Manually confirm the dropdown opens on tap"
- "User to validate keyboard navigation"

…and nothing in the framework refuses the closeout. The V0/V1/V2/V3 ladder is followed when the model remembers to follow it. When the model drifts (long context, tired session, post-compaction), there is no Stop hook, no transcript scanner, and no `verify-promotion` validator that fails closeout on these delegation patterns.

Compare to existing enforcement primitives the framework DOES have for analogous problems: the concern scanner (`scripts/scan-concerns.mjs`), the destructive-git-ops pre-check, the session-contract pre-flight guard. Each of these mechanically blocks the failure mode. There is no equivalent for V-ladder violations.

## Evidence

- `verify-promotion/SKILL.md:103` — V0/V1/V2/V3 ladder already documented
- `references/anti-patterns.md` AP-31 — user-delegation pattern named
- `proposals/done/2026-05-08-runtime-verification-must-not-delegate-to-user.md:5-23` — repeated user-eyeball fallback despite available Playwright
- `hooks/` directory — no Stop hook scans transcripts for delegation language
- `test-framework/evals/tier-1/` — no validator parses skill receipts for delegation phrases

## Impact

Behavioral verification quality depends on the model remembering AP-31 mid-closeout. Across long sessions, parallel hosts, and post-compaction recovery, that compliance is not reliable. The framework treats AP-31 as model-aware doctrine when it should be a hard gate.

## Proposed Fix

Three mechanical enforcement primitives:

1. **Stop hook `svc-verification-delegation-guard`.** On every Stop event, scan the assistant transcript window for blocking phrases ("manually verify", "please open", "user to confirm", "user to validate", "you can check", "open the browser and"). If matched AND the active task graph has an unverified behavioral AC AND no Playwright/screenshot/live-DOM evidence is attached to the task receipt, return `decision: "block"` with a reason citing AP-31 and the V-ladder.
2. **Transcript scanner CLI `scripts/scan-verification-delegation.mjs`.** Reusable engine the Stop hook calls; also runnable standalone for backlog audits. Reads the last N events from `.svc/pipeline-decisions.jsonl` + the in-flight transcript, surfaces matched delegations.
3. **`verify-promotion` Self-Verify gate.** Add a check that the skill receipt for any task with a behavioral AC contains a structured `evidence` field (V1 = live DOM snapshot path, V2 = Playwright run id, V3 = screenshot file). Free-text "user verified" closeouts fail the check.

The phrase list is configurable in `references/verification-delegation-patterns.json` so projects can extend it without code changes.

## Acceptance Criteria

- AC1: `hooks/svc-verification-delegation-guard.sh` exists, is wired in `hooks/hooks.json` for Stop events, and blocks closeout when delegation phrases match without evidence.
- AC2: `scripts/scan-verification-delegation.mjs` exists, has a tested phrase-match engine with documented false-positive carve-outs (e.g., test-fixture seeding, demo scripts).
- AC3: `verify-promotion` Self-Verify includes a check for structured `evidence` fields on behavioral-AC receipts; free-text closeouts fail.
- AC4: Tier-1 validator `validate-verification-delegation-guard.sh` exercises the Stop hook against a fixture with a delegation phrase + missing evidence; expects exit-3 (hard block).
- AC5: Replay fixture demonstrates that the historical delegation pattern from `proposals/done/2026-05-08-runtime-verification-must-not-delegate-to-user.md` is now blocked.

## Closeout

Closed 2026-05-10. Phase B Stop-hook enforcement landed.

Mechanical enforcement is now wired:
- `hooks/svc-verification-delegation-guard.sh` runs as a Stop hook and hard-blocks AP-31 delegation phrases in the latest assistant closeout text when no nearby V1/V2/V3 evidence anchor exists.
- `scripts/verification-stop-guard.mjs` extracts the latest assistant text from Stop JSON or transcript, reuses `scripts/scan-verification-delegation.mjs`, and emits host-compatible `{ "decision": "block" }` output.
- `hooks/hooks.json` and `scripts/wire-hooks.mjs` install the Stop guard.
- `verify-promotion/SKILL.md` now requires structured `target_class`, `evidence_level`, and `evidence_artifacts` checks for browser-visible work.
- `test-framework/evals/tier-1/validate-verification-delegation-guard.sh` replays delegated-verification closeout text and requires a hard block.
- `test-framework/evals/tier-1/validate-verification-delegation-detection.sh` is no longer advisory for false positives/false negatives.
