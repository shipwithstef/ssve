# WI-211: Phase-receipts Phase B — migrate canonical 5 skills

## Goal

After WI-191 Phase A landed the schema and advisory tier-1 validator, migrate the **canonical 5 skills** to declare a `phases:` block in their frontmatter and emit `phases_executed[]` in their task receipts. Tier-1 validator flips to FAIL **only for these 5** — the rest of the corpus stays in advisory mode until Phase C.

## Canonical 5 (in this order)

| Skill | Why first |
|-------|-----------|
| `diagnose-bug` | The motivating example in the 2026-04-23 proposal: 10 process tasks, 3 flags, 20 self-verify checks, all currently un-traced. Highest leverage. |
| `test-journeys` | The `proposals/done/2026-04-30-journey-execution-trace-validation.md` 10-criteria template was authored for this skill — has the most detailed phase definitions ready to lift. |
| `write-journeys` | Coupled with `test-journeys`; both produce/consume the same artifacts. Migrating together prevents schema drift between sibling skills. |
| `verify-promotion` | The skill that ENFORCES V0/V1/V2/V3 — must declare its own phases so Phase D's Stop hook can validate it without recursion ambiguity. |
| `execute-changeset` | Every framework + product feature passes through this skill. Trace-validating it makes every other skill's phases visible at the lane level. |

## Per-skill scope (one PR per skill, parallelizable)

For each of the 5 skills:

1. Add `phases:` block to SKILL.md frontmatter following `references/phase-receipts.md` schema.
2. Update the skill's process to record `phases_executed[]` in `skill_receipt` at completion. Use `scripts/task-graph.mjs` to write the receipt; if a new helper is needed, add `record-phase` subcommand to `task-graph.mjs`.
3. Add tier-2 trace assertions to that skill's scenario fixtures (`test-framework/evals/tier-2/scenarios/<skill>-*.md`) — replace string-existence checks with `jq`-based receipt structure checks.
4. Update tier-1 validator `validate-skill-receipt-shape.sh` to flip from advisory → FAIL **for this skill specifically** when its `metadata.skill` matches and a declared `required_for_completion: true` phase is absent from the receipt.

## Acceptance Criteria

- AC1: All 5 canonical SKILL.md files declare `phases:` blocks that lint cleanly against `references/phase-receipts.md`.
- AC2: Tier-2 scenarios for the 5 skills assert receipt structure, not string existence. Each scenario has at least one `jq`-based assertion.
- AC3: Tier-1 validator FAILs when one of the 5 migrated skills closes a task without matching receipt entries; PASSes for unmigrated skills (advisory mode preserved).
- AC4: `task-graph.mjs` accepts a `record-phase` subcommand: `node scripts/task-graph.mjs record-phase <path> <task-id> <phase-id> --evidence <type>:<path>` appends a `phases_executed` entry atomically via `state-io.mjs`.
- AC5: Replay fixture demonstrates that a phase-skipping run on each of the 5 skills now FAILs the validator.

## Dependencies

~1 day per skill (SKILL.md edit + tier-2 scenario rewrite + helper command). Parallelizable across the 5; total wall-clock 2-3 days.

### Resolution

Phase B is implemented for the canonical five skills. `diagnose-bug`,
`test-journeys`, `write-journeys`, `verify-promotion`, and
`execute-changeset` now declare required `phases:` blocks and document
`task-graph.mjs record-phase` emission before task completion. Phase enforcement
is forward-only: new Phase B-era completed task receipts for the canonical five
must include required phase IDs, while older historical task graphs and
unmigrated skills remain advisory until Phase C/D.

- Added `record-phase` to `scripts/task-graph.mjs`; it appends
  `skill_receipt.phases_executed[]` evidence via `scripts/state-io.mjs`.
- Added required phase declarations and receipt-emission commands to the five
  canonical SKILL.md files.
- Upgraded `validate-skill-receipt-shape.sh` to fail for missing required
  phase receipts on the migrated five after the Phase B cutoff.
- Added `validate-phase-receipt-migration.sh` to prove the migration surface,
  record-phase helper, missing-phase failure, unmigrated advisory preservation,
  and tier-2 jq assertions.

  updated `test-framework/evals/evals.json` assertion counts.
