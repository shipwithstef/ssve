## Goal

Give Claude, Codex, Cursor, Grok, and AGY the closest behavior their native
capabilities permit, while making receipt integrity and post-execution closeout
outcomes portable and mandatory across every host and linked worktree.

## Context

WI-542/WI-543 proved that installed hook registration is not sufficient evidence
of host compatibility. A Grok closeout worktree lacked the gitignored
`.svc/chain-policy.json`, silently used warn behavior while the canonical checkout
was configured to refuse, and allowed a high-impact closeout commit with an
incomplete receipt envelope to push. The Stop guard then accepted task statuses
without revalidating the explicit canonical receipt requirement. Emitting
verify-promotion receipts for WI-542 and WI-543 on the same SHA also left only the
second WI's receipt, exposing a receipt-key overwrite hazard.

## Hypothesized Value

Operators can move work between available subscriptions without losing product
delivery state or receiving a false “done.” Receipt durability, review/audit
continuity, promotion verification, and closeout are the primary product value.
Security controls remain intact, but identical host mechanics are not the goal
when native capabilities differ.

## Broad Scope

- Define a **portable mandatory core** for every host: durable receipts,
  non-destructive multi-WI evidence, honest task status, post-execution
  review/audit, promotion verification, and no success report while canonical
  closeout evidence fails.
- Define a **capability-aware extension layer** for host-native features such as
  lifecycle hooks, native task APIs, sandboxes, subagents, and fresh-session
  launch. Each host implements the closest supported behavior. A missing native
  primitive produces an explicit adapter or capability-limited blocker, never a
  false claim of parity.
- Resolve effective chain policy from repository-shared canonical state so every
  linked worktree observes the same owner-selected mode. Missing or unreadable
  policy must not silently downgrade `refuse` to `warn`; report policy provenance.
- Add a finalization barrier that runs canonical receipt validation against the
  exact implementation, promoted, and closeout SHAs before task completion,
  VERIFIED status, Stop success, or final success reporting. Task-graph status is
  an index, not authority over failed canonical evidence.
- Make receipt writes collision-safe for multiple WIs on one SHA. Key or store
  receipts by both receipt type and WI, merge atomically, and reject destructive
  overwrite unless an explicit supersession contract applies.
- Define capability-declared behavioral conformance fixtures for Claude, Codex,
  Cursor, Grok, and AGY: fresh linked worktree, effective policy, canonical
  finalization denial, multi-WI receipt preservation, post-execution closeout,
  and a valid completion path. Test host-specific hook/push behavior only where
  that host declares the primitive.
- Include installation/runtime checks for governed shell adapter executable modes;
  keep the immediate Grok/Cursor mode-bit repair in WI-545.
- Emit a compact failure card naming the failed invariant and remediation command;
  mechanical conformance execution should remain delegable to the active
  orchestrator instead of requiring owner-led manual inspection.
