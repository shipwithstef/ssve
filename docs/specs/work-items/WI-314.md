## Problem

The framework lacks a connected mechanism for identifying when an implementation is blocked by a missing capability or when planning is extending deprecated legacy code instead of challenging the foundation. These are both pre-implementation routing failures.

## Evidence

- `proposals/done/2026-04-25-capability-blocker-auto-diagnosis.md`
- `proposals/done/2026-04-25-inertia-detection-deprecated-api-check.md`

## Acceptance Criteria

- [x] Add capability-blocker auto-diagnosis that routes to the right skill before implementation churn.
- [x] Add a code-scan-before-design gate where capability availability is uncertain.
- [x] Add a deprecated-foundations registry or equivalent project-local source.
- [x] Route design-tech and plan-changeset through the registry before extending legacy APIs.
- [x] Add replay tests for "missing capability" and "deprecated foundation extension" failures.

## Route Recommendation

Run through improve-framework; likely touches route-workflow, design-tech, plan-changeset, and capability-registry/concierge.

## Notes

This WI keeps pre-implementation blocker detection separate from post-implementation validation.
