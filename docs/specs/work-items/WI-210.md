# WI-210: Historical proposals remain open without a triage SLA

## Problem

The framework reliability review found HIGH issue F-040: Historical proposals remain open without a triage SLA.

## Evidence

Open proposals include critical/high reliability items from 2026-04-25 through 2026-05-09, including deterministic quality hooks, dynamic reliability review, end-to-end mode, bundle-grep validation, intent parsing, and chrome journeys.

## Impact

The framework repeatedly rediscovers already-filed gaps because proposals are not forced into WIs, rejected, or expired.

## Proposed Fix

Add proposal triage validator: every open proposal older than N days must have `accepted_wi`, `rejected_reason`, or `deferred_until` metadata.

### Resolution

Open proposals now have a hard triage SLA. Any direct `proposals/*.md` file
that reaches the `proposals/triage.json` `max_open_days` window must carry one
of three dispositions: `accepted_wi`, `rejected_reason`, or `deferred_until`.
Metadata can live in the proposal body or in the central registry.
`proposals/done/` remains the archive for implemented proposals and is not part
of the open-proposal SLA.

### Changes

- Added `proposals/triage.json` with `max_open_days: 1` and seeded all current
  SLA-aged open proposals with explicit `deferred_until` metadata.
- Added `test-framework/evals/tier-1/validate-proposal-triage-sla.sh` with
  self-test fixtures for missing triage metadata, accepted WI metadata, and
  valid deferred metadata.
- Updated `proposals/.template.md` and `improve-framework/SKILL.md` so new
  proposals and pending-proposal scans point at the SLA gate.
