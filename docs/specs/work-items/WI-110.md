# WI-110: Tier-1 aggregate harness stalls mid-run on a downstream validator

**Type:** bugfix
**Status:** VERIFIED
**Closed:** 2026-04-26
**Closed-via:** AC-01 + AC-03 satisfied — per-validator timeout added to `run-all-evals.sh`; sweep no longer stalls and now names the culprit (`validate-host-manifests.sh`). AC-04 (state-isolation audit) and AC-05 (rg dependency doc) deferred to follow-on WI.
**Severity:** medium
**Filed:** 2026-04-25
**Source:** session observation during framework backlog burndown (PR #22)
**Lane:** bugfix

## Goal

`bash test-framework/evals/run-all-evals.sh --tier1` stalls / times out at >90s on a validator that runs after `validate-honest-diagnosis.sh`. The next validator in the sequence is `validate-host-manifests.sh`. Each individual tier-1 validator passes when run in isolation, but the aggregate harness exits exit 1 with no clear error or hangs past timeout.

## Reproduction

```bash
cd /workspace/seriousvibecoding
timeout 90 bash test-framework/evals/run-all-evals.sh --tier1 > /tmp/t.log 2>&1
echo "exit=$?"   # observed: 124 (timeout)
tail -10 /tmp/t.log
# last line: "Running validate-host-manifests.sh..." with no further output
```

Each individual validator passes:

```bash
bash test-framework/evals/tier-1/validate-host-manifests.sh   # PASS
bash test-framework/evals/tier-1/validate-loop-guard.sh        # PASS (11/11)
bash test-framework/evals/tier-1/validate-capability-registry.sh   # PASS (8/8)
bash test-framework/evals/tier-1/validate-capability-concierge.sh  # PASS (8/8)
bash test-framework/evals/tier-1/validate-capability-rediscover.sh # PASS (8/8)
bash test-framework/evals/tier-1/validate-honest-diagnosis.sh      # PASS (9/9)
bash test-framework/evals/tier-1/validate-cross-project-state.sh   # PASS (5/5)
```

## Suspected root causes (to be confirmed during diagnose-bug)

1. **State leakage between validators.** Some test writes to `.svc/loop-guard-state.json` or `~/.svc/capabilities/registry.json` and a later validator reads stale state. Symptom matches: validate-loop-guard.sh failed once in the suite ("expected exit=2 got 0") but passes in isolation — implying a sibling validator left loop-guard state in a state where the test pre-flight didn't reset it.
2. **Subshell hung on missing dep.** `validate-framework-self-management.sh` line 180 logs `rg: command not found` (ripgrep absent on this WSL2 box). If it falls through into a blocking call rather than failing loud, the suite would stall.
3. **Cumulative output buffering.** The new tier-1 validators emit JSON via `node ... | head` patterns that may interact badly with `set -o pipefail` in the wrapper.

## Acceptance Criteria

- **AC-01** Reproduce the stall and identify the responsible validator + line number.
- **AC-02** `bash test-framework/evals/run-all-evals.sh --tier1` completes in <60s on a clean clone with the same set of installed scripts (~33 tier-1 validators currently).
- **AC-03** Add a per-validator timeout in `run-all-evals.sh` (e.g. `timeout 30 bash $script`) so a single hanging validator can never stall the whole sweep — emit a `FAIL: <script> — timed out at 30s` and continue.
- **AC-04** State-isolation guard: validators that touch `.svc/` or `~/.svc/` files MUST run in a temp HOME or use a script-scoped env var override (already done by my new validators; audit existing ones for compliance).
- **AC-05** Document `rg` as either an optional dep with a `command -v rg` guard, or add to the install instructions.

## Rollback

Revert the per-validator timeout addition; aggregate sweep returns to current behavior (which is broken anyway, so rollback is low-risk).

## Dependencies

None.

## Size / Risk

Small-medium. ~3-5 hours. The fix is mechanical (per-validator timeout wrapper + state isolation audit). The investigation to find the actual stalling validator might take longer than the fix.
