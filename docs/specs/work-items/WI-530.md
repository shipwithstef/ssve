# WI-530 — Package framework skills under `skills/`

**Status:** VERIFIED
**Severity:** high
**Filed:** 2026-08-10
**Base:** `4d7543f6a8008a90cb3c841961125214c4aea2cb`

## Affected Files

- `skills/`: packaged first-party skill source tree.
- `setup`, `scripts/`, `hooks/`, and `test-framework/`: source resolution, installation, enforcement, and migration proof.
- `skills-manifest.json` and current framework documentation: authoritative source-layout contract.

## Outcome

Move every first-party SVC skill from a repository-root directory to the conventional source package layout `skills/<skill-name>/SKILL.md`, without changing skill identities, routing, contracts, host-visible installation paths, or runtime behavior.

## Acceptance criteria

- **AC-530-1:** All 103 entries in `skills-manifest.json.includedSkills` exist exactly once under `skills/<name>/SKILL.md`.
- **AC-530-2:** No repository-root directory contains a first-party `SKILL.md`, and no root compatibility symlinks recreate the old clutter.
- **AC-530-3:** Every host still installs skills flat as `<host-skill-root>/<name>/SKILL.md`; no host receives a `skills/` or `svc/` wrapper directory.
- **AC-530-4:** Setup, drift detection, routing, validators, review launchers, task dispatch, and evals resolve source skills through the packaged source root.
- **AC-530-5:** Skill names, YAML metadata, lane order, core pack membership, bootstrap order, and progressive behavior remain unchanged.
- **AC-530-6:** Current operational docs describe the packaged source layout; immutable historical evidence remains unchanged.
- **AC-530-7:** Focused layout/install tests, manifest lint, relevant Tier-1 validators, and the full Tier-1 comparison show no migration-caused regression.
- **AC-530-8:** Independent exact-candidate review finds no Critical or High issue; post-merge all-host setup/drift proves the installed contract.
- **AC-530-9:** Skill-local executables resolve framework files correctly from their new depth, with focused execution proof for every affected helper family.
- **AC-530-10:** Source discovery rejects symlinked skill directories, symlinked `SKILL.md` files, path escapes, and manifest/source mismatches before installation mutates a host.
- **AC-530-11:** Consumer `.agents/skills` remains a project metadata/prompt surface only and cannot override central framework enforcement code.
- **AC-530-12:** Ensuring a WI whose requested branch is already checked out at a preserved nonstandard `.worktrees/` path adopts that registered worktree instead of trying to create a duplicate.
- **AC-530-13:** A same-session v1 claim/binding whose branch metadata is stale after a real Git branch rename self-heals under authority locks without changing the worktree HEAD, files, or generation; live foreign and ambiguous tuples remain blocked.
- **AC-530-14:** Canonical Codex bootstrap routing requests controller-lease-v2 promotion and converged hook installation exposes one governed dispatcher, so owner recovery is not defeated by a parallel stale isolation hook.
- **AC-530-15:** Controller-v2 promotion and multi-binding branch convergence are idempotent and crash-forward-completable with a durable rollback receipt; exact pre-intent v2 controllers resume without retroactive artifacts, generation-lineage bindings remain authoritative through partial repair retry and rollback, and duplicate registrations, symlinked worktree/authority state, ambiguous session owners, changed migration leases, or manifest/source name mismatches fail before external mutation.
- **AC-530-16:** A centrally invoked `svc-reconcile` resolves framework-owned helpers from the canonical SVC package while Git and state operations remain anchored to an explicit consumer worktree; `--help` is side-effect-free and consumer-local helper files cannot shadow enforcement.
- **AC-530-17:** Framework pre-commit from a feature worktree resolves its portable slot to that worktree and validates the candidate for every provisioned host without changing live installs; only canonical main performs host drift repair/setup, preventing premature failure, stale absolute-hook routing, and dangling worktree links.

## Non-goals

- No rename of the `svc` technical namespace or any skill.
- No product behavior, deployment, database, or external API change.
- No nested `skills/svc/<name>` source layout.
- No mutation of old receipts, archived plans, raw review output, or other historical evidence solely to modernize a path string.
- No automatic takeover of a live foreign owner, adoption outside the repository `.worktrees/` containment root, or heuristic selection when more than one WI candidate exists.
