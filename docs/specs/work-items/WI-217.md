# WI-217: Use git commit time for freshness validators

## Goal

Stop freshness validators from false-failing in fresh worktrees because filesystem mtimes are new.

## Context

The audit found that mtime-triggered validators can treat freshly checked-out files as newly stale or newly modified in every worktree. The intended signal is source freshness, not checkout time.

## Acceptance Criteria

- AC1: Mtime-based freshness checks use `git log -1 --format=%ct -- <path>` for tracked files instead of filesystem mtime.
- AC2: Untracked-file behavior remains explicit and documented.
- AC3: The validators pass in a fresh worktree when the underlying tracked file has not changed.
- AC4: Tier-1 fixtures or smoke tests cover tracked file commit time and untracked fallback behavior.

## File Impact

- `test-framework/evals/tier-1/validate-research-activity-scorecard.sh`
- `test-framework/evals/tier-1/validate-research-applied-knowledge.sh`
- Any shared freshness helper if one exists or is introduced
