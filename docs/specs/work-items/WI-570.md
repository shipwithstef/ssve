# WI-570: Configurable work-item and GitHub Issues tracking

## Problem

The September 18 conceptual proposal defines local, GitHub-backed, and hybrid tracking, while the current sync script only pushes local files to GitHub. It derives the project from its installed location, permits implicit bulk publication, truncates bodies, and can close a PROMOTED item before verified completion. The sync skill still describes a different one-way model. The plan review also identified that structurally complete tests can be redundant or fail to observe meaningful behavior. This work covers both concerns, with separate implementation and validation checkpoints for the plan-value change.

## Decision and authority

The repo-local work item remains the execution, worktree, receipt, and verification authority in all modes. GitHub is public intake and a remote projection only. Configuration never chooses a mode based on repository visibility. Both remote modes require explicit per-item actions. In github-backed mode only adopted `WI-GH-N` mirrors may be published; internal local WIs remain valid but require switching to hybrid-governed for publication. Hybrid-governed permits explicit publication of both local WIs and adopted mirrors. Local-only is the default and performs no issue API calls.

`close_trigger` is `manual` by default or `verify-promotion`. Manual mode reports the explicit close command after local G7 verification. The latter attempts remote closure only after the valid receipt is emitted. Remote failure records `close-pending` in the shared map while preserving local VERIFIED and its receipt. Configuration in `.svc/config.json` contains only non-sensitive tracker settings. Optional private terms are owner-local at `~/.svc/issue-tracker-private-terms.json`, keyed by repository, with 0600 owner-only mode; absence means no configured terms and never claims all private data is detected.

## Acceptance Criteria

- **AC-570-01:** Without explicit configuration, local-only mode keeps local capture, listing, and execution usable offline and makes zero GitHub Issue API calls; setup neither publishes nor imports.
- **AC-570-02:** Configuration preserves unrelated `.svc/config.json` keys, validates mode and exact repository before network, forbids private terms or secrets in repo config, and never silently changes modes or backlog records.
- **AC-570-03:** A mode-by-operation gate accepts explicit pull, publish, and close only in remote modes; github-backed publishes only adopted `WI-GH-N` mirrors, hybrid-governed also publishes local WIs, and capture, onboard, and local listing remain local in every mode.
- **AC-570-04:** Commands resolve the invocation Git worktree or explicit `--root`, use only the configured github.com repository, reject escaping or symlink writes and conflicting identities, bound subprocess time, and make legacy implicit sync flags fail nonzero without a GitHub call.
- **AC-570-05:** Explicit pull creates a canonical `WI-GH-N` mirror with trusted metadata and every imported body line prefixed as untrusted quoted content inside a safe fence; real list parsing keeps trusted priority, empty dependency edges, null close date and open status despite hostile bold metadata lines; a second identical pull is a no-op, while remote or local changes, PR responses, repository mismatch, or secret-bearing content refuse overwrite.
- **AC-570-06:** Explicit publish requires curated public title and body, sanitizes home paths and optional private terms, rejects recognizable credentials before writes, retains the complete accepted body, preserves human text, comments, and unrelated labels, and makes unchanged content a no-op.
- **AC-570-07:** A Git-common-dir identity map and lock prevent duplicate issues across sibling worktrees; first new publication does not scan the repository, while lost POST responses, legacy map adoption, duplicate markers, capped pending recovery with explicit issue adoption, explicit verified dead-lock recovery, lock contention and repository changes fail or recover without blind retry or overwrite.
- **AC-570-08:** Publication leaves an issue open, and close only accepts a local VERIFIED WI with a matching successful durable verify-promotion Git note and a reachable verified commit; PROMOTED, wrong-WI, failed, stale, or unmerged evidence cannot close.
- **AC-570-09:** Closing with `--commit SHA` reads authority solely from the matching durable Git note, appends an owned block without changing a pulled issue’s human body or title, transmits only sanitized generated commit and receipt facts in one issue PATCH, preserves local verification if GitHub fails, records retryable close-pending, and never uses PR auto-close keywords for this policy.
- **AC-570-10:** Work-item schema, existing parsers, routing, worktree binding, receipts, trailers, sync skill, and operator documentation consistently accept adopted `WI-GH-N` while retaining local WIs and offline behavior.
- **AC-570-11:** Tracker tests exercise the real CLI through temporary consumer repositories and a recording `gh` stub with independent expected requests and state outcomes; live read-only GitHub checks are optional reachability evidence, not a substitute for or prerequisite to offline proof.
- **AC-570-12:** Focused hermetic checks, the free full Tier 1 suite, manifest lint, and all-host install drift checks pass after the implementation; required checks are never turned into skips to make a candidate pass.
- **AC-570-13:** Plan authoring and holistic review demand each material risk have a meaningful independent outcome and sufficient observation; the reviewer prompt explicitly challenges mock-echo, duplicate, implementation-mirroring, fictional, and missing-runtime tests without adding a second model stage or keyword gate.
- **AC-570-14:** Plan-value changes receive their own focused checkpoint, review, and validator proof so a regression in the review launcher cannot be hidden inside tracker validation.

## Source and constraints

The recovered proposal is preserved in `docs/plans/2026-09-26-work-item-tracking/original-proposal.md`. The existing `scripts/sync-github-issues.mjs`, `skills/sync-work-items/SKILL.md`, and `references/work-item-schema.md` define current behavior. The two independent September 26 plan reviews are dispositioned in `docs/plans/2026-09-26-work-item-tracking/review-resolutions.md`. This spec adopts the resolved safe choices rather than every example in the conceptual proposal. No daemon, generic provider framework, automatic backlog migration, or automatic public bulk sync is in scope.
