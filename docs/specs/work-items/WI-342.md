## Problem

`discuss-phase` is currently `human_checkpoint: true`, which pauses route-workflow on every bounded gray-area decision. Most of those decisions are mechanically resolvable from the same context the skill already loads (router context, project state, decision logs, active spec/WI, FRAMEWORK-STATE, rules, framework-learnings). The human pause is doing two jobs at once: catching errors (mechanically fixable with rules + validators) and providing adversarial friction (the "but have you considered…" challenge that prevents the author from converging on the first plausible answer). Removing the human without replacing the adversarial friction makes autonomous discuss-phase strictly worse than the checkpointed version.

The framework already has the adversarial-review primitive in `review-cross-model` (code review via a second-family model) and `review-plan` tier 2 (plan adversarial review via Codex). The same shape applies to decision artifacts.

## Notes

This WI deliberately does NOT change other `human_checkpoint: true` skills (`strategic-decision`, `validate-feature`, `audit-session-execution`, etc.). Those have different blast radii and require their own evaluation. The follow-up sweep WI is responsible for that classification.

The proposal makes one point worth re-stating: the adversarial reviewer is NOT a substitute for human judgment on high-stakes decisions (strategy, legal, money, irreversible architecture, "should we build this"). Those stay checkpointed. The reviewer substitutes for the human ONLY on bounded gray areas where the skill's loaded context is sufficient evidence for a defensible resolution.
