## Problem

The `svc-eval-gate-pre` PreToolUse hook only fires on the `TaskUpdate` tool. In the
2026-04-25 example-marketplace session, the agent flipped `tasks[].status = "completed"` by
**editing the `.svc/lane-tasks-*.json` file directly via the `Edit` tool**. The
TaskUpdate matcher never fired, so the eval-gate that requires a populated
`eval_matrix` was bypassed entirely.

Existing schema-level guards (skill_receipt required when status=completed) caught
some shapes but did NOT enforce eval_matrix populated. An agent could supply a
schema-valid `skill_receipt` and still ship completed tasks with empty/missing
`eval_matrix`.

## Scope

Extend `hooks/svc-lane-tasks-validator.mjs` (which fires PostToolUse on Edit|Write
of `.svc/lane-tasks-*.json`) with a status-transition discipline check:

1. Read prior content from git HEAD; parse the new content from the file.
2. For every task whose status flipped from non-completed → completed:
   - Require `eval_matrix` to be a non-empty array.
   - Require every `eval_matrix[].value` to be non-null/non-empty.
3. On any violation, exit 2 with a clear remediation message.
4. Honor `SVC_LANE_TASKS_ALLOW_RAW_EDIT=1` for wholesale-rebuild scenarios where
   no individual transition is occurring.

Plus: a tier-1 validator
(`test-framework/evals/tier-1/validate-g1-lane-tasks-edit-guard.sh`) that bootstraps
a temp git repo, simulates the bypass shape, and asserts exit 2 fires (5 smoke
tests covering missing/empty/unfilled/filled eval_matrix and the override).
