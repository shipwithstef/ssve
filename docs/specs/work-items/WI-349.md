# WI-349: Receipt-emission --sha pinning for multi-session collision prevention

## Problem

The framework's one-call receipt emitter (`scripts/emit-receipt.mjs`) infers the target commit for receipt association by executing `git rev-parse HEAD` at the moment of emission. When multiple concurrent agent sessions or subagents operate on the same physical checkout, Session B switching checkout HEAD mid-run can cause Session A's emitted receipts to be mis-routed and written to the wrong commit (e.g., in `.svc/receipts/<wrong-sha>/` and the wrong git note).

## Impact

* **Friction & Delays:** Active developer/agent session confusion and manual git recovery overhead (~15–30 minutes) to clean up misplaced receipt files and re-emit them.
* **Refused Pushes:** The mandatory chain check (`check-chain-receipts.mjs`) on push will fail and refuse the push because the target commit is missing its required receipts.

## Fix

- **Option A implementation:**
  - Add a required `--sha <sha>` flag to `scripts/emit-receipt.mjs`.
  - Deprecate the implicit fallback to `git rev-parse HEAD` by logging a deprecation warning to `.svc/pipeline-decisions.jsonl`.
  - Update all receipt-emitting pipeline skills (`plan-changeset`, `review-plan`, `execute-changeset`, `review-exec`, `audit-implementation`, `land-changeset`, `verify-promotion`) to capture the intended SHA once at the start of their run and pass it explicitly.
  - Update `references/chain-receipt-contract.md` to document the `--sha` requirement.
  - Add a regression/unit test verifying that receipt emission correctly pins to `--sha` even when HEAD changes.

## Acceptance Criteria

- [x] `emit-receipt.mjs` accepts `--sha <full-sha-or-short-sha>` and uses it as the target for both `.svc/receipts/<sha>/` mirror and the git note.
- [x] If `--sha` is omitted, log a deprecation entry to `.svc/pipeline-decisions.jsonl`.
- [x] Chain skills capture `BASE_SHA=$(git rev-parse HEAD)` once at the start of receipt emission and pass it to every `emit-receipt` call in the chain.
- [x] Update `references/chain-receipt-contract.md` to document the `--sha` requirement.
- [x] Regression test verifies that receipt emission correctly binds to `--sha` under dynamic HEAD switches.
