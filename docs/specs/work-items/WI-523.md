## Items

**1. Third loader asymmetry (finding 5).** `references/stage-registry.json` has three consumers. `scripts/audit-story-receipts.mjs` rejects duplicate stage keys and a profile naming a situational stage; `scripts/stage-activation.mjs` and `scripts/task-graph.mjs generate` do not. Nothing green-lights silently today — the validator's stricter load is downstream and exits 2 loudly — but this is the third time in one WI that a check reached some registry consumers and not others, and the pattern is the WI's own recurring defect. Prefer one shared loader over a fourth copy of the checks.

**2. Genesis header format drift (finding 6).** `write-spec/SKILL.md:96` (pre-existing) tells the agent to write `Derived-at: HEAD` at genesis, but `parseBranchIndex` requires `[0-9a-f]{7,40}` and rejects a literal `HEAD` as a malformed header. The template correctly says `<full sha>`. So the new line at `:105` claiming `check-branch-index` returns EMPTY for a genesis index is wrong for a file that followed `:96` — it would be rejected as malformed instead. Align `:96` with the template.

**3. `route-workflow` hot-path budget (finding 3).** 226 → 235 lines against a declared budget of 220. Pre-existing red, aggravated by +9 from WI-521's P3 invocation block. Either trim or re-justify the budget with evidence.

**4. Abbreviated command in prose (finding 7).** `route-workflow` P3 cites `task-graph.mjs generate --activation <this-output>`, omitting the required positional path and `--wi` / `--story-type` / `--lane`. An agent copying it verbatim gets a usage error. Spell it out — the whole point of the literal-bash-block convention is that it runs as written.

**5. Shell interpolation, theoretical (finding 8, INFO).** `svc-auto-drive.mjs findStoryReceiptSha256` uses one `execSync` with an interpolated path. The path comes from a git-derived, regex-filtered list, so exposure is theoretical — but the file's own neighbours use `execFileSync` arg-arrays. Convert for consistency.
