## Problem

Framework health is spread across many validators and install checks. A consolidated `svc doctor` command would reduce repeated manual validator selection and make framework state problems visible before a session spends tokens on the wrong path.

## Evidence

- `proposals/done/2026-05-08-svc-doctor-consolidated-healthcheck.md`
- Recurring sessions required manual combinations of tier-1, install drift, proposal triage, knowledge provenance, and hook checks.

## Acceptance Criteria

- [ ] Define the `svc doctor` command scope and output contract.
- [ ] Compose existing validators without duplicating their logic.
- [ ] Include install drift, proposal triage, main tier-1 health, hook loadability, and knowledge provenance summaries.
- [ ] Provide machine-readable and human-readable output modes.
- [ ] Add a tier-1 self-test for the doctor command.

## Route Recommendation

Run after WI-305/WI-307 unless healthcheck consolidation becomes the fastest way to prevent repeated validation misses.

## Notes

This should be a wrapper over existing validators, not another independent source of truth.
