# WI-186: SessionStart healthcheck only verifies Claude install — six other provisioned hosts have zero install verification

## Problem

The original framing ("only mentions Claude in shared hooks config") understated the failure surface. Concrete reality:

- `svc-session-start-healthcheck` per `hooks/hooks.json:89` scans only `~/.claude/skills`.
- The framework provisions seven hosts: Claude, Kimi, Codex, Gemini, OpenCode, Antigravity, Cursor (per `provision/hosts/*.json`).
- That means **six of seven hosts have no SessionStart install-drift verification at all.** A user running Kimi, Codex, Gemini, OpenCode, Antigravity, or Cursor with a corrupt or partial install gets zero signal — the framework appears healthy because the healthcheck is gated to a path that doesn't exist on those hosts.

This is silent failure. A drifted install on Kimi (missing skill symlinks, stale `provision/` link, broken hooks wiring) produces confusing skill-not-found and "command not allowed" errors with no upstream healthcheck to point at the root cause. The user has to diagnose install-drift manually on every non-Claude host.

The drift compounds with WI-137 (shared-content-dirs) and the multi-host symlink model — exactly the surfaces most likely to drift after host provisioning is updated.

## Evidence

- `hooks/hooks.json:89` — healthcheck path hardcoded to `~/.claude/skills`
- `provision/hosts/` — seven host manifests: claude, kimi, codex, gemini, opencode, antigravity, cursor
- `scripts/detect-host.sh` — host-detection primitive already exists and is used elsewhere in route-workflow

## Impact

- Six of seven supported hosts have no install-drift signal. Drift surfaces as cryptic per-skill errors.
- New host onboarding inherits the gap silently — adding an eighth host requires authoring per-host healthcheck logic that doesn't exist.
- Host-specific symlink model (per CLAUDE.md "Shared-Content Registry") means drift on one host doesn't necessarily mirror on others; per-host verification is required.

## Proposed Fix

1. **Make the healthcheck host-aware.** `svc-session-start-healthcheck` reads `scripts/detect-host.sh` output to determine the active host's skills path, then scans that path against the corresponding `provision/hosts/<host>.json` manifest's `infra_dirs` + skill list.
2. **One implementation, seven hosts.** Lift host-specific paths into a single resolver helper `scripts/resolve-host-paths.mjs` so future host additions are one JSON file (the existing pattern from `setup`).
3. **Drift-detection coverage parity.** The healthcheck must verify, for the active host: (a) skills symlinks present, (b) `infra_dirs` from manifest present, (c) hooks wired in the host's settings file (or marked "no hooks" if the host doesn't support them).
4. **Tier-1 validator covering the negative path.** `validate-session-start-healthcheck-multi-host.sh` simulates a drifted install on each non-Claude host and asserts the healthcheck surfaces the drift.

## Acceptance Criteria

- AC1: `svc-session-start-healthcheck` resolves the active host via `scripts/detect-host.sh` and scans the host-appropriate skills path, not a hardcoded one.
- AC2: For all seven provisioned hosts, a missing skill symlink under that host's skills root is surfaced in the SessionStart output.
- AC3: Adding an eighth host requires only a new `provision/hosts/<host>.json` (no code change in the healthcheck) — proven by adding a fixture host in tests.
- AC4: Tier-1 validator `validate-session-start-healthcheck-multi-host.sh` runs in `run-all-evals.sh --tier1`, exercises the drift path on each host, and fails on missed drift.
- AC5: Documentation in `FRAMEWORK-STATE.md` and `CLAUDE.md` no longer references Claude-only healthcheck behavior.

## Closeout

Closed 2026-05-10. The SessionStart healthcheck now resolves the active host and scans that host's install paths instead of hardcoding `~/.claude/skills`.

Changes:
- Added `scripts/resolve-host-paths.mjs` as the manifest-backed host path resolver.
- Updated `hooks/svc-session-start-healthcheck.mjs` to detect `SVC_HOST` / `scripts/detect-host.sh`, resolve `provision/hosts/<host>.json`, scan the host-specific skills path, and rerun `./setup --host <host>` during self-heal.
- Updated `hooks/hooks.json` description to describe host-aware behavior.
- Added `test-framework/evals/tier-1/validate-session-start-healthcheck-multi-host.sh`.
- Pinned existing Claude self-heal tests to `SVC_HOST=claude` for deterministic behavior under non-Claude sessions.
- Updated `FRAMEWORK-STATE.md`.
