# WI-503: Normalize external-review artifact paths and fail closed on receipt-display errors

**Type:** framework review-adapter regression
**Status:** identified
**Severity:** medium
**Filed:** 2026-07-20
**Source:** WI-502 Fable plan review invocation

## Problem

`scripts/review-plan-codex.sh` accepts `SVC_EXTERNAL_REVIEW_ARTIFACTS_DIR`. When that value is relative, the launcher successfully writes the findings, summary, and receipt, but the adapter's final Node expression calls `require()` with the relative string `.svc/.../summary.json`. Node interprets that as a package id rather than a relative file, prints `MODULE_NOT_FOUND`, and the command can still report success because the failure occurs inside command substitution used by `printf`.

## Acceptance criteria

- [ ] Normalize custom artifact directories to an absolute path before creating or reading summary/receipt files.
- [ ] Read summary JSON with `fs.readFileSync`/`JSON.parse` rather than module resolution.
- [ ] A missing/malformed summary or receipt makes the adapter exit nonzero after a nominal provider success.
- [ ] A relative custom artifacts directory fixture returns findings plus an exact existing receipt path without stderr stack trace.
- [ ] The fix does not create another provider call and does not alter reviewer tuple/fallback/cache policy.

## Boundary

Independent follow-up; do not fold into WI-502 authority implementation or rerun the paid review solely for this display defect. The WI-502 receipt at `.svc/external-review-artifacts/plan/WI-502-round1/receipt.json` is valid and server-attested.
