# WI-199: No mechanical block on V0 bundle-grep substituting for live verification

## Problem

The V0/V1/V2/V3 ladder in `verify-promotion/SKILL.md:103` already says bundle-grep is V0 and is insufficient for behavioral closeouts on browser-visible changes. AP-31 reinforces this. The doctrine is in place.

The actual gap is **mechanical enforcement**. A skill or agent can close a browser-visible-change task by greppping the deployed bundle for a string ("verified — `Submit` appears in `dist/main-abc123.js`") and nothing in the framework refuses the closeout. The 24-PR Example Marketplace campaign documented in `proposals/done/2026-05-09-bundle-grep-is-not-validation.md:17-24` is exactly this failure mode — every PR's closeout cited V0 bundle-grep, none cited V1 (live DOM) or V2 (screenshot/Playwright), and no validator failed.

This WI is the V0→V1 transition half of the same enforcement primitive that WI-197 builds for V-ladder delegation. They share infrastructure but cover different failure modes:

- **WI-197** = "user, please verify" closeouts (delegation outward)
- **WI-199** = "I greppped the bundle, ship it" closeouts (V0 substitution)

Compare to existing enforcement primitives the framework DOES have for analogous problems: `scripts/scan-concerns.mjs`, the destructive-git-ops pre-check, and the route-workflow live-evidence task-graph obligation for visual-output skills. Each mechanically blocks its failure mode at its declared enforcement layer. There is no equivalent that refuses V0-only closeouts on browser-visible changes.

- `verify-promotion/SKILL.md:103` — V0/V1/V2/V3 ladder
- `proposals/done/2026-05-09-bundle-grep-is-not-validation.md:17-24` — 24-PR campaign closed at V0
- `proposals/done/2026-05-09-bundle-grep-is-not-validation.md:64-73` — proposed hard gate
- `hooks/` directory — no hook fails on V0-only receipts for browser-visible work
- `test-framework/evals/tier-1/` — no validator inspects skill receipts for V-ladder evidence shape

## Impact

Static deployment evidence (a string appearing in `dist/`) masquerades as runtime user evidence. Bugs that survive the bundle but fail at runtime (CSS, hydration, event wiring, RTL, locale, theme) close as verified. The Example Marketplace 24-PR campaign is the worst observed instance; the same failure mode is reproducible in any project using `verify-promotion` whenever the model defaults to V0.

## Proposed Fix

A V-ladder enforcement primitive shared with WI-197:

1. **Skill-receipt schema with structured `evidence` field.** `verify-promotion` and `execute-changeset` write task receipts that include:
   - `evidence_level: "V0" | "V1" | "V2" | "V3"`
   - `evidence_artifacts: [{type, path, captured_at}]`
   - `target_class: "browser-visible" | "api" | "data-only" | "infra"`
2. **Validator `validate-verification-evidence-shape.sh`.** Tier-1 validator. For each task whose `target_class` is `browser-visible`, fail if `evidence_level` is `V0`. For `api` / `data-only` tasks, V0 is acceptable. The classifier is conservative — defaults to `browser-visible` when unsure.
3. **Stop hook integration with WI-197 guard.** The same `svc-verification-delegation-guard` (from WI-197) extends to also block closeouts where the receipt's `evidence_level` is `V0` and `target_class` is `browser-visible`. Single hook covers both delegation and V0 substitution.
4. **Live-evidence chain wiring.** When a `browser-visible` task closes without V1/V2/V3 evidence, route-workflow's live-evidence task-graph obligation is invoked to obtain the screenshot before the task can be marked completed.

## Acceptance Criteria

- AC1: Skill receipt schema for `verify-promotion` and `execute-changeset` includes structured `evidence_level`, `evidence_artifacts`, `target_class`.
- AC2: Tier-1 validator `validate-verification-evidence-shape.sh` exists and fails browser-visible tasks closed at V0.
- AC3: Stop hook `svc-verification-delegation-guard` (shared with WI-197) blocks closeout on V0-only receipts for browser-visible tasks.
- AC4: Auto-invocation of live-evidence capture wired so V0 receipts for browser-visible tasks transition to V2 before completion (or the task fails the validator).
- AC5: Replay fixture from the Example Marketplace 24-PR campaign demonstrates closeouts now fail at the validator and the Stop hook.

## Closeout

Closed 2026-05-10. Phase B Stop-hook enforcement landed.

Mechanical enforcement is now wired:
- `hooks/svc-verification-delegation-guard.sh` runs as a Stop hook and hard-blocks V0 bundle-grep closeout claims for browser-visible work when no nearby V1/V2/V3 runtime evidence anchor exists.
- `scripts/verification-stop-guard.mjs` loads `references/bundle-grep-substitution-patterns.json` and emits host-compatible `{ "decision": "block" }` output for actionable HIGH findings.
- `hooks/hooks.json` and `scripts/wire-hooks.mjs` install the Stop guard.
- `verify-promotion/SKILL.md` and `execute-changeset/SKILL.md` now require structured evidence classification on browser-visible task receipts.
- `test-framework/evals/tier-1/validate-verification-delegation-guard.sh` replays a V0 bundle-grep closeout and requires a hard block.
- `test-framework/evals/tier-1/validate-bundle-grep-substitution.sh` is no longer advisory for false positives/false negatives.
