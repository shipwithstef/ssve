# WI-208: `.svc` active state contains stale completed-file naming inconsistencies

## Problem

The framework reliability review found HIGH issue F-038: `.svc` active state contains stale completed-file naming inconsistencies.

## Evidence

`.svc/lane-tasks-WI-134.completed-52.json`, `.svc/lane-tasks-WI-137.completed-53.json`, and `.svc/lane-tasks-WI-139.completed-54.json` have filenames saying completed while top-level JSON status is `pending`.

## Impact

File-name based scripts and human scans will disagree with JSON content.

## Proposed Fix

Add a lane-tasks filename/status parity validator and migrate completed archives to a separate directory.

### Resolution

Completed lane-task archives no longer live in the active `.svc` root, and the
archive filenames now agree with the top-level JSON status.

### Changes

- Moved legacy completed lane-task archives into
  `.svc/archive/lane-tasks/`.
- Corrected `WI-134`, `WI-137`, and `WI-139` archive JSON from top-level
  `status: pending` to `status: completed`; their task entries were already
  completed or skipped.
- Renamed `WI-SPINE-001` from a misleading completed filename to a blocked
  archive filename and added top-level `status: blocked`.
- Added `test-framework/evals/tier-1/validate-lane-tasks-archive-parity.sh`
  to block completed archives in the active root and enforce archive
  filename/status parity.
