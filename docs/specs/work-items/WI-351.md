# WI-351: Stop hooks session-isolation for parallel execution safety

## Problem

Under the current Serious Vibe Coding (svc) hook model, the stop hooks (`svc-stop-quality.js` and `svc-task-completion-guard.sh`) lack state isolation across concurrent sessions or hosts operating on the same repository directory. Specifically:

1. **Accumulator Crosstalk (`svc-stop-quality.js`):** The stop-quality hook accumulates edited file paths in a single, hardcoded shared file (`.svc/svc-edited-files.json`). When multiple concurrent sessions/hosts modify files in the same directory, their changes accumulate in this single file. When one session stops, it runs type-checking and formatting against *all* accumulated files and clears the shared file, leaving other sessions without their edited file lists.
2. **Task Graph Crosstalk (`svc-task-completion-guard.sh`):** If the environment variable `SVC_WORKER_WI` is not set, the completion guard aggregates and scans *all* active `.svc/lane-tasks-*.json` graphs. If one session has pending tasks, it blocks *all* sessions/hosts on the repository from stopping.
3. **Session Contract Race Condition (`svc-task-completion-guard.sh`):** The completion guard reads the very last line of `.svc/session-contract.jsonl` to check the execution mode and WI. When two sessions run concurrently, whichever session started last overwrites the context of the other, causing the first session's stop hook to mis-resolve its execution mode, WI, and intent.

## Impact

* **High Friction:** Concurrent agents/sessions block each other from stopping, run quality checks on unrelated files, and suffer from state pollution.
* **Flaky Checks:** Sessions fail formatting/typechecks for files they did not edit, or bypass required quality checks entirely when another session clears the accumulator file.
* **Multi-Host Failure:** Prevents reliable parallel development across different terminals, subagents, or hosts (e.g. Claude Code + Gemini CLI + Codex CLI concurrently).

## Fix

We will implement robust session isolation in Stop hooks:
1. **Session-Specific Accumulator:** Update `svc-stop-quality.js` to write to a session-specific accumulator file (e.g. `.svc/svc-edited-files-<session_id>.json`). Resolve `session_id` from the hook payload or host-specific environment variables.
2. **Session-Bound Completion Guard:** Update `svc-task-completion-guard.sh` to resolve the active `session_id` and match it against the exact starting entry in `session-contract.jsonl` to find the correct active WI and execution mode, rather than blindly reading the last line of the file.
3. **Branch-Name Fallback:** Provide a fallback to parse the work item ID from the current git branch name if no matching session contract is found.
4. **Task Filtering:** Ensure the completion guard only checks the task graph corresponding to the resolved active WI, rather than aggregating all active task graphs.
5. **Tier-1 Regression Test:** Add a test verifying session isolation across concurrent synthetic session hook triggers.

## Acceptance Criteria

- [x] `svc-stop-quality.js` writes to `.svc/svc-edited-files-<session_id>.json` and performs format/typecheck checks only against files edited in that specific session.
- [x] `svc-task-completion-guard.sh` resolves the `session_id` from hook payloads or env vars, and uses it to locate the matching starting session contract entry to determine the active WI and execution mode.
- [x] `svc-task-completion-guard.sh` filters the checked `.svc/lane-tasks-*.json` graphs to only include the active session's WI (or parent/deps) when a session is active.
- [x] Hooks fallback gracefully to branch-name parsing or fail open if the session is detached or anonymous.
- [x] A dedicated Tier-1 regression test `test-framework/evals/tier-1/validate-stop-hook-session-isolation.sh` checks concurrent session hook isolation.
- [x] All Tier-1 validators pass cleanly on the repository.
