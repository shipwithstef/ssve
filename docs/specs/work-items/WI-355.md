# WI-355: Persona Trace Evidence Gate Across Feature Artifacts

## Problem

WI-354 and the earlier persona coverage task-graph gate prevent a feature-class
WI from omitting persona coverage entirely. They do not fully prove the personas
were used downstream. A feature can still carry `build-personas` while the spec,
journeys, UX/UI, technical design, implementation plan, E2E, and feature
validation ledger only say `customer`, `admin`, `all users`, `PASS`, or
`satisfied`.

That is too weak for product-sensitive feature work. Reviewers need to see which
persona created the AC pressure and which journey/test protects it.

## Acceptance Criteria

- [x] Feature closeout ledger validation fails when `Persona(s)` contains only
  weak status/generic text such as `PASS`.
- [x] Feature closeout ledger validation passes with concrete persona ID
  evidence such as `P2`.
- [x] Feature closeout ledger validation passes with concrete persona path
  evidence such as `docs/specs/personas/P2.md`.
- [x] System-only ACs can still use an explicit `N/A - ...` reason.
- [x] Producer skills instruct agents to carry Persona Trace through spec,
  journey, UX, UI, tech design, planning, E2E, and review.
- [x] Tier-1 regression coverage proves the validator behavior.
- [x] Framework state and capability docs record the new gate.
