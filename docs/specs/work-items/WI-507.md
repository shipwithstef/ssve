## Problem

The company operating fleet currently assumes a repository-local `company-state/`, exposes only decision and outcome commands, and names a legacy subset of operator roles. Product repositories therefore cannot safely resolve a parent company state, SessionStart cannot provide a bounded company briefing, and promoted Work Item knowledge is not indexed for later sessions. The framework also lacks portable diagnostics for cross-worktree topology, sibling-app contract drift, and Playwright failure classification.

The correction must remain universal. Framework source and installed hooks must not contain a company name, owner identity, or fixed repository path. Concrete company topology belongs only in repository-local `.svc/company-link.json` and the parent repository's `company-state/apps.json`.

## Operating invariants

1. **Generic framework:** no company identity, owner identity, or product path is hardcoded in framework source, tests, skills, hooks, or manifests.
2. **Explicit resolution:** `--state-dir` wins; otherwise the nearest repository `.svc/company-link.json` resolves the parent; otherwise a local `company-state/` is used. Invalid links fail closed.
3. **Append-only operations:** open-item mutations append JSONL events under the existing company-state lock and atomic-write discipline. They never rewrite or silently discard a valid historical event.
4. **Backward compatibility:** legacy role names and existing decision ledgers continue to parse. The 15 canonical skill names are added without migrating old records.
5. **Immune Mesh is explicit:** peer review is required only for declared risk domains. The CLI never infers regulated or high-risk impact from prose.
6. **Promotion-only memory:** work-in-progress changes are not indexed. A memory entry requires the promoted commit, completed G7 evidence, and an idempotency key.
7. **Diagnostics are non-mutating:** topology, contract guard, and auto-healer inspect and report. Auto-healer never edits code, tests, specs, traces, or DOM snapshots.
8. **Session hooks fail open:** hook failures cannot block host startup. Briefing cache entries expire after 30 seconds and are keyed by canonical state path plus input freshness.
9. **Proposer-only brains:** skills may analyze and append reviewable cards; they do not send, pay, publish, deploy, sign, purchase, or contact third parties.
10. **Proof states stay distinct:** locally implemented, locally validated, merged, installed, and live-resolved are separate closeout claims.

## Canonical schemas

### `.svc/company-link.json` v1.0.0

```json
{
  "schema_version": "1.0.0",
  "company_repo": "/absolute/path/to/parent-repository",
  "app_id": "repository-stable-id"
}
```

`company_repo` must resolve to an existing Git repository containing `company-state/`. Unknown keys are rejected. `app_id` is required for product repositories and may equal the parent app's registry id when the link is self-referential.

### `company-state/apps.json` v1.0.0

```json
{
  "schema_version": "1.0.0",
  "apps": [
    {
      "id": "repository-stable-id",
      "repo_path": "/absolute/path/to/repository",
      "owner": "repository-local-owner-label",
      "status": "active",
      "contracts": [{"name": "company-state", "path": "company-state/SCHEMA_VERSION"}]
    }
  ]
}
```

Application ids and canonical repository paths are unique. Status is `active`, `paused`, or `retired`; contract paths are repository-relative regular files. The framework validates this schema but supplies no company-specific values.

### Open-item event model

The existing `company-state/open-items.jsonl` append-only model is authoritative. A create event carries `id`, `ts`, `front`, `owner`, `direction`, `title`, `opened`, `sla_days`, `due`, `next_check`, `ref`, `checklist`, `priority`, and `status`. Later events for the same id may carry only changed fields plus `ts`. Materialized state is a deterministic, ordered merge by id. `open`, `checking`, and `closed` are the allowed states; legacy records remain readable.

### Immune Mesh declaration

Decision cards may add `risk_domains` and `peer_reviews`. Declared domains map to independent reviewers: `finance` → `fin-analyst`, `legal` → `counsel`, `security` → `security-ops`, `privacy` → `privacy-dpo`, and `reliability` → `infra-sre`. Each required reviewer must differ from `proposed_by`, supply `pass`, `concern`, or `block`, and cite evidence. Missing reviews or any `block` reject append; cards without `risk_domains` retain legacy behavior.
