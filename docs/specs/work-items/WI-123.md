## Problem

WI-116 added 5 new lifecycle hooks (`svc-session-start-healthcheck`,
`svc-prompt-stale-state`, `svc-pre-compact-snapshot`, `svc-session-end-log`,
`svc-notification-surface`) wired into `hooks/hooks.json` (Claude Code's
config format) but NOT into the per-host wire scripts. Result: Kimi, Codex,
and Gemini sessions never see the new coverage.

WI-114's G-4 hook (`svc-skill-artifact-authenticity`) lives in
`hooks/hooks.json` but isn't enumerated in `scripts/wire-hooks.mjs`, so the
cross-host gate validator (`validate-cross-host-hook-conformance.sh`)
records it as "no MUST host". The hook is real; it just wasn't visible to
the validator.

There is also no validator-time guard against stale references to renamed
or missing hook scripts (the WI-072 `.js → .mjs` rename hit this in the
past).

## Scope

### In scope
- Add Claude wire entries for G-4 + the 5 R-1 lifecycle hooks in `scripts/wire-hooks.mjs`
- Add Kimi wire entries for the 5 R-1 hooks in `scripts/wire-kimi-hooks.mjs` (invoked via `node`, since the .mjs hooks are host-agnostic)
- Add Codex wire entries for the 2 R-1 hooks Codex actually supports (SessionStart, UserPromptSubmit) in `scripts/wire-codex-hooks.mjs`
- Add Gemini wire entries for the 4 R-1 hooks Gemini actually supports (SessionStart, SessionEnd, PreCompress, Notification) in `scripts/wire-gemini-hooks.mjs`
- Promote G-4 to `must_hosts: ["claude"]` in `references/canonical-gates.json`
- Add 5 new gates (one per R-1 lifecycle hook) to `references/canonical-gates.json` with claude=MUST and per-host MAY/SKIP per actual host capability
- New tier-1 validator `validate-hook-scripts-loadable.sh` that `node --check`s every script referenced from `hooks/hooks.json`

### Out of scope
- Porting G-4 to Kimi/Codex/Gemini (left as MAY)
- Porting svc-prompt-stale-state to Gemini (Gemini has no UserPromptSubmit event)
- Codex parity for PreCompact/SessionEnd/Notification (host-side feature gap)
