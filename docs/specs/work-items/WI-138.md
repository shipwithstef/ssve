## Goal
Tighten the four medium/low edge cases that survived G5 review on WI-134 — none blocked landing, but all are real gaps in Strategy 3's terminal self-heal contract.

## Context
WI-134 shipped Strategy 3 (filesystem-scan terminal fallback in `detectRepoRoot()`) and closed the 5-WI worktree-symlink-rot recurrence family. G5 review (Codex Tier-2 cross-review) surfaced 4 findings that were correctly classified as non-blocking but are real edges around the core fix. Bundled here so they ship as one coherent hardening pass rather than four trickling WIs.

## Hypothesized Value
Tighter Strategy 3 contract → fewer "almost-self-heal" edge cases for any contributor with a non-default install layout (multiple clones, `SVC_REPO_SEARCH_PATHS` set, macOS BSD `find`, etc.). Beneficiary: every framework user, especially those onboarding the framework on a non-Linux/non-WSL host or running multiple clones for testing.

## Broad Scope
Four discrete tightenings, all in `hooks/svc-session-start-healthcheck.mjs` + the two T2/T3 validators:

1. **G5-015 (medium):** `SVC_REPO_SEARCH_PATHS` semantic — currently it ADDS roots to the default `~/app-workspaces` pool and tie-breaks by mtime across the union. Better: when set, treat as override-only roots (skip the default).
2. **G5-016 (low):** `find -maxdepth` portability. Replace `execSync("find ...")` in `scanForCanonicalRepo()` with a Node `readdirSync` traversal, and make T2 fail-loud (not silent zero-scan) when `find` itself errors.
3. **G5-017 (medium):** T3 (`validate-self-heal-survives-double-dead-pointer.sh`) safety-contract overclaim. Comment says "backs up live install state"; reality is it only restores `.source-repo` + `scripts` symlink. Either rewrite the comment to be precise OR run the test against an isolated `$HOME` so collateral state is contained.
4. **G5-018 (low):** Strategy 3 shell-interpolates `SVC_REPO_SEARCH_PATHS` paths into `execSync("find ...")` — narrow injection surface (user-self-trust boundary), but cleaner to switch to `spawnSync("find", [root, …])` or do the scan in Node.

Coupling note: items 2 and 4 both go away if `scanForCanonicalRepo()` is rewritten in pure Node (`readdirSync` + `lstatSync`). Worth doing as one refactor.
