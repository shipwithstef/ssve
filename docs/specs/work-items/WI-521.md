## Problem

WI-512 landed the one-lane cluster, and its own fresh-context global review found the result honestly: **the machinery ships promises, not enforcement.** `stage-activation.mjs` is invoked by nobody. `branchIndexFresh()` has zero callers. An empty genesis index is permanently GREEN. Four separate stage vocabularies exist with no mapping between them. `land-changeset` verifies none of it.

Two deliverables close that gap.

**1. The stage-receipt spine.** svc has per-commit chain receipts (`plan-manifest → review-plan → exec-record → review-exec → audit-implementation`, git-notes-backed, push-gated). The ported `audit-feature`/`align-feature` skills describe a *second*, per-WI-stage receipt model — with no validator in this repo and no relationship to the first. This WI makes the second one real and states the boundary between them explicitly: **two granularities, explicit roles, no merge.** One canonical stage registry, the example-marketplace validator ported and parameterized, per-WI receipts seeded at genesis, stages materialized as the harness task pile with conditional add/remove, and one hash cross-link so forging either side alone becomes detectable.

**2. Branch-index effectiveness.** The owner's bar, stated plainly: *"build context and know it changed, without losing 3 hours in bullshit."* The index must be cheap to author (script-derived, not hand-walked), cheap to read (size-bounded), impossible to silently trust when stale (CLI check with exit codes, citations required, sidecar committed), and wired into gates so no agent has to remember any of it. Today **none of the loop's 8 links closes.**

## Invariants

1. **No embedded fallback stage list.** The validator loads stages from the registry or exits 2. A fallback copy would be a second drift-prone vocabulary — the exact G4 disease this WI exists to cure.
2. **The `stages` array order IS the canonical stage order.** Nothing else defines ordering; `blocked_by` chaining and validator print order both derive from it.
3. **Essential stages stay exactly** `plan, review-plan, implement, review-exec, spec-sync, index-restamp`, and the essential-fence `exit 2` survives the re-basing.
4. **The two receipt systems are NOT merged.** Chain receipts stay per-commit and push-gated; story receipts stay per-WI-stage; exactly one hash cross-link.
5. Story-receipt land gate is **phase-in**: if the receipts file exists it must exit 0; if absent, WARN — legacy WIs are not retroactively blocked.
6. Exit codes of the ported validator are unchanged (0/1/2); `--json` is additive.
