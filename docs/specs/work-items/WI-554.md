# WI-554: Centrally installed check-chain-receipts must verify reviewer evidence against the consumer repo

**Type:** framework bugfix
**Status:** in_progress
**Severity:** critical
**Filed:** 2026-08-21
**Source:** HoursHub live cutover — ordinary `check-chain-receipts` against consumer SHAs failed when the centrally installed checker resolved evidence under the framework object store
**Lane:** framework
**Related:** WI-547, WI-549, WI-550
**Depends on:** —
**Follow-up:** —
**estimated_minutes:** 90

## Goal

When `scripts/check-chain-receipts.mjs` is invoked from a centrally installed
framework copy against a consumer repository, schema-v3 `review-plan` /
`review-exec` evidence must resolve against the **invocation/consumer** Git
root (`repoRootForCache()`), not `join(SCRIPT_DIR, "..")` (the framework
checkout that owns the script bytes).

## Boundaries

In scope: the `verifyReviewerEvidence({ root })` call inside
`validateReceipt` for schema_version >= 3 review receipts, plus a tier-1
regression that runs the real checker from a separate consumer repo.

Out of scope: new CLI flags, retroactive-attestation root selection,
framework-only WI-472 backlog paths, unrelated receipt-identity work (WI-550).

## Acceptance Criteria

- [ ] AC-554-1: `verifyReviewerEvidence` is called with `root: repoRootForCache()` (not `join(SCRIPT_DIR, "..")`).
- [ ] AC-554-2: A centrally executed checker with cwd = separate consumer repo accepts valid consumer-local reviewer evidence for `execute-changeset`.
- [ ] AC-554-3: The same path rejects candidate digest tampering / mismatch.
- [ ] AC-554-4: Focused tier-1 plus existing `validate-reviewer-run-evidence.sh` and `validate-svc-reconcile-consumer-routing.sh` pass.
- [ ] AC-554-5: After land, ordinary checks for the five HoursHub cutover SHAs pass with `GIT_ALTERNATE_OBJECT_DIRECTORIES` and `SVC_REVIEW_EVIDENCE_STORE` unset.
