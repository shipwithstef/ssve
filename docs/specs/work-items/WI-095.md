# WI-095: Hard Close-Out Gate — Runtime Verification Required Before WI Done

**Type:** feature
**Status:** VERIFIED (v1 framework-lane gate)
**Closed:** 2026-04-24
**Severity:** high
**Filed:** 2026-04-24
**Source:** capture-idea (from /insights friction analysis)
**Lane:** framework
**Scope note:** v1 lands the framework-lane close-out gate as a tier-1 validator (`validate-wi-closeout-evidence.sh`) backed by `scripts/verify-wi-closeout.mjs`. The product-lane additions — Playwright-on-prod-URL + bundle-hash check — are deferred to a follow-up WI that depends on WI-097 (browser-verify doctrine + compact wrapper), because running raw Playwright without a token-conscious wrapper regresses session economy.

## Goal
A WI cannot be marked done unless runtime verification ran and passed: prod E2E green OR Playwright check on live URL within the last N minutes, with evidence committed to the WI folder.

## Context
Across at least 5 recent sessions (WI-077, WI-081, WI-073, WI-076, WI-065), the orchestrator declared completion on faulty reasoning, the user pushed back, and the work had to be redone. This is the single highest-leverage friction in the pipeline.

## Hypothesized Value
Eliminates the premature-completion failure mode at the source. Costs one extra verification step; saves one full-cycle revert per occurrence (and the trust hit).

## Broad Scope
- Block the WI close-out action (in `verify-promotion` / `land-changeset` or wherever close happens) until evidence is present:
  - Bundle hash check confirms deploy completed, AND
  - At least one E2E spec passed against production URL within last N minutes (configurable, default 5), with screenshot/transcript committed to the WI folder.
- Refuse to close + surface what's missing if either is absent.
- "Completion claim audit" sub-step: re-read original ACs and confirm each has a corresponding passing test before allowing close.
- Override path requires explicit user decision logged to `.svc/pipeline-decisions.jsonl` as `taste`.

## Persona Fit
Framework operator.
