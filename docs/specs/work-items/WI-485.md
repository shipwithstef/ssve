## Problem

Codex derives continuation and skill authenticity from shared/fallback repository state rather than exact current-session authority. A live Stop hook tried to continue another session's WI-479, and the installed Codex skill loader points to a Kimi-only script that exits on Codex.

## Affected Files

- Codex hook configuration and setup, prompt-authority/skill-load receipt helpers, and Stop/mutation guards
- Installed-state diagnostics and Codex-specific fixtures listed in the WI-485 manifest

## Acceptance Criteria

- [x] **AC-485-1:** The recorded foreign WI-479 incident allows Stop and emits no continuation prompt.
- [x] **AC-485-2:** Only an explicit binding for the current session and current turn, or a route binding created in that same session/turn after the prompt-authority record, can authorize Codex continuation.
- [x] **AC-485-3:** Fresh foreign claims cannot be resumed or stolen by Stop or plain `continue WI-N`.
- [x] **AC-485-4:** Governed Codex mutations fail before an exact skill-load receipt and pass after it.
- [x] **AC-485-5:** Foreign-session, wrong-task, wrong-worktree, and wrong/stale-hash receipts fail; later turns in the same unchanged task/session remain allowed.
- [x] **AC-485-6:** Canonical `apply_patch` payloads and actual `docs/plans/` artifact paths are covered.
- [x] **AC-485-7:** Non-Codex source, registry/dry-run, installed-config, and fixture hashes remain unchanged.
- [x] **AC-485-8:** Setup distinguishes configured, effective-single-Stop, trusted, and runtime-observed hook states.
- [x] **AC-485-9:** Documentation states PreToolUse limitations and preserves post-action validation.
- [x] **AC-485-10:** No raw prompt text or secret is persisted in authority or skill receipts.

## Route recommendation

Urgent first pillar. Create lazily from current `origin/main`; full mandatory chain. Runtime proof requires one deny, one allow, and one foreign-Stop allow trace after `/hooks` trust review.
