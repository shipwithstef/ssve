# WI-112 — External-state lifecycle thinking gate

**Status:** VERIFIED
**Lane:** framework
**Created:** 2026-04-25
**Closed:** 2026-04-25
**Branch:** wi-112-external-state-lifecycle
**Merge commit:** 530a6d6 (PR #25)

## Problem

Today's WI-111 caught an implementation bug (`./setup` run from a worktree
repointed 79 host symlinks → cleanup left them dangling) AFTER the fact, by
breaking every Stop hook and PreToolUse hook in the user's session. The
framework's plan-changeset, review-plan, review-gate, and audit-implementation
flow inspected only source artifacts and never asked: *"what state outside
this artifact does this change touch, and what happens to that state when the
artifact's lifecycle ends?"*

The user articulated the generalization:
> "there should be a generic type of error that was made in the design and
> planning and review that was not checked, a specific type of generic
> wrapper question to lead to this type of thinking, a specific check was
> missed."

This WI installs that generic wrapper at the framework level so the same
class of failure (regardless of variant) is caught at plan/review time.

## Scope

Three changes, no scripts:

1. **NEW** `references/external-state-lifecycle-protocol.md` — the wrapper
   question, the 15-environment taxonomy, the finding-type spec, and a
   "Lessons" log that grows the taxonomy when new environment classes
   surface in real failures.

2. **NEW** AP-30 in `references/anti-patterns.md` — concrete anti-pattern
   entry pointing at the protocol doc, with the WI-111 incident as the
   load-bearing example.

3. **CONTRACT CHANGE** `plan-changeset/SKILL.md` — adds a MANDATORY
   `## External State Lifecycle` section that requires every manifest to
   include a populated table covering the taxonomy walk. Empty section is
   invalid.

4. **CONTRACT CHANGE** `review-plan/SKILL.md` — adds Step 1.5 (mechanical
   external-state check) between existing Tier 1 and Tier 2. Five mechanical
   sub-checks with HIGH-severity finding type `external-state-uncoupled`.
   Runs before any model is invoked.

### Out of scope

- Scripts (e.g. an automated diff-vs-section verifier). Step 1.5 prescribes
  the checks; an automated implementation can follow as a v2 WI once
  rollout shows the manual checks are stable.
- Extending review-gate and audit-implementation. Same rationale — start
  with plan-time enforcement; reviewer-time enforcement is layered later.

## Acceptance criteria

1. `references/external-state-lifecycle-protocol.md` exists with: wrapper
   question, 15-row taxonomy, finding-type spec, plan-time section format,
   Lessons table seeded with WI-111 → WI-112 entry.
2. `references/anti-patterns.md` contains `## AP-30: External State
   Uncoupled from Artifact Lifecycle` referencing the protocol doc.
3. `plan-changeset/SKILL.md` contains a new `## External State Lifecycle
   (MANDATORY)` section between `## Manifest Contents` and `## Review
   Surface`.
4. `review-plan/SKILL.md` contains a new `### Step 1.5 — External-state
   coupling check` between Step 1 and Step 2.
5. `node scripts/lint-skills-manifest.mjs` exits 0.
6. All tier-1 evals pass.

## Risk

LOW — pure documentation + skill-contract change, no scripts touched.
Worst case: the new section is too detailed, planners cargo-cult it.
Mitigation: the taxonomy walk is explicit so cargo-culting still surfaces
the right environments.
