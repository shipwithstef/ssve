# WI-385: Risk-tiered receipt envelope (graded, re-derived from diff, fail-closed)

**Status:** in_progress (worktree wi385; tier derivation + mechanical cross-family fence + graded check-chain branch + validator built & verified — 10/10. DEFAULT-OFF: the reduction is dormant until `.svc/chain-policy.json` opts in with `risk_tiering:"graded"`)
**Lane:** framework
**Size:** L
**Stage:** S4
**Source:** flow-architecture audit (wf_e0063433), 2026-06-08

## Problem
Every non-exempt code commit pays the full 5-receipt envelope regardless of blast radius. `check-chain-receipts.mjs` is strictly binary (`REQUIRED_TYPES_FULL`=5 vs `QUICK_FIX_TYPES`=1; no middle tier; no `risk_tier` token in the enforcement path). Receipt history shows full ceremony repeatedly re-verifying low-blast changes (≤2 INFO/MEDIUM findings). `delivery_tier` is selected per-WI by the user and fully decoupled from the pushed envelope.

## Mechanism
Reuse the existing risk-flag/delivery_tier classifier (WI-320/297). Load-bearing new work = a GRADED pre-push receipt envelope: low tier = plan-manifest + exec-record + ONE consolidated cross-family review receipt; high tier = full 5 + mandatory Tier-3. The pre-push validator re-derives path/LOC/concern class from the actual commit diff and fails closed on tier mismatch.

## Mechanism (as built — DEFAULT-OFF)
A graded path added to the chain-enforcement core, gated behind a machine-local opt-in so the value-reduction is **dormant until deliberately enabled** (mirrors WI-383 measured-tiering default-OFF; on this machine `.svc/chain-policy.json` is absent → full-5 enforcement byte-identical):
1. **`scripts/derive-receipt-tier.mjs`** — `deriveTier(sha)` re-derives `low|full` from the commit's OWN diff (changed files + LOC + concern class); pure `classifyFiles(files,loc)` for hermetic testing. **Fails CLOSED to full** on infra/hot-path touch, runtime-invisible logic (not journey/E2E-exercisable), CRITICAL concern, LOC ≥ 150, empty/binary, or any error.
2. **`scripts/lib/cognitive-family.mjs`** — `familyOf(host)` (claude→anthropic, codex→openai, gemini→google) + `crossFamily`. The mechanical resolution behind the never-self-review fence.
3. **`scripts/check-chain-receipts.mjs`** — under the `risk_tiering:"graded"` opt-in AND a diff that re-derives to `low`, accepts `LOW_TIER_TYPES` = plan-manifest + exec-record + ONE consolidated review-exec; otherwise the full 5. The declared tier is NEVER trusted (re-derived from the diff); a declared-low/derives-full commit fails the full-5 missing check (fail-closed).
4. **mechanical cross-family fence** — the low-tier review-exec MUST carry `author_family` + `reviewer_family` and they must DIFFER (rejected wherever equal, both tiers). `scripts/emit-receipt.mjs` AUTO-RESOLVES them from the actual review hosts (orchestrator = author, the USED adversarial host = reviewer), so the fence can't be forged.
5. **validator** — `test-framework/evals/tier-1/validate-receipt-tier.sh`.

## Acceptance Criteria (deterministic exit)
- [x] The low-tier "consolidated review receipt" MUST remain a real cross-family adversarial pass — NEVER author self-review. *(Verified: low tier requires review-exec with `author_family`≠`reviewer_family`; validator (c) proves a same-family low review is REJECTED.)*
- [x] review-exec carries `author_family` AND `reviewer_family` as mechanically-resolved fields; validator rejects `reviewer_family==author_family`. *(Verified: emit-receipt auto-resolves both from the real hosts; check-chain rejects equal families wherever present; validator (c)/(d).)*
- [x] Validator never trusts declared `risk_tier` — re-derives from the diff, fails closed. *(Verified: check-chain calls `deriveTier(sha)`; validator (e) proves a declared-low/infra commit needs full 5.)*
- [x] Runtime-invisible logic excluded from low tier regardless of LOC; concern-registry CRITICAL forces full tier. *(Verified: `classifyFiles` → full on any non-runtime-visible path or CRITICAL concern; unit assertions.)*
- [x] Exactly TWO non-quick-fix tiers (not a 4-tier SEV ladder). *(Verified: the classifier only ever returns `low|full`; unit assertion.)*

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-receipt-tier.sh`
- **failure_class:** the graded envelope failing OPEN — a value-reduction that lets a high-blast change land on the reduced (3-receipt) envelope, a forged/self-review consolidated review passing the fence, or the tier derivation trusting a declared token instead of the diff.
- **promotion_signal:** condition 3 — this is the chain-enforcement core (`check-chain-receipts.mjs`, the pre-push L3 gate); a fail-open regression lets unreviewed code through.
- **expected_runtime_budget:** <3s (pure-classifier unit + a temp-git-repo integration over the real check-chain; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** a value-reduction on the gate that decides how much review code receives is catastrophic and silent if it fails open; the fail-closed + mechanical-fence + default-off invariants must be re-proven every lint.

## Value-preservation
**⚠ VALUE-REDUCTION RISK — reduces ceremony.** Contained by: verify-promotion G7 + tier-1 + post-merge external-state scan run on ALL tiers; the surviving low-tier review is still cross-family adversarial. A compressed-tier miss is re-caught downstream against the real diff. Do not ship without the cross-family fence.

## Vision fit (whole-company / versatile PM)
