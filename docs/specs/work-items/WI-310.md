## Problem

The framework has background-agent and delivery-graph pieces, but no first-class skill contract for "handle these N work items in parallel" that plans waves, chooses transport, assigns disjoint file ownership, detects conflicts, and merges worker outputs back into the parent graph.

## Evidence

- `proposals/done/2026-04-14-parallel-wi-dispatch.md`
- Existing WI-125 provides detached Kimi execution infrastructure, but not a complete parallel WI wave contract.

## Acceptance Criteria

- [x] Add or extend a skill to accept a WI list and produce a parallel wave plan.
- [x] Document transport selection across subagents, detached Kimi, and local execution.
- [x] Require affected-file/dependency extraction before dispatch.
- [x] Add merge-back contract: worker summaries, changed files, validation evidence, conflict handling, and parent graph mutation.
- [x] Ensure hooks/task graph behavior works for multi-session waves and does not assume parent-session tool parity.
- [x] Add replay fixtures for parallel dispatch with conflicting and non-conflicting WIs.

## Closeout Evidence

Implemented the first-class parallel WI dispatch contract:

- `dispatch-waves/SKILL.md` accepts a WI list, plans conflict-aware execution
  waves, selects worker transport, assigns write ownership, and requires
  merge-back validation before parent graph mutation.
- `references/parallel-dispatch-transport.md` documents transport selection
  across `local-inline`, `subagent`, `detached-kimi`, and `headless-worker`,
  including the `SVC_SUBAGENT=1` file-state-only rule for worker sessions.
- `scripts/plan-parallel-wi-dispatch.mjs` extracts affected files, one-hop
  dependencies, shared config serializers, conflict graph, waves, ownership,
  transport, and dispatch blockers.
- `scripts/validate-parallel-merge-back.mjs` validates worker result JSON for
  summaries, changed files, validation evidence, clean worktree status,
  parent graph mutation, and conflict handling.
- `route-workflow` routes parallel/concurrent multi-WI requests to
  `dispatch-waves` before worker spawning.
- `skills-manifest.json`, `README.md`, `EXTERNAL_ADDONS.md`, and
  `route-workflow/references/routing-rules.md` include `dispatch-waves` in the
  routing-safe skill surface.
- `test-framework/evals/tier-1/validate-parallel-wi-dispatch.sh` replays
  non-conflicting waves, dependency conflicts, shared config serialization,
  unknown-scope blockers, 4-WI headless transport, valid merge-back, and
  out-of-scope changed-file rejection.
