# WI-303: Fix research skill global knowledge path resolution

## Goal

Prevent the `research` skill from writing global framework knowledge into the current project repository because relative `references/knowledge/...` paths resolve from `process.cwd()`.

## Problem

The May 10 proposal reports that `research/scripts/*` and `research/SKILL.md` rely on relative paths for the global knowledge base. When those scripts run from a project workspace, domain and competitor knowledge can be written under the project instead of the installed framework skill repository.

## Proposed Fix

1. Resolve the knowledge base relative to the script or installed skill path, not `process.cwd()`.
2. Add `SVC_KNOWLEDGE_DIR` as an explicit override.
3. Update `research/SKILL.md` so final git operations happen in the intended knowledge repository.
4. Add fixtures covering project-root invocation, skill-root invocation, and override behavior.

## Acceptance Criteria

- AC1: `research/scripts/` resolves the default knowledge directory from the skill/framework path.
- AC2: `SVC_KNOWLEDGE_DIR` overrides the default path.
- AC3: Running research helpers from an arbitrary project root does not create or update `<project>/references/knowledge` unless explicitly configured.
- AC4: `research/SKILL.md` documents the canonical knowledge path and git working directory.
- AC5: Tier-1 or focused smoke fixtures cover default and override path behavior.
