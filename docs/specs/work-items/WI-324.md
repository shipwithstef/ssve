# WI-324: Base44 schema-write guard for `coding/write`

**Type:** enabler
**Status:** VERIFIED
**Severity:** medium
**Filed:** 2026-05-11
**Source:** proposals/done/2026-04-25-deterministic-quality-hooks.md#G-5
**Lane:** framework
**Related:** WI-308, WI-312

---

## Problem

Direct `coding/write entities/...` calls can mutate Base44 schema or app-state
surface without a schema-change plan, rollback note, or probe evidence. WI-308
adds backend verification, but it does not yet guard ad hoc schema writes at the
Bash command surface.

## Evidence

- `proposals/done/2026-04-25-deterministic-quality-hooks.md#G-5`
- `references/knowledge/domains/base44/CAPABILITIES.md` documents the live
  `coding/write` round-trip requirement, but `svc-bash-guard` does not classify
  schema writes.

## Acceptance Criteria

- [x] Detect Base44 `coding/write` schema/entity mutations in Bash guard input.
- [x] Require a schema-change artifact or explicit logged override before the
      write proceeds.
- [x] Reuse WI-308 persistence/RLS probe evidence where applicable.
- [x] Add tier-1 fixtures for blocked ad hoc schema write and allowed planned
      schema write.

## Route Recommendation

Run after WI-308 so this guard can reuse the Base44 verification pack.

## Implementation

- `hooks/svc-workflow-guard.mjs` now detects Bash-surface Base44
  `coding/write` entity-schema mutations and blocks them unless the command has
  `SVC_BASE44_SCHEMA_WRITE_ARTIFACT=<repo-relative-path>`,
  `--schema-change-artifact <path>`, or an explicit
  `.svc/pipeline-decisions.jsonl` override with reasoning and approver.
- Schema-change artifacts must be repo-local and include rollback plus
  round-trip, persistence, RLS, probe, or WI-308 evidence.
- Function `coding/write` recovery remains allowed; the guard is scoped to
  `entities/*`.
- `base44-environment/SKILL.md` documents the enforced artifact/override
  requirement in the entity schema deploy flow.
