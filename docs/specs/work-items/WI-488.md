## Problem

Cross-model review selects a reviewer host without one mechanically consumed model/version/effort tuple or reproducible external invocation contract. This permits drift, invalid CLI syntax, accidental over-provisioning, unstructured output, hidden fallback, duplicate paid calls, and receipts that cannot prove the effective reviewer.

## Affected Files

- Adversarial reviewer resolver and Claude/Codex launchers
- Model-routing authority and cross-model review contracts
- Canonical external-review launcher and shared findings schema
- Reviewer-selection and invocation parity fixtures

## Required policy

- Claude review path: Codex 5.6 sol at **high**.
- Codex review path: Fable 5 at **high** when available.
- Fable-unavailable fallback only: Opus at **xhigh**.
- Higher settings require an explicit, receipted owner override.

## Acceptance criteria

- [x] Resolver emits and consumers enforce reviewer, exact model/version, effort, availability, fallback reason, and override state.
- [x] Codex 5.6 sol high and Fable 5 high are the normal effective tuples.
- [x] Opus xhigh activates only after a failed Fable 5 availability probe.
- [x] Missing Codex 5.6 sol on the Claude path hard-fails with a probe receipt and no model/effort substitution.
- [x] Default Fable xhigh/max and Codex effort above high are rejected.
- [x] Declared and actual CLI invocation tuples must match.
- [x] Alias version drift and forged/unreceipted overrides fail validation.
- [x] One canonical launcher consumes review packages through stdin and eliminates obsolete Codex `-p`/`--output-format` usage plus consumer-local direct calls.
- [x] Codex is explicit, read-only, ephemeral, user-config/rules isolated without losing `CODEX_HOME` auth, strict-configured, schema-constrained, and stream-separated; Claude is safe-mode isolated, OAuth/keychain-compatible, tool/MCP disabled, plan-permission, non-persistent, one-turn, schema-constrained, and timeout/budget bounded.
- [x] The primary invocation doubles as the availability probe; only classified Fable-5 model unavailable/model-entitlement/provider-overload results launch a separate Opus-xhigh fallback. Auth, shared subscription-quota exhaustion, network, timeout, and schema failures hard-fail without fallback.
- [x] Receipts include input hash, CLI/launcher/schema versions, requested/effective tuple, usage/cost metadata when exposed, exit classification, and fallback/override provenance.
- [x] A valid content-addressed primary receipt prevents duplicate paid review of identical inputs only when requested and effective tuple match and no fallback occurred; fallback receipts never satisfy later primary requests, and changed package, tuple, schema, or launcher version forces a new review.
- [x] Tier-1 uses fixtures rather than paid live calls and covers missing CLI capabilities with an actionable hard failure.
- [x] Codex and Claude provider attempts are timeout-bounded; a failed Opus fallback stops after exactly two total attempts.
- [x] The paid-action kill switch and empty-stdin boundary both emit receipts and make zero cache/provider calls.
