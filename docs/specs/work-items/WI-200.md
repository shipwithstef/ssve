# WI-200: Multi-PR verification sampling is not required

## Problem

The framework reliability review found HIGH issue F-030: Multi-PR verification sampling is not required.

## Evidence

The bundle-grep proposal defines deterministic N/3 sampling for campaigns at lines 75-79.

## Impact

Large parallel waves optimize for cheap text proof across all PRs and skip any real rendered proof.

## Proposed Fix

Add sampling to `verify-promotion` and make cumulative summaries list verification tier per PR.

## Acceptance Criteria

- AC1: The specific F-030 failure mode from the source review is fixed by a deterministic multi-PR campaign sampling contract in `verify-promotion/SKILL.md`.
- AC2: `test-framework/evals/tier-1/validate-verify-promotion-multi-pr-sampling.sh` proves the helper and contract, including deterministic order, first/middle/last inclusion, and 24-item N/3 sampling.
- AC3: `scripts/verification-sampling.mjs` provides the reusable deterministic sampler and `verify-promotion/SKILL.md` requires cumulative summaries to list `verification_tier`, `sampled`, and evidence paths for every campaign item.
- AC4: `bash test-framework/evals/run-all-evals.sh` passes with the WI-200 validator included.

## Closeout

Status: VERIFIED on 2026-05-11.

Implemented:

- Added `scripts/verification-sampling.mjs`, a deterministic SHA-256 sampler for multi-PR or multi-surface campaigns.
- Updated `verify-promotion/SKILL.md` so campaigns with `N >= 3` must sample `ceil(N/3)` items, include first/middle/last at minimum, require V1/V2 evidence for sampled browser-visible items, and list `verification_tier` plus `sampled` for every item in the cumulative summary.
- Added `test-framework/evals/tier-1/validate-verify-promotion-multi-pr-sampling.sh` to lock the behavior.

Validation:

- `bash test-framework/evals/tier-1/validate-verify-promotion-multi-pr-sampling.sh`
- `bash test-framework/evals/run-all-evals.sh`
