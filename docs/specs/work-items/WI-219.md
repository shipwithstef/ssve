# WI-219: Codify review-gate policy for framework-lane risk surfaces

## Goal

Make it explicit when framework-lane PRs must run `review-gate` before merge.

## Context

The audit found that framework-lane PRs introducing validators and framework enforcement relied on tier-1 and self-review, with no clear policy requiring `review-gate`. The ambiguity belongs in the lane model, not in agent judgment.

## Acceptance Criteria

- AC1: `route-workflow/references/lane-model.md` lane 7 states which framework changes require `review-gate`.
- AC2: Tier-1 validators, Stop hooks, and `hooks/` changes are explicitly listed as requiring review-gate.
- AC3: Low-risk references-only or fixtures-only framework PRs may skip review-gate only with a logged justification.
- AC4: Task-graph examples or docs show `metadata.skill: "review-gate"` for required review tasks.

## File Impact

- `route-workflow/references/lane-model.md`
- `route-workflow/SKILL.md` if the short hot-path summary needs a pointer
- Optional tier-1 check if policy becomes machine-enforced
