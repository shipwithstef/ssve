# WI-392: Intended-owner action-time guard (route tasks to their owning skill/app)

## Problem
The #1 MEASURED friction in the usage report is wrong-approach (11 occurrences): generic CLI deploys blocked by the permission classifier instead of the base44-environment skill; manual discovery work instead of the Novisenti app ("THIS FUCKING APP IS SUPPOSED TO DO THIS NOT YOU"); hung CLI/admin-token probing instead of Playwright browse mode. The framework has the right owners; it doesn't route to them at action time.

## Mechanism
A registry of task-class → owning skill/app (deploy→base44-environment, browser-verify→Playwright browse mode, per-project app owners via project `.svc/task-owners.json`), enforced at action time via the WI-361 injector (PreToolUse Bash signals — deploy/curl-against-app/discovery patterns inject "the owner of this task class is X — route through it") + an owner-resolution line in route-workflow P2.

## Mechanism (as built)
The AC reads "a REGISTRY enforced via the injector" — so owner mappings are registry ROWS (AC3), not rule files, and enforcement reuses the proven WI-361/WI-384 PreToolUse additive-injection mechanism via a dedicated sibling hook (mirroring WI-384's `svc-learning-inject`, keeping owner logic cohesive without adding project-file I/O to the single most safety-critical hot-path hook):
1. **`skills-manifest.json` `ownersRegistry.entries`** — one row per mapping (AC3): `{task_class, owner, owner_kind, message, signals:{bash[],paths[]}}`. Seeded high-precision: `deploy`→`base44-environment`, `browser-verify`→Playwright browse mode.
2. **`.svc/task-owners.json`** (per-project, exempt-class — AC2) — same row shape; a project row of the same `task_class` SHADOWS the global one entirely (shadow at load time, before signal eval — Codex G6 F3). Project signals are matched as **literal substrings** (never compiled), so an arbitrary project file can never inject a catastrophic regex into the hot path (Gemini G6: a regex heuristic is fundamentally bypassable, so the untrusted-regex surface is removed, not guarded).
3. **`hooks/lib/owner-index.mjs`** — `loadOwners` (manifest + project, fail-open, load-time shadow) / `matchOwners` (global=trusted regex behind a `safeRe` ReDoS guard + 2K input cap; project=literal substring; order-stable: project-first then task_class asc, deduped by class) / `renderInjection`.
4. **`hooks/svc-owner-inject.mjs`** — PreToolUse (Edit|Write|Bash): injects ≤2 owner reminders as `additionalContext` with `permissionDecision:"allow"` (never blocks — AC1), per-session memo dedup. Fail-open by construction (dynamic imports inside a guarded async `main()` + `main().catch` + `uncaughtException` → exit 0). *(New `hooks/svc-*` file placed under explicit user authorization past the config-protection guard.)*
5. **wiring** — `scripts/wire-hooks.mjs` + `hooks/hooks.json` register it; `.svc/perf-baseline.json` PreToolUse bumped 11→12 (deliberate WI-397 latency review).
6. **`route-workflow/SKILL.md` P2** — owner-resolution line so the owning skill/app is sequenced into the lane-task graph at routing time, not discovered after a blocked command.

## Tier-1 promotion note (rules/tier-1-promotion.md)
- **validator_path:** `test-framework/evals/tier-1/validate-owner-injection.sh`
- **failure_class:** the action-time owner injector silently DENYING/blocking a tool call (it must be additive-only), losing match determinism (same command → different/reordered owners), or failing to load the project `.svc/task-owners.json` shadow layer.
- **promotion_signal:** condition 3 — protects a framework hot path (a new PreToolUse hook on every Edit/Write/Bash, `rules/plan-changeset-trigger.md` signal 2); an additive→blocking regression would break every tool call.
- **expected_runtime_budget:** <1s (synthetic in-memory match + a few live hook spawns over a temp registry+project file; no network/LLM).
- **why_tier_2_or_targeted_is_insufficient:** the hook runs on every Edit/Write/Bash; an additive→blocking or non-deterministic regression is catastrophic and silent, so the additive-only + order-stable + fail-open invariants must be re-proven every lint.
