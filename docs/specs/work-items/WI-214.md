# WI-214: Enforce fresh session contract when lane task graphs are created

## Goal

Prevent multi-WI sessions from reusing a stale `.svc/session-contract.jsonl` entry when a new `.svc/lane-tasks-*.json` task graph is created.

## Context

The 2026-05-10 session audit found that WI-191 wrote a fresh session contract, but subsequent chained framework WIs reused that contract even as the active WI changed. This weakens the anti-drift binding that `route-workflow` depends on for intent alignment.

## Acceptance Criteria

- AC1: A mechanical guard fails or warns when a new `.svc/lane-tasks-WI-*.json` file exists without a session-contract entry referencing that WI in the last 60 minutes.
- AC2: The guard accepts either `bound_to: "wi-backlog"` or `bound_to: "user-request"` when the entry references the active WI.
- AC3: A tier-1 fixture covers pass, stale-contract fail, wrong-WI fail, and missing-contract fail.
- AC4: Documentation names the expected recovery action: write a new session-contract entry before dispatching the WI.

## File Impact

- `.svc/session-contract.jsonl` validation path
- `scripts/` or `hooks/` guard surface
- `test-framework/evals/tier-1/` validator and fixtures
- `route-workflow/SKILL.md` or `route-workflow/references/task-graph-protocol.md` if the recovery text needs clarification

### Resolution

Task-graph creation is now mechanically bound to a fresh session contract. `scripts/task-graph.mjs init` blocks creation of `.svc/lane-tasks-WI-###.json` unless `.svc/session-contract.jsonl` contains a matching WI entry from the last 60 minutes.

### Changes

- Added a session-contract guard to `scripts/task-graph.mjs init`.
- Required the task-graph path to match the WI id (`.svc/lane-tasks-<WI>.json`).
- Allowed fresh contracts bound to `wi-backlog`, `user-request`, or `framework-evolution`.
- Added `test-framework/evals/tier-1/validate-task-graph-session-contract.sh` with fixtures for pass, stale-contract fail, wrong-WI fail, missing-contract fail, and path mismatch fail.
- Updated `route-workflow/references/task-graph-protocol.md` to require writing the session contract before task-graph init and to name the recovery action.

### Evidence

- `bash test-framework/evals/tier-1/validate-task-graph-session-contract.sh` PASS (7/0).
- `node --check scripts/task-graph.mjs` PASS.

### Acceptance Criteria

- AC1: PASS — `task-graph.mjs init` blocks new WI task graphs without a matching fresh session-contract row.
- AC2: PASS — fixtures cover accepted `wi-backlog` and `user-request` bindings; `framework-evolution` is also accepted for framework backlog sessions.
- AC3: PASS — fixtures cover pass, stale-contract fail, wrong-WI fail, missing-contract fail, and path mismatch fail.
- AC4: PASS — task-graph protocol docs name the recovery action: append a new `.svc/session-contract.jsonl` row before dispatching the WI.
