# WI-320: Explicit route-workflow delivery tier declaration

**Type:** enabler
**Status:** VERIFIED
**Severity:** high
**Filed:** 2026-05-11
**Source:** OPEN-PROPOSALS.md FP-009
**Lane:** framework
**Closed:** 2026-05-12
**Related:** WI-198, WI-305

---

## Problem

Route-workflow can silently default to a compressed or fastest path instead of declaring whether a request is using full, compressed, rush, or end-to-end delivery. That lets validation depth become implicit, which is exactly how standalone skills can be skipped or weakened without a visible decision.

## Evidence

- `OPEN-PROPOSALS.md` FP-009
- Related end-to-end mode work exists in WI-198, but the open proposal remains specifically about explicit tier declaration at route time.

## Acceptance Criteria

- [x] Route-workflow records `delivery_tier` or equivalent in the task graph before dispatch.
- [x] The tier declares which validation skills are mandatory, skippable, or blocked behind explicit override.
- [x] Compressed/rush mode cannot be selected silently; it requires a decision-log entry and reduced-scope rationale.
- [x] Verify-promotion and closeout classification include the selected delivery tier.
- [x] Add a tier-1 fixture proving a feature-class request gets an explicit tier and cannot silently skip validation obligations.

## Route Recommendation

Implement with route-workflow and delivery graph compiler changes. Coordinate with WI-305 so full feature validation is the default for user-facing feature work.

## Notes

This is the routing-side companion to the feature validation ledger.

## Closeout

Closed 2026-05-12. Route-workflow delivery graphs now carry explicit
`delivery_tier` data before dispatch:

- `scripts/compile-delivery-graph.mjs` emits `delivery_tier.mode`,
  `selected_by`, `rationale`, `decision_log_ref`, and a validation policy that
  names mandatory skills, skippable skills, and validation blocked behind
  explicit override.
- `scripts/validate-delivery-graph.mjs` rejects missing delivery tiers, invalid
  tier modes, silent `compressed`/`rush` tiers, missing reduced-scope rationale,
  missing decision-log references, and tier policies that omit required skills.
- `scripts/classify-delivery-graph-closeout.mjs` includes the selected tier in
  closeout output and writes `closeout_delivery_tier` in `--write` mode.
- `route-workflow/SKILL.md`,
  `route-workflow/references/task-graph-protocol.md`, and
  `verify-promotion/SKILL.md` document the tier contract and closeout
  reporting requirement.
