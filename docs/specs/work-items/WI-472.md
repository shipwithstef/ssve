# WI-472: Deterministic bounded reconcile

**Type:** framework enforcement performance and strictness correction
**Status:** VERIFIED-L3 (headless framework; post-merge CLI behavior, receipt portability, mutation-red fixtures, and focused Tier-1 proof passed)
**Severity:** high
**Filed:** 2026-07-06; activated 2026-07-21
**Lane:** framework
**Parent:** WI-471
**Source:** `docs/analysis/framework-3x-proposals-2026-07-06.md` P1; owner activation and no-mass-waiver constraint on 2026-07-21

## Problem

`scripts/svc-reconcile.mjs` is an every-session and post-land gate, but its Git, GitHub, receipt-check, and auto-drive child processes are unbounded. Responsibility A starts one receipt validator per commit even though `check-chain-receipts.mjs --range` already exists. Responsibility B runs the full auto-drive verification synchronously and advances `last_pr_watcher_run` even when GitHub is unavailable or the drive dies. The result is both a throughput failure and a strictness hole: operators terminate the silent gate, while failed drives can fall out of the watcher window.

The existing checkpoint interval also contains a durable receipt backlog. The default checkout currently reports 72 unresolved commits, while portable notes-authoritative validation reports 78 because six envelopes survive only in a gitignored mirror cache. This WI must resolve that backlog through per-commit evidence and independent review, never through a blanket `AUDIT_EXEMPT` or `EMERGENCY_OVERRIDE`.

## Locked design

- Bound every Git, GitHub, receipt-check, and synchronous child call in reconcile to approximately 15 seconds and report timeout/degraded state explicitly.
- Batch Responsibility A onto one `check-chain-receipts.mjs --range <checkpoint>..<origin-main>` call. Retain the first-run last-five per-SHA behavior.
- Batch the pre-push receipt slot onto one range validation per pushed ref.
- Start auto-drive as a detached, lock-filed background job. It writes a durable atomic drive-outcome receipt; reconcile never adopts the child's exit status as its own.
- Advance the PR watcher cutoff only when GitHub was available and every candidate in the window is already verified or has a terminal durable drive outcome. A missing, running, timed-out, or failed drive keeps the cutoff unchanged.
- Preserve the refuse-mode blocking decision and user-visible verdict semantics.
- Resolve every backlog SHA through one reviewed ledger row and a distinct, tree-bound `retroactive-attestation` receipt. The attestation records the evidence and actual independent verdict without claiming that historical plan/review/exec/audit phases ran.

## Acceptance criteria

| ID | Acceptance criterion |
|---|---|
| RC-01 | Every child-process call in `scripts/svc-reconcile.mjs` has an explicit timeout no greater than 20 seconds; timeout and spawn failure produce structured degraded evidence instead of hanging or silently succeeding. |
| RC-02 | With an existing checkpoint, Responsibility A invokes `check-chain-receipts.mjs` exactly once with `--range`; first-run last-five behavior remains per-SHA; batch and legacy per-SHA result sets are identical over the live checkpoint interval. |
| RC-03 | `hooks/git/pre-push.d/10-receipts-complete` validates one range per pushed branch ref and preserves refuse/warn verdicts and notes-ref exclusion. |
| RC-04 | Reconcile schedules auto-drive detached behind an atomic per-SHA lock and durable drive-outcome receipt; duplicate preflights do not launch duplicate jobs, and reconcile does not wait for or mirror the child exit status. |
| RC-05 | `last_pr_watcher_run` advances only when `gh_available:true` and every candidate is covered by an existing verify-promotion note or terminal drive-outcome receipt; GitHub timeout, missing outcome, running job, or failed job leaves the prior watcher value unchanged. |
| RC-06 | OLD-vs-NEW golden verdict/output fixtures are byte-identical for five states: clean, unaccounted/warn, unaccounted/refuse, GitHub degraded, and merged-unverified; only new structured timing/drive metadata may be additive outside the locked legacy projection. |
| RC-07 | Five live preflights on the reconciled current interval have p95 below 10 seconds, and a simulated GitHub hang returns within 20 seconds without advancing the watcher. |
| RC-08 | Two Tier-1 validators cover timeout completeness and watcher-advance strictness, and each validator proves red against an intentional mutation before proving green on the implementation. |
| RC-09 | All 78 portable unresolved commits in `docs/specs/audit/wi-472-reconcile-backlog.json` reach a valid notes-authoritative receipt state through their reviewed per-SHA disposition; zero `AUDIT_EXEMPT` and zero `EMERGENCY_OVERRIDE` rows are added. |
| RC-10 | Default-checkout and fresh-worktree receipt checks return the same zero-unaccounted set after remediation; mirror-only success is impossible for the reconciled interval. |

## Evidence and review boundary

- Audit report: `proposals/2026-07-21-session-audit-wi-472-reconcile-backlog.md`.
- Machine ledger: `docs/specs/audit/wi-472-reconcile-backlog.json`.
- Every ledger mutation waits for `review-plan` approval.
- Every retroactive attestation basis and final note set is rechecked by independent `review-exec` and `audit-implementation` before landing.
- Any rejected row remains unresolved and keeps reconcile red; the implementation may not convert rejection into a waiver.

## Non-goals

- Do not weaken, remove, reorder, or tier down any plan/review/exec/audit/promotion gate.
- Do not implement WI-473 receipt-notes concurrency sync; WI-473 remains sequenced after this WI.
- Do not mass-copy envelopes without tree equality and schema validation.
- Do not claim a historical phase ran solely from a commit subject or PR title.
- Do not change host settings, install state, branch protection, or remote authentication configuration.
