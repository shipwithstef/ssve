# WI-394: Insights rule batch — never-fabricate + settings-write validation hook

**Status:** in_progress
**Lane:** framework
**Size:** S
**Stage:** S6
**Source:** Claude Code Insights report (2026-05-08..06-07), cross-checked 2026-06-08

## Problem
Two user-caught failure classes the report names: (1) Claude fabricated a payslip and a lawyer-document request and inflated capital/loan figures across multiple business-setup sessions, forcing repeated corrections; (2) an invalid `~/.claude/settings.json` schema write caused a live regression that made Claude refuse settings load in every other folder — caught by the user, not by any gate (framework-learning `host-settings-schema-live-verify-before-write` c9 exists but nothing mechanical enforces it).

## Mechanism
(a) A `never-fabricate-documents` rule: document contents / figures / external facts → mark TBD + ask, signal-gated on business/legal/document paths. (b) A PostToolUse validation hook on `~/.claude/settings.json` writes: `jq` parse + schema-shape check against a known-valid example (mechanizes the c9 learning). (c) Dedupe map of the report's 5 suggested CLAUDE.md additions vs existing svc rules (3 of 5 already covered: verify-state-before-context, long-output-to-file, owner-routing→WI-392).

## Acceptance Criteria (deterministic exit)
- [x] Negative fixture: a malformed `~/.claude/settings.json` write is REJECTED (jq+schema-shape) and the prior settings RESTORED from the WI-359 backup. — `scripts/svc-settings-write-guard.mjs` (PostToolUse Edit|Write) parses the on-disk file, shape-checks `skillOverrides`/`hooks`, and on violation copies back the newest `*.svc-backup-*` sibling then `exit(2)`. Proven by `validate-settings-write-guard.sh`: malformed-shape, invalid-JSON, and bad-enum fixtures each REJECTED (exit 2) and on-disk content == prior GOOD.
- [x] settings hook is machine-local config — paired with the backup+restore line per the learning (backup necessary but not sufficient). — The reject path emits the backup path + a `cp "<bak>" "<settings>"` restore command; the no-backup branch still rejects loudly, warns it cannot auto-restore, and does NOT clobber the bad file. Validator asserts both branches (AC2 checks). Live PostToolUse wiring in `hooks/hooks.json` is the machine-local config edit — deferred (protected file); see "Deferred wiring" below.
- [x] never-fabricate rule registered in `skills-manifest.json` rulesRegistry with signals. — Already satisfied by `rules/no-fabrication.md` (the never-fabricate-documents rule; notes cite the same insights-report payslip/lawyer-doc class). Registered as `auto_inject: signal` with `paths`/`bash`/`content` signals. Not duplicated (the no-duplicates validator + lint would block a second entry); validator AC3 checks assert exactly-one signal entry with signals.

## Deferred wiring (protected hot-path edit)
The guard ships as `scripts/svc-settings-write-guard.mjs` rather than
`hooks/svc-settings-write-guard.mjs` because `hooks/svc-*.{js,mjs}` and
`hooks/hooks.json` are protected hot-path globs in `svc-workflow-guard.mjs`
config-protection — a brand-new file there is hard-blocked under subagent
execution. The script is functionally complete and hermetically proven; the
remaining step to make it a LIVE PostToolUse hook is one additive entry in
`hooks/hooks.json` PostToolUse:
```json
{ "id": "svc-settings-write-guard",
  "description": "WI-394: PostToolUse on Edit|Write — shape-checks ~/.claude/settings.json after a write; on a malformed skillOverrides/hooks shape, restores the newest WI-359 *.svc-backup-* and blocks. Mechanizes c9 learning host-settings-schema-live-verify-before-write.",
  "matcher": "Edit|Write",
  "command": "node scripts/svc-settings-write-guard.mjs" }
```
This edit must be made by the landing orchestrator (the user/PR author who can
touch protected config), then `scripts/wire-hooks.mjs` installs it into the
machine-local `~/.claude/settings.json` (which the guard itself then protects).

## Tier-1 promotion note
- `validator_path`: `test-framework/evals/tier-1/validate-settings-write-guard.sh`
- `failure_class`: host-config corruption — a malformed `~/.claude/settings.json`
  write (wrong `skillOverrides` shape / invalid JSON) makes Claude refuse
  settings load in EVERY folder; a silent regression in the guard would
  re-open that fail-class.
- `promotion_signal`: signal #1 (observed ≥2×) + signal #3 (hot-path). The
  live regression is recorded in framework-learning
  `host-settings-schema-live-verify-before-write` (c9, WI-365) and named again
  in the 2026-05-08..06-07 Claude Code Insights report (source of this WI). The
  validator guards a host-wiring hot path: a break would let the c9 regression
  recur on every install/session that touches settings.
- `expected_runtime_budget`: < 1s (measured ~0.55s over 3 runs; hermetic — temp
  `SVC_SETTINGS_PATH`, no real `~/.claude`, no network, no LLM).
- `why_tier_2_or_targeted_is_insufficient`: the guard is the fail-closed half of
  a c9 learning whose other half (backup) already lives in the always-run
  install path (`wire-hooks.mjs`). Tier-2/targeted runs on demand; a settings
  corruption is silent and user-facing the moment it lands, so the guard's
  correctness must be asserted on every lint alongside the wire-hooks dedup
  validator (`validate-wire-hooks-variant-dedup.sh`) it pairs with.
