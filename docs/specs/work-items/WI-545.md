## Goal

Governed Grok (and Cursor) Stop adapters should be committed executable so
`svc-enforce` can run them without classifying a present file as dangling.

## Context

WI-542/WI-543 verify-promotion on host grok was interrupted by
`SVC-ENFORCE-HOOK-DANGLING` for `hooks/grok/svc-grok-task-completion-guard.sh`.
The file exists in the durable checkout. `bin/svc-enforce.mjs` requires
`runner === "bash"` hooks to be owner-executable. `classifySource` then
returns `dangling` for mode `100644`, and the denial receipt reports
`target_exists: false`. The receipt recovery (`./setup --host grok`) recopies
the same non-executable blob and does not fix it.

`git ls-tree origin/main` shows:

- `100644 hooks/grok/svc-grok-task-completion-guard.sh`
- `100644 hooks/cursor/svc-cursor-task-completion-guard.sh`
- `100755 hooks/kimi/svc-kimi-task-completion-guard.sh`
- `100755 hooks/svc-task-completion-guard.sh`

A session-local `chmod +x` on the default checkout unblocked Stop. That chmod
must not be committed on the WI-542 closeout branch.

## Hypothesized Value

Stop can run the completion guard after install without a hidden chmod. Grok
and Cursor match Kimi's adapter mode.

## Broad Scope

- Commit `git update-index --chmod=+x` on the Grok adapter and, if Cursor
  uses the same `svc-enforce` bash runner, the Cursor adapter.
- Make setup/wirer fail closed if a governed bash hook is not executable
  after materialize.
- Add a tier-1 check that every `svc-enforce` `runner: bash` relpath is
  `100755` in git.
