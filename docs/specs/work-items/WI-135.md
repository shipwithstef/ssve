# WI-135: Blend coreyhaines marketing skills v1.9.0 — adopt 4 architectural patterns, keep skills as external addon

**Type:** framework
**Status:** backlog
**Severity:** medium
**Filed:** 2026-04-28
**Source:** `proposals/done/2026-04-28-blend-coreyhaines-marketing.md` — extraction filed 2026-04-28 (commit 8c07b44).
**Lane:** framework

## Summary

Adopt 4 architectural patterns from the coreyhaines/marketingskills repo (v1.9.0 / 1bcff9f) into svc, while continuing to use the 40 marketing skills + 61 CLIs + 53 integration guides as an external runtime addon (not re-implemented inside svc).

The 4 patterns:

1. **"Before Starting" context gate** — convention so every skill reads existing context before asking questions. svc adapts to a 4-source chain (`docs/specs/project-state.md` → `~/.svc/builder-profile.md` → `docs/specs/domain-profile.md` → relevant feature spec), NOT a single file.
2. **Behavioral evals** in `test-framework/evals/tier-2/` — deterministic conversation→assertion format. Fills the gap between structural tier-1 and LLM-judge tier-3.
3. **Progressive disclosure convention** — core instructions in SKILL.md, depth in `references/*.md` loaded on demand. Convention for new skills + reinforcement for existing skills that don't follow it.
4. **Foundation marketing context** — `analyze-marketing` gains a canonical output `docs/specs/marketing-context.md` (svc-flavored path; the proposal suggested `.agents/product-marketing-context.md`). Must include explicit no-duplication coverage matrix vs `domain-profile.md`, `feature-mining-tracker.json`, and `personas/`.

## Why this is framework lane (not skipped or addon-only)

Per `rules/plan-changeset-trigger.md`:
- Pattern 1 changes the implicit contract for every skill (must read context before asking) → contract change.
- Pattern 4 modifies `analyze-marketing`'s declared `outputs.produces` → contract change.
- Patterns 2 and 3 are additive — would otherwise be skip-trigger eligible — but bundled with 1 and 4 for one coherent blend changeset.

## ACs

- AC-01 — `CONTRIBUTING.md` documents the 4-source context-loading chain and mandates a "Before Starting" section in every new SKILL.md.
- AC-02 — `_shared/before-starting.md` (or equivalent shared snippet) exists and is referenced from at least 5 hot-path skills (route-workflow, write-spec, plan-changeset, execute-changeset, validate-feature).
- AC-03 — `test-framework/evals/tier-2/behavioral/` exists with the conversation→assertion JSON format, runner script, and ≥3 example evals against pipeline-critical skills (route-workflow, write-spec, validate-feature).
- AC-04 — `references/skill-conventions.md` documents the progressive-disclosure rule (core in SKILL.md, depth in `references/*.md`); `define-code-style` or equivalent reviewer checks that new skills declared after this WI follow it.
- AC-05 — `analyze-marketing/SKILL.md` declares `docs/specs/marketing-context.md` in `outputs.produces`; the skill's process writes this artifact.
- AC-06 — `analyze-marketing/SKILL.md` includes an explicit no-duplication coverage matrix declaring what content lives in `marketing-context.md` vs `domain-profile.md` vs `feature-mining-tracker.json` vs `personas/`. No content overlap.
- AC-07 — `EXTERNAL_ADDONS.md` has a section for `coreyhaines/marketingskills` v1.9.0 with install command, integration points (analyze-marketing, validate-feature, find-opportunity, write-spec), and explicit list of what svc does NOT rebuild.
- AC-08 — Tier-1 validator (`test-framework/evals/tier-1/validate-skill-before-starting.sh`) exists and runs as part of `test-framework/evals/run-all-evals.sh --tier1`. Currently advisory (not blocking) for legacy skills; blocking for skills created after this WI lands.
- AC-09 — `references/framework-learnings.jsonl` records the blend completion with confidence 8 + the load-bearing decision rationale.
- AC-10 — Linter (`scripts/lint-skills-manifest.mjs`) keeps passing across the 5 source-of-truth files. No regressions in tier-1.

## Out of scope (explicit non-goals)

- Re-implementing the 40 marketing skills inside svc.
- Re-implementing the 61 CLIs or 53 integration guides.
- Refactoring all existing skills to adopt the "Before Starting" section in this WI (convention applies to new skills + 5 hot-path skills only; legacy refactor is a separate WI).
- Migrating tier-2 integration scenarios to the new behavioral format. Behavioral format SUPPLEMENTS, does not replace.

## Risk

- **MEDIUM:** Pattern 4 duplication risk if coverage matrix is sloppy. Mitigation = AC-06 explicit boundary table.
- **LOW:** Pattern 1 token regression if every skill reads all 4 sources. Mitigation = chain is read-as-needed, not read-all; documented in `_shared/before-starting.md`.
- **LOW:** Pattern 2 maintenance cost if behavioral evals proliferate. Mitigation = scope to ≥3 pipeline-critical skills initially; expand on demand.
