## Technical Design

### Architecture

Keep `scripts/resolve-dispatch.mjs` as the only owner-policy decision engine.
Adapters bind an exact WI and reviewed plan, request a resolved tuple, transport
that tuple without remapping, and write evidence that the guard revalidates
against the current policy. One executable Node helper with `bind-plan`,
`preflight`, and `verify-receipt` subcommands owns WI/review-log discovery and
dispatch-evidence validation so preflight and the guard cannot drift again.

```text
 plan manifest + branch                 protected owner policy
          |                                      |
          v                                      v
 +-------------------+                  +----------------------+
 | exact WI binder   |                  | resolve-dispatch.mjs |
 +---------+---------+                  +----------+-----------+
           |                                       |
           v                                       v
 +-------------------+    authorized     +----------------------+
 | matching review   |------------------>| exact EXEC tuple     |
 | terminal state    |                   | host/model/effort    |
 +---------+---------+                   +----------+-----------+
           |                                       |
           +-------------------+-------------------+
                               v
                    +-----------------------+
                    | dispatch worker/log   |
                    | exact tuple + exit    |
                    +-----------+-----------+
                                |
                                v
                    +-----------------------+
                    | pre-commit guard      |
                    | re-resolve + compare  |
                    +-----------------------+
```

### Data Model

No persistent application data changes. The existing JSONL dispatch receipt is
extended compatibly. New entries must contain:

```json
{
  "schema_version": 2,
  "ts": "RFC3339",
  "wi": "WI-...",
  "decision": "dispatch",
  "skill": "execute-changeset",
  "mode": "dispatch",
  "host": "grok",
  "family": "xai",
  "model": "grok-4.6",
  "effort": "high",
  "policy_sha256": "...",
  "review_log_sha256": "...",
  "duration_ms": 1234,
  "exit_code": 0
}
```

Legacy rows remain readable but cannot authorize a governed commit unless their
fields happen to prove the complete current tuple; missing WI/family/effort or a
nonzero exit therefore fails closed.
`duration_ms` is audit/FinOps telemetry and is not part of the guard's authority
comparison.

The existing explicit emergency override remains a separate
`decision: "owner-override"` path. It must bind the exact WI, accepted reason,
and successful exit in schema-v2 evidence. It never pretends to be an EXEC
tuple and cannot make a legacy override row sufficient. This changes no owner
approval semantics and is not used for WI-559 or the HoursHub execution.

### State Machine

```text
 UNBOUND
   | exact one WI + matching manifest/review log
   v
 REVIEW_BOUND
   | terminal_state in execution-authorized set
   v
 AUTHORIZED
   | resolve current owner-policy EXEC tuple
   v
 PREFLIGHTED
   | launch exact tuple
   +---------------------+
   | exit 0              | nonzero / timeout
   v                     v
 RECEIPTED_SUCCESS    RECEIPTED_FAILURE (terminal, cannot authorize)
   | recent + exact policy tuple + exact WI
   v
 COMMIT_ALLOWED

Any missing, ambiguous, mismatched, stale, or policy-invalid input -> DENIED.
DENIED never calls a review or execution provider.
```

### Data Flow

1. Review adapter reads the manifest's structured `Work item`/`WI` field and
   branch identity, normalizes `WI-[A-Z0-9]+(?:-[A-Z0-9]+)*`, and requires one
   exact value with no branch/manifest mismatch.
2. It invokes the external-review launcher with policy config plus only those
   mode/station options explicitly supplied by the owner. The launcher's
   resolver chooses the configured default mode and eligible station.
3. Execute preflight binds the requested WI to exactly one active plan directory
   and its review log, requires `PROMOTED`, `PROMOTED_WITH_DISPUTES`, or
   `REVISED_AND_REVIEWED`, and calls
   `resolve-dispatch.mjs model --label EXEC --wi <WI> --format json`.
4. Preflight emits one compact JSON line containing `decision`, WI, review-log
   path/hash, and exact resolved tuple/digests. Errors go to stderr and exit
   nonzero; there is no permissive `not-required` result for a governed WI.
5. The orchestrator invokes `dispatch-log.sh <resolved-host>
   execute-changeset @<payload>` with `SVC_WORKER_WI` set. Dispatch worker
   verifies the requested harness/model/effort against a fresh
   resolution. For Grok it executes `grok --cwd <worktree> --model grok-4.6
   --reasoning-effort high --permission-mode auto --no-subagents
   --disable-web-search --single <prompt>`.
6. Dispatch log appends the resolved fields and subprocess exit. The guard
   rebinds the staged WI/review log, re-resolves EXEC, and accepts only a recent
   (maximum six hours) row with the same WI, current review-log hash, policy
   digest, host/family/model/effort, skill, and `exit_code: 0`.

The guard retains its existing activation boundary (staged `src/` product
changes). Broadening enforcement to every possible repository layout is a
separate policy change; WI-559 corrects evidence identity once the existing
guard activates.

### External Dependencies

No new dependency. Node and Bash are already required. Grok CLI 1.0.5 is a
pre-existing installed host capability; current flag evidence is recorded in
`docs/specs/research-log.md`. Missing Grok or a changed incompatible CLI fails
before mutation with an actionable transport error.

### Technology Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Policy authority | Resolver-centric adapters | Removes duplicate defaults/cardinality/allowlists while preserving protected owner policy and overlays. |
| WI/review binding | Shared strict Node helper | One parser can test structured manifests, named WIs, ambiguity, mismatch, and exact review-log selection without fragile shell regex drift. |
| Preflight output | Compact JSON schema v2 | Exact nested tuple and digests are unambiguous and safe to parse; nonzero exits distinguish denial from dispatch. |
| Grok permissions | `auto`, no subagents, web disabled | Allows bounded implementation while retaining CLI permission enforcement and preventing unsanctioned parallel/web behavior. |
| Evidence enforcement | Re-resolve and re-hash review log at commit time | A once-correct but now stale policy tuple or superseded review cannot authorize later mutation. |

The ranked five-way alternatives are recorded in
`docs/specs/decisions/WI-559.md`.

### Cost Model

| Dimension | Unit cost | Expected volume | Monthly estimate | Scaling curve | Paid by |
|---|---|---|---|---|---|
| Local compute | sub-100 ms parsing/resolution per preflight/commit | tens per WI | negligible | linear | operator |
| Storage | one compact JSONL row per dispatch | under 2 KB/dispatch | negligible | linear | repository owner |
| Bandwidth | no added framework network calls | zero | $0 | constant | N/A |
| External API calls | exactly the already-configured review/build call | one per governed phase | no incremental calls | linear with WIs | repository owner |
| Background jobs | none | zero | $0 | constant | N/A |

Scaling trigger: at hundreds of thousands of dispatch rows, rotate/archive the
JSONL log; this is far beyond current volume. First-month and year-1 incremental
infrastructure cost are $0 because the repair removes failed provider retries
and adds only local parsing. Provider usage remains owner-policy controlled.

### Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Loose WI parsing accepts prose or partial token | Wrong plan/provider binding | Structured header first, anchored canonical token, set comparison, zero-call negatives. |
| Policy or review decision changes between preflight and commit | Wrong executor evidence accepted | Receipt binds policy and review-log SHAs; guard re-resolves/re-hashes and compares. |
| Shell quoting corrupts JSON/CLI args | Incorrect dispatch or injection | Node JSON parsing, argv arrays, no `eval`/`source`. |
| Legacy consumer expects `DISPATCH=sonnet` | Integration break | Update canonical skill reference and focused fixtures in same changeset; JSON is versioned. |
| Accepted emergency override is silently broken | Incident workflow blocked | Preserve it as an explicit schema-v2 owner-override decision, never as a fake resolved tuple. |
| Grok flag drift | Build unavailable | Verify installed CLI help in fixture/probe; fail closed, no unsafe substitute. |

### Trade-offs

| Trade-off | Chose | Over | Rationale |
|---|---|---|---|
| Strictness | Governed WI without authorized log exits nonzero | `not-required` permissive continuation | Missing proof must not authorize implementation. |
| Compatibility | Schema-v2 exact evidence | Treating old MiMo/Sonnet rows as sufficient | Security boundary outweighs permissive legacy reuse. |
| Abstraction | One small shared helper | More shell one-liners | Prevents another preflight/guard split-brain. |
| Rollout | Land/install then real consumer replay | Direct product workaround | Fixes all consumers and proves the original path. |

### Layered Review Findings

- [Layer 1] [Confidence: 10/10] The review adapter overrides the protected
  default and independently imposes exact-one station cardinality
  (`scripts/review-plan-codex.sh:42-65`); remove both policy decisions.
- [Layer 1] [Confidence: 10/10] Numeric-only WI extraction rejects the named
  consumer identity (`scripts/review-plan-codex.sh:67-85`); replace it with one
  strict shared binder.
- [Layer 1] [Confidence: 10/10] Preflight selects the first unrelated review log
  and the retired MiMo/Sonnet matrix (`scripts/execute-dispatch-preflight.sh:72-124`);
  bind the requested WI before resolving EXEC.
- [Layer 2] [Confidence: 10/10] The guard recognizes model-name substrings rather
  than owner-policy identity (`hooks/svc-execute-dispatch-guard.sh:69-102`);
  exact policy-digest and tuple comparison is required.
- [Layer 3] [Confidence: 9/10] A resolver-only unit test could stay green while
  adapters regress again; the original named-WI/multi-station/Grok path must be
  a single integration fixture and post-install replay.

### Rollback

Revert WI-559 as one changeset and reinstall the prior framework bundle. No
database or remote migration exists. Rollback restores the known-broken legacy
adapters, so product execution remains halted until a corrected replacement is
reviewed; receipts are never deleted.
