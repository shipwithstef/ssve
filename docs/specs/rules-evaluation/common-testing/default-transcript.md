## Pass 1 — Default behavior (no rule context)

**Scenario 1 — new feature:**
I recommend TDD (write test first) but I don't mandate it or refuse to implement
without tests. I'd suggest it, explain the benefit, and defer to project
workflow. I don't have a "MANDATORY" framing.

**Scenario 2 — test coverage:**
I recommend "good test coverage" and often mention 80% as a reasonable target.
But I treat this as a guideline, not a hard minimum. Projects vary.

**Scenario 3 — writing a test:**
I naturally use AAA structure (Arrange-Act-Assert) and descriptive test names
that describe behavior. I'd write tests with clear, readable names. This is
my default style.
