## Two-Box Planning

Run once before each substantive changeset conversion, across features, bugs, refactors, and framework changes. Keep the existing mechanically eligible lightweight path, required spec synchronization and proof; do not restore a separate quick-fix lane.

1. Open Box: fresh planner with original user requirements and read-only repository facts, without SSVE planning instructions, preferred solutions, competing drafts or inherited chat. Preserve real user constraints and host safety. Allow natural free-form planning; preserve the immutable original before normalization.
2. Contract Box: independently form a solution using applicable SSVE specs, designs, decisions and constraints. No Open Box output until both candidates exist.
3. Dual-Pass Re-exploration Narrowing: two inexpensive fresh scouts inspect ONLY the initial Contract Box plan. Harness assigns concrete roots and questions using the archetype/risk classification. Forward traversal follows requirements/entrypoints through behavior, state, dependencies and tests. Reverse traversal follows affected internals back to callers, consumers, lifecycle and regressions. Record coverage boundaries and cited findings; incomplete reads cannot be reported as complete coverage.
4. Revise affected Contract Box decisions, retaining its initial candidate. Fresh assessor selects Open, Contract, or a grounded combination by requirement coverage, feasibility, simplicity, operational effects and useful innovation. Neither model prestige nor framework convention automatically wins. Record evidence-backed dispositions and unresolved questions.
5. Reconcile consequential selected changes into authoritative specs/design decisions, then prepare implementation contract and formal review.

Reuse blind-control-plan as compatibility skill identifier; replace its old default-off post-manifest shadow route for new substantive plans, never run both. Existing historical results remain readable. No theoretical best-of-two quality guarantee.

## Deterministic Transmutation

The complete transition from a finalized solution to executable changeset: prepare the implementation contract for review, obtain the existing holistic review-plan verdict, then seal the reviewed contract into the executor handoff without unreviewed semantic changes. This is not an extra review loop or a new lane.

Contract: original ACs; intended behavior; implementation approach; architecture/interfaces/state ownership; material failure handling; exact task/file scope and dependencies; validation commands/expected proof; recovery; explicitly permitted local decisions. Preserve inline original-context bindings/generated views and full dispatch packets. Do not regress inline into duplicating all code at planning prices.

Executor decides reversible local details, repairs task-caused bugs and recoverable in-scope failures, and can challenge the approach with concrete evidence. An alternative that preserves consequential decisions and authority can be applied with justification and validation. Behavior/interface/architecture/dependency/write-authority/proof changes reopen only the affected decision and review lens before dependent execution. Reuse current user authorization; only genuinely unresolved owner decisions need questions. Never silently reduce requirements or blindly follow contradicted instructions. Align existing contradictory auto-fix/deviation language, including dependencies/configuration.

For each consequential uncertainty analyze locally, score confidence 1-10 with cited basis, and ask whether external information can resolve it. Explicit user research requests and necessary freshness verification remain honored. Freshly verified sources can resolve an external question without another network request. Unsupported memory of volatile facts cannot earn a high score. Return research only to its requesting decision and reopen affected work.

Remove blanket research insertion from delivery-graph compiler/validator, mandatory five-example floors, research-every-paradigm/every-implementation commands and contradictory downstream activations. Keep conditional research receipts honest: local-only analysis does not fabricate research completion. A missing confidence assessment is unknown, not sufficient evidence to skip or automatically dispatch research.

## Binding decisions after Cursor review (supersede underspecified earlier wording)

1. **Enforcement location:** keep the existing essential `plan` stage. Its pre-conversion phase invokes Two-Box once before P3 manifest mapping. Direct plan-changeset invocation, lane/compiler dispatch, stage-segment execution and issuance all require the same evidence. Update stage/segment/runtime contract metadata to carry control-plan, without adding a new lane or duplicate holistic review. The old dual_track toggle, infra/M+ heuristic and .svc/dual-track.off never exempt new substantive plans.
2. **Lightweight authority:** only the existing quick-fix-eligibility/classify-change-risk machinery may prove an actual eligible trivial diff. The file-count-only blind-floor shortcut is retired. Missing/prospective diff proof cannot exempt a substantive planning invocation. Keep its spec/proof obligations and retired-lane status.
3. **Isolation implementation:** continuation.fresh_session_launch is a different capability (resuming stage ownership), not proof of analysis-context isolation. Add an explicit `isolated_plan_analysis` capability for the planning transport, proven by fixtures and a live canary. Start with concrete existing Codex ephemeral/read-only/ignore-rules/ignore-user-config controls; support other configured transports only after equivalent controls pass. Use a frozen, contained neutral source view and stdin/file-backed prompt; do not call the existing review-package builder for Open Box because it always injects AGENTS/CLAUDE. Preserve necessary product facts. Known disallowed-methodology leakage makes Open Box ineligible and blocks selection pending an isolated rerun; inherently visible SSVE implementation concepts are declared as source exposure, not misrepresented as removal of all prior model knowledge. Unsupported isolation routes require an explicitly configured compatible transport, never a silent model switch or forged success.
4. **Receipt versions:** control-plan v1 retains its historical floor meaning; strict v2 means Two-Box and does not reuse floor_verdict. v2 requires WI/input/source bindings, immutable candidate refs and hashes, two assigned scout result/coverage refs, final selected solution and per-decision dispositions, role identity/provenance and nullable actual usage/cost. Its validator checks referenced content, not just shape. Plan-manifest v5 adds the bound planning/transmutation contract for new issuance, preserving v4 inline and v3 dispatch historical readers. The converter must specify the issuance epoch using the existing history-epoch mechanism and actual public base, plus replay rules; new commits cannot select old versions to evade the gate. No retroactive fabrication; no global historical all-receipts requirement without epoch qualification.
5. **No digest cycles:** prepare complete selected-solution and contract fields BEFORE review. Copy authoritative clauses and accepted decisions; derive mappings/views mechanically. Every consequential task/interface/scope/proof choice names its source decision; a missing choice returns to solution analysis instead of being invented during conversion. Review-plan covers that exact complete contract. Canonical semantic contract hashing excludes only defined envelope/self-digest fields; generated display views do not introduce authority. Existing review-plan receipt separately binds the reviewed plan; do not put a future review receipt hash inside the plan being reviewed. Seal verifies unchanged bindings and issues, never semantically regenerates a reviewed plan.
6. **Winning deviation rule:** a missing import referencing an existing approved dependency is local repair. A new/upgraded dependency, new config/env requirement, changed API or broadened files/authority is a consequential amendment. All other discretion follows the AC09 preserved-decisions test, not a blanket STOP/auto-fix keyword. Reopen affected decisions and proofs using prior owner authorization; only unresolved product/authority tradeoffs require owner input.
7. **Research consumer census:** converter builds a grep-derived inventory of active auto-research producers and validators, including write-spec, validate-feature, analyze-domain, execute-changeset, design-tech and explore-solutions. One shared predicate returns resolved/analysis_required/external_research_required from per-question evidence, score, external resolvability, explicit request and freshness. Missing assessment => analysis_required. Score 6 with external missing evidence => research; 7 with sufficient current evidence => no network. Explicitly requested external research capabilities remain intentional. Remove blanket examples/search quotas only where they force unsolicited research.
8. **Selected-solution coverage:** scouts cover Contract Box only. Open-win and combination packets preserve those limits. Formal review covers the complete selected implementation contract and changes from both original candidates, including Open-only decisions. Any unresolved consequential conflict blocks conversion; it cannot silently become a Contract win.
9. **Role keys and compatibility:** named optional role overrides are open_box, contract_box, scout_forward, scout_reverse and assessor, through the existing dispatch policy. Absent planning role overrides inherit the owner's resolved PLAN for authors/assessor and EXEC for scouts, with explicit provenance; user-configured role entries win. Actual executor continues using the configured EXEC contract. Use existing policy deny/allow/overlay precedence and reviewer authority. Recommendation recipes never mutate installed global policy. A role whose chosen transport lacks isolation fails explicitly before spend, independent of whether its model is generally available.
10. **Durable evidence and testing:** content-address candidate/context/scout/selection payloads through the existing durable evidence store and reference hashes in control-plan. Future worktree cleanup cannot remove required source proofs. Offline fixture results remain labeled; run one bounded real planning canary on an explicitly configured supported transport, and report what it does and does not prove. Do not launch a broad paid benchmark suite to claim superiority.
