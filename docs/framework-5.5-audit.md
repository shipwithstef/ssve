# Framework audit for 5.5-class models (2026-10-10)

**Question.** svc was built to force behaviour that weaker models skipped. The main workforce is now Claude Opus 5.5, with Codex gpt-6.x (Sol/Astra) and Grok as workers. Which parts still add value beyond what these models do by default? Which parts only cost tokens, ceremony and latency?

**Answer in one line.** The evidence, receipt, contract and orchestration layers still earn their place. The always-loaded surface did not: it was about 67K chars per turn, half of it restated defaults or one project's data, and it could re-bloat because its budget gate was broken. This PR cuts it to about 34K chars (−49%) and repairs the gate. Every behaviour backed by a recorded failure is kept.

## 1. Per-turn cost, measured

Measured with `node scripts/measure-always-loaded.mjs --compare <main-report>` (new in this PR). Characters are exact. Tokens are a chars/4 **estimate**, not a tokenizer count.

| Paid every turn | main | this PR | saved |
|---|---:|---:|---:|
| Skill descriptions (98 model-invocable of 106) | 41,812 | 22,906 | 18,906 |
| Agent descriptions (28 agents, Agent tool listing) | 13,953 | 8,531 | 5,422 |
| Always-on rules (Claude `~/.claude/rules`) | 11,447 (5) | 3,053 (4) | 8,394 |
| **Total** | **67,212 ≈ 16.8K tok** | **34,490 ≈ 8.6K tok** | **32,722 ≈ 8.2K tok/turn** |

| Paid once per session per rule (20-event corpus, fresh session each) | main | this PR |
|---|---:|---:|
| Rule-injector text delivered | 100,089 chars | 55,403 chars |
| Deliveries judged irrelevant to the action | 11 | 3 |

How the numbers matter:

- **Truncation.** Claude Code's skill listing is budgeted at about 1% of context, around 40K chars. At 41.8K active chars (45K counting all 106 skills), svc ran at about 107% of that budget, so some descriptions were being cut. Below the budget, every description is listed in full again, which improves triggering on top of the token saving.
- **Re-bloat.** `validate-context-budget.sh` read `<name>/SKILL.md` instead of `skills/<name>/SKILL.md`. It counted 0 chars and passed while the catalog grew from 36K to 45K. Fixed, with a fail-closed check on unreadable skills.
- **Other hosts.** Codex installs no rules. Grok, Kimi, Cursor, Gemini, OpenCode and MiMo install every universal-stack rule (36 files, 126,689 bytes) into their rules directory, because they have no injector (`setup:706`). Whether those hosts load the whole directory every turn was not verified here; see owner decision D3.
- **This repo's own context.** When working on the framework itself, Claude also loads this repo's `CLAUDE.md` (11.9K) and Codex loads `AGENTS.md` (29.4K). Neither changed in this PR: 10+ validators pin `AGENTS.md` text. See D7.

This audit extends that direction to the always-loaded surface.

## 3. Changes in this PR (top 10)

1. **Context-budget gate repaired** (`validate-context-budget.sh`). It now resolves `skills/<name>/SKILL.md` and fails when any skill is unreadable. Ceilings tightened: catalog 42000 → 28500, always-on rules 14000 → 4000 bytes.
2. **All 106 skill descriptions slimmed** to "what it does + phrases users say + any not-for boundary" (41.8K → 22.9K active chars). Receipt paths, phase ids and WI numbers moved out. The routing index was recompiled and the router corpus still passes 100%.
3. **route-workflow no longer claims every request.** It routes svc work and says that questions, explanations and read-only lookups do not need it. This removes the largest ceremony-on-trivial-task trigger. The body is unchanged: 33 validators pin its phrasing.
4. **Always-on rules 11.5K → 3.1K chars.** Each keeps its load-bearing lines. `tool-selection` goes always → lazy. The verify-state incident narrative and the per-program canonical-ref map move to `references/rule-details/` (no information lost).
5. **Rule injection gated by `signals.repo_markers`.** Base44 rules no longer fire on `public/`, `dist/`, `functions/`, `rls` or `otp` paths in non-Base44 repos. `plan-changeset-trigger` now fires only in the framework repo. `web/performance` fires only on web file types. Provider-fidelity fires only on provider/AI test files.
6. **Dead signal fixed.** `no-fabrication`'s written-content triggers lived under `content`, a key the injector never reads. They are now under `keywords`.
7. **Injected rule text drops YAML frontmatter.** Metadata is for tooling. Each injected rule is about 300–500 chars smaller, and more rules fit the 8.5K budget as full text instead of pointers.
8. **`svc-preflight-skill` installed on the `Skill` matcher only.** `hooks.json` already documented this, but `wire-hooks.mjs` still used `*`: one node spawn (80–200ms measured) on every tool call for a hook that exits immediately unless the tool is Skill.
9. **15 role-agent descriptions slimmed** (13.9K → 8.5K chars). Role, propose-only, secrets posture and never-self-selects are all kept. `.claude/agents` regenerated.
10. **base44-environment body 72KB → 39KB.** One project's inventory (functions, collections, DB dump, walkthroughs, cron) moved verbatim to `skills/base44-environment/references/environment-reference.md`, with a section map. Auth, secrets, deploy gotchas, RLS audit and post-deploy evidence stay in SKILL.md.

Also: the retire candidates `quick-fix` (already retired, WI-512), `extract-bootstrap`, `honest-diagnosis` and `craft-prompt` get `disable-model-invocation: true`. They cost nothing per turn and remain slash-invocable. They were **not** moved to an archive folder; see D1.

New tests: `validate-always-loaded-budget.mjs` (7 cases: measurement, noise ceiling, Base44 gating both directions, frontmatter stripping, `--compare`, usage errors), `validate-skill-ab-eval.mjs` (6 cases), plus a matcher assertion in `validate-preflight-enforcement.sh`. Updated: `validate-rule-injection.sh` (always set 5 → 4) and the lint allowlist.

## 4. Testing skill value from here on

The bar is the one this audit applied: **a skill earns its tokens only if it beats the bare model on something checkable.**

1. **Per-turn cost: deterministic, free, in CI.** `scripts/measure-always-loaded.mjs` reports per-turn chars, plus rule-injection noise over `test-framework/fixtures/always-loaded/events.json`. Each event is labelled with the rules a reviewer judged relevant. `validate-always-loaded-budget.mjs` and `validate-context-budget.sh` fail on re-bloat or new noise. Add an event whenever you add or retune a signal rule.
2. **With-skill vs bare: paid, run on demand.** `EVALS=1 node scripts/skill-ab-eval.mjs --tasks test-framework/evals/skill-ab/tasks.json --repeat 3` runs each task twice: the bare prompt, and the prompt plus SKILL.md (so the with-skill arm pays the skill's real context cost). Graders are deterministic, regex or command. The report gives the pass-rate delta, the token delta and a verdict (`earns-keep`, `no-gain` or `regresses`). Any runner works, e.g. `--runner "codex exec -"` for Codex. The hermetic fake runner keeps the harness itself under tier-1. **Not run in this PR:** it spends paid tokens, so no with-skill vs bare numbers are claimed here.
3. **Grade the contract, not the prose.** A frontier model writes a good spec without the skill. What the skill must add is the artifact other svc tooling reads (`Status: DRAFT`, AC tables, brief sections, receipts). Write each task's grader against that contract plus one correctness check. A tie on such a grader is real evidence that the skill can be slimmed or retired.
4. **Quality comparisons** keep using the existing blind comparator in `skills/create-skill` (`agents/comparator.md`). **Description triggering** keeps using `skills/create-skill/scripts/run_eval.py`. **New rules** keep going through `evaluate-rule`.
5. **Workflow for the owner:** before a SLIM or RETIRE of any KEEP skill, add one task for it to `tasks.json`, run the A/B at `--repeat 3` and attach the report. That replaces this audit's judgement with measurement.

## 7. Method and limits

- **Who classified what.** Six read-only inventory passes classified every skill (106), rule (48) and hook entry (44 rows: 38 catalog plus 6 installed-only). Each pass cited the SKILL.md or rule lines, `references/framework-learnings.jsonl` keys, callers in the manifest and other skills, and recent commits. Repository history was squashed on 2026-09-14, so older commit evidence is not available. I reviewed every proposed description before applying it, and restored boundaries where a proposal dropped one (for example research's "not for ordinary coding uncertainty").
- **How "default behaviour" was judged.** By reading what the Claude Code harness prompt and tool descriptions already instruct, and what frontier models do unprompted. It was not measured. The A/B harness in §4 is how to turn those judgements into numbers.
- **Where it was ambiguous**, the conservative class was chosen: SLIM over RETIRE, `disable-model-invocation` over archive, lazy over delete. Every RETIRE is pending the owner.
