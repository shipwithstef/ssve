# Optional GitHub Projects guidance

SSVE work items remain local execution, worktree, receipt, and verification authority. `issue_tracker` is `local-only` by default. GitHub Issues is optional public intake/projection, configured explicitly for one exact `OWNER/NAME` repository. The framework does not require a GitHub Project, custom fields, a private project name, board views, labels, or an automation that moves an issue to Done when a PR merges.

For `github-backed`, explicitly pull a selected issue as `WI-GH-N` before routing; only adopted mirrors may be published. For `hybrid-governed`, explicit publication may also use a local numeric WI. Capture, onboard, list, and execution remain offline in all modes. Never turn a local work-item file into an issue by copying its raw body, and never bulk publish or infer remote mode from repository visibility. Use `sync-work-items` with a reviewed public title and body file for each selected publication. The tracker CLI owns only its delimited issue-body block; it preserves human text, comments, and unrelated labels.

A PR for a mapped issue may say `Related to #N`. Do not use GitHub auto-close keywords (`Fixes`, `Resolves`, `Closes`) because merge precedes G7 verification. Only `--close-wi ID --commit SHA`, after a matching passing durable `verify-promotion` note, may close it. If the optional `close_trigger` is `manual`, print that command after G7; if set to `verify-promotion`, run it after the receipt is emitted. A GitHub outage leaves local `VERIFIED` and the note intact and leaves a visible `close-pending` retry. See `docs/issue-tracking.md` for configuration and commands.

Teams may configure their own GitHub Projects fields and views outside this framework. Those choices do not change work-item authority or authorize issue publication or closure.
