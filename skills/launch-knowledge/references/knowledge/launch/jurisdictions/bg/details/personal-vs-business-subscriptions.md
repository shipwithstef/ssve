# BG EOOD — Personal vs Business AI/Dev Subscriptions

**Layer:** 3 (detail)
**Topic:** When and how to switch from personal subscriptions to business-account subscriptions for software companies operating under a BG EOOD
**Sources:** Anthropic Claude ToS, OpenAI ChatGPT Plus/Business comparisons, GitHub Copilot plans documentation, Cursor community forums, Bulgarian tax practice references

---

## Mechanism

When a Bulgarian EOOD operates with software/AI tools, every subscription has THREE layers that determine its handling:

### Layer A — Provider's Terms of Service

| Provider | Personal plan permits | Personal plan forbids |
|---|---|---|
| **OpenAI ChatGPT Plus** ($20/mo) | Commercial use of outputs, output ownership | (data may train models unless opted out) |
| **Anthropic Claude Pro** ($20/mo) | "Limited commercial use with substantial human contribution" | **Powering multi-user services**, selling raw outputs, thin wrappers, reselling access |
| **GitHub Copilot Individual** ($10/mo) | User owns generated code, commercial use | (no IP indemnity from Microsoft, usage data collection) |
| **Cursor Pro** ($20/mo) | Personal/professional use | (VAT must be added post-purchase as separate step) |

**Critical distinction:** "individual" plans usually permit commercial use of OUTPUTS but the plan itself is licensed for individual use, not corporate deployment. Multi-user SaaS products that route end-customer requests through a personal plan typically violate ToS.

### Layer B — Bulgarian tax deductibility

| Invoice recipient | Deductible by EOOD? | VAT treatment |
|---|---|---|
| EOOD legal entity (with ЕИК + VAT number on invoice) | Fully deductible business expense | Reverse charge under чл. 97а ал. 1 (foreign vendor, mandatory monthly declaration) |
| Individual personally (Diana's name on invoice) | NOT directly deductible | Personal expense, no business VAT treatment |
| Individual then reimbursed by EOOD | Conditionally deductible (requires documentation, board decision, business-purpose justification) | Indirect; tax authorities scrutinize |

For ongoing subscriptions, switching the billing identity from individual to EOOD is the cleanest path. Reimbursement is OK for one-off purchases but problematic for recurring monthly charges.

### Layer C — Operational hygiene

- **IP ownership chain** — when personal-plan subscription generates code that ships in EOOD's product, the IP-transfer chain gets a question mark: did the personal-plan ToS actually grant the EOOD rights, or just the individual? Business plans give clean entity-level rights.
- **Data privacy** — personal plans (especially OpenAI free/Plus) train on data by default; business plans contractually exclude training
- **Audit defense** — clean entity-level subscriptions = clean accountant workflow; mixed personal/business = explanations to NRA

## Analysis

### When personal plans are acceptable

- **Pre-revenue, EOOD not yet operational** — building/learning, no customer-facing deployment
- **Personal experimentation, education, side-research** — clearly not in EOOD's product path
- **One-off small purchases** — books, courses, single API tokens for testing
- **Sole-founder solo dev with NO customer-facing AI in production** — gray-area but defensible

### When personal plans become problematic

- **Production code uses the AI tool** — code generated by Cursor/Copilot/Claude personal plan ships to customers as part of Example Marketplace features → IP-transfer chain gets murky
- **End-customer requests route through your personal AI plan** — e.g., Example Marketplace's AI deal generation calls OpenAI/Claude API; if billing is on Diana's personal account, that's a multi-user service powered by a personal plan = ToS violation for Claude Pro explicitly
- **Subscriptions cross the threshold of "regular ongoing business expense"** — monthly subscriptions paid personally for >3-6 months become hard to reimburse cleanly through the EOOD
- **Enterprise customers do vendor diligence** — finding personal subscriptions in production stack is a flag

### Example Marketplace-specific application

Example Marketplace uses AI in production (per CLAUDE.md): `generateAIDeal`, `processReceipt` (OCR), `PersonalizedOffer`. AI credits as a paid tier feature. This means:

1. **Claude Pro is INSUFFICIENT** — Pro's ToS explicitly forbids "powering multi-user services" — Example Marketplace's `generateAIDeal` IS a multi-user service. Either:
   - Use Anthropic API on commercial terms (pay-per-token) for Example Marketplace features
   - Upgrade to Claude Team/Enterprise

2. **OpenAI Plus is borderline** — outputs commercially usable, but plan licensed for individual; for production deployment use OpenAI API (pay-per-token) instead of routing through Plus account

3. **GitHub Copilot Individual is acceptable** — Microsoft licenses it for any code (including commercial), only difference vs Business is IP indemnity (worth $19 vs $10 if shipping to enterprise customers)

4. **Cursor Pro is acceptable** — for development tool usage; add EOOD VAT number after purchase to enable reverse charge

### Phased migration plan

| Phase | Trigger | Action |
|---|---|---|
| Pre-formation | EOOD not yet incorporated | Personal plans acceptable for dev/learning; document which are for business |
| Post-ЕИК, pre-revenue | EOOD has ЕИК + bank account | Switch development tooling subscriptions (Cursor, GitHub Copilot) to EOOD billing |
| Pre-production-deployment | First version using AI in customer-facing flow | Switch to API-based commercial terms for production AI calls (OpenAI API, Anthropic API); keep personal Pro plans for dev only |
| Post-first-customer | Real revenue flowing | All subscriptions on EOOD; consider Team/Enterprise plans where solo-friendly |
| Pre-enterprise-pitch | B2B customer doing vendor diligence | Move to Business/Enterprise plans across all AI tools for indemnification |

## Single-person EOOD — common confusion clarified

A frequent question from solo founders incorporating an EOOD: "Will the platforms have an issue with my personal subscription if I'm a single-person EOOD?"

**Short answer: NO, single-person EOOD status doesn't change anything. Platforms don't care about company size — they care about TWO separate things:**

### What actually matters

| Concern | What the platform/authority cares about | NOT this |
|---|---|---|
| ToS compliance (provider) | What the tool is DOING (personal use vs multi-user service) | Whether you're solo or 100-person |
| Tax deductibility (НАП) | WHO is invoiced (EOOD legal entity vs individual) | Whether the account login is "personal email" or "business email" |

The "single-person EOOD" status is irrelevant to both. Solo founders use personal-tier plans constantly without issues — Cursor, GitHub Copilot Individual, ChatGPT Plus, Claude Pro all support solo dev work explicitly.

### The line that DOES matter — "what is the tool doing"

| Use pattern | Personal-tier plan acceptable? |
|---|---|
| Founder uses Cursor / GitHub Copilot / Claude Pro / ChatGPT Plus to write code, draft documents, learn | ✅ YES — personal tier explicitly allowed for solo commercial use |
| Founder asks AI tools business questions, plans architecture, debugs | ✅ YES |
| Product backend automatically calls AI API on behalf of end-customers in production | ❌ NO — needs API on commercial terms (separate from Pro/Plus subscriptions); personal tier ToS prohibits "powering multi-user services" |
| Product UI shows AI-generated content to end-users without API integration | ❌ NO — same as above |

The distinction:
- **Tool helps the founder personally** → personal-tier plan ✅
- **Tool powers a multi-user product feature** → API on commercial terms ✅, personal plan ❌

### Why this matters for Example Marketplace-style products

Example Marketplace's `generateAIDeal`, `processReceipt`, `PersonalizedOffer` features call AI APIs on end-customers' behalf. These are multi-user service flows, NOT personal use of the AI tool. Therefore:

- Founder's personal Claude Pro / ChatGPT Plus = fine for IDE coding, dev work, learning
- Example Marketplace backend MUST call Anthropic API / OpenAI API on commercial terms for production AI features
- These are TWO DIFFERENT billing relationships, not one

A solo founder of an EOOD typically ends up with:
1. Personal Pro/Plus subscriptions for dev work (own usage, billed to either personal or EOOD)
2. Separate commercial API accounts for production product calls (always billed to EOOD)

Both are valid. The fact that the EOOD has 1 person rather than 10 doesn't change the structure.

### What providers actually check at signup

| Check | Provider runs it? |
|---|---|
| Verify you're solo vs team | ❌ No — providers don't ask company size at consumer-tier signup |
| Verify ToS compliance with how you use the tool | ⚠️ Reactive only — they don't audit; they enforce if you violate (rate limits, account suspension for clear ToS breach) |
| Check if you're a registered legal entity | ❌ No — they don't require this for personal-tier plans |
| Validate VAT number for billing | ✅ Yes — when adding billing details, they verify the VAT number is real |

So at the platform level, a solo founder using ChatGPT Plus to research and Claude Pro to code is invisible — same as any other Plus/Pro user. The platforms have no way of knowing you have an EOOD, nor do they care.

The only exposure is if you violate Pro plan ToS by routing multi-user product traffic through it — and that's the same risk regardless of EOOD size.

## Migration mechanics — when ЕИК lands

The Bulgarian tax authority cares WHO is invoiced, not WHO uses the service. The account email can stay personal — what matters is the BILLING details on the account showing EOOD legal name + ЕИК + VAT number.

### Three migration paths per provider

**Path 1 — Update billing details only (preferred where possible):**
Same account, same email, same usage. Open Settings → Billing → add VAT + company info. Provider's next invoice goes to EOOD entity. Works for: Cursor, ChatGPT Plus, Claude Pro, GitHub Copilot Individual.

**Path 2 — Parallel account on EOOD email (required for org-level products):**
Create a separate account under business email. Personal account stays for dev/learning; EOOD account handles production. Required for: Anthropic API (console.anthropic.com), OpenAI API (platform.openai.com), GitHub Copilot Business (via GitHub Organization).

**Path 3 — Cancel and re-subscribe (avoid):**
Cancels current subscription, creates new under EOOD billing. Loses history, settings, saved prompts. Only use if Path 1 and Path 2 are both unavailable.

### Critical prerequisite: EOOD bank account + card

Before ANY billing migration is useful, the EOOD needs:
1. Bank account in EOOD's name (Wise Business / Revolut Business — free, opens within days of ЕИК)
2. Debit/credit card issued by that account

Without an EOOD card, "updating billing details" is pointless — the personal card is still funding the subscription, which is the same problem with extra paperwork.

### Standard sequence

| Step | When | Cost |
|---|---|---|
| EOOD ЕИК issued | T+0 (week 1-2 after lawyer engagement) | — |
| Wise/Revolut Business account opened | T+2 days | Free |
| EOOD card issued | T+1 week | Free |
| Update billing on all consumer-tier subscriptions (Cursor/ChatGPT Plus/Claude Pro/Copilot Individual) | T+1 week, ~30 min total | No new cost |
| Sign up for Anthropic + OpenAI API as NEW accounts under EOOD | Before production AI features ship | Pay-per-token, no upfront |
| Migrate production code to use org API keys | Before public launch | — |

### Provider-specific notes

| Provider | Account email | Billing change path | Special notes |
|---|---|---|---|
| Cursor | Personal OK | Path 1 — Settings → Manage Subscription → Add VAT | Stripe-backed, accepts mid-cycle billing changes |
| ChatGPT Plus | Personal OK | Path 1 — Settings → Billing → Tax info | Plus is "personal license"; Team requires Workspace setup (Path 2) |
| Claude Pro | Personal OK | Path 1 for dev use | For Example Marketplace production: Path 2 separate Anthropic API account |
| GitHub Copilot Individual | Personal OK | Path 1 for dev use | For Business: Path 2 — create EOOD GitHub org, buy org seats |
| Anthropic API (commercial) | EOOD email | Path 2 only | NEW account at console.anthropic.com — different from Pro |
| OpenAI API (commercial) | EOOD email | Path 2 only | NEW org at platform.openai.com — different from Plus |

### What NOT to do

- ❌ Cancel personal account and re-subscribe under EOOD email — loses chat history + settings; no tax benefit
- ❌ Pay personally and reimburse through EOOD monthly — accountant headache, NRA scrutiny
- ❌ Use personal Pro plans for production AI calls in customer-facing flows — ToS violation (Anthropic explicit, OpenAI gray area)
- ❌ Mix personal and EOOD billing on the same account by alternating cards — confuses invoice trail

### What to ask the accountant

When the consultation arranges this, specifically ask:
1. Format of invoice required for full deductibility — does provider's invoice need EOOD-stamped or is electronic invoice with EOOD details sufficient?
2. чл. 97а ал. 1 reverse charge mechanics for monthly recurring foreign-vendor invoices — monthly declaration cadence
3. VAT-number registration timing — chl. 97а ал. 1 mandatory before first foreign vendor invoice arrives at EOOD
4. Treatment of pre-EOOD-existence subscription expenses — Diana paid personally before EOOD existed; reimbursable retroactively or written off?
