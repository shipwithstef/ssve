# OpenTable for Restaurants — Fill seats, build relationships, grow revenue

**URL:** https://restaurant.opentable.com
**Captured:** 2026-04-27 (pattern.md only; hero.png/.webm TODO-capture)
**Sector:** b2b-saas-vertical (reservation + guest CRM)

## What it does well

- **Hero leads with the diner-network number, not the software.** "Reach 134 million diners on OpenTable" — the marketplace is the moat; software is table stakes. Visitor immediately understands they're buying access to demand, not just a calendar widget.
- **Hero visual is a packed-restaurant photo with reservation-list overlay.** Emotional + functional in one frame — packed dining room (the goal) + the operator UI (the means).
- **Three-tier pricing on hero with diner-cover-fee transparency.** Most reservation platforms hide the per-cover commission — OpenTable shows it ("$0.25 per cover" or similar) up front. Honesty about cost differentiates from Resy / SevenRooms.
- **"Switch from Resy / Yelp / Tock" CTA strip below hero.** Direct competitor naming with migration-assistance promise. Aggressive but works because OpenTable has the demand-side scale to back it up.
- **Mid-page "GuestCenter" demo video uses a real host on a real shift.** No actor; the visitor sees the actual UX in a real chaotic Friday-night context. Builds credibility that the product survives real pressure.
- **Network-effect proof: "diners who book on OpenTable spend 23% more."** Sourced number that benefits the operator (your diners spend more when they came through us). Aligns the marketplace's interest with the operator's.
- **Help-center search is the first thing in the footer.** Signals "we know operators need fast answers during shift" — small but telling product-empathy detail.
- **Cuisine + price-tier filtering on diner-side proof points.** "Italian / Sushi / Steakhouse / Vegan" segmentation lets operators in any category see relevant peer success stories.
- **Mobile-host app preview included.** Tablet-to-phone responsive showcase — communicates that staff can run from a phone when iPads aren't available.

## What it gets wrong

- The diner-cover-fee model creates ongoing tension with operators (Resy's flat-fee model is a wedge). Page doesn't acknowledge this directly, which feels evasive once the visitor learns about it elsewhere.
- Loyalty-points system for diners isn't explained from the operator perspective — operators don't understand how it benefits THEIR business, just how it benefits OpenTable.
- "Switch from competitor" CTAs don't quantify the migration effort — operators worry about losing reservation history during cutover.

## Reusable archetype name

**Marketplace-scale hero with cost-transparency wedge** — hero leads with demand-side scale number (network is the product), pricing transparency used as differentiator against opaque competitors, competitor-switching CTA strip leveraged because marketplace scale earns the right to be aggressive.

## When to use this archetype

When the product has a genuine demand-side network effect (millions of consumers using the marketplace) AND competitors hide their pricing structure. Cost transparency only works if your model is genuinely competitive. NOT a fit for: pure-supply-side tools, products without consumer-facing network.

## Feature mix surfaced

- "Reach 134M diners on OpenTable": full-page hero number + diner-network animated counter
- "GuestCenter — manage reservations, waitlist, tables in one screen": sub-hero with live-shift video
- "Guest CRM: track preferences, allergies, repeat-visit history": mid-page section with sample profile screenshot

## Adoption notes

When porting this archetype, the most common mistake is copying the surface aesthetic without copying the underlying buyer-context that makes it work. Verify the buyer-segment fit BEFORE imitating the visual signature — the archetype name names the technique, not just the look. If the buyer-context match is weak, downgrade to a borrowed sub-element (one bullet) rather than the whole pattern.
