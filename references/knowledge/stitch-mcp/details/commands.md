# Commands (Layer 3)

## `init` — 9-step wizard

1. **ClientSelectionStep** — antigravity, vscode, cursor, claude-code, gemini-cli, codex, opencode
2. **AuthModeStep** — API key vs OAuth
3. **GcloudInstallStep** — install bundled gcloud at `~/.stitch-mcp/google-cloud-sdk/` (OAuth only)
4. **AuthStep** — runs `gcloud auth login` + `gcloud auth application-default login` (OAuth only)
5. **TransportStep** — stdio (proxy) or http (direct)
6. **ProjectSelectStep** — pick GCP project (OAuth only)
7. **IamApiStep** — verify IAM role, install gcloud beta, enable Stitch API (OAuth only)
8. **ConfigStep** — write MCP config to client-specific path
9. **TestConnectionStep** — hit Stitch API, verify (OAuth only)

Flags: `--client`, `--transport`, `--yes` (auto-approve), `--defaults`, `--local` (install gcloud in project dir instead of `~/`).

## `doctor` — 7 health checks

| Check | Mode | Fix |
|-------|------|-----|
| API Key Detected | API key | Set `STITCH_API_KEY` |
| gcloud Installed (≥400.0.0) | OAuth | Run `init` |
| Authentication | OAuth | `gcloud auth login` |
| Application Default Credentials | OAuth | `gcloud auth application-default login` |
| Project Configured | OAuth | `gcloud config set project <id>` |
| API Key Connection | API key | Check key + billing |
| API Connection | OAuth | Check project + billing + API enable |

`--verbose` prints HTTP error details.

## `logout`

- `--force` — skip confirmation
- `--clear-config` — delete entire `~/.stitch-mcp/` dir

## `serve -p <id>`

Vite dev server. Key features (see serve-and-preview.md for details):
- `/screens/{screenId}` routes
- `/_stitch/asset?url=<encoded>` asset proxy (fonts, images)
- CSS `url()` rewriting
- Disk cache at `.stitch-mcp/cache/`
- Hot reload

## `screens -p <id>`

Terminal browser with `v`/`c`/`o`/`q` keys.

## `view`

Tree browser. Flags: `--projects`, `--name`, `--sourceScreen`, `--project`, `--screen`, `--serve`. Keys: arrows, Enter, `c`/`cc`, `s`, `o`, `q`.

## `site -p <id>`

Generates Astro project. Flags: `-o output`, `-e export`. Interactive mapper with include/exclude/discard per screen. Produces:
```
package.json, astro.config.mjs
src/layouts/Layout.astro
src/pages/{route}.astro   # one per mapped screen
public/assets/            # downloaded images/fonts
```
`--export` emits `build_site`-compatible JSON instead of scaffolding.

## `snapshot`

UI snapshot given data state. `-c <command>` `-d <data.json>` `-s` (print schema).

## `tool [name]`

Invoke any MCP tool from CLI. Flags: `-s` schema, `-d` JSON inline, `-f` JSON file, `-o json|pretty|raw`. Steps pipeline: ParseArgs → ListTools (if no name) → ValidateTool → ShowSchema (if `-s`) → ExecuteTool.

## `proxy`

Start MCP proxy. Flags: `--transport stdio|http`, `--port <n>`, `--debug`.

## Analysis

Every command follows the Spec & Handler pattern (see architecture.md). Each
`src/commands/<name>/` has `command.ts` (commander binding), `spec.ts` (Zod
contract), `handler.ts` (implementation), `handler.test.ts`, `spec.test.ts`,
and usually a `steps/` dir of multi-step wizards via `StepRunner`.

The 9-step `init` is a textbook example of breaking a complex flow into
reviewable, testable, re-runnable steps — each step is its own class
implementing `CommandStep`.

## Layer 4 pointers

- All command handlers: `src/commands/<name>/handler.ts`
- Step implementations: `src/commands/<name>/steps/*.ts`
- Framework: `src/framework/StepRunner.ts`, `CommandDefinition.ts`, `CommandStep.ts`
- CLI entrypoint: `src/cli.ts` → `src/index.ts`
- Bin: `bin/stitch-mcp.js` (generated by `scripts/generate-bin.ts`)
