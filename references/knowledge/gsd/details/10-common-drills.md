# Deep Drills: Top 10 Common Implementations

This document drills down into how GSD implements 10 "common" agentic framework features—problems that both Serious Vibe Coding (SVC) and GSD must solve (like parsing markdown, building prompts, or loading configs). Reviewing GSD's approach provides alternative architectural patterns for SVC.

---

## 1. Markdown Frontmatter Parsing (`bin/lib/frontmatter.cjs`)

**The Common Problem:** Standard YAML parsers (like `js-yaml`) are bulky and often fail on LLM-generated malformed YAML.
**GSD's Implementation:**
GSD wrote a bespoke, zero-dependency state-machine parser (`extractFrontmatter`). 
- It strictly matches `^---\r?\n([\s\S]+?)\r?\n---` anchored at byte 0, ignoring any `---` horizontal rules in the markdown body.
- It calculates indentation (`line.match(/^(\s*)/)[1].length`) to track nested objects using a stack.
- It includes a specialized `splitInlineArray` function that is quote-aware, correctly splitting `tags: ["a, b", c]` without breaking on the inner comma.

## 2. Config Loading & Merging (`bin/lib/config.cjs`)

**The Common Problem:** Managing defaults, global user preferences, and local project settings.
**GSD's Implementation (`buildNewProjectConfig`):**
It uses a strict 3-tier deep merge strategy:
1. **Hardcoded Defaults:** (e.g., `model_profile: 'balanced'`).
2. **Global Overrides:** Reads `~/.gsd/defaults.json`. Automatically migrates deprecated keys (e.g., silently migrating `depth` to `granularity`).
3. **Local/User Choices:** Project-specific arguments.
The deep merge uses the spread operator down to specific sub-objects (like `git` and `workflow`), guaranteeing no missing keys.

## 3. LLM XML Tag Parsing (`sdk/src/plan-parser.ts`)

**The Common Problem:** Extracting structured tasks generated by the LLM inside markdown.
**GSD's Implementation:**
Uses non-greedy regex matching to pull XML elements out of markdown blocks:
- Tasks are extracted via `/<task[^>]*>([\s\S]*?)<\/task>/g`.
- For each task, it runs targeted regexes: `/<name>([\s\S]*?)<\/name>/`, `/<files>/`, `/<action>/`, `/<verify>/`.
- It dynamically generates `warnings` if `<verify>` or `<done>` tags are missing, but produces hard `errors` if `<name>` or `<action>` are omitted, cleanly separating malformed plans from sub-optimal ones.

## 4. Agent Prompt Building (`sdk/src/prompt-builder.ts`)

**The Common Problem:** Assembling a massive execution prompt from a task plan.
**GSD's Implementation (`buildExecutorPrompt`):**
Rather than building prompts ad-hoc, it uses a modular assembly line:
1. **Agent Definition:** Reads `gsd-executor.md`, extracts the `tools:` frontmatter, and grabs the core persona from the `<role>` block.
2. **Context Injection:** Formats `plan.context_refs` into a strict list: `- @path/to/file` (which the Prompt Sanitizer later resolves).
3. **Task Formatting:** Iterates over the tasks array, assembling the `Action`, `Verify`, and `Done when` blocks sequentially, injecting them below the role definition.

## 5. Event Stream Transport & ANSI Coloring (`sdk/src/cli-transport.ts`)

**The Common Problem:** Emitting rich, colored CLI output without relying on external dependencies like `chalk` or `kleur`.
**GSD's Implementation (`CLITransport`):**
- Defines raw ANSI codes as constants (`const GREEN = '\x1b[32m'`).
- Implements an event-listener model (`onEvent(event: GSDEvent)`).
- Intercepts `GSDEventType.CostUpdate` events to maintain a stateful `this.runningCostUsd`, automatically injecting the accumulated session cost into the terminal output in real-time.

## 6. Temp File Garbage Collection (`bin/lib/core.cjs`)

**The Common Problem:** Frameworks that use `/tmp/` for passing context between hooks and agents eventually bloat the user's hard drive.
**GSD's Implementation (`reapStaleTempFiles`):**
Runs opportunistically before new writes.
- It scans the `os.tmpdir()` for files starting with `gsd-`.
- It checks the `mtime` (modified time).
- If the file is older than `maxAgeMs` (default: 5 minutes), it unlinks it. This guarantees the temp folder is self-cleaning without needing background cron jobs.

## 7. Cross-Platform Path Normalization (`bin/lib/core.cjs`)

**The Common Problem:** Windows backslashes (`\`) break regex matches (like detecting `/src/migrations/`).
**GSD's Implementation (`toPosixPath`):**
A brutal, universal normalizer used instantly on any incoming file path:
```javascript
function toPosixPath(p) {
  return p.split(path.sep).join('/');
}
```
This guarantees all internal drift detection, schema detection, and worktree mapping functions can safely use forward-slash regexes regardless of the host OS.

## 8. Sub-Repo Detection (`bin/lib/core.cjs`)

**The Common Problem:** Knowing if a folder is a monorepo package or an independent git repository.
**GSD's Implementation (`detectSubRepos`):**
```javascript
const entries = fs.readdirSync(cwd, { withFileTypes: true });
// Skips hidden dirs (.git, .vscode) and node_modules
if (entry.name.startsWith('.') || entry.name === 'node_modules') continue;
// Checks if `<entry>/.git` exists.
```
This is significantly faster than shelling out to `git status` for every folder, allowing rapid, synchronous topology mapping.

## 9. JSON Error Boundaries (`bin/lib/core.cjs`)

**The Common Problem:** When an orchestrator script crashes, it spits text to stdout. If a bash hook was expecting JSON, the bash hook crashes.
**GSD's Implementation:**
GSD implements a global `_jsonErrorMode` toggle.
When `setJsonErrorMode(true)` is called, the global `error()` function stops throwing `process.exit(1)` with text, and instead writes `{"decision": "block", "error": "message"}` to stdout. This allows CLI scripts to fail gracefully when invoked by rigid JSON-parsing pipelines.

## 10. Git Command Wrapper (`bin/lib/core.cjs`)

**The Common Problem:** Managing `child_process` execution for Git without throwing unhandled exceptions on expected failures (like `git rev-parse` failing on a fresh repo).
**GSD's Implementation (`execGit`):**
Wraps `spawnSync`. Instead of throwing, it always returns a structured object: `{ stdout, stderr, exitCode }`. This allows the framework to do safe probes (like checking if a branch exists) by just checking `if (result.exitCode === 0)` rather than wrapping every git call in a verbose `try/catch` block.
