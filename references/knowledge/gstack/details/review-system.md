# gstack Review System — Details

## Mechanism

### Review Army (7 specialists)

Dispatched in parallel during `/review` and `/ship`. Each specialist has a
focused scope and outputs structured findings.

| Specialist | Scope |
|---|---|
| testing | Missing negative-path, edge-case, isolation, flaky, security tests |
| maintainability | Dead code, magic numbers, stale comments, DRY, conditional side effects |
| security | Input validation, auth bypass, injection, crypto misuse, secrets, XSS, deserialization |
| performance | N+1 queries, missing indexes, algorithmic complexity, bundle size, rendering, pagination |
| data-migration | Reversibility, data loss risk, lock duration, backfill, index creation, multi-phase safety |
| api-contract | Breaking changes, versioning, error consistency, rate limiting, docs drift, backwards compat |
| red-team | 5 adversarial attack vectors against the diff |

### Adaptive Gating

`gstack-specialist-stats` computes per-specialist hit rates from review JSONL.
- GATE_CANDIDATE: 0 findings in 10+ dispatches → specialist may be skipped
- NEVER_GATE: security + data-migration always run regardless of hit rate
- Finding fingerprints enable cross-review dedup between `/review` and `/ship`

### Review Checklist (review/checklist.md)

Two-pass review: AUTO-FIX obvious issues, ASK for judgment calls.

Categories:
- SQL & Data Safety
- Race Conditions
- LLM Output Trust Boundary
- Shell Injection
- Enum Completeness
- Async/Sync Mixing
- Column/Field Name Safety
- Dead Code
- LLM Prompt Issues
- Completeness Gaps
- Time Window Safety
- Type Coercion
- View/Frontend
- Distribution & CI/CD Pipeline

Severity classification: P0 (data loss/security) → P4 (style).
Fix-First heuristic: if fix is <5 lines and safe, just fix it.

### Design Checklist (review/design-checklist.md)

5 categories with confidence tiers:
1. AI Slop Detection (generic gradients, stock icons, meaningless animations)
2. Typography (font pairing, line height, hierarchy)
3. Spacing & Layout (inconsistent padding, alignment)
4. Interaction States (missing hover/focus/disabled/loading)
5. DESIGN.md Violations (design token drift)

AUTO-FIX vs ASK classification per finding.

### Greptile Integration

`review/greptile-triage.md` — process for triaging Greptile PR review comments:
- Fetch comments via API
- Check suppressions
- Classify: Tier 1 (auto-reply with fix) or Tier 2 (needs context)
- Severity assessment and re-ranking
- Reply via API with structured templates

### Review Readiness Dashboard

Generated by `{{REVIEW_DASHBOARD}}` resolver for `/ship`. Shows which reviews
have been run (PR review, design review, test coverage, adversarial, etc.)
and their status before shipping.

### Cross-Review Dedup

Findings users already skipped in a prior `/review` or `/ship` are auto-suppressed
on re-run (unless relevant code changed). Uses finding fingerprints.

## Analysis

The Review Army pattern of dispatching 7 specialized reviewers in parallel is
more thorough than single-pass review. The adaptive gating is data-driven:
specialists that consistently find nothing get gated, reducing token cost.
Security and data-migration are NEVER_GATE — good safety design.

The two-pass AUTO-FIX/ASK approach reduces noise: obvious fixes happen silently,
judgment calls surface explicitly.

The cross-review dedup between `/review` and `/ship` prevents review fatigue
from seeing the same findings twice.
